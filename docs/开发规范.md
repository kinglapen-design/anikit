# 开发规范

> 本规范对人与 AI 同时生效。与其配套的还有根目录 `AGENTS.md`（AI 工具入口）。

## 1. 架构分层

- 三层结构：**数据层**（JSON 读写、迁移、备份）→ **业务层**（命令与查询 API）→ **UI 层**。
- **单一写点：** 每个数据文件（folders.json、tags.json 等）只有一个模块负责写，其他模块只能通过它的接口操作。
- **UI 无业务：** UI 文件只调用命令接口、订阅状态，禁止写业务逻辑，禁止直接读写数据文件。
- **前后端解耦：** 所有功能（含基础操作）一律抽象为命令接口（command / query），UI、AI Agent、动画软件插件复用同一套接口——这是 PRD 8.3 AI Agent 的前提，也是插件生态的前提。

## 2. 接口与适配器

- 预览、动画软件通信、缩略图、搜索引擎、系统能力（剪贴板 / Shell 缩略图 / 全局热键 / 文件监听）全部走适配器接口。
- UI 行为由**能力标志**驱动（supportsTags、supportsSort 等），禁止在 UI 里散落 `if (封闭模式) else` 判断。
- 新软件、新格式 = 新增一个适配器实现，不修改既有代码。
- **Tauri 命令线程纪律：** 非 async 命令在主线程执行——凡涉及窗口创建 / IO 重活 / COM 调用的命令一律 `async fn`（线程池），主线程内 build 窗口会死锁（见踩坑 013）；纯内存快操作才用 sync。

## 3. 代码规模与组织

- 单文件目标 ≤ 300 行，硬上限 500 行，超出按职责拆分。
- 单函数 ≤ 50 行，条件嵌套 ≤ 3 层。
- 命名以 PRD 术语为准：Asset / Placement / originName / info 文件夹 / 素材库 / 工作空间，不造同义词。

## 4. 文档同步纪律（红线）

- **改需求先改 PRD，再写代码。** PRD 是唯一事实来源。
- 完成功能即时更新：接口文档（07）、项目进度（05）；踩坑即记（06）。
- 文档与项目实际状态不符视为 bug，发现即修；改样式时同步更新 `docs/06_UI重构/规范/口径速查/` 对应文档（2026-07-21 用户要求；2026-09-07 起原 02_样式与布局 并入 UI 重构/规范/）。
- **文档拆分纪律（2026-09-07 用户定）：一个任务一个文件。** 开发日志、当前状态等按 `YYYY-MM-DD[_NN]_标题.md` 命名，同一日期完成多个任务必须拆成多个文件；长表格按日期分文件；单个文件尽量 ≤ 40KB。每个文档文件夹配 `Index.md` 索引，新增 / 拆分文件时同步更新索引。
- UI 开发遇到没有 token 或设计参照的部分，先询问用户，禁止凭感觉自创样式。
- **样式值一律走 token 变量（`tokens.css`）**，禁止在组件中散落硬编码的颜色 / 间距 / 字号 / 圆角等数值；确属布局算法需要的常量集中在 `lib/layouts.ts` 并注释与 token 的对应关系；token 没有的值先补档（间距档 / 透明度档），不直接写字面量（2026-07-23 用户要求）。
- UI 线条（边框）禁止用 CSS `border`，一律 `box-shadow: inset 0 0 0 {宽}px {色}` 模拟——Figma 描边 inside 不占空间，border 外扩会让所有带边框容器比设计稿宽出一个边框厚度（见踩坑 008）。**例外：内容铺满容器时（图片 / SVG / 三栏面板 / 浮层卡片），inset shadow 绘制在内容之下会被不透明内容完全遮盖，改用真 border 或 ::after 伪元素绘制**（2026-07-23 主窗口 / 素材卡片 / 文件夹卡片实践）。
- **三段式手势（按下-移动-松开：框选 / 拖拽 / scrub）的结束条件禁止只挂 `pointerup` / `pointercancel`**——系统层随时会抢指针（截图、分屏 snap、系统级窗口移动），必须 `lostpointercapture` + `window blur` 双兜底强制取消，否则手势视觉层永久残留（见踩坑 026）。
- **`:hover:not(X)` 的 `:hover` 与 `:not()`（按参数计）都计入特异性**——合计高于普通双类。新增"悬停期间也要显示的状态类"（选中 / 拖拽 / 高亮）时，必须用 `:not(状态)` 排除法检查既有 hover 规则会不会压掉状态背景，禁止只堆状态类特异性（见踩坑 028）。

## 5. Git 纪律

- 改动前确保工作区干净（先提交或 stash）；功能分支开发，不直接在 main 上写。
- 小步提交：一次提交只做一件可以独立说明的事。
- 提交信息格式：`type: 内容`，type ∈ feat / fix / docs / refactor / perf / test / chore。
- 大改动（重构、数据迁移、批量删文件）前先打一个备份提交。
- reset / clean / push --force 等破坏性操作必须先经用户确认。
- AI 可在完成任务后、大任务开始前自行提交（2026-07-18 用户授权）；push / reset / rebase / clean 等破坏性操作仍须当场确认。

## 6. 错误处理与日志

- 不吞错误；用户可见的错误给中文人话文案，不给堆栈。
- 关键链路必须留日志：导入、备份、迁移、异步改名任务队列、缩略图生成、动画软件通信。

## 7. 性能纪律

- 列表必虚拟化（只渲染可视区 + 缓冲区）；图片解码必异步（createImageBitmap / 后端预生成多尺寸）。
- 布局预计算：等高不等宽用 metadata 的宽高算，滚动时不读图。
- 快速滚动降级：先显示主色占位（颜色提取数据），再替换清晰图。
- 超大列表滚动：采用自定义 transform 驱动滚动（原生滚动条瞬移必闪白，见踩坑 005）。
- 写操作先落盘再更新内存；大批量操作走任务队列，进度可见、可取消。
- **assets 池访问纪律：** 热路径禁止枚举 assets/ 根目录，一律按 ID 推导路径直接访问；`ID → info 路径`推导只经 core 单点函数，禁止各处自行拼（见 PRD `01_储存空间.md`，2026-08-12 定）。

## 8. 测试

- 数据层、版本迁移、命令 API 必须有单元测试；UI 层不强制。
- **裸 `tsc` 不检查 `.vue`**（vite/rolldown 只转译不查类型）——"tsc / build 全绿"不等于 SFC 无类型错；.vue 关键改动（尤其新引用变量）必须实际点一遍对应交互才算验证（见踩坑 027；vue-tsc 补盲评估中，09 待办）。
- 各阶段验收标准见 [05_项目进度](05_项目进度/Index.md)。

## 9. 依赖与轮子

- **有成熟轮子就不自研：** 布局、虚拟列表、Markdown 渲染、颜色提取、音视频处理、AI 模型推理等一律优先现成方案；自研只留给核心差异点（Asset/Placement 数据层、Animate 剪贴板格式、JSFL 插件、性能管线的组装）。
- **引入前四问：** 还在维护吗（近半年有提交 / issue 响应）？协议兼容吗（MIT / Apache / BSD，避开 GPL 传染）？体积代价多大？现有依赖里是不是已经有一个能解决？
- 依赖锁定版本；引入或更换大依赖时在 04_开发日志 记选型理由。
