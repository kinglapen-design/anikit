## 066 存在性判断误用 `iter().all(==)`——空表/全匹配两极端都成立，懒建变重复建档（2026-09-01）

- **现象：** 7.1 二十三轮走查续——用户实机报「角标改名后，中间面板卡片的角标消失了」：右栏详情面板显示新角标正常，网格卡片角标整个不见。
- **根因：** `set_archive_cover_settings` 记录懒建条件误写 `archives.iter().all(|a| a.folder_id == folder_id)`——`all` 在**空迭代器上恒 true**、在**全表皆本档案记录时**也 true：用户库里恰只有这一个档案有记录，每次确认封面都追加一条同 folderId 空壳副本。读侧不对称把 BUG 伪装成「改名丢失」：详情 `get_archive_data` 用 `find`（首条 = 真数据，面板显示新值正常），卡片 `list_archives` 全量返回、前端 `map[folderId] = a` **后写覆盖** → 空壳副本赢，角标/属性全空。同条件在「他档有记录、本档无」时 all 不成立 → 懒建跳过 → 紧随的 `.expect()` 直接 panic（未爆只是没走到）。
- **修法：** 条件改 `all(|a| a.folder_id != folder_id)`（custom_data.rs 既有正确口径——「全都不是」=「不存在」）；存量坏数据由开库自检 `fix_archives` 加**同 folderId 去重保留首条**自愈（更新永远落 find 命中的首条，后追加的副本必为陈旧空壳）。
- **预防：** ① 写「不存在则 X」判断就用 `!iter().any(==)` 或 `iter().all(!=)`，**禁用 `all(==)`**——空表语义反直觉（vacuous truth）；② 同一数据有 find-first / 全量-list 两条读路径时，写侧 BUG 会呈「一处正常一处丢」的假象——排查先比对两条读路径各自拿到哪条记录；③ 回归测试要覆盖「列表非空但无本档」与「唯一记录即本档」两个极端（原测试只测空表懒建，全匹配分支漏网）。
