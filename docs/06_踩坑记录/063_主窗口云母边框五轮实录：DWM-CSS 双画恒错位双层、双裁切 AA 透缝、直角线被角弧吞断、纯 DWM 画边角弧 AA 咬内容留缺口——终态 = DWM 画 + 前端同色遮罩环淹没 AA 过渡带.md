## 063 主窗口云母边框五轮实录：DWM/CSS 双画恒错位双层、双裁切 AA 透缝、直角线被角弧吞断、纯 DWM 画边角弧 AA 咬内容留缺口——终态 = DWM 画 + 前端同色遮罩环淹没 AA 过渡带

- **现象：** 2026-08-30（阶段七 7.1 十八轮八/十/十一/十三轮，用户实机连报）。云母模式主窗口：①前端 1px 描边与 DWM 边框叠画成双重线；②四角圆角与边框间透缝（露云母亮色）；③选择模式边框双层（外 DWM 暗色 + 内前端品牌框）；④二轮修法（前端直角线 + DWM 裁边）后四角描边断开、双层依旧；⑤三轮同色容错后角部仍"空出一个像素点"（选择模式高亮框下尤其明显）。
- **根因链（实机像素级测量坐实）：** DWM 边框线弧与 CSS `inset:0` 线弧是**两套光栅化路径**（圆心/半径差 ~1 物理 px 级）——异色双画显双层、同色双画只能遮直边、**角弧分叉带永远存在**；窗口圆角 CSS radius 8 裁切与 DWM 系统圆角裁切**双裁切**，AA 差四角透缝；直角线借 DWM 裁边 = 角弧内陷 ≈2.3px（radius 8×(1−√0.5)）> 线宽，角弧段被整段吞断；`DWMWA_COLOR_NONE` 抑制在本机（Win11 25H2 26200）未达预期观感。**测量存档：DWM 圆角裁切弧半径 = 10.3 物理 px @150% ≈ 7 逻辑 px（非 8）**——PIL 角部像素最小二乘圆拟合（探针不可见层，实机截屏法）；DWM 边框线宽 ≈1 物理 px。
- **四轮方案（后被实机否掉）：云母模式前端零线条**——圆角 DWM 裁（radius 0）、边框 DWM 染画、picking DWM 切染独存（`.window.fx-mica.picking::after` border 0）。实机 100%/125%/150% 缩放**四角仍有缺口**（Windows 搜索面板同病）：纯 DWM 画边时角弧 AA 过渡带直接咬内容色，深内容/浅壁纸对比把 AA 半透像素暴露成缺口——不画线 ≠ 没问题，AA 带里填什么色才是关键。
- **五轮终版（同日用户供 Codex 思路定稿）：同色遮罩环淹没 AA 过渡带**——`.window.fx-mica::before`：1px 边框线 + 1.5px 零模糊外扩阴影（`box-shadow: 0 0 0 var(--border-strong) <色>`），**同为边框色**（常态 `--n-g6` #333 / picking `--brand-border` #3DDDD2 随 DWM 切染同步）——过渡带整圈淹没成边框色、内容边缘退入弧内不暴露给 DWM AA；与 DWM 染色线同色重叠合一故无双层。几何：环圆角 `calc(--n-radius-8 - 1px)` = 7 = DWM 裁切弧内缩 1 贴其内缘，外扩阴影兜底各 DPI 裁切弧 ≤9 分叉；最大化 DWM 不裁角不画边 → 环同隐（`.window.maximized.fx-mica::before` 后置与 picking 环同 0,3,0 优先级拼顺序压）。实色模式（Win10）纯前端不变。**与四轮的本质区别：四轮让 AA 带裸奔，五轮把 AA 带涂成边框色——弧线对齐问题不复存在（整个分叉带都是自己人）。**
- **预防：** 窗口级装饰每一层只由**一方**画主色；云母模式边框/圆角主权交 DWM，前端若参与只能画**与 DWM 同色的遮罩层**（淹没 AA 过渡带），绝不画第二条异色/异径线；实色回退模式无 DWM 参与才可放心前端自绘。探针侧：headless 截不到 DWM 层，此类 BUG 只能实机验；**DWM 层实机排障法**：mss 截主屏物理像素 + PIL NEAREST 放大角部读像素 / 弧半径最小二乘拟合；ctypes `DwmGet/SetWindowAttribute` 直读直写（**BORDER_COLOR 只写属性，Get 返回 E_INVALIDARG 正常勿误判**；Set S_OK + 截屏看变色 = 链路有效实证）；EnumWindows + GetProcessTimes 反查进程启动时间，破解「dev 实机跑的是哪版代码」谜。
- **六轮实录（同日续，用户实机再报"圆弧变细/四边粗细不一/拉窗口到特定像素缝隙好转"）——五轮遮罩环被推翻，终态 = CSS 零绘制纯 DWM + transparent:false 方案一：**
  - **像素测量基线**（新立 `tools/win-border-measure.py`：mss 物理截屏 + PIL 剖线 + MoveWindow 相位驱动）：@150% **DWM 线 = 2 物理 px** 四边均匀；**Chromium 把 CSS 1px border 吸附成物理 1px 锐线**（宽度吸附设备像素无半透列——"分数 DPR 下 1px 必糊"假设被推翻）；但五轮遮罩环与 DWM 线并集左右不对称（左/上边视口缘贴 DWM 线内缘 → 并集 3px；右/下边视口缘伸入 DWM 线区 1px → CSS 被盖 → 并集 2px）= **四边 3vs2 粗细不一**；角部 CSS 弧（7 逻辑 = 10.5 物理）与 DWM 裁切弧（10.3 物理）异径分离露内容色缝。任何 CSS 线都逃不掉这套系统错位。
  - **修复一（描边零绘制）**：`.window.fx-mica::before` border 0 + box-shadow none——边框主权 100% 交 DWM（"别人的完美边框"即纯 DWM 路径）：四边恒均匀 2 物理 px、角弧原生、分离缝消。picking = DWM 切染品牌色独存。实色模式前端自绘不变（无 DWM 干涉）。
  - **角部钩形再查**（用户："边框线在圆角处像被橡皮擦掉半截，透出下层白色按钮"）：聚焦态差分掩膜（窗口原地 vs 移开两帧 diff）测不到穿透、失焦态截图钩形现形，用户确认与焦点无关；CSS 四角垫块无效（垫在 WebView 位图内，钩在非客户区）；`DwmExtendFrameIntoClientArea(-1)` 在 transparent:true 下单独加无效。
  - **真根因（用户查证）**：月牙 = "DWM 圆角描边曲线"与"方形客户区角"之间的**非客户区窄缝**；tao `transparent:true` 用的是 blur-behind 空 region hack——整窗表面（含非客户区）按 alpha 合成，缝 alpha=0 成透底洞；WebView 只填客户区，故 CSS 怎么垫都够不着。
  - **终版（方案一）**：`transparent:false + backgroundColor:#00000000 + shadow:true + ExtendFrame(-1)`——Mica 由 DWM 在窗口表面底下合成（不需要 tao transparent），真正要透明的只有 WebView2 默认背景；DWM 帧/backdrop 填充覆盖非客户区缝（ExtendFrame）。实机验证：UI 完整、Mica 正常、月牙缝消失。057"配置终态"同步修订。
  - **预防补：** 窗口装饰问题先分清三层归属再动手——客户区（WebView 位图内，CSS 可及）/ 非客户区（DWM 帧管辖，CSS 够不着）/ 窗外（下层正常显示）；"垫色块淹没"类修法只对客户区有效；差分掩膜抠穿透区时注意焦点态影响 DWM 合成完整性（聚焦态可能掩盖失焦特有的裸露）。
