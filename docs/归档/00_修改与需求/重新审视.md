# 复盘

以 eagle 为参照，让软件的使用体验更趋向图片整理和设计师用户，离动画师管线的流程比较远。

自适应布局和瀑布流布局更趋向于图片本身即信息，只适合用在场景图片和参考里，真正的动画导出的素材都帧率和分辨率都高度统一，镜头素材基本也都维持统一的宽屏。

# 资源库结构

模仿了 eagle 的资源库文件夹结构管理，其实不太适合我们。

我们会很频繁的调用视频路径作为剪辑素材，作为特效素材引用，对路径依赖很高。

我们让用户选择的不应该是资源库的位置，而是一块专属于 AniKit 的储存空间。

无论多个资源库，还是需要实际物理层级的项目，都应该在这个空间内，互相用相对路径引用。

需要实际看到工作空间和项目，可以用符号链接将文件夹链接至其他处。

# 数据

模仿 eagle 的数据模式，是单张图的单元数据模式，互相独立，没有关联，还有一堆需要人工打的标签、批注、注释、评分、描述等等数据。

动画里通常有着复杂的复用机制，不论是角色动画、沙雕动画、AI 动画，角色会参演多部剧本。

一个角色他在不同的动画里叫什么名字、是什么身份、和其他人的关系、参演过那几集、是主角还是配角、他的动作库有哪些动作、他的表情库有哪些动作、有哪些服饰、不同的动画里有他的哪些专属道具（今天演的修仙需要一把剑、明天演的总裁需要一辆车）、AI 生视频时这个角色固定的音色参考是哪个、这个角色生产时的提示词是什么等等数据。

熟练之间是节点结构，而非单一的元数据，人物与人物_走路之间连接着，他们是角色本身与角色动作库、人物配音与人物之间是连接的，素材之间相互关联，这个图片的 XMP 数据回追从哪个 PSD 导出的， 如 obsidian 的原子笔记那般。

AI 项目里，每个镜头都是一个组，这个组里引用了哪些提示词、哪些参考图、哪些音频视频、生成过几个版本等。

# 资源管理

现在走的是通用资源管理模式，文件夹套文件夹，然后展示内容，每个文件是什么属性，现在有的 UI 布局满足不了大量的节点式信息。

应该走生产管线的管理模式，剧本、设定、角色、场景、道具、特效、配音、其他等。

虽然本质上还是文件夹套文件夹，但是 UI 展现的方式可以更加偏生产流程的管线。
