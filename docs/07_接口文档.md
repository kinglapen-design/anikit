# 07_接口文档

> 所有功能（含基础操作）抽象为命令接口，UI / AI Agent / 插件统一调用（01_开发规范 第 1 条）。本文档随开发持续更新；接口签名以代码为准，本文档为索引与协议说明。接口过多时按模块拆分子文件，本文件保留索引。

## 1. 命令 API（Tauri commands，占位分组，实现后逐条补签名）

- **库管理（2.1 空间化重写，2026-08-12；PRD 01_储存空间）：**
	- `create_space(parent_path: string, name: string, auto_import: bool) -> SpaceInfo` —— 在父目录下创建储存空间（`<name>/` 内建 space.json + assets/ + workspace/ + inbox/）；已是合法空间视为打开（幂等）；非空非空间目录返回中文错误；打开时按空间 autoImport 启停收件箱（盘符 + 监听）
	- `open_space(path: string) -> SpaceInfo` —— 校验空间结构（space.json 可解析，assets/ 与 inbox/ 缺失自愈补建）后打开并记 config spaces 最近列表；非空间结构报"该文件夹不是 AniKit 储存空间"
	- `get_current_space() -> SpaceInfo | null` —— 当前打开的储存空间
	- `list_space_libraries() -> string[]` —— 当前空间内库名列表（扫空间根一级子目录中含 folders.json 者，排序；无当前空间返回空）
	- `create_library(name: string) -> LibraryInfo` —— 当前空间内创建资源库（库目录 = 5 数据文件 + backup/cache/vectors，素材实体统一入空间 assets/ 池；自动导入为空间级设置，建库不带）
	- `open_library(name: string) -> LibraryInfo` —— 当前空间内按名打开；校验 + 版本迁移检查（迁移前自动备份）+ 24h 定时备份；旧版库结构（库根自含 asstes/）报"旧版库结构，请新建资源库"不迁移
	- `get_current_library() -> LibraryInfo | null` —— 当前打开的库；前端启动据此决定是否走向导
	- `list_recent_libraries() -> LibraryEntry[]` —— 全局配置 config.json 的资源库最近列表（最近在前）；启动自动重开（reopenLastSession）与打开空间后选库使用
	- `set_auto_import(enabled: bool) -> SpaceInfo` —— 自动导入开关（**空间级**，space.json 单写点；inbox 空间级共用，2026-08-12 用户定）：开 = 启动收件箱（盘符挂载 + 监听，目标 = 当前打开的库），关 = 停止收件箱（卸载盘符）；空间打开 / 切换时按该设置启停
	- `reorder_libraries(order: string[]) -> string[]` —— 库列表拖动排序持久化（08 稿抓手拖动，space.json `libraryOrder` 单写点）；order 与实扫库名集合不一致报中文错；list_space_libraries 返回即按此序（外来目录排尾字典序，create_library 自动入尾）
	- `delete_library(name: string, deleteOrphans: bool) -> string[]`（剩余库名列表）—— 删除资源库：删当前打开的库先清 state/undo 再删目录（库内数据不可恢复；确认弹窗在前端）；order 移除；删当前库后的切换由前端据返回列表驱动（切剩余第一个 / 无剩余回向导第二步）。**deleteOrphans（2026-08-12 孤儿清理定案）**：先算孤儿集再删库——孤儿 = 该库引用集（folders ∪ recycle）与其余各库引用集并集的差集，true 时这些 info 实体从 assets 池递归删除（共享素材保留；按 ID 删，不枚举 assets/）
	- `count_library_orphans(name: string) -> u64` —— 统计该库孤儿素材数（删库确认弹窗的复选框文案用）
	- 路径纪律：ID → info 路径推导唯一出口 `core/paths.rs`（assets 池访问纪律，PRD 01_储存空间），业务侧禁止自行拼 assets 路径
	- **UI 设置与窗口几何持久化（2026-07-28 用户复验定："用户设置要持久化，包括窗口大小，位置"）**：落全局 config.json 的 settings 子树（core/config.rs 单一写点，应用级不随库）
		- `get_ui_settings() -> Record<string, unknown>` —— settings.ui 子树原样返回（从未保存 = 空对象，前端按默认值补齐并做类型对照校验）；前端启动时调用覆盖 ui store（多预览窗口各自独立 Pinia 各自加载，不做跨窗口同步）
		- `save_ui_settings(settings: Record<string, unknown>)` —— 前端 ui store 变更 $subscribe 防抖 500ms 整体写回（单点覆盖 settings.ui）
		- `save_window_state(state: { x, y, width, height, maximized })` —— 主窗口 resize/move 防抖 500ms 提交（预览子窗口不记录）；**最大化时后端只刷标志位、几何保留上次还原尺寸**（退出最大化不丢位置）；启动恢复在 Rust setup（tauri.conf `visible: false` 先隐后显防跳变；显示器拔除致坐标落空时只恢复尺寸不恢复位置；saved maximized 则先设尺寸再 maximize）
	- 类型：`LibraryInfo = { name, path, assetCount, folderCount }`；`LibraryEntry = { name, path, lastOpenedAt }`；`SpaceInfo = { name, path, autoImport }`
	- 关闭 / 备份 / 版本回滚命令：待后续阶段
- **系统（1.3 落地）：**
	- `exit_app() -> ()` —— 退出应用（14 汉堡菜单"退出"点亮，2026-08-11 用户定：完全结束进程 = app.exit(0)，菜单快捷键标注 alt+F4）
	- `get_window_fx_mode() -> "mica" | "solid"` —— 主窗口背景效果模式查询（7.1 十七轮主窗口骨架轮）：Win11 22H2+（build ≥ 22621，注册表 CurrentBuildNumber 判定）= mica（云母，Rust setup 时 set_effects 接入，窗口 transparent 为前提），其余 = solid（实色回退 --n-g-a1-solid，2026-08-30 用户定不做 Acrylic）；前端启动查询后切 .window 底色（基态即 solid 防首帧半透明闪），预览子窗口同口径（open_preview_window 创建时各自 apply）
	- `create_document(kind, targetFolder: string | null) -> PlacementView` —— 新建文档入库（3.1 二轮通用化，2026-08-15 用户定：放弃 shell 检测模式 detect_doc_apps 废除，固定七类恒显）：kind ∈ md / txt / fla / psd / ai / docx / xlsx——md/txt 空内容建档，二进制五类以 assets/templates/ 空白模板为内容（编译期内嵌 include_bytes!）；不走导入管线——info 目录 + 模板内容（唯一显示名"新建文档[-N].{ext}"，library::unique_name 同导入口径）+ metadata.json（size/hash = 模板内容实测）+ 前插 origin Placement + 格式图标保底（cache/thumbs/{ext}.webp）；撤销 = info 目录移入 cache/tmp 备份、重做 = 移回（DiskOp::Rename 成对）。AE 不建档（工程素材为链接路径、需打包工程，属工作空间而非资源库，2026-08-15 用户定）
- **导入（阶段 3.1 落地，后台任务 + Channel 流式；4.1 序列帧打包）：**
	- `classify_paths(paths: string[]) -> { kind: "files" | "folder" | "mixed", fileCount }` —— 拖拽 / 菜单共用预判；fileCount 为递归展开后文件总数
	- `detect_sequences(paths: string[]) -> SequenceGroupInfo[]` —— 序列帧检测（后端为唯一事实来源，4.1）：递归展开后按"同目录 + 基础名 + 扩展名 + 序号位宽"分组（`标题001` / `标题 (1)` / `标题_001` / `标题-001`），序号连续（缺帧 ≤ max(2, 跨度/10)、同组同号不判）且 ≥3 且为图片格式（png/jpg/jpeg/gif/webp/bmp）才判定；`SequenceGroupInfo = { name, ext, frameCount }`（name = 基础名即资产标题）。09 导入弹窗确认后调用，命中则追加弹 12_序列帧弹窗
	- `import_paths(paths: string[], structure: "flatten" | "keep", source: "copy" | "move", targetFolder: string | null, sequenceMode: "pack" | "scatter", onEvent: Channel<ImportEvent>) -> taskId` —— **立即返回 taskId，导入在后台线程执行**（分段短锁：扫描 / hash / 复制 / 缩略图在锁外，索引与 folders 写盘在锁内毫秒级，UI 不阻塞）；keep 按原结构建文件夹节点（同级同名复用）并先发 folders 事件；move 跨盘回退 copy+删；hash 命中挂起待 resolve_conflicts 决策；单文件失败不阻塞整批。**sequenceMode = "pack"（4.1）：检测到的序列帧整组打包为一个 Asset**——`{ID}.info/frames/` 归一重命名 `标题-序号.扩展名`（序号补齐位宽），metadata 记 fps（默认 24）/ frameCount / thumbFrame（首帧文件名），缩略图复用图片管线取 thumbFrame；组 hash = 各帧 sha256 按序号升序串联后再 sha256；Placement 显示名 = `标题.扩展名`；复制/剪切对整组生效（剪切整组帧移走）；"scatter" = 逐文件导入（现状；剪贴板 / 收件箱恒 scatter）。started.total 按单元计（散文件数 + 组数）
	- `import_clipboard(targetFolder: string | null, onEvent: Channel<ImportEvent>) -> taskId` —— 剪贴板导入（2026-07-27 扩）：先读图片（截图 → PNG 落 cache/，命名 剪贴板-yyyyMMdd-HHmm 重名 -序号，导入后清理临时文件），无图再读文件列表（资源管理器 Ctrl+C 的文件 / 文件夹，CF_HDROP），再读 **base64 文本（2026-08-14 用户定）**：data URI / 裸 base64 容忍空白，解码按魔数定扩展名（psd/psb/png/jpg/gif/bmp/webp/wav/mp3/mp4/mov/svg），魔数不在表内不认，上限 512MB，落 cache/ 临时文件同命名口径导入后清理；**来源恒 Copy**（剪贴板复制的文件绝不 Move 走用户原文件）+ flatten + scatter；三者皆无报中文错"剪贴板里没有图片或文件"（有文本但不可导入报"剪贴板里没有可导入的内容"）
	- `cancel_import(taskId: number)` —— 置位取消标志，管线在当前单元写完后中断（已导入部分保留）
	- `resolve_conflicts(items: ConflictResolution[], source: "copy" | "move") -> { resolved, failed }` —— 冲突决策（导入完成后统一处理）；`ConflictResolution = { sourcePath, existingAssetId, targetFolder, action: "useExisting" | "copy" | "link" | "skip", sequence?, sourceThumbPath?, importedFrom? }`；useExisting 把已有资源 origin Placement 移至 targetFolder（目标处链接去重），copy 继承 source 建档（**序列帧冲突按回传的 sequence 组信息重新打包**，4.1；新资产继承 importedFrom 批次渠道标记——自动导入冲突"保留两个"进"已导入"视图，2026-08-13；**copy 显示名 = 源文件原名不唯一化**——2026-08-14 用户定：库允许同名，自动加序号废除），link 建链接 Placement（显示名 = 源文件原名），skip 不动（源文件保留）；~~newName~~（**2026-08-13 用户定：弹窗内嵌批量重命名过度设计废除**，字段同步删除——命名导入后走独立批量重命名弹窗）；**sourceThumbPath 原样回传——决策成功（含 skip）即删除该预览缓存，且 cache/tmp 为会话级临时、打开库时整目录清空（4.2，2026-07-23 用户定）**；**决策落点不设限（2026-08-13 用户定案"不替用户做整理决定"）：useExisting / link 的 targetFolder 允许 root（未分类）——原"候车区护栏后端兜底拒绝"废除**
	- 事件流 `ImportEvent`（tag="type" camelCase）：`{type:"started",total}` → keep 模式 `{type:"folders"}`（层级已建，前端重拉文件树）→ 逐单元 `{type:"asset",placement:PlacementView}`（到一个显示一个）→ `{type:"finished",imported,conflicts:ConflictItem[],failed:{path,reason}[]}`
	- 冲突挂起项 `ConflictItem`（携双侧显示数据，供 10_重复添加提示）：`{ sourcePath, sourceName, sourceSize, sourceW, sourceH, sourceThumbPath, targetFolder, targetFolderName, existingAssetId, existingName, existingW, existingH, existingSize, existingExt, existingThumbPath, existingFolderName, sequence? }`——**sourceThumbPath（4.2 补）**：webview 直渲不了的格式（PSD/PSB/SVG 等）后端经解码管线生成的预览缓存绝对路径（cache/tmp/{路径+大小散列}.webp，幂等）；图片格式为 null，前端直读源文件。**不复用已有侧缩略图**：将来支持剪贴板自定义缩略图后 hash 相同缩略图也可能不同（2026-07-23 用户定）；**序列帧冲突（4.1）**：sourceName = `标题.扩展名`、sourcePath = 首帧路径（弹窗预览首帧）、sequence = `{ name, ext, width, frames: [{path, number}] }`（帧按序号升序，前端原样回传给 resolve_conflicts）
	- **根目录约定：Placement.folder 用保留 ID `"root"` 表示，Folder 列表不放 root 节点**
	- **新导入前插（2026-07-25 用户定）：新 Placement 插到目标文件夹段首（add_placement 锚点保批内到达序，新批次排旧批次前），显示顺序 = items 数组顺序；order 向负生长（仅相对键，7.1 排序落地时统一重排）；前端流式导入同语义前插（started 锚点清零，finished 后 refresh 全量对齐）**
