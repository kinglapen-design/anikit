# 07_接口文档

> 所有功能（含基础操作）抽象为命令接口，UI / AI Agent / 插件统一调用（01_开发规范 第 1 条）。本文档随开发持续更新；接口签名以代码为准，本文档为索引与协议说明。接口过多时按模块拆分子文件，本文件保留索引。

## 1. 命令 API（Tauri commands，占位分组，实现后逐条补签名）

- **库管理：**
	- `create_library(path: string) -> LibraryInfo` —— 在选定空文件夹创建素材库（文件夹名即库名）；已是资源库 / 非空文件夹返回中文错误
	- `open_library(path: string) -> LibraryInfo` —— 校验结构（asstes/ + folders.json 可解析且版本合法）后打开；打开流程内含版本迁移检查（迁移前自动备份）与 24h 定时备份
	- `get_current_library() -> LibraryInfo | null` —— 当前打开的库；前端启动据此决定是否弹"创建/打开资源库"模态
	- `list_recent_libraries() -> LibraryEntry[]` —— 全局配置 config.json 的资源库最近列表（最近在前）
	- 类型：`LibraryInfo = { name, path, assetCount, folderCount }`；`LibraryEntry = { name, path, lastOpenedAt }`
	- 关闭 / 备份 / 版本回滚命令：待后续阶段
- **导入（阶段 3.1 落地，后台任务 + Channel 流式）：**
	- `classify_paths(paths: string[]) -> { kind: "files" | "folder" | "mixed", fileCount }` —— 拖拽 / 菜单共用预判；fileCount 为递归展开后文件总数
	- `import_paths(paths: string[], structure: "flatten" | "keep", source: "copy" | "move", targetFolder: string | null, onEvent: Channel<ImportEvent>) -> taskId` —— **立即返回 taskId，导入在后台线程执行**（分段短锁：扫描 / hash / 复制 / 缩略图在锁外，索引与 folders 写盘在锁内毫秒级，UI 不阻塞）；keep 按原结构建文件夹节点（同级同名复用）并先发 folders 事件；move 跨盘回退 copy+删；hash 命中自动建立链接（询问弹窗待设计稿）；单文件失败不阻塞整批
	- `import_clipboard(targetFolder: string | null, onEvent: Channel<ImportEvent>) -> taskId` —— 剪贴板图片 → PNG 落 cache/ 后以 move + flatten 走同一管线；命名 剪贴板-yyyyMMdd-HHmm，重名 -序号；剪贴板无图片报中文错
	- `cancel_import(taskId: number)` —— 置位取消标志，管线在当前文件写完后中断（已导入部分保留）
	- `resolve_conflicts(items: ConflictResolution[], source: "copy" | "move") -> { resolved, failed }` —— 冲突决策（导入完成后统一处理）；`ConflictResolution = { sourcePath, existingAssetId, targetFolder, action: "useExisting" | "copy" | "link" | "skip", linkName? }`；useExisting 把已有资源 origin Placement 移至 targetFolder（目标处链接去重），copy 继承 source 建档，link 建链接 Placement（linkName 或原名），skip 不动（源文件保留）
	- 事件流 `ImportEvent`（tag="type" camelCase）：`{type:"started",total}` → keep 模式 `{type:"folders"}`（层级已建，前端重拉文件树）→ 逐文件 `{type:"asset",placement:PlacementView}`（到一个显示一个）→ `{type:"finished",imported,conflicts:ConflictItem[],failed:{path,reason}[]}`
	- 冲突挂起项 `ConflictItem`（携双侧显示数据，供 10_重复添加提示）：`{ sourcePath, sourceName, sourceSize, sourceW, sourceH, targetFolder, targetFolderName, existingAssetId, existingName, existingW, existingH, existingSize, existingExt, existingThumbPath, existingFolderName }`
	- **根目录约定：Placement.folder 用保留 ID `"root"` 表示，Folder 列表不放 root 节点**
- **内容浏览（阶段 3.1 落地）：**
	- `list_folder_tree() -> FolderNode[]` —— 文件夹树（按 order 排序）；`FolderNode = { id, name, count, children }`，count 为直接 Placement 数
	- `list_placements(folder: string | null) -> PlacementView[]` —— folder=null 为"全部"；`PlacementView = { assetId, folderId, name, w, h, ext, thumbPath, origin }`；thumbPath 为缩略图绝对路径（无则 null），w/h 无尺寸为 null（前端按 400×300 默认比例布局）
- **收件箱 Inbox（阶段 3.2 落地；无新命令，事件 + 托盘驱动）：** 随 `create_library` / `open_library` 自动启动（库切换重建、应用退出收尾）；库内 `inbox/` 挂载为盘符（DefineDosDeviceW 会话级映射，A / B 优先其后 Z→E 选空闲；托盘"收件箱盘符"开关手动挂 / 卸）；notify 增量监听（写入完成检测：静默 2s + 大小两轮一致 + 全部文件可移走——GENERIC_READ|DELETE 探测，与 move 同口径；逐条目独立判定：占用条目自己等放手不拖累其他条目，recover 类临时文件随之入库由用户自删；启动清点存量）→ 就绪批次串行走 import 管线（keep + move 过境语义：导入后即移走、目录常态为空）→ 事件 **`inbox-import`**（负载 = ImportEvent，与导入 Channel 同形状），前端复用 11_导入进度条与 10_重复添加提示（冲突决策走 `resolve_conflicts`，source 恒 "move"）；**自动合并**：撞 hash 且已有资产同为 inbox 渠道（`metadata.importedFrom`）时静默合并——已有资产改名为新文件真实名（磁盘 originName + 词干缩略图 + origin Placement）、新文件作为重复丢弃、发 asset 事件，正式资产（非 inbox）不受影响照常询问（PRD 01-2.3 注，2026-07-22 定案）
- **Placement：** 移动 / 链接 / 副本 / 重命名（异步改 originName）/ 删除 / 排序 / 克隆文件夹
- **标签：** 增删改 / 合并 / 群组
- **搜索：** 分词搜索 / 筛选
- **缩略图：** 生成 / 重建 / 封面帧设置 / 系统缩略图（按格式缓存）
- **回收站：** 列表 / 还原 / 彻底删除 / 清空

## 2. 动画软件通信通道（WebSocket）

- 服务：`ws://127.0.0.1:{port}`，端口动态分配并写入全局配置；插件启动后连接并保持长连接。
- 请求：JSON `{ id, action, payload }`；响应：`{ id, ok, data | error }`。
- 事件（插件 → AniKit 主动上报）：`progress` / `done` / `error`。
- Animate 适配器起步动作：`sendToStage`（剪贴板载荷 + clipboardPaste 原位粘贴）/ `exportThumbnail` / `getState`。
- 协议细节待阶段 0 剪贴板格式验证后补充。

## 3. anikit:// 协议

- `anikit://item/{ID}` —— 软件内跳转；外部软件（如 Obsidian）点击调起 AniKit 并跳转（安装时向系统注册协议处理，Windows 注册表 / macOS Info.plist）。
