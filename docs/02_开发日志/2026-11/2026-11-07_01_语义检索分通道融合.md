# 语义检索分通道融合

2026-11-07，feat/new-ui。用户从既有排序精化立项中选定 B 路，提前放进 1.0 收尾：解决画面与文本片段原始相似度直接混排导致的文本霸榜，不引入 reranker 或 FTS5 混合检索。

## 定案与真实基线

改动前通过 MCP 对真实库执行「血迹」「女人脸上的血」「枪指着头」「啤酒放在桌子上」四条查询。当前库经基础重分析后只剩 `visual` 段，四条查询均命中同一素材，最佳段分别为 27.917s、28.000s、9.375s、20.250s。因此这组基线用于约束单通道顺序不变，不能冒充混合通道质量对照。

混合场景由构造回归和真实模型 + 模拟详细分析闭环覆盖。没有使用真实 provider、密钥或额度，也没有让开发实例打开真实库。

## 实现

新增 `services/semantic/rank.rs`。`visual` 为画面通道，`description`、`event` 及后续文本类归入文本通道；两路各自按原始余弦相似度排名，再用等权 RRF（k=60）转换成名次分，同分优先画面通道。每个素材只取最高融合分参与素材排序，不累加多段，避免片段数量本身形成额外优势。

`storage.rs` 仍计算并返回原始相似度，`search.rs` 保留融合后的素材、`best` 与片段顺序，不再按原始分二次重排。`score` 字段含义不变，但不能跨通道比较。数据库 schema、模型、依赖和既有索引均不变，无需重新分析。

定位消费同步取消「无条件优先 event」的临时止血逻辑，改为在融合顺序中跳过全片 `description` 后取首个窄段。卡片徽标、命中帧图、预览跳转与片段创建继续共用 `pickLocateSegment`。

真实探针同步改用融合契约：不再断言不同素材的原始分全局降序，改验 `best` 与片段首位一致。另修正旧视口残留、输入防抖等待、序列帧加载空窗、DOM 元素序列化判定和 MCP 工具数 40 的既有探针问题。

## 验证

新增 7 项回归：5 项覆盖通道排名、同分画面优先、文本名次仍可胜出、单通道不变和截断；1 项覆盖 SQLite 混合检索；1 项钉住上层不重排。全量 `cargo test` 为 733 项通过、0 失败、20 项按需忽略；`real_provider_loopback_and_offline_search` 单独运行通过。

`cargo clippy --lib --bins -- -D warnings`、`pnpm build`、`pnpm typecheck` 均通过。测试构建仍显示 `services/purge.rs` 既有测试导入警告，本轮未改该模块。

隔离 Tauri 实例最终完整探针通过：真实中文搜索、界面顺序与计数、视频 / 动图 / 序列帧定位、MCP 40 工具、虚拟与物理片段闭环全绿。验收使用独立配置、隔离库与项目内受管模型，实例已关闭；本轮未重打免安装包。
