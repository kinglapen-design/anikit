# 2026-11-03_01 搜索响应提速与等待状态

## 根因与定案

用户实机反馈当前文件夹搜索常等 1～2 秒。实测同一「音色」文件夹、同一关键词「雪牧」，分词查询返回 3 条仅需 8ms，语义查询连续两次分别为 1.161s 与 0.661s。根因不是名称匹配慢，而是 auto 模式虽然并联发起分词与语义查询，却在写分词命中前等待语义命令结束。

本轮按用户确认的三步执行：分词结果先显示；语义范围过滤前移并支持无索引早退；等待期间显示「搜索中...」，不再把在途查询误报为「无搜索结果」。

## 实现

前端 search store 新增 pending 状态。输入后立即作废旧请求并进入查询中，分词命令返回即写入命中；语义命中随后按原相关度与去重规则追加。新查询清除上一轮语义命中，避免分段呈现时跨查询混卡。ContentArea 复用既有搜索空态样式显示「搜索中...」，零新组件、零新样式。

后端先按 scope 生成候选 assetId 集。范围内没有当前模型版本的有效片段时，在模型清单加载与文本推理前直接返回。非全局检索在读取向量二进制和点积计算前排除范围外资产，并在范围内排序截取 Top N；全局检索维持原路径。另补回归测试，覆盖范围外高相似度资产不得挤掉范围内结果、无有效片段预检和超过 500 个候选的分批查询。

## 验证

`pnpm typecheck`、`pnpm build`、生产代码 `cargo clippy --lib --bins -- -D warnings` 均通过。全量 `cargo test` 为 707 项通过、20 项忽略，另有 CLI 4 项通过，零失败。

真实隔离 Tauri 实例中，新建无索引文本文档后，同一文件夹的分词查询为 2.1ms，语义查询为 75ms且 `actualBackend = unknown`，确认未启动文本推理。真实页面将语义响应人为延迟 3 秒，分词卡片仍先显示且 pending 保持；空态依次呈现「搜索中...」与查询完成后的「无搜索结果」。临时文件夹、文档与探针均已清理，实例已关闭。

headless 搜索探针两次分别遇到探针状态读取不兼容与 CDP 启动超时，未进入本轮核心断言；按探针纪律停止重跑，未保留未执行成功的探针改动。`cargo clippy --all-targets -D warnings` 另报既有 `analysis.rs` 三处 needless_borrow 与 `provider_store.rs` 两处 cloned_ref_to_slice_refs，均不在本任务改动文件内，未顺手修改。本轮未重打免安装包。
