# 2026-11-02_10 智能搜索并联合并（分词 + 语义双通道）

2026-11-02，feat/new-ui。用户实机：库里「左轮」是资产图片名，搜"左轮"只出图片、视频出不来；搜"左轮手枪视频"（分词无命中）才出视频——**降级路由把向量结果遮盖了**，用户问"是不是要规划二级菜单"。

## 根因与定案

现状（search.ts `run()`）：auto 模式先跑分词，**分词有命中即短路**（`hasResults=true` → clearSemantic），语义只在零命中时兜底。PRD 03「智能路由」原口径即此。

方案取舍：用户提"二级菜单"，但手动切模式已存在（搜索图标 → 智能/分词/语义）——问题不是缺开关，是**默认行为遮盖**。定案 = **auto 改并联合并**：分词与语义并发双跑，分词命中按视口序在前、语义命中按相关度去重追加在后（同 assetId 去重，分词卡优先占位）。语义命中卡以命中徽标 / 命中帧图为天然区分，**零新 UI 元素**（不要二级菜单）。手动"分词 / 语义"模式强制单通道口径不变。

## 落地（纯前端 store 层，后端不动）

- `runSemantic` 加 `keepKeywordHits`——并联时不清关键词命中（原实现开头即清 hits/hitArchives）
- `run()`：auto 模式关键词与语义**并发**起跑（语义内部自捕错误不 reject；并联路径 error 归 runSemantic 自管，防关键词成功清错吞掉语义错误）；手动分词模式不跑语义
- `resultPlacementsFor`：纯语义模式原口径（仅语义命中按相关度）；分词/智能模式 = 关键词视口序 + 语义相关度去重追加
- PRD 03_查找文件「智能路由」节改写为并联口径（改需求先改 PRD）

## 验证

typecheck 过。探针走查：cdp-semantic-live-probe / cdp-semantic-probe 均走手动"语义搜索"模式（纯语义路径），不受并联影响。实机待用户走查：搜"左轮"应 = 图片资产在前 + 视频（带命中徽标/命中帧）追加在后。重打包出 `release/anikit-portable-next/`。
