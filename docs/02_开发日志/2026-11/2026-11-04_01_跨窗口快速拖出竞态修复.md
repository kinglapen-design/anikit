# 2026-11-04 跨窗口快速拖出竞态修复

## 现象与根因

用户实机反馈：素材随手一拖一送经常到不了剪映，刻意慢一点才成功；两段录像都是第一次快速手势未落入，第二次放慢后成功。

代码链路与 `drag 2.1.1` 的 Windows 实现坐实竞态：旧实现先维护应用内 pointer 拖拽，直到指针越出窗口才通过一次异步 IPC 调 `drag_assets`，再由主线程执行 `DoDragDrop`。快速松手时，OLE 尚未进入模态拖拽循环，Windows 已看到左键松开，目标软件不会收到文件。不是剪映导入耗时，也没有人为设置的等待定时器。拖出主链自 2026-10-01 后未改，近期 WebView2 Runtime 更新不是本次根因证据。

## 修法

文件卡移动超过既有 6px 阈值、形成拖拽时即提前发起 OLE，不再等越界。窗内 `enter / over` 事件继续喂原落点引擎，因此移动、排序、跨分屏和 Ctrl 建链接仍复用原业务路径；曾出窗再返回维持取消且不回导的 10-01 口径。

`drag_assets` / `ws_drag_paths` 返回真实落窗结果、窗口客户区物理坐标和松手时 Ctrl 实态，前端据此统一收口应用内落点或跨窗口结束。返回坐标在落点判定前除以 `devicePixelRatio`，避免 125% 缩放下把右侧、底部误判为窗外。

PRD 05-02 / 02-13、接口 02_系统、踩坑 122 已同步。
