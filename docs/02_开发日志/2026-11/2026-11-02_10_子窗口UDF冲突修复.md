# 2026-11-02 子窗口 UDF 冲突修复（踩坑 121）

用户实机报「多实例窗口打不开了，新建窗口、插件窗口都打不开」。当日中午新包后首报，但日志坐实与当日代码无关——**WebView2 Runtime 156.0.4314.58（11-01 自动更新）起，与主窗口共享 user-data-dir 时第二个 WebView 创建报 HRESULT 0x8007139F**，当日 14:20 首条报错早于所有改动。

## 根因与弯路

先按「透明创建全灭」跳过 transparent(true) 改 build(false)，dev 日志证伪——**透明与否无关，同 UDF 多 CoreWebView2Environment 冲突才是根因**（Microsoft Q&A 同症）。主窗口 transparent:false 只是表面幸存特征，不是机制。另有两个应用侧放大器：wry 报 ERROR 后 build 仍返回 Ok（透明降级链从未触发）× visible(false) + on_page_load 才 show（永不 Finished = 永不显示），把创建失败变成「点了没反应」。

## 修复

- `open_child_window`：**每 label 独立 UDF**（`app_local_data_dir/EBWebView-children/{label}`），主窗口与子窗口、各子窗口彼此全隔离；透明首试 + 非透明降级链保留，圆角视觉不变。另加**先隐后显 3 秒超时强制 show 兜底**（已 show 幂等），此后任何加载失败窗口可见可关不再隐形。
- `PreviewWindow.vue`：**refreshWhenLibraryReady**——排查中用户截图坐实的相邻小 bug：启动早期子窗口 content.refresh() 吃「请先打开素材库」（AppState 库未就绪），主窗口有库就绪等待子窗口没有；仅拦该错 200ms×50 重试，其余错误原样抛。

## 验证

dev 实例（CDP 9333）实证：插件窗真实渲染 MCP 全内容（含 CLI 组）、预览窗正确 assetKey 后大图正常显示，两窗日志再无 wry ERROR；typecheck 0 错 + clippy 净 + cargo test 全绿。UDF 隔离副作用（探针方法论坑，已记踩坑预防节）：子窗口独立 browser process → 主窗口 CDP 看不到子窗口 target（断言要查 Windows 窗口标题 / 截屏）；document.title 不改原生标题（探针状态写 DOM）；open_preview_window 的 assetKey = `${assetId}|${folderId}` placementKey（传纯 assetId 会 current null 黑屏——探针参数错非产品 bug）。

## 待办与边界

`EBWebView-children/{label}` 逐窗累积的清理策略留待办（Runtime 修复共享 UDF 创建后可回滚隔离）。release 重打与包内实窗冒烟随本轮打包日志。
