# 长期运行内存增长排查

## 用户现象与实测

用户反馈 AniKit 早上启动约 18 MB，使用到晚间约 150 MB，不关机到次日超过 200 MB，担心长期运行会涨到 1 GB。本轮没有改动内存相关代码，任务是确认是否需要优化。

检查当时正在使用的 `release/anikit-portable-next/anikit.exe`，主进程工作集为 222.3 MiB、私有内存为 224.9 MiB。这个数值是主进程本身，不含 WebView2 子进程，因此不能只用前端图片或字体缓存解释。

## 已确认的放大点

`core/undo.rs` 的撤销栈限制为 50 步，但每一步保存受影响 JSON 文件的操作前、后整份文本快照，只有步数限制，没有总字节上限。文件夹移动、Placement 整理等常见操作都会记录 `folders.json`，所以内存会随操作次数和库体量增长。

当前打开素材库有 4,448 个资产，`folders.json` 实测 1,096,895 字节。若 50 步都记录该文件，仅前后快照约占 104.6 MiB，与“启动很低、使用后明显增长”的现象吻合。撤销与重做合计受同一批 50 步条目约束，因此这不是逐日无限累积的直接证据；但库更大、单步涉及更多文件时，没有字节上限确实可能继续涨到 1 GiB。

## 结论与后续

**需要优化，但当前证据不足以认定全部增长都是泄漏，也不能认定内存必然每天线性增长。** 第一阶段建议给撤销栈增加总快照字节预算，与 50 步形成双重限制，超出后淘汰最旧步骤。随后在隔离库连续执行 50 次以上写操作，观察主进程私有内存是否进入平台期，再决定是否继续治理其他常驻缓存。
