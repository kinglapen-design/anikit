# inbox 实况三件补齐（4.4，用户批准口径，代码完成待用户复验）

**inbox 实况三件补齐（4.4，用户批准口径，代码完成待用户复验）**：① 快照分层防卡——原 `snapshot` 每顶层条目递归算 size + 占用探测，文件多会卡；拆两层：`snapshot_fast` 供 list_inbox_snapshot 同步返回（文件 size 取 metadata.len、occupied 单文件探测；目录 size=0 / occupied=false 占位，目录 autoImportable 仍递归扩展名全白名单但只读目录项不递归算大小），`snapshot_details`（= 原完整逻辑）由 detail worker 后台算——fs 变化 / 启动时经 AtomicBool 防重入起线程、延迟 200ms 合并连发，`app.emit("inbox-disk-details")` 推前端整体替换（占用标记与目录大小以 details 合并后为准，快层占位是已知过渡态）；图标缓存写库 cache/ 不在 inbox 监听范围，天然不递归触发 fs-changed。② 实况接 shell 格式图标——InboxEntry 加 iconPath：快层只命中已缓存 cache/thumbs/{ext}.webp（只判存在绝不触发 shell），details 层复用 4.2 `ensure_format_icon` 生成 / 命中（thumbnail.rs 拆出 `format_icon_path` 路径辅助，只写 cache/thumbs 不写 info；shell 调用只允许在 detail worker）；前端 InboxDiskSection 文件条目优先 `<img :src="convertFileSrc(iconPath)">` contain（48px 上限，不新造 token），空回退扩展名角标，目录仍 folder-closed。③ failed 残留重投——竞态：watcher 就绪出队后 run_import 的 move 阶段失败（探测后软件又锁住），failed 源文件留在 inbox 不再自动重试；补：dispatch_loop 取 run_import 返回 outcome，failed 项源仍存在且位于 inbox 根内的经 `services::inbox::requeue_failed`（从 AppState.inbox 取 watch）→ `WatchHandle::requeue`（wake mpsc 发带路径 synthetic Event，EventKind::Other）重投监听等待队列，走常规就绪判定自动入库；conflicts 不重投（skip/useExisting/link 是用户决策，源保留属预期），手动 import_inbox_entry 失败不重投（用户显式动作，错误已回前端；requeue_failed 与触发来源无关，以后统一可直接复用）。命令测试快照用例拆 fast / details 两层 + 新增图标分层用例（快层未缓存 None → details 生成 → 快层命中，cfg windows）；notify 6 无 add_some_paths，requeue 逐条 add_path。cargo test 119 过零警告，tsc / vite build 全绿。遗留风险：非占用原因的持续失败（如磁盘满）会按"就绪节拍"反复重投重试，暂无重试上限。
