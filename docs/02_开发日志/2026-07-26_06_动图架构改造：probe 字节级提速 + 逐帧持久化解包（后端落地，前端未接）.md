# 动图架构改造：probe 字节级提速 + 逐帧持久化解包（后端落地，前端未接）

**动图架构改造：probe 字节级提速 + 逐帧持久化解包（后端落地，前端未接）**。① **GIF probe 改字节级扫描**（动机 = 用户反馈"导入 GIF 等半天"：根因是 probe_gif 用 image crate into_frames **全量解码像素**来数帧/算时长）——重写为纯字节解析块结构（Header + 逻辑屏幕拿宽高 + 块循环：0x21 扩展块（0xF9 拿 delay）/ 0x2C 图像描述块数帧 / 0x3B 结束，子块链跳过），不解像素微秒级返回；接口签名不变调用点零改动；正确性用既有测试 + 新增与 image crate 解码路径交叉校验（frameCount/duration 一致）+ 截断畸形返回 None 用例兜底。② **逐帧持久化定案**（用户 2026-07-26 新定案，**推翻 2026-07-25 cache 会话级定案**，用户原话依据：逐帧播放需要高清图配合所以持久化）——动图 = 导入时自动解包的序列帧：`services/anim_unpack.rs` 逐帧高清图持久化 `info/frames/{标题}-{序号5位补齐}.webp`（归一命名与序列帧同格式，webp q80 长边 ≤4096）+ `info/frames.json`（`{version, delays:[ms]}` 单一写点，INFO_DATA_FILES 收录进备份）；帧条小图仍 cache/frames 会话级按需生成不预生成；幂等跳过、失败清理半成品 frames/。③ **解包队列** `services/unpack_queue.rs`：仿 preview_queue 单 worker 但**无代际作废**（解包是建档的一部分，切换作废会丢解包；库切换清空 pending）；挂钩 import_task 单元注册完成且资产为动图（手动导入 / 收件箱同一管线）；完成发 `anim-unpacked { assetId }`、失败发 `anim-unpack-failed { assetId }`（资产仍可用维持原生播放兜底）；库打开不自动补解包（5.1 期间存量动图归 5.4 查缺补漏评估补刷）。④ **list_sequence_frames 扩展动图分支**：FrameEntry 加 `delayMs`（动图从 frames.json 逐帧下发，序列帧恒 null 兼容前端 1000/fps 预填）、SequenceFrames 加 `unpacking` + fps 改可空（动图恒 null）；未解包返回空清单 + unpacking=true。⑤ **5.2 cache/anim 链路清理**：list_anim_frames 命令（commands/anim.rs 整文件）、PreviewTask::AnimFrames、preview-anim-frames-ready 事件、cache/anim 目录约定与开库清空名单、save_anim_frame/anim_frame_path/anim_frame_name 全删；set_thumb_frame 动图分支并入统一 info/frames/ 路径（未解包报"动图解析中，请稍后重试"）。cargo test 157 过零警告、clippy --all-targets -D warnings 清零。
