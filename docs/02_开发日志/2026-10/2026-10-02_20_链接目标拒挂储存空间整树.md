# 链接目标拒挂储存空间整树（2026-10-02）

用户走查提问：「万一别人选文件夹的时候选了储存空间自身该怎么办」。拆解后发现一层已防、一层有洞，当轮补上。

## 两层分析

**空间根自身**（如 `E:\anikit`）本就拒——工作空间是空间根的直接子目录，空间根命中防循环校验的祖先判定。**但空间的兄弟目录有洞**：`assets`（库素材池，空间级共享）、`自动导入`、库数据目录与 `workspace` 平级，「在 root 内」和「祖先」两条校验都不沾边——素材池挂进工作空间 = 用户经磁盘实况视图直接改库文件，库元数据（info/ 体系）必然脱钩，封闭式资源库的完整性红线被穿。

## 修复

`check_link_target` 首道闸改为**拒挂储存空间整树**：ws root 恒为空间根直接子目录（`core::space::WORKSPACE_DIR`），`root.parent()` 即空间根，canonicalize 前缀命中即拒——「储存空间内的目录不能挂载（素材池 / 自动导入 / 库数据是 AniKit 自留地）」。原「root 内 / 祖先」两校验保留（root 内是空间树的子集但文案场景不同；祖先校验留作防御）。边界记录：空间外的库目录（若有）只含元数据不含素材内容，不在本批拒绝范围。

测试：`add_and_retarget_link_validate_and_register` 补「空间根 / 素材池兄弟目录拒绝」两断言；原有「外部」目标移出空间根到独立 tempdir（夹具本身踩了新规则——正是校验生效的证明）。`ws_retarget_link` 同闸自动获得。

`cargo test` 563 测绿 + `cargo clippy --all-targets` 净。PRD 02 落地口径与接口 20 的 `ws_add_link` 拒绝清单同步补「储存空间整树」。
