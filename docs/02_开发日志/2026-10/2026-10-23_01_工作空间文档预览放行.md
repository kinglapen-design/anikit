# 2026-10-23 工作空间文档预览放行

## 背景与定案

用户使用免安装版工作时提出：工作空间与库式的唯一区别是没有数据，文档预览、悬停播放这类能力为什么不能复用。排查坐实：2026-09-26 三类填充卡轮把这些收窄为「另立按路径任务」只是当时的主动收口，并非技术阻碍——按路径命令如今齐备，ws 预览面板分支的音视频自动播放（`get_media_source_by_path` + `loadPath`）早已在用同一条链路，与库侧零差异。用户拍板：完善工作空间体验优先于 1.0 收尾的向量项，分两轮走——本轮 = 文档预览放行；下一轮 = 卡片悬停播放 / 自动播放（开工底稿记待办 2026-10-23）。

改需求先改 PRD：PRD 04「工作空间磁盘实况下 docx 与字体 / 文本同口径降级 other」旧口径作废；PRD 02 技术口径新立「文档预览」条——**txt / md / docx / 字体在 ws 预览面板进对应预览页，md / txt 只读不编辑**（直接写回磁盘文件的编辑链路另立），预览「默认应用打开 / 其他应用打开」出口同轮放行（按路径命令，与 ws 右键菜单同一出口）。

## 改动

后端一处新增 + 一处注册：`read_docx_binary_by_path`（commands/docx.rs）= 预览 mammoth 链路按路径版，原始二进制 IPC 回包（前端 invoke 得 ArrayBuffer）；越界 / 不存在 / 非 docx 校验抽 `check_ws_docx` 与 `read_docx_by_path` 共用，64MB 容量闸仍在 services::docx。卡片层 2026-09-26 三命令（read_text_by_path / get_font_info_by_path / read_docx_by_path）直接复用零改动。

前端七处，零新组件零新样式零新 token：

- preview store ws 分支放行 font / text / docx 三个 kind——放行后 previewSpecs 注册表查表、上/下一个翻页、搜索态同源（previewList 唯一入口）全部自动成立；`openDefaultApp` 增 ws 分流 `open_path_with_default_app`（ws 无最近使用语义，不刷 refreshRecent）。
- PreviewText ws 只读：load 分流 `readTextByPath`；enterEdit 守卫（铅笔钮 / Ctrl+E / 分屏信号全到此为止）+ 任务框 toggle 禁回写 + txt textarea readonly；保存管线对 ws 天然不触发（draft 无变更源），md 渲染 / 大纲栏 / 复制代码块 / anikit 链接跳转等纯读功能照常。
- PreviewDocx / PreviewFont 按 wsPath 分流：docx 吃新命令原始字节喂 mammoth（表格 / 图片内嵌与库侧同引擎同观感）；字体吃既有 `getFontInfoByPath`，安装钮 ws 不出（系统级写入只认库资产，同卡片 installable 口径）。
- FloatBarMarkdown 新 `readonly` prop：ws 语境视图组只留大纲钮；FloatBarHost 经 $attrs 透传（`mdActive && wsPath` 才给 true，undefined 不落 DOM，同 editing 口径）。
- PreviewTitleBar「默认应用打开」与 PreviewUnsupported 按钮组对 ws 放行（后者「其他应用打开」分流 `open_path_with_dialog`）；「新窗口打开」维持不出（子窗口数据链按 assetId 不接 ws 假 id）。
- preview 陈列：PreviewBars MarkDown 工具栏组补 ws 只读 cell。

## 验证与遗留

typecheck 0 错 + cargo 643 测绿（+1：字节与源文件逐字节一致 / 越界 / 不存在 / 非 docx 四态）+ clippy 净。本轮不起 dev 实例、不重打免安装包（用户正用免安装版工作；单实例插件下 dev 根本开不出窗口，打包覆写 exe 需用户实例退出）——打包与实机走查随用户发话。
