# 剪贴板导入内容级重试——外部复制马上粘贴「空值」根治（2026-10-08）

用户实机报：外部复制一张图片，马上 Ctrl+V 粘贴进 APP「会类似空值」，需要稍微等一下再粘才成功。排查定因后一轮落地。

## 定因：单次读取 × 外部程序异步提交

先讲清现状链路：Ctrl+V 先经 `useGlobalKeys` 仲裁（内部剪贴板非空且系统剪贴板序号未变 = 内部链接/移动粘贴；序号变了 = 外部覆盖，让位系统导入），系统导入走后端 `import_clipboard`，按 图片（arboard 认 PNG / CF_DIBV5，QQ·微信截图走 CF_DIB 兜底）→ 文件列表（CF_HDROP）→ base64 文本 三路单优先级读取，三者皆无报错，前端按 2026-07-27 既定口径静默降级（只 console.debug）。

竞态在第一公里：**外部程序写剪贴板是异步的**——截图工具先走 UI 动画再提交位图，浏览器复制大图要先编码。用户按下 Ctrl+V 的那一刻内容常常还没到，单次读取三路必空 → 报错 → 被静默吞掉，用户看到的就是「没反应、像空值」；等几百毫秒写入完成再粘自然成功。

另有一个同款竞态不治：内部剪贴板非空时，外部写入未提交、序号还没变的那一刻按 Ctrl+V 会被仲裁成内部粘贴（粘出库内旧内容）。治它要在内部粘贴前等序号变化，会拖慢纯内部粘贴手感，维持原案；失败静默同为既定设计，不加 toast。

## 落地：内容级重试

`import_clipboard`（commands/import.rs）的三路读取收进重试循环：三路皆空不立即报错，按 50ms 间隔重读、最多 10 次 ≈ 最长等 500ms 等内容到达；**任何一路有内容（含不可导入的纯文本）即停**——有内容 = 写入方已提交完毕，再等也不会变。三分支的优先级、临时文件落 cache/tmp、恒 Copy 等既有语义一律不动。

## 验证

`cargo check` 净 + 599 测绿。重试包的是系统剪贴板不可单测，**待实机走查：截图工具复制即粘 / 浏览器复制大图即粘 / 纯文本粘贴仍静默不打扰 / 库内复制后 Ctrl+V 内部粘贴手感无回归**。踩坑 107 新立，接口 03_导入 同步。

## 顺带踩坑：cargo 的 .cargo/config.toml 按工作目录发现

验证时从仓库根跑 `cargo check --manifest-path src-tauri/Cargo.toml`，ffmpeg-sys-next 构建脚本回落 pkg-config 报错（`FFMPEG_DIR` / `LIBCLANG_PATH` 没生效）——cargo 的 config 发现按**当前工作目录**向上找，不看 `--manifest-path`。本项目一切 cargo 命令必须在 `src-tauri/` 目录下跑（`src-tauri/.cargo/config.toml` 的 `[env]` 才吃得到）。
