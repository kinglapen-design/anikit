# 分组名称/标签退出互斥转移（分词累加权重归属）

2026-10-08 十二轮。

## 背景

用户实机提问：同一文件夹里「杰森 / 杰森妈妈 / 杰森助理」三类角色图（文件名前缀重叠：`杰森_三视图.png` / `杰森妈妈_三视图.png` / `杰森助理_三视图.png`）怎么用名称规则分成三组。用户试过给「杰森妈妈」组输入「杰森、妈妈」两个分词，**输入「杰森」时原「杰森」组的分词被自动删除、分组存不下**；只输「妈妈」一个词，妈妈图又被「杰森」组带进去，除非把妈妈组排到杰森组上面。

## 定因：两个机制叠加，且与 09-17 权重修订直接矛盾

**机制一 · 单规则组互斥转移一刀切**（PRD 02-04 条款 2，`GroupManageDialog.onPickValue`）：在别的组输入某单规则组已占用的值，该值即从原组摘除。条款 2 原文只写「扩展名 / 类型 / 日期」（单值域天然互斥），但代码对所有 kind 一刀切——在妈妈组输「杰森」即从杰森组摘除，杰森组变空范围被保存预检拦下。

**机制二 · 权重平局按定义顺序兜底**（`lib/grouping.ts matchGroup`）：妈妈组只配{妈妈}时与杰森组{杰森}对妈妈图各命中 1 词，平局归排在前面的组——这就是「移动组顺序才有效」的来源。

矛盾点：2026-09-17 权重修订（名称按命中词数计）的设计意图就是支持**名称词前缀重叠**的组共存——名称{P1} vs 名称{P1,2K}，「P1_02_2K」命中词 1 vs 2 归组二。但互斥转移恰恰让这种配置在管理弹窗里根本输不进去（输「P1」即从组一摘除）。P1 案与杰森案是同款场景。

## 定案（用户拍板「分词的累加来提升权重」）

**名称词 / 标签词退出互斥转移**，互斥只剩扩展名 / 类型 / 日期（一个文件只落一个扩展名 / 类型 / 日期档，天然互斥）。正解配置：

- 杰森组 名称{杰森}（命中权重 1）
- 杰森妈妈组 名称{杰森,妈妈}（妈妈图命中权重 2 > 1 → 归妈妈组，**与组顺序无关**）
- 杰森助理组 名称{杰森,助理}（同理）

标签同此理（{角色} vs {角色,破损}），随名称一起退出——旧「标签互斥同扩展名口径」（09-17 走查追加时所定）废除。

## 改动

- `src/components/GroupManageDialog.vue`：`onPickValue` 入口对 name / tags 早退（唯一的互斥执行点；新建分组弹窗本无互斥），头部注释同步。
- `src/components/GroupRulesEditor.vue`：两处注释同步（编辑器说明行 + 名称规则行注释）。
- `src-tauri/src/services/operations/folder.rs`：`set_folder_groups` 文档注释补互斥范围限定（后端本就不拦重叠，零行为改动）。
- PRD `02_文件整理/04_分组.md`：条款 2 收窄为「仅扩展名 / 类型 / 日期」+ 名称 / 标签不互斥定案（含杰森案例）；标签段旧互斥句废除改写。

## 验证

`pnpm typecheck` 0 错。归组权重逻辑（`matchGroup` 命中词数多者优先）09-17 已就位，本次只解放编辑器输入侧，无逻辑新增。后端 `set_folder_groups` 校验（空范围 / 完全相同）不受影响——名称重叠的两组规则集合本就不同，查重不拦。
