# 工作空间搜索 rel 映射修复（实机二轮三报同根，2026-10-07）

> 用户实机走查 10-03 两轮（_15 落地 / _16 走查修复）后再报三条：预览显示格式不支持（实际支持）、
> 搜索仍无缩略图、「打开目标文件夹」连环报错回退到根。三报同根 = 一个映射 bug。

## 根因

`ws_search` 的命中映射把 Everything 返回的绝对路径按**搜索锚点**（scope 目录）剥前缀——子目录视口搜索时，rel 丢了「视口前缀」段：真实位置 `02_创作/01_原创动画/01_计划中/224/07_音乐/BGM/224.wav` 被映射成 `224/07_音乐/BGM/224.wav`。根视口搜索（scope=""）不发病——探针与首轮自测全在根视口，恰好掩盖。

错误 rel 的连锁伤亡：
- 预览：wsPath = 根 + 错 rel → 文件不存在 → 播放源解析 None → 「该格式暂时无法播放」+ 降级「暂不支持此文件格式预览」；
- 缩略图：缓存键按错 rel 查不中 + 前端可见卡上报的 abs 路径不存在 → 入队解析静默丢弃 → 永不生成；
- 「打开目标文件夹」：导航到不存在的错 rel → list_dir Err → missing 置位 → 幽灵回退链连环 toast 直至根。

## 修法

`services/ws_search.rs` 范围解析改「查询腿」模型：每条腿 =（查询锚点 anchor，命中映射词法前缀 base）——主腿 base 恒 = scope_rel（门词法），链接补查腿 base = 链接 rel；`rel = base + 剥锚后的子路径`，恒为**工作空间根相对**。新增回归测试 `map_hits_scoped_stays_root_relative`。

顺带硬化：剔除 Everything 索引滞后的幽灵命中（`is_file` 逐条校验，千条毫秒级）——索引对搬走/删除的文件有滞后（文件夹索引尤甚），不剔除则预览/缩略图/跳转会落到不存在路径上。

## 验证

- 单测：ws_search 9 绿（含新回归 + 链接门 base 不丢深度断言）；
- 真机定点（`live_real_workspace_focused`，scope = `02_创作/01_原创动画/01_计划中`）：`224.wav` rel 根相对正确 + 缓存波形缩略图回填命中；定妆照 png 无缓存留 null（交前端上报生成链）；
- 全量 cargo test 绿 + clippy 净 + typecheck 0 错（终审见本条收尾）。
