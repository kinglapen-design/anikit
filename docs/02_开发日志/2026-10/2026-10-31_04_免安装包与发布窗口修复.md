# 免安装包与发布窗口修复

## 发布窗口问题

开发实例可用 `TAURI_CONFIG={"app":{"windows":[]}}` 控制窗口，但 release 已嵌入默认 `main`，该环境变量不是运行时覆盖配置。验收分支原先无条件再建 `main`，因此启动即报 `a webview with label main already exists`。现在只在 `main` 不存在时创建验收窗口；release 复用默认窗口，并用 `WEBVIEW2_USER_DATA_FOLDER` 隔离浏览器目录、`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 提供本次 CDP 端口。普通启动的单实例、协议注册与窗口行为不变，CDP 没有永久开放。

`open_devtools()` 仍只在 debug 构建调用，release 不依赖 DevTools feature。实际 release 页面经 `http://tauri.localhost/` 连接成功，不依赖 Vite 或 spike。

## 构建与独立验收

在正确的 Rust 工作目录完成 `cargo check --lib`、`cargo clippy --bins -- -D warnings` 和 `pnpm tauri build --no-bundle`，再运行 `tools/pack-portable.py 20261031 anikit-portable-semantic`。便携目录为 `release/anikit-portable-semantic/`，实际大小约 **1312 MB**；ZIP 为 `release/anikit-v0.1.0-20261031.zip`，约 **866 MB**。模型必要 ONNX 与 tokenizer 为 895,027,948 bytes，许可、模型卡和运行时 notices 随包携带。

启动验收实例时不设置模型、worker 或运行时覆盖路径，使用新的隔离配置和 WebView2 用户目录。`test_semantic_runtime` 证明模型来自便携目录、后端为 CPU；真实中文检索、视频 / 动图 / 序列帧定位、右键创建虚拟片段、三类虚拟范围播放、物理单帧及 MCP 32 工具全部通过。 ffmpeg sidecar、semantic-worker、ORT / DirectML DLL 均从包内加载。

ZIP `testzip()` 完整性通过，必要 exe、模型 manifest、运行时 DLL、ffmpeg / ffprobe 和许可文件逐项存在。发布实例已关闭，没有覆盖用户正在使用的 `anikit-portable-new`。
