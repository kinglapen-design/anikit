# 工作空间性能优化二轮（2026-10-01）

待办细节清单 2026-10-01「工作空间性能优化候选」三点立项项 + 观察项一次落地（用户点名，worker 池并发「提高一点」）。一轮已在 2026-09-26 做过（缩略图 worker 池 / spawn_blocking / 视口合批），本轮针对剩下的三根热埂。

## ① fs-changed 精准重扫（收益最大项）

现状是 `workspace-fs-changed` 负载恒 `()`，前端 300ms 去抖后 `rescanLoaded()` 全量重扫**所有**已加载目录——展开树深、开过视口多时，任何一处变动 = N 个目录全量列举。

改法按待办口径落地：后端 `start_watch` 回调把 notify 事件路径集转成**变更涉及的目录 rel 去重排序集**随事件带出（`services/workspace.rs changed_dirs`），前端去抖窗口内多拍取并集，只重扫交集中的已加载目录（`ws.rescanDirs`，新增 action）。`.anikit` 过滤与 known_ops 回声消重原样不动。

两个实现要点：

- **词法 strip_prefix，不 canonicalize**——删除事件的旧路径已不存在，`rel_of` 那套规范化必败，会把所有删除事件打成全量兜底。notify 8.2 Windows 后端源码实证：事件路径 = 注册监听根原样 join 相对段（不 canonicalize），词法剥前缀可靠；任一非缓存路径剥不出 → 负载 null，前端整窗回退全量重扫（保留 `rescanLoaded` 作兜底）。
- **每条路径取父目录 + 祖父目录**。父目录好理解（条目增删改殃及所在目录列举）；祖父目录是为了树展开箭头不回归——`hasSubDir` 存在父目录条目里（祖父列举的一份），目录级增删不重扫祖父就会留下箭头陈旧（原全量重扫无此问题）。两级零 stat 开销，换来与全量重扫等价的箭头新鲜度。

前端 `wsOps.initWsListeners` 加窗口合并态（`fsDirs` 并集 + `fsAll` 标志：窗口内混入 null 拍整窗回退全量）。

## ② list_dir 逐文件 syscall 瘦身

现状每次列举对每个文件最多做：魔数 probe 读源文件头 + `fresh_thumb_path` 两次 is_file（webp/png 双扩展名）+ 非图片缓存命中再读缩略图头 + exe 一次 is_file——万级目录每次列举数万次 syscall。

落地 = `services/workspace.rs` 新增趟内共享缓存 `DirScan`（list_dir 趟初建、趟末收尾）：

- **thumbs 目录文件名快照集合**（待办②最优先）：趟初一次 `read_dir` 进 `HashSet`，内容缩略图双扩展名探测、exe 文件级图标探测（`fresh_exe_icon_path` 退役并入）、按扩展名格式图标探测全部改集合匹配，零逐文件 syscall；趟中新落盘的图标名顺手补进集合，同趟后续同扩展名条目不再走 ensure 的内部 is_file。
- **魔数探测持久缓存**（待办①次之）：`.anikit/probe.json`，`{ job_key: [w,h] | null }`——键同 thumbs 键径（内嵌 mtime+size，源变化键自然失效无需主动清）；**含非图片 / 失败负缓存**（否则视频 / 文本条目每次列举都重开文件头，是非图片目录的大头）。趟末有新增才回写：进程级锁内重读合并（list_dir 在 spawn_blocking 可多趟并发，防互抹新增）+ `write_text_atomic` 原子写（踩坑 095 口径）+ 条目超 5 万按本趟触及键白名单重建防膨胀。纯缓存可删可重建，读失败 / 落盘失败均静默降级。

## ③ 视口挂载无新鲜度重读

`ContentArea` 挂载 ws 视口原恒 `loadDir` 全量重读。待办注明「依赖①落地（有精准失效后才敢跳过）」——①已落，评估结论 = 可做：已加载目录的新鲜度此后由 fs-changed 精准重扫维持，挂载跳过是安全的（监听盲区以右键「刷新」`refreshDir` 兜底）。

落地 = `ws.ensureDir(rel)` 新 action（`loaded` 命中即返回，否则走 `loadDir` 首发），ContentArea 的 viewKey watch 与 WorkspaceTree 的层级挂载（根层 + pin 目录计数预取）改调它。树懒加载、视口可见卡缩略图补发（AssetCard 上报链）均不受影响。

**配套修复（前置安全问题）**：前端 ws store 原在切空间后不清——目录缓存以 rel 为键跨空间撞名、`root` 缓存指向旧空间（存量隐患，原靠挂载全量重读部分掩盖）。`libraryOps.openSpace` / `createSpace` 成功后 `useWsStore().$reset()`，保证「事件维持新鲜」的前提（缓存归属当前空间）成立。

## 观察项④ worker 池并发提高（用户定「提高一点」）

`ws_thumb_queue` worker 数 = 可用并行度一半的**上限 4 → 8**（下限 1 不动，留一半核给 UI / 系统的口径不变——宽核机不再被低上限卡住，音视频 ffmpeg 子进程随之至多 8 并发）。按队列深度弹性暂不做（观察项原话「再评估」，等实机数据）。

## 发现与边界

- **notify Windows 后端的监听静默死亡盲区**（读源码发现，非本轮引入）：RDC 缓冲区溢出（`ERROR_NOTIFY_ENUM_DIR`）走 notify 8.2 windows.rs 的未知错误分支 = log + **unwatch**，且 Windows 后端从不发 `Flag::Rescan`（fsevent / inotify 才有）——溢出后热刷新整体静默停摆，全量时代与精准时代同盲。已记待办细节清单观察项，本轮不修。
- ③ 的跳过以事件流为前提：`.anikit` 内变更本就被滤（缩略图缓存写回），若用户手动删 `.anikit/thumbs`，条目 thumbPath 陈旧要到下次该目录有事件才自愈——可接受边界，刷新按钮兜底。
