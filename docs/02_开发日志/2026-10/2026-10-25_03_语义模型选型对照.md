# 2026-10-25 语义模型选型对照

## 结论

1.0 基础模型定为 `sentence-transformers/clip-ViT-B-32-multilingual-v1` 文本塔 + 其对齐的 `openai/clip-vit-base-patch32` 图像塔，输出 512 维。两塔必须保持训练时的对齐组合，不与其他文本 / 图像塔混搭。

选择依据不是“模型能运行”，而是同一真实质量集上的质量、许可和成本三项共同比较。Chinese-CLIP 不再进入产品，SigLIP 2 也不替换当前组合。

## 同集对照

验收集来自 BridgeData V2（CC BY 4.0），包含 50 条轨迹、首中末 150 帧、17 条常规中文查询和 1 条零正例诊断查询。覆盖水槽、餐具、锅、海绵 / 刷子、微波炉 / 抽屉、擦锅 / 擦灶台、布料和取放动作，并保留主体对动作错、动作对主体错的 hard negatives。

| 指标 | Chinese-CLIP | multilingual-v1（选定） | SigLIP 2 |
| --- | ---: | ---: | ---: |
| Top1 | 23.53% | **35.29%** | 23.53% |
| Top5 | 29.41% | **52.94%** | 29.41% |
| Top10 | 52.94% | **64.71%** | 58.82% |
| MRR | 31.69% | **42.36%** | 30.09% |

“机器人洗碗”没有可支持的直接正例，只作诊断，不纳入指标。擦锅不等于洗碗，干水槽里的放锅 / 放餐具也没有被冒充为洗碗正例。

选定组合的许可路径为文本 Apache-2.0、OpenAI 官方 CLIP MIT；revision 与 notices 已固定。Chinese-CLIP 权重未声明许可，不能因技术可用就发布。SigLIP 2 虽为 Apache-2.0，但四项指标均下降，模型与 tokenizer 合计约 1.54GB（选定组合约 0.90GB），CPU 图像 P50 约 476ms（选定组合约 17ms），没有替换收益。

## 运行验证

三套模型均使用 Rust `ort` + ORT DirectML 1.24.4 / DirectML 1.15.4 验证 CPU 与 DirectML，主代理独立复跑结果一致。选定组合的 warmed-up 文本 P50 约 16ms（CPU）/ 1.3ms（DirectML），图像 P50 约 17ms（CPU）/ 2ms（DirectML）；DirectML 实际只使用 DML EP，没有回退。

Rust 原生预处理、token IDs、512 维输出、L2 归一化和官方样例均已验证。SQLite spike 另通过 3 项测试与 clippy：分段幂等替换、确定性 topK、模型维度隔离、任务重开续跑。

相关提交：`484816eb`（Chinese-CLIP 双后端）、`0d2fa9e1`（质量集与原生预处理）、`6b027805`（多语言 CLIP）、`262fbc91`（SQLite）、`12a1147d`（SigLIP 2 对照）。

## 仍须保留的边界

质量集显示明显静态场景偏置，开关微波炉 / 抽屉、连续动作和因果不能只靠 CLIP 排名承诺。选定组合只是基础画面检索底座，详细动作描述与事件链仍由外部 provider 增强。

本轮未做统计显著性检验、公开 benchmark、更多语言或正式性能基准；千帧耐久在主模型上单独补跑。下一步进入主业务 SQLite、本地运行时和设置持久化实现，路线图第 2 项仍不提前勾销。
