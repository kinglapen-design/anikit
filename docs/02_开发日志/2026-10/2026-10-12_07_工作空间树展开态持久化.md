# 2026-10-12_07 工作空间树展开态持久化

## 需求

用户实机报：工作空间每次打开视口会记住上次关闭时停留的文件夹（lastWsView 记忆），但文件树的展开状态没有记住，每次都需要重新展开。

## 落地（纯前端三文件，零后端零新组件零新样式）

**`lib/treeExpansion.ts`**：ws 树展开态从共享 openSet 拆出独立集合——`openSet` 维持库树专用（文件夹 id，会话级不变），新增 `wsOpenSet`（relPath 键）与 `isWsTreeOpen` / `toggleWsOpen` / `restoreWsExpanded` 三接口。顺手根治一个潜伏串台：库树右键「折叠所有」的 `collapseAll` 原把 ws 展开键一并清掉，分集后两树互不干扰。

**`stores/ui.ts`**：新增 `wsTreeExpanded: Record<空间 rootPath, 展开 relPath 清单>` 并进 PERSIST_KEYS——与 lastWsView 同一持久化通道（`settings.ui` 子树透传，$subscribe 防抖 500ms 写回），settings.ui 是 `serde_json::Value` 透传故**零 Rust 改动**。loadSettings 补形状兜底（pluginOrder 同先例：config 手改变形逐项剔净）。**按空间分键不共享**——踩坑 100 教训：路径类记忆跨空间重放必出幽灵态（甲空间展开的 relPath 在乙空间同名目录被误展开）。

**组件两侧**：`WsTreeRows.vue` 展开判定 / 切换换用 ws 集两接口；`WorkspaceTree.vue` 根实例（isRoot 守卫，递归子层不管）在 onMounted 与既有 `watch ws.root` 空间就绪重引点调 `restoreWsExpanded(rootPath)`。

**恢复与写回口径**：恢复 = 读本空间清单 → `wsDirsExist` 批量 stat 剔除已删 / 改名目录的僵尸键（`pruneWsViewKeys` 同口径，判定失败保守不清）→ 应用进集 → 剔除结果回写归一；幂等（同空间重复调用跳过，会话内展开变化不被回拉覆盖），代际守卫（ws store epoch 同模式）防恢复在途又切空间时旧清单盖新。写回 = `toggleWsOpen` 变化即同步 ui store，随统一防抖落盘。区块标题折叠态（pinsOpen / treeOpen）与库树展开态维持会话级不持久化。
