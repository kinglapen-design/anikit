# 侧栏区块标题递归文件夹总数 + 预览计数视口跟随修复（2026-10-03）

> 2026-10-03 · 第一轮。用户实机报两条：① 侧栏区块标题数量（「创作 / 1」「项目 / 4」「文件夹 / 3」）只数顶级文件夹，要显示递归总数；② 预览标题栏「x / y」总数停留首次打开预览的视口值不刷新（02_修改 只有 1 个文件却显示 1/6），上/下一个按钮亮着但点击无反应——用户自察「总数取决于第一次打开预览的文件夹的文件数」。

## 根因

- **BUG1（口径遗漏）**：LibraryView 区块标题 `:count="sec.nodes.length"` 只数顶级节点；MovePanel 早有递归 `countNodes`（移动窗区块标题已是递归总数），侧栏漏同步。
- **BUG2（响应式依赖缺失）**：preview store `total` / `index` 是 pinia computed，列表源经 `tabs.viewKeyOf` 直读 dockview `panel.params.viewKey`（store 自述非响应式）——viewKey 变化不构成依赖，`total` 缓存停留首视口值（`index` 因 assetKey 在依赖里幸免于难，所以「当前位对、总数旧」）；按钮 disabled 按缓存 total 判定（亮）、`step` action 按实时列表越界 return（无反应）——「亮但点不动」的分裂感根因。详见 [踩坑 102](../../04_踩坑记录/091-120/102_dockview参数非响应式与pinia_computed缓存——预览计数停留首视口，viewKeyOf锚定tabs镜像建依赖（2026-10-03）.md)。

## 修复（纯前端三处）

- `stores/content.ts`：`BlockSection` 增 `folderCount`（递归文件夹总数，含全部后代层级），`blockSections` getter 同趟产出；
- `LibraryView.vue`：区块标题 `:count` 换 `sec.folderCount`（MovePanel 搜索态需按过滤后节点计数，其本地 countNodes 语义不同，保留不动）；
- `stores/tabs.ts`：`viewKeyOf` 先 touch `tabs` 响应式镜像建立依赖，取值仍以 api 实时为准——视口替换经 `syncMirror` 重建镜像即触发 getter 重算，current / index / total 同愈。
