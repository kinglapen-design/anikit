# 语义搜索与真实界面验收

## 验收环境

使用 `ANIKIT_E2E=1`、独立 `ANIKIT_CONFIG_DIR`、独立 WebView2 用户目录和隔离素材库，不打开或改写真实用户库。测试媒体为 MP4、GIF 和三帧序列包，模型与运行时均使用受管文件，实际后端为 CPU。探针只走真实 Tauri command、CDP 鼠标输入和 MCP HTTP，不用直接改库制造通过结果。

## 实际通过项

- 基础分析、暂停 / 恢复 / 取消 / 重试及三类素材分析 3/3 完成。
- 搜索菜单切到语义模式，真实中文查询产生分段命中，相关度顺序与计数一致；可见卡片与后端命中源一致。
- 单击不打开预览；双击视频从命中时间起播；GIF 使用真实帧流定位原始帧 1，序列帧定位原始帧 0，对应 `blank-test_1.png`，不按平均 fps 猜帧。
- MCP 完成 initialize、notifications/initialized、tools/list 和 tools/call。工具面为 **32 个 = 只读 12 + 写 20**，检索、任务控制、库隔离和写入闸均通过。空 assetIds 拒绝分析，未配置 provider 拒绝详细分析。
- 完整探针 S0–S9 最终通过，包含右键创建片段与三类虚拟范围播放，不是只做后端导入或编译检查。

分析重试会替换 segmentId，因此启动时即监听完成事件，各面板按当前视口刷新语义命中；创建前再重查一次，避免完成事件与点击之间的竞态。后端继续拒绝陈旧命中，不通过放宽校验掩盖问题。

## 回归与证据

最终全量后端 **703 项通过、0 失败**，20 项按需 ignored。语义模块 39 项通过、帧流 9 项通过；动态 WebP 与 APNG 的导出也做真实逐帧解码验证。`cargo clippy --bins -- -D warnings`、`pnpm typecheck`、`pnpm build`、`pnpm inventory` 全过。组件台账为 170 个组件，new=83、business=85、dead=2，无 legacy token；dead 项是既有 FolderPickNode、SectionHeader，没有在本轮扩张。
