# 2026-10-13_04 新增区置顶期间拖拽排序失效修复（用户实机"排序提示成功但没用、切目录又好了"）

用户实机录屏报：链接文件（P2_雪牧分屏_1）与原始文件（P2_雪牧分屏）同在一个文件夹时，拖链接卡片到目标间隙，toast「已调整顺序」照弹但卡片纹丝不动；切一下目录再回来，顺序又是好的，之后拖拽也恢复正常。根因 = **新增区置顶期间可见序 ≠ 存储序**：链接粘贴 / 导入时 `markArrivals` 登记 `assetId|folderId`（自洽子域，不区分同夹多条位置——origin + 链接同夹时**两条同钉**段首，10-11 选择域独立化的撞键后缀口径不参与），置顶钉住期间 `dropAssetsGap` 自定义排序分支仍按**存储序**发 `reorder_placements(items, beforeItem)`——拖 pinned 项时存储侧可能是无操作（它本就处在那个存储邻位），即便存储真动了，refresh 后显示层仍按置顶钉回段首，两路都呈现「提示成功但没执行」；切目录 `clearArrivals` 归位后自愈（用户「现在又好了」正对应）。同族第三例：树名称排序拖拽物化（08-14）、素材显示排序拖拽物化（08-19）之后，新增区置顶这条脱钩路径漏了物化。

修法 = 与显示排序同口径收进既有物化分支（`dropAssetsGap`）：目标段可见清单含 pinned 项即把该层可见序（含新增区置顶段）物化为存储序、拖拽组按落点并入整层重写（`reorder_placements` 全层序列 + 段尾锚点），落笔后 `clearArrivals` 归位——pinned 位置由自定义序承接，所见即所得；`ui.sortBy` 仅在显示排序进分支时切回自定义（pinned 进分支时本就自定义，不动）。无 pinned 的常态路径零变化。PRD 04-06 排列物化条同步补「自定义排序下同口径」。

验证 = 新探针 `tools/cdp-arrivals-drag-probe.py` 全 PASS（S1 链接粘贴后撞键两条同钉段首复现用户现场 → S2 置顶期间拖拽 = 物化全层 4 项序列 + beforeItem null → S3 refresh 后显示序随拖拽生效 → S4 归位后基线路径单项 + 锚点不破）+ **反向对照**：stash 修复后复跑，S2/S3 如期 FAIL（调用退化为单项 + beforeItem、显示钉住盖回）复现用户报错，pop 恢复后全绿；typecheck 0 错。探针注记：旧 `cdp-sort-probe.py` 因阶段七 UI 重构选择器漂移（`.title`→`.kc-name`、工具栏控件族换代）S0/S1a 起不了，其 S9 物化场景已由新探针覆盖，旧探针适配另轮。踩坑 112 新立（可见序与存储序脱钩期落点必物化）。**待实机走查：同夹链接拖拽排序即生效 / 导入后新增区未归位时拖普通项同样即物化归位**。
