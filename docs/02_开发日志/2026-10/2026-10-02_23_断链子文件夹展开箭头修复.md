# 断链子文件夹展开箭头修复（2026-10-02）

链接走查四连报：断链文件夹在树里「连展开箭头都没有，已经没有子文件夹了」——用户先以为断链门被故意隐藏，展开后才发现是父目录的箭头整个没了。

## 根因

`has_visible_sub_dir`（树展开箭头判定）用跟随式 `is_dir()` 扫描子级——断链 junction 穿透失败得 false，于是「只含断链门」的父目录被误判**没有子文件夹**，展开箭头消失，断链子夹在树里彻底不可达（条目本身列目录正常——卡片和子列表都对，唯独箭头没了）。同族隐患：有效 junction 因子目录穿透得 true 不受影响，只有断链触发。

## 修复

`has_visible_sub_dir` 与 `list_dir` 的目录判定对齐：**reparse 目录（含断链）也算子目录**——`DirEntry::file_type`（Windows 零 syscall、不跟随）疑似 reparse 的候选补一次 `is_reparse_dir` 检测，普通文件与真实目录零额外开销。测试补「只含断链门的父目录 has_sub_dir = true」断言（ junction 只能向活目标建，先建活目标再删造断链——首版测试向已删目标建门反被自家适配器拒，顺带又验证了一遍适配器口径）。

`cargo test` 563 测绿 + `cargo clippy --all-targets` 净；接口 20 的 `hasSubDir` 口径同步。

**待用户实机走查**：只含断链门的目录展开箭头回归 / 展开后断链子夹 warning + 置灰可见 / 有效链接目录箭头照常。
