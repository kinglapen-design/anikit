## 跳转 = 新开标签页（不打断当前视口）

`tabs.openInFreshTab(viewKey)` 新立：已有同 viewKey 标签页 = 激活复用（防频繁点击堆积，同浏览器标签堆积教训），没有 = 新开。`jumpToAnikitRef`（anikitLink.ts）全链路改走它——media-open 事件 / links 输入框钮 / MD 渲染态点击 / deep-link 冷启动一处同愈；item → origin 所在文件夹视口新开页 + requestReveal 滚进视野 + 选中，folder 同构。relationOps `jumpToAssetPlacement`（详情区块「跳过去」语义）不动。APP 内永不拉浏览器：http open 形态链接在 APP 内点击被 parseAnikitRef 认出（(open/) 前缀同认）走内部新开页，只有真外部 http 链接才走 open_external_url。

## deep-link 系统协议复活（浏览器标签干扰的根治）

用户问「外部也要拉起浏览器么，有没有无头方案」——有，且就是当日废案的回头：注册 anikit:// 系统协议后外部点击**零浏览器标签页**直达。废案复活的两个事实基础：①浏览器标签堆积干扰实机坐实（ http /open 端点每点一次多一个标签页）；②基础设施比当初估计的现成得多——tauri_plugin_single_instance 回调本就携带命令行参数（`init(|app, args, _cwd|)`），注册表写几行 HKCU 即可，单实例参数转发零新增机制。

落地三件：**adapters/deep_link.rs**（新立）——启动时 `ensure_registered` 幂等覆写 HKCU\Software\Classes\anikit 三件套（Default = URL:AniKit Protocol / URL Protocol 空值 / shell\open\command = exe "%1"；免提权 portable 绿色，exe 漂移自愈；失败仅日志不阻断启动）+ `parse_args`（core::anikit_ref 新增 `parse_ref` 供调用，5 测）+ 冷启动 pending（OnceLock，setup 存 / `take_pending_deep_link` 命令一次性取走）；**lib.rs 接线**——单实例回调解析 args → emit media-open + 窗口前置（运行中实例直达），setup 注册 + 冷启动参数存 pending；**前端** initMediaOpenListener 注册后 take pending，库未就绪（启动开库在途）watch placements 首批到达再跳（防「目标不在本库」误报）。
