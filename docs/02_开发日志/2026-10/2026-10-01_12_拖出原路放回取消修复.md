# 拖出原路放回取消修复（2026-10-01）

互通轮实机走查再报（用户）：拖一个文件出去、发现拖错了、没松手原路放回 UI——居然触发了导入（自己的文件被当外部文件回导；库走导入流，ws 落 `_n` 副本）。库式与 ws 式拖出同病。

## 根因与修法

拖出 = 指针越出窗口边界后移交 OLE 系统拖放（`drag_assets` / `ws_drag_paths`，DoDragDrop 模态循环接管指针直至松手）。但我们的窗口始终是合法放置目标——拖回来时 Tauri 照常发 `enter / over / drop`，落盘逻辑无从分辨这条 OLE 拖是自己发起的，当成普通外部拖入处理。

修法 = **自身拖出窗口期整体抑制**：`dragOperation` 新增 `osDragOutActive` 标记（invoke 发起 OLE 拖放时置位、DoDragDrop 返回即 resolve 时清位），`App.vue` 的 `onDragDropEvent` 入口早退——窗口期内收到的 enter / over / drop 全是自己的拖：不高亮、不落盘，OLE 侧报无放置 = 拖取消。单指针同一时刻只有一条系统拖放，布尔标记足够；库与 ws 两条拖出路径一处标记同愈。

## 验证与文档

- `pnpm typecheck` 0 错（纯前端）。
- PRD `05_导入与导出/02_打开素材.md` 补「拖出后未松手原路放回 = 取消」口径（ws 按路径拖出同口径）。
- 待实机走查：库 / ws 拖出 → 原路放回 = 无任何动作（无导入、无 `_n` 副本、无高亮）/ 正常拖到 Explorer 落盘不受影响 / 取消（Esc）后再次拖入外部文件正常。
