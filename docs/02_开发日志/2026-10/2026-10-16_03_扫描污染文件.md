# 2026-10-16_03 扫描污染文件（污染区块的全库总览）

**背景**：污染文件区块（同日 01 轮落地）是单资产视图——用户点出痛点：不常点开的资产里污染会沉淀无感知，并问「全 assets 扫描是不是开销很大」。评估结论 = **开销很小**：判定唯一出处 `list_pollution` 每资产 2~3 次目录级 syscall（read_dir info + origin 实体探测 + frames/ 探测），metadata 全在内存，不读文件内容、不重算 hash；万级资产秒级内，比导入期逐文件 sha256 便宜几个数量级。用户拍板「按步骤做」，链接扫描（02 轮）验证全绿后本轮落地污染扫描。

## 口径定案（PRD 03_查找文件 §05 新立）

- **全库单范围**：逐资产 read_dir info 过滤已知集（与详情区块零分叉）；候选 = 有 ≥1 条活 Placement 的资产（回收站条目与无位置记录不扫）；无主 info（孤儿 / 他库资产）不在此列——开库自检与无主资产弹窗另管。后台线程执行（spawn_blocking 两段短锁：快照 meta 集 → 锁外 read_dir → 命中装卡片视图）。结果按污染条目数降序，平手按显示名 + id（确定性）；无结果不弹窗 toast「未发现污染文件」。
- **弹窗 = 714 扫描族壳**，每行一个污染资产（ni-card 52 横条：40 缩略图 + 名称 + 「N 个污染文件 · 所在文件夹」）。**点击行 = 定位**：`jumpToAssetPlacement` 复用（跳转 origin 视口 + 选中卡片）+ `ui.detailTab = "links"` 切污染区块所在 tab，弹窗即关，处置动线在详情区块继续（三动作见 PRD 03_数据链接 02）。
- **行 hover 滑入两动作**：打开资源管理器（info 目录，reveal_orphan_info 池内校验复用）/ 全部丢到回收站（该资产异物逐条 `trash_pollution_file`——三层校验不变、系统回收站兜底、不进撤销；全清摘行，部分失败留行报数）。底部 = 计数 + 关闭单钮，**不设跨资产一键全清**——处置前至少过一眼行列表，逐资产清是有意的力度。
- 入口 = 菜单栏「查找 ▸ 扫描污染文件」单处（不进 scanEntries 共享组——污染扫描是全库治理，不是位置语境动作）。

## 实现

- 后端 `services/pollution.rs`：`PollutionAssetView { asset: DupAssetView, infoPath, items }`（scan.rs `dup_asset_view` 提 pub(crate) 复用，行卡零新结构）+ `scan_pollution`（纯 IO 段，单资产失败记 log 跳过）；`commands/pollution.rs` 同名命令注册。测试 +1（只收污染资产 / 干净与 info 缺失不命中）。
- 前端 `lib/pollutionScanOps.ts`（模块单例态 + busy 闸；open / locate / reveal / trashAsset；详情区块若正开在该资产，全清后 `repollPollution` 对齐摘行）；`PollutionScanDialog.vue`（壳与滚动复用 scanDialog.css scd- 族）+ `PollutionScanRow.vue` 行件（forceState 陈列惯例同 PollutionFileItem）。
- **`.ni-act` 滑入动作钮（18×18 l4→l2）自 PollutionFileItem scoped `.act` 抽入 items.css**（同款第二处抽象），PollutionFileItem 改吃共享类；多钮组 `flex:none` 完整滑入口径不变。
