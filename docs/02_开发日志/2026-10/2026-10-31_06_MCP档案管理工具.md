# MCP 档案管理工具

## 需求与范围

用户要求把档案的创建、数据、删除等功能交给 MCP。此前通道只有 `list_archives`，Agent 能看档案清单，却不能建档案、填写档案数据或删除档案。

本轮新增 8 个工具：只读 `get_archive_data`，写工具 `create_archive`、`convert_to_archive`、`convert_to_folder`、`set_archive_props`、`set_archive_descriptions`、`set_archive_links`、`delete_archive`。工具面由 32 增至 **40 个 = 只读 13 + 写 27**。改名、移动和提示词绑定继续复用既有文件夹与提示词工具，不另造重复入口。

## 共用命令路径

新增 `commands/archive_ops.rs`，把档案新建、两种转换、三类数据编辑与删除的锁序、撤销快照和业务调用整段抽出。APP 原 Tauri 命令与 MCP 工具都调用这层，保持 `library → undo` 锁序和单撤销步；MCP 只负责参数归一化、写入闸、错误回包和 `mcp-library-changed` 热刷新广播。

`convert_to_archive` 保留两段式：有子文件夹且未确认时返回 `need_confirm`，不改数据；确认后才平移子树 Placement 并删除子文件夹节点。三类数据编辑均为终态整体替换，沿用 APP 的 trim、去空和去重规则。

`delete_archive` 只接受档案。它删除档案节点与数据记录，把档案内 Placement 移到未分类，**不删除素材实体**，也不提供任何物理删除入口。

## 删除残留修复

排查时发现 APP 原删除路径只删 folders.json 节点，archives.json 记录要等下次开库自检清理。现在单删、批量删除和物理删除路径都会当场清除子树对应的档案记录；可撤销删除记录 folders.json 与 archives.json 双快照，撤销时一并恢复节点、数据和 Placement。封面缓存文件不在删除时物理清除，仍由开库缓存自检处理，避免破坏撤销恢复。

## 验证

新增 2 个共享命令测试，覆盖新建→属性 / 描述 / 链接编辑→删除→撤销恢复，以及两段式转换和普通文件夹删除守卫。全量后端 **706 项通过、20 项 ignored**；`cargo clippy --lib -- -D warnings`、`pnpm typecheck` 均通过，`pnpm tauri build --no-bundle` 成功。

使用 `ANIKIT_E2E=1`、独立 `ANIKIT_CONFIG_DIR`、独立 WebView2 profile 和临时素材库启动真实 release 页面，经 MCP 实际握手与调用确认：40 个工具及只读 / 写入注解正确，关闸写入被拒绝；新建、两段式转换、三类数据编辑、`anikit://folder/{id}` 参数归一化、档案内容热刷新、删除后素材落未分类、archives.json 当场清理、撤销恢复和解散档案全部通过。隔离实例与临时库验收后已关闭、清理。
