# 语义基础分析与运行时

本轮把 1.0 收尾的向量分析从 spike 推进到真实业务：本地 CLIP 分析、分段索引、任务控制、中文检索与前端基础接线。外部详细分析、MCP、千帧耐久和发布验收仍继续推进，路线图暂不勾销。

## 原生运行与模型

主进程通过独立 worker 调用 multilingual-v1 文本塔及配套 CLIP 图像塔。CPU 默认、DirectML 可选，失败回退后复用 CPU；任务固定启动时的模型 revision 与设备，不在中途混用另一套向量空间。响应等待有 180 秒上限，取消会终止子进程，文本塔最后使用超过两分钟会卸载，模型清单缓存避免每次搜索重复校验大文件。

接入 `mock_app` 时还修复了 Windows 测试资源问题：库单测没有 Common Controls v6 manifest，装载 `TaskDialogIndirect` 时进程直接退出。最终只在 `cfg(test)` 下补链接资源，未让正式程序重复嵌入 VERSION；详见踩坑 114。

## 媒体与任务一致性

视频以真实 PTS 索引，末段没有精确到毫秒的下一帧时，解码末段并取最后一个真实 PNG 帧，不猜平均帧率。GIF、WebP、APNG 按实际 delay 保留帧号和显示时间；序列帧复用真实编号清单，短窗也按实际时长收缩，首中末采样去重。APNG 由源文件内容探测，PNG 序列帧不会误判成动图。

分析任务快照固定库 root、assets_dir 和素材元数据，切库不会串写。SQLite 保存逐项检查点、真实后端与失败原因；暂停、恢复、取消、失败重试和重启恢复共用状态机。基础分析失败移除旧向量，外部增强失败保留基础结果。任务使用的模型与设备随启动固定，后台进度不再取可能属于其他查询的全局状态。

真实验证覆盖 MP4、GIF、WebP、APNG 与一个三帧序列包：分析后中文查询命中屏幕序列帧，序列帧时间为 0 / 42 / 83ms，视频末帧 PTS 也正确。CPU / DirectML 探针均返回 512 维，取消与 APNG 实测通过。全量后端 675 项通过，语义专项与 Clippy 通过。

## 检索与前端接线

检索先按 asset 求最佳片段，再按相关度排序，避免一个长视频占满候选名额。`matchCount` 单独记录可跳转片段总数，不以截断后的数组长度冒充命中总数。预览 open 统一接收命中段：视频按秒 seek，动图和序列帧按原始帧索引定位，不按平均帧率反推。

搜索支持智能回退、手动分词与手动语义，结果网格、计数和预览翻页共用同一有序结果源。分析入口复用现有 AI 工具集菜单，进度与取消复用导入进度条。TypeScript 检查已通过，真实交互探针和外部 provider 闭环另行验证，未将未目验的界面当成完成。
