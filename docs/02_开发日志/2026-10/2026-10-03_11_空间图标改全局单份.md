# 2026-10-03_11 空间图标改全局单份（IconFile %APPDATA% 方案）

## 需求

用户否决初版落盘方式：AniKit.ico 存每个储存空间根 = 多建几个空间每处一份副本，应全局跟软件走或放 appdata。

## 方案（desktop.ini 旧式 IconFile 键的环境变量展开）

`IconFile` 键支持 `%APPDATA%` 环境变量展开（`IconResource` 新式键不展开——社区既定行为，XP 起沿用至今），由此做到**图标单份随软件、每个空间只落一个几行 ini**：

- 图标 = `%APPDATA%\AniKit\space-folder.ico`（全局配置目录，config.json 同目录），apply 时 ensure（字节一致跳过 / 不一致覆写 = 版本升级随 exe 换新）。
- ini 内容恒定与用户无关（`IconFile=%APPDATA%\AniKit\space-folder.ico` + `IconIndex=0` + InfoTip），空间搬迁 / 换机 / 换 Windows 用户免维护；无 AniKit 环境打开 = 默认黄文件夹（优雅降级）。
- ini 覆写分流：不存在写、含「AniKit」指纹（我们两代模板）覆写换新、用户自定义不动；空间根初版遗物 `AniKit.ico`（字节 = 嵌入图 = 我们写的）顺带清理。

## 过程坑（测试抓住）

首版测试直调 `apply`——它内部 `dirs::config_dir()` 解析真实 %APPDATA%，测试断言的 tempdir 恒无文件（实际把 ico 写进了真实配置目录）。拆 `apply_with(root, icon_path)` 注入路径，薄壳 `#[cfg(all(test, windows))]` 防生产 dead_code。真实目录那份文件正好是功能目标产物，留作手动迁移的一步。

## 验证

568 测绿（space_icon 全流程重写：全局落地 / 指纹分流 / 遗物清理 / 覆写）+ clippy 净。真实空间手动迁移已做（%APPDATA% 放 ico + E:\anikit 换新 ini + 删遗物 AniKit.ico，ini 隐藏位保留）；**IconFile 环境变量展开的渲染结果交用户实机目视**（E:\ 下 anikit 文件夹 F5——不展开则回退 IconResource 绝对路径 + ini 自愈方案）。免安装包随轮刷新（build + portable-new 换 exe + 重打 zip）。
