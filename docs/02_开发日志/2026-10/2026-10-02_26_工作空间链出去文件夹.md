# 工作空间「链出去」文件夹落地（方向 a′ 产品化）

> 2026-10-02 · 第二十六轮。待办 2026-10-02「从 WS 里链出去」立项兑现——方向 a′（真 WS 留库内 + 外部便利入口 junction）从零代码推荐用法升级为 APP 内建功能：WS 内真实文件夹一键在外部常用位置摆入口 junction。

## 背景与定案

用户在方向 b 实机走查后明确了链接的完整产品哲学：**链接是双向的**——外部目录既能 junction 挂进 WS（方向 b，本日白天已落地），也应该能反过来：文件夹本体留在 WS、把入口 junction 摆到外部常用位置。硬价值（用户原话要点）：内容物理留在储存空间卷 = 阶段九硬链接落盘「想跨盘符都不给机会」，同卷成 / 异卷败的交汇问题从根上消失；摆在外部的入口只是门，误删十秒重建，内容零风险。

生命周期口径（立项时已定，本轮照做）：**只管创建不管存续**——入口在 root 外，不登记 `links` 台账、不补监听、无徽章、无断链标记。内容本体在 WS 内已被主 watcher 全覆盖，热刷新天然通畅；方向 b 的断链标记体系只管 WS 内的门，root 外的门 APP 无感也无需感。

## 落地

**后端**（services/commands/lib.rs 三处）：

- `services/workspace.rs` 新 `link_out(root, rel, dest_dir)`：`resolve_existing` 常规校验（越界 / `.anikit` / 存在性）→ 源必须 is_dir（文件拒「链接入口只能建在文件夹上」；**断链门单独报「断链的链接文件夹请先重新定位」**——is_dir 跟随穿透失败分支，给送修指引而非笼统报错）→ 落点校验（存在且是目录；**拒储存空间整树**，与方向 b `check_link_target` 同闸——workspace 内摆入口 = 同一内容两个词法身份，素材池 / 库数据 = 自留地；落点是源的祖先无害：入口指向子孙不构成环）→ 入口名 = 源文件夹名、`unique_target` 重名 `_n` 规避 → `junction::create` 建门，返回入口绝对路径。不登记不 `note_known_op`（root 外 watcher 不可见，无回声可消）。源是方向 b 的门时 create 内 canonicalize 展平，入口直指最终目标（NTFS 少一层穿透，内容仍只有一份——嵌套兼容性结论的实践）。
- `commands/workspace.rs` 新 `ws_link_out(relPath, destDir) -> string`（返回入口绝对路径供 toast）；无需 AppHandle——不动链接拓扑不重建监听。lib.rs 注册。

**前端**（wsOps + menuSpecs 两处，零组件零 token）：

- `lib/wsOps.ts` 新 `linkOutWsFolder` 封装；不经 ws store（root 外创建无任何视图状态可刷新）。
- `menuSpecs/workspace.ts`：文件夹菜单链接组「添加链接文件夹…」之后加「**在外部位置创建链接…**」（树行经共享 builder 自动获得；多选只作用被右键项，§65 链接菜单口径）；`pickLinkTarget` 加可选 title 参——链出去选的是「入口摆放位置」与方向 b 选「目标」语义相反，选择器标题「选择链接入口的摆放位置」防混淆。成功 toast 入口绝对路径，校验拒绝中文错 toast。
