# 2026-10-16_01 污染文件区块业务（1.0 收尾第 5 项）

**背景**：路线图 1.0 收尾第 5 项——6.2「工程恢复文件」与详情链接 tab「污染文件」区块同物（2026-10-12 路线图体检用户确认），从未立项；区块与 PollutionFileItem 组件 7.1 已贴稿封装，一直是 UI 占位。本轮把占位接成业务：资产 info 文件夹里的异物条目（动画软件崩溃恢复文件 RECOVER_* / 恢复_*、外部程序误写、用户误拖入、改名残留缓存）对详情可见，并给处置三动作。

## 口径定案（PRD 03_数据链接 02 先行修订）

**污染判定 = 已知集反向过滤**：info 目录单层 read_dir，凡不在已知集的条目（文件或子目录）即污染。已知集字段驱动 + 写死名，**禁后缀盲扫**（cache.rs 红线早有诱饵测试：用户 origin 可能恰叫 `xx_thumbnail.png`，盲扫必误伤）——写死名 `metadata.json` / `notes.json` / `annotation.json`（备份清单三件套同口径）+ origin 实体（`metadata.originName`）+ 缩略图（`metadata.thumbnail`，组件级纯文件名校验拦 `../`）+ 动图缓存推导名 `{origin词干}_anim.webp` + `frames/` 目录（仅序列帧形态算已知——判据复用 `frames_dir_if_sequence`，其余资产冒出 frames/ 即异物）。

**三动作（稿 hover 滑入按钮组）**：打开资源管理器 = 复用 `reveal_orphan_info`（池内校验对文件同适用，命令层零新增）；导入 = 既有导入管线 `probeSequences` 全链继承，**剪切语义 move = 导入即清污**（稿另有回收站钮，copy 留底违背清理意图），落点 = 当前查看位置所在文件夹，序列帧检测 / 撞 hash 冲突挂起 / 进度条 / 失败重试全部自然继承零新增；丢回收站 = 系统回收站（无确认弹窗，工作空间删除同口径——回收站即兜底），命令侧三层校验（单组件名 / 不在已知集 / 存在）保证永不误删库管文件。点击行无操作（稿无 prose）。区块标题行恒渲染、无动作组（稿口径不变），无异物不渲染内容容器；档案无 info 目录恒空。

**附带修复（堵增量）**：`rename_origin` 原只同步改 origin 与词干缩略图，`{旧词干}_anim.webp` 动图缓存改名后残留——污染判定按当前 origin 推导，残留缓存必成误报。本轮 rename_origin 补动图缓存同步改名（paths::anim_preview_file 单点推导；目标撞名 = 名称回收场景删旧保留现存，可重建缓存不占撤销对）。存量旧词干缓存不迁移，会在污染区块显形由用户一键清。
