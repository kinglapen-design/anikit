# 2026-10-11_04 文件夹批量重命名

## 背景与定案

用户实机发现：文件夹没有批量重命名业务（素材 3.4 就有 37 稿弹窗，文件夹多选后 F2 / 右键只有单条就地重命名）。用户定命名方式 = **「_[序号]」方式**——即素材批量重命名的序号命名同款：`名称_编号`（位宽 <100 两位 / ≥100 三位，起始编号可改，序号格式 2026-09-23 统一 `_数字`）。

范围定案：只做**库文件夹域**（文件夹树 / 条带卡片，档案同域混选同批——档案 = Folder kind 标记，改名同一数据层）；**工作空间不做**（ws 磁盘实况无批量改名业务，与素材批量重命名 ws 排除同口径——素材弹窗 2026-09-23 起就排除 ws）。替换命名不做（用户只定序号方式，文件夹无词频替换场景，后续要再补）。

先改 PRD 再动工（规范）：`02_文件整理/14_批量编辑.md` 批量重命名条补 ws 排除明示 + 新立「批量重命名文件夹」条。

## 实现

**后端**（`services/operations/folder.rs`）：`rename_folders(lib, items)` 逐条 trim + `validate_library_name` 校验（与单条 rename_folder 同口径）后改名——**失败项（非法名 / 陈旧 id）跳过汇总进 failed 不整体回滚**，同名幂等仍计 renamed、同名不拦截（文件夹名本就允许重复）；全部处理完单次落盘（不像单条逐次落盘），复用 `BatchRenameFailed` 报告结构。命令 `rename_folders`（commands/operations.rs）= 撤销三步接入单撤销步（标签「批量重命名 N 个文件夹」，folders.json 快照），返回 `BatchRenameReport{ renamed, failed }`——与素材批量重命名报告同构。Folder 是数据层分组无磁盘实体，改名不动磁盘、无 DiskOp 登记。新单测两条：批量部分失败矩阵（非法名 / 陈旧 id / 同名幂等 / 撞名照改 / 全失败不落盘）+ undo 一步回滚整批。

**前端**：

- selection store 新草稿 `renameFolderDraft: string[] | null`（与 renameDraft 互斥——两选择域天然互斥）+ `selectedFolderIdsInTreeOrder()`（**编号按树 DFS 视觉序**，与素材「编号按视觉序」（2026-10-08_13）同口径；条带选中 = 树同父级 children 序，天然是 DFS 序子序列，折叠未见的选中项同样覆盖）。
- `placementOps.renameFoldersBatch`：invoke → refresh → toast 汇总（部分失败换 fail 图标文案、带撤销动作）——与 renamePlacementsBatch 同口径。
- `BatchRenameDialog` 扩**文件夹模式**（不新建组件——同壳同 37 稿版式）：`folderMode = renameFolderDraft 非空`；行数据源换 content.folders（名称 / 自定义图标 / 档案 archive 图标 / 颜色 tint 同树行口径，TwoToneIcon 24 居中、缩略位无底块）；**仅序号命名**（分段切换不渲染，mode 恒 sequence）；无词干拆分（文件夹无扩展名），表头「原名称 / 新名称」；打开聚焦「名称」、确认 / 关闭双草稿同清。
- 三入口接线同径：F2（useGlobalKeys 文件夹域多选分流，回收站只读不触发照旧）、右键菜单「批量重命名」（folder.ts 与 archiveCard.ts 同口径——触发项在多选域内才变批量，单选照旧就地）、编辑菜单（renameFlow + canRename 放开文件夹多选 + label 动态「批量重命名」）。App.vue 挂载条件 = 两草稿或。
