## 后端：portals 台账 + 三命令

- **台账**：`workspace.json` 的 ViewState 扩 `portals: [{ rel, portal }]`（扁平多条，一文件夹可多个入口；与 pinned / links 同文件同写点 write_text_atomic）。`link_out` 创建成功后登记（登记失败不拆门只 warn——门已建好能用）。**rename / move / delete 挂钩点零新增**：`update_link_rel` / `unregister_link` 扩成 links + portals 同平移同剔（函数内循环加 portals 遍历，调用点不动）。
- **`ws_link_overview()`**（面板数据源）：links = 台账 + 存活态（ok = 门在且目标在，断链口径同 `WsEntry.linkOk`）；portals = 按文件夹分组 + **指向对账**（ok = 门在且 `read_target` canonical == 该 rel 当前真实路径——文件夹改名 / 移动后台账词法平移、旧门指向原路径即断）+ `relOk`（文件夹本体在不在）。未开空间 / 目录缺失 = 空总览不报错（`ws_list_pinned` 同惯例）。
- **`ws_remove_portal(rel, portal)`**：门在 = 门进系统回收站（红线 a 同口径只删门）+ 剔登记；门没了 = 仅剔登记（「删除记录」同径）。
- **`ws_reveal_external(absPath)`**：reveal 链接关联的外部路径（`validated_ws_path` 的 ws 内约束不适用——链接目标 / 链出去入口都在 workspace 外；无害只读操作仅校验存在性）。
- 测试 +1（`link_out_registry_and_overview`）：登记 / 建成即对账 ok / 改名平移 + 旧门断 / 门没了剔登记 / 父目录剔除同剔子树 portals / links 存活态两态。565 测绿 + clippy 净。
