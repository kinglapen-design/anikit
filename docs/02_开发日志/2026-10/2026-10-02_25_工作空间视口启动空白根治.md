# 工作空间视口启动空白根治（暂态降级入缓存 + 复位后无重引）

> 2026-10-02 · 第二十五轮。用户实机报：上次关闭 APP 停留在 WS 视图，重开后中栏一直空白、侧栏「文件夹 / 0」、常用区块消失，标签页标题倒是恢复正确；非要切一次库再切回 ws 才正常。

## 根因

启动四条异步线并发（设置恢复 / `initWsListeners` / `reopenLastSession` 开空间 / 标签恢复），两条交错缺一不可：

1. ContentArea 与 WorkspaceTree 挂载即 `loadDir`，跑在 `open_space` 完成前，吃后端「未开空间 → `Ok([])`」的**暂态降级**（踩坑 100 修复时保留的口子）——空列表被当真入缓存（`loaded` 置位），与真空目录不可区分；
2. `open_space` 兑现后前端 `$reset()` 把毒缓存顺带抹掉，但**四条重扫通路全断**：`initWsListeners` 幂等、`viewKey` watch 已发过、树 onMounted 已跑过、后端开空间不发事件——「干净但死寂」态（`root=null`、`loaded` 空、`pinned` 空）正好对上用户看到的三个症状。「切库再切回」= viewKey 真变化 + 树重挂载，才补上那一次 `ensureDir`。

## 修复（纯前端，零后端零命令）

「空间就绪驱动自愈」三件套：

- **`loadDir` 加 root 闸**（ws.ts）：`ensureRoot()` 后 root 仍 null → 直接返回，暂态降级数据不入缓存不置 `loaded`；
- **`openSpace` / `createSpace` 的裸 `$reset()` 换 `ws.reseedAfterSpaceChange()`**（libraryOps / ws store 新 action）：`$reset` + **代际递增**（在途 `loadDir` 兑现按代际比对丢弃，防旧空间在途数据写毒复位后的 store——顺手堵掉手动切空间的同款 latent 竞态）+ 立即重拉根信息；
- **消费方 watch `ws.root` 各自重引**（ContentArea 视口目录 / WorkspaceTree 树 + pinned）——不依赖启动与切空间的调用时序，root 重新就绪是唯一可信信号。

## 验证与走查

`pnpm typecheck` 0 错。启动时序竞态无法 headless 复现（须真实重启 APP），**待用户实机走查**：

- 停留 WS 视图关闭 APP → 重开：中栏出内容、树出文件夹、常用区块出现（不再需要切库再切回）；
- 库视图关闭重开无回归；
- 手动切换储存空间后 ws 树与视口正确刷新（本修复顺带覆盖的同款 latent）；
- 断链 / 幽灵视口回退（踩坑 100 场景）不回归。
