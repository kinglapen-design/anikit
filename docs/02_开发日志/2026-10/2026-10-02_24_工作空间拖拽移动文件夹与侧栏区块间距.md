# 工作空间拖拽移动文件夹（树 + 卡片）与侧栏区块间距贴稿

> 2026-10-02 · 第二十四轮。用户两条补充调整：① 剪切移动文件夹已经做了，把树和卡片的拖拽移动文件夹补上；② 工作空间侧栏大纲区块间距拉开，与库式侧边栏一致（原来挤在一起）。

## 拖拽移动文件夹

工作空间的「移动」此前只有剪切 + 粘贴一条路径。拖拽链路其实已具一半——引擎落点三分支（树行 / 文件夹卡 / pane 视口）与落盘动作 `dropWsAssetsInto` → `ws.move` → `ws_move` 在 PRD 02 步骤 2 就通了，缺的只是**文件夹作为拖拽源**的起点：ws 树行与 ws 文件夹卡片此前都不能起拖（树行无 pointerdown 接线；卡片在 `gridPointerDown` 落到框选回调，又被框选的 `.folder-card` 守卫拦掉，什么都不启动）。

补起点两处。前提 = ws 文件夹 2026-09-26 起已进素材选择域（`ws:rel|ws:父级rel` 键形），以 asset kind 起拖天然命中引擎全部 ws 落点分支，库文件夹的排序 / `move_folders` 语义一律不沾：

- **树行**：WsTreeRows 行 `@pointerdown` → `beginAssetDrag(rowKey)`。展开钮 / 命名输入框由 `beginAssetDrag` 的 `button, input` 守卫排除；选择模式（6.2）禁用拖拽，库 `beginFolderDrag` 同口径。未过 6px 阈值松开 = 原 click 导航语义不动，拖完 `suppressClick` 吞紧随 click 不误导航。
- **文件夹卡片**：引擎 `gridPointerDown` 补 `data-ws-folder` 分支 → `beginAssetDrag`（键形词法推导父级，对齐 FolderStrip `wsCardKey`）。

多选整组随选择域天然成立（树行 Ctrl/Shift 多选 2026-09-26_18 已通）。拖拽源半透明 = `dragView.assetKeys` 补接树行 `dimmed` 与 ws 卡片 `dimmed`（库文件夹卡 `dragView.folderIds` 同口径）。

**落点守卫新立 `wsMovableRels`**（wsOps 导出，引擎落点判定与 `ws.move` 同一份口径）：剔除同父空移 / 目标 = 自身 / 目标在源子树内——后两类是后端 `ws_move` 护栏的前端前置：文件夹拖到自己或自己的子目录上不出高亮、松手无操作，而不是弹「不能移动到自身」报错；pane 分支原「同目录禁高亮」守卫（2026-10-01 用户定）一并并入，三处落点统一一个判定函数。

## 侧栏区块间距贴稿

工作空间树原写法是「容器统一 padding 8 12、区块无 padding」，相邻区块只剩容器 gap 8；库侧（与设计稿 左侧边栏-树容器 一致）是「容器 padding 0 + gap 8，区块各自 padding 8 12」，相邻区块视觉间距 8+8+8 = **24**。修法 = WorkspaceTree 纯样式：`.ws-tree.root` 的 padding 删除（`root` 类一并摘除，探针只用 `.ws-tree` / `.ws-section` 不受影响），`.ws-section` 补 `padding 8 12`，快速入口容器行 gap 2 与行内样式不动。头注释与 09-17 起沿用的错误自述（「padding 由容器统一给」）同步修正，速查 §20 回补定案。
