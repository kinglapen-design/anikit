# 2026-10-23 工作空间卡片悬停播放与自动播放放行

## 背景与定案

ws 体验两轮之 ②（① = 同日文档预览放行）。① 轮的排查结论对卡片层同样成立：2026-09-26 三卡轮「悬停播放 / 自动播放维持禁用」是主动收窄而非技术阻碍——播放源命令 `get_media_source_by_path` 早已存在且被 ws 预览面板在用（等于链路已实机验证），ws 卡片缺的不是能力，只是三处前端闸没放开。

定案先行：PRD 02 技术口径新立「卡片悬停播放与自动播放」条 + PRD 04 卡片悬停分发定案补「工作空间卡片同行为」条——**ws 视频 / 音频 / GIF 卡片的悬停播放与自动播放放行，库侧口径（进入延迟分档 / 数量闸 / 可见性联动）原样生效**。范围外两项：动态 WebP（ws 无 animated 元数据，需 probe.json 魔数探测补 ANIM 位，待办另立）、序列帧（ws 无打包语义）。

## 改动

纯前端四文件，后端零改动零新命令：

- AssetCard 三闸摘除：悬停层挂载的 `!isWs`、wantAutoplay 的 ws 早退（仅留 wsPath 未就绪窗口期闸）、音频胶囊的 isWs 空串。isWs 定义提前到 isAnim 之前；isAnim 对 ws 扩「GIF 按扩展名直认」（无 animated 元数据的务实口径，静态 GIF 罕见且直渲无害）。
- 音频胶囊时长补数：ws 无 duration 元数据——未悬停不出胶囊（不显示 0:00），悬停装载后由 HoverAudioLayer 的 duration emit（元素元数据）回填；库侧时长缺失边界同愈（原显示 0:00）。
- HoverVideoLayer / HoverAudioLayer 取源分流：`asset.wsPath ? getMediaSourceByPath(wsPath) : getMediaSource(assetId)`（loadSource + 转码兜底两处），by-path 回 null（非音视频 / 越界）保持底层静态封面不报错。视频层顺带接入响应里的实时 fps（`fpsLive`）——ws 胶囊帧号显示照常（media.rs 每次响应实时探测下发）。
- AnimImgLayer ws 分支：ws 无 info 的 320 小动画缓存，GIF 直渲原文件 Chromium 原生循环（与 ws 预览面板 GIF 同口径）。
