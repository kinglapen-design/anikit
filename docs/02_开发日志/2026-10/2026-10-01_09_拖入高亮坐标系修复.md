# 拖入高亮坐标系修复（2026-10-01）

_08 高亮轮实机走查再报：OS 拖入悬停时，指针还在侧边栏右侧就触发视口整片高亮，拖到内容视口右侧反而消失——命中区整体向左偏。用户实机 1920 屏 125% 缩放。

## 根因：物理像素 × 逻辑像素混用（踩坑 096）

`onDragDropEvent` 的 `payload.position` 是**物理像素**（`PhysicalPosition`，@tauri-apps/api 2.11.1 `webview.d.ts:25` 类型定义实证），而命中用的 `elementFromPoint` / `getBoundingClientRect` 是 **CSS 逻辑像素**。缩放 100% 时两者相等无感；125% 时事件坐标直接当逻辑坐标用，命中区放大 1.25 倍 = 屏幕上看整体左移——左边越界进侧边栏、右侧缺一块，与走查现象逐点吻合。

同一错位其实在库里潜伏已久：`onDrop` 库导入流从 2026-09 起就用事件坐标 `elementFromPoint` 找 `[data-folder-id]`——缩放下树行导入目标静默错，失败时落回「导入到当前文件夹」兜底，无报错所以无人察觉；直到 _08 把命中区可视化，错位才显性（踩坑预防③：兜底逻辑会把定位错误吞成「大致能用」，可视化是让错位显性的手段）。

## 修法

`App.vue` 的 `onDragDropEvent` 处理器入口统一换算：`position / window.devicePixelRatio` 转逻辑像素，再分发给悬停高亮（`osFileDragHover`）与落盘（`onDrop`）——一处换算，高亮、ws 拖入落点、库导入树行落点三条链同愈。

## 验证与文档

- `pnpm typecheck` 0 错（纯前端）。
- 踩坑 096 新立（坐标系混用指纹与预防）；预防措施沉淀进开发规范 §4（系统 / Tauri 事件坐标喂 DOM 前先除 devicePixelRatio）。
- 待实机走查（125% 缩放本机）：OS 拖入高亮左右边界与视口严格对齐 / 树行与文件夹卡落点精准 / 松手落盘目录正确 / 库导入拖到树行目标正确。
