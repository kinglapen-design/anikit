# 工作空间 ↔ 资源管理器拖拽与剪贴板互通（2026-10-01）

待办细节清单 2026-10-01 立项候选 A 节兑现（「工作空间 ↔ 资源管理器拖拽联动」，用户当日指示优先做）。按立项要求先改 PRD 再动工——定案写入 `02_文件整理/13_基础操作.md`「索引式工作空间」节五条 + `01_资源与数据/02_索引式工作空间.md` 新增「与资源管理器联动」节；库 ↔ ws 互拖与复制粘贴语义、符号链接方向（B 节）不在本轮。

## 定案要点

拖入（Explorer → ws）**一律复制**——非破坏口径，与剪贴板导入「来源恒 Copy」同哲学，决策点上选择了立项原文推荐的方案，不做同盘移动 / 修饰键分流。拖出（ws → Explorer）与库拖出同机制且同为复制语义（drag crate `Options::default` = `DragMode::Copy`，只宣告 `DROPEFFECT_COPY`，源文件不动——查 crate 源码实证的既定行为，ws 直接继承）。剪贴板方向是本轮新开口径：ws 的复制 / 剪切都同步写系统剪贴板（CF_HDROP），**剪切附 `Preferred DropEffect=MOVE`** 让资源管理器能接力移出——与库侧「剪切不写系统剪贴板」相反，原因是库剪切是数据移动 APP 内流转，ws 剪切是真实磁盘移动。粘贴走库 2026-09-17 同款剪贴板序号仲裁：序号未变 = 内部粘贴，序号已变 / 内部空 = 读系统剪贴板文件列表，复制来源恒复制、剪切来源移动入。菜单「粘贴」出现条件扩为 内部剪贴板非空 || 系统剪贴板含文件。

## 边界与遗留

- **内部剪切粘贴后系统剪贴板仍留 MOVE 清单**：随后在资源管理器粘贴会报源不存在。PRD 未定「内部粘贴后清系统剪贴板」，定案最小实现；走查觉得碍事再立清理项。
- 库 Ctrl+C → ws Ctrl+V = 库 origin 文件被复制进 ws（等价导出副本）——「内部空 → 系统剪贴板粘贴」定案语义的自然结果，库 ↔ ws 复制粘贴正式语义仍属另行立项。
- ws 粘贴仲裁只认 CF_HDROP；图片 / 文本 / base64 剪贴板内容在 ws 不导入（库导入专属）。
- 外部剪切移动入走「复制后删源」时源删除失败会中文报错但副本已落盘——与资源管理器跨盘移动同款 partial 风险，不吞错误。
