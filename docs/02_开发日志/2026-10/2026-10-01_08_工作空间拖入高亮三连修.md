# 工作空间拖入高亮三连修（2026-10-01）

_07 互通轮实机走查，用户两连报：①应用内拖拽的 pane 高亮触发奇怪——往下拖一点就消失，且同目录空拖也亮；②真正从资源管理器拖文件进来反而没有任何高亮，让人迷惑这高亮是干嘛的。三点一次修完，高亮口径统一为「只回答松手会不会落到这」。

## pane 高亮下半视口不触发（命中层错位）

根因：pane 落点命中判定用网格注册表的 `layer()`，而 AssetGrid 注册时传的是**卡片层**（`cardsLayerRef`）——它只到内容高度（一行卡片时很矮），指针落到卡片层以下的视口空白就判不中，整片高亮（CSS 挂在 `.grid-viewport` 上）随之消失。命中区与视觉区错位，用户「是不是实际容器没撑满下面」的猜测方向完全正确。

修法 = 注册项 `layer` 改传**视口根**（`viewportRef`）——该字段全库只有 pane 命中一处消费（间隙解析的卡片层坐标系由 `makeGridResolver` 自持 ctx，不受影响），dockview 隐藏标签页 rect 全零天然不命中的性质保持不变。顺带收益：库侧跨分屏并入落点在目标 pane 的空白下半区也生效了（与整片高亮视觉自洽）。

## ws 同目录禁止高亮（用户定）

ws 分支此前没有库分支的「被拖项全已在目标文件夹则不出落点」守卫（库侧 2026-09-17 跨分屏轮就有），同目录空拖也亮。补上同口径守卫：被拖 ws 项 `folderId` 全等于目标视口目录 → 不高亮、不落点（落了下也是 store 过滤的无操作）。

## OS 拖入悬停高亮（外部拖入无提示）

`onDragDropEvent` 此前只处理 drop，enter / over 没有任何视觉反馈——外部文件拖进来完全靠猜。落地 = `dragOperation` 新导出 `osFileDragHover(x, y)` / `osFileDragHoverEnd()`：落点解析与 App.vue `onDrop` 同语义（树行 = 并入高亮、ws / 库文件夹卡片 = 并入高亮、可导入视口 = pane 级整片；虚拟视图 / 回收站视口 = 拒入不高亮），视觉槽复用内部拖拽的 `dragView.tree / folderCardId / paneDrop`——单指针同一时刻只拖一样，两引擎不并发；App.vue 注册链改为 enter / over 驱动高亮、leave / drop 清槽后走原落盘流。

## 验证

- `pnpm typecheck` 0 错（纯前端，cargo 未动）。
- 待实机走查：应用内 ws 拖拽整片视口（含下半空白）恒亮 / 同目录不亮 / 跨目录树行·文件夹卡·视口三级高亮；OS 拖入悬停 ws 与库各落点高亮、虚拟视图不亮、松手落盘不回归。
