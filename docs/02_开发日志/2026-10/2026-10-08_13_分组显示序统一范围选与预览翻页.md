# 分组显示序统一：范围选 / 全选 / 预览翻页（2026-10-08）

用户实机两报同根：分组视口下 Shift 范围选把下面分组的文档带进了选中集；预览翻页（上/下一个）走的顺序与用户预料的"下一个文件"不一致。

## 根因

三条顺序链各取各的。网格显示序 = `placementsFor`（存储序 + 显示排序键 + 新增区置顶）再经 `groupPlacements` 组拼接（未分组在头 + 组按定义序，组内保持输入流相对序）；而范围选（`selection.clickItem` 缺省 order = `visiblePlacements`）、全选锚点、选中集输出（`selectedRefs`）、预览翻页（`previewList` = `placementsFor`）全用**未分组序**。分组在显示层把条目重排后两套顺序即分叉——锚点区间与翻页步进按未分组序走，视觉上就是跨组乱带。

MCP 实机取证（现场文件夹 P1，排序 = 自定义即存储序原样）：`04.png → v03_提示词.md → v03.png → v02_提示词.md → v02.png → 20261008_提示词.md → v01.png → 03_白膜 → 03 → …`——图片与提示词文档成对入库，存储序里本来就穿插，截图箭头标的"下一个跳到提示词文档"正落在这条链上。

## 修法

立唯一口径：content store 新 getter **`displayOrderFor(viewKey)`** = `placementsFor` + `folderGroupsFor` 组拼接扁平（`folderGroupsFor` 已自带视口门类与递归显示闸），与 AssetGrid `displayItems` 同源同序。

- `selection`：clickItem 缺省 order / selectAll 键序 / selectedRefs 输出序三处同换 displayOrderFor（批量重命名编号等顺序敏感消费方随之按视觉序）；
- `AssetGrid`：卡片点击显式传本网格 `displayItems` 键序——覆盖 store 够不着的两个边缘：搜索态平铺过滤集（分组失效）与非激活 panel 点击（不以激活视口为准）；
- `preview`：`previewList` 库视口非搜索态换 displayOrderFor（current / index / total / step 同源自动跟随）；搜索态分组失效平铺（与 AssetGrid 同口径）保未分组序，ws 搜索态不动。

## 验证

`pnpm typecheck` 0 错（纯前端：content / selection / preview / AssetGrid 四文件 + grouping 头注）。待实机走查：分组视口 Shift 范围选不跨组带项 / 预览翻页 = 网格视觉下一个 / 批量重命名编号按视觉序 / 无分组与搜索态无回归。
