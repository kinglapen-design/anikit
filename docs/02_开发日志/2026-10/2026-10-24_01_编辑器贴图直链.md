# 2026-10-24 编辑器贴图直链（Typora / Obsidian 粘贴即入库回链）

## 背景与定案

（定案与主体动工 2026-10-23，跨零点收口 10-24。）用户痛点：Typora / Obsidian 的附件目录改到 Z 盘后图片全被移走、md 相对路径全丢——Z 盘是 AniKit 自动导入收件箱，move 语义入库是本职而非 bug。讨论定案：不改用户「截图顺手粘贴」的习惯，让粘贴动作自己把图送进库并把链接吐回来——小工具直拷收件箱（走既有自动导入管线），文档当场写 **by-name 链接**（写链时资产尚未入库拿不到 id，按 originName 解析最新一笔，唯一时间戳名保确定性）。PRD 先行：`09_链接` 加「by-name 形态」条、`05_导入素材` 加「编辑器贴图直链」条。

## 构成（三件套 + AniKit 侧解析链）

- **by-name 解析链（后端）**：`core/index.rs latest_by_origin_name`（小写归一 + 排回收站 + 排 hidden 伴生 + imported_at 最新，纯 core 可测）；媒体服务 `GET /item/by-name/{文件名}`（图源口径与 /item/{id} 同，查表段抽共用）；深链 `anikit://item/by-name/{文件名}`（parse_ref 先于裸 item 前缀判，core 自实现 percent 编解码）；命令 `resolve_asset_by_origin_name`——前端 `jumpToAnikitRef` 新增 item-by-name 分支：点击时才解析成 id 走既有 item 跳转，查无 toast。
- **anikit-paste.exe（Typora 自定义上传命令）**：`src/bin/anikit-paste.rs`——argv 收图片路径 → 拷入收件箱**真实目录**（读 `%APPDATA%\AniKit\config.json` 的 spaces[0].path + `自动导入`；盘符退出即卸所以不走盘符，AniKit 没开也能贴、下次启动存量导入）→ stdout 每图一行 `http://127.0.0.1:{port}/item/by-name/{名}`（端口读 `mcp-server.port`，缺省 17701）。控制台子系统（Typora 要读 stdout）；`mod core` 顺势改 `pub mod core` 单点复用。
- **Obsidian 插件** `plugins/obsidian-anikit-paste/`（零构建纯 CommonJS）：editor-paste / editor-drop 双接管（无白名单图片完全不干预默认行为），插**双形态链接**（内层 http 渲染 + 外层 anikit:// 点击拉起；设置里可切纯 http）；设置页 = 收件箱目录覆盖 + 链接形态。
- **插件面板第三条目「编辑器贴图直链」**（桥接类，速查 §37 口径零新样式）：详情窗四组 = 说明 / Typora（配置块 + 复制钮）/ Obsidian（选择库安装钮）/ 路径；新命令 `get_paste_link_info`（Typora 命令文本 + exe 路径 + 收件箱真实目录）与 `install_obsidian_plugin`（插件文件 **include_bytes 嵌 exe**、安装时写出——portable / dev 无路径分叉）；更多菜单加「安装 Obsidian 插件…」分支；preview 陈列壳同轮补。
- **md_bundle 打包导出支持 by-name**：scan_refs 续读捕获全串 + export_bundle 解析最新资产（未命中进 skipped 明示「尚未导入或已删除」）——不收的话贴图链接打包时会被静默跳过，本功能闭环的最后一环。
