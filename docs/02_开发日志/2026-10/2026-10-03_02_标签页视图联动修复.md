# 标签页视图联动修复（分段选择器跟随定位 + 新建标签页落点）（2026-10-03）

> 2026-10-03 · 第二轮。用户实机录屏报：工作空间和库的标签页切换时，左侧边栏的分段选择器没有定位到对应库 / 工作空间视图（侧栏树与内容区各说各话）；并定新建标签页落点跟随停留视图——停在库 → 全部，停在工作空间 → 工作空间根视图。

## 根因

- **联动缺失**：切标签页时 tabs `syncMirror` 只回写 `content.sidebarSelected`（侧边栏高亮跟随激活标签页），App.vue 的 watch 按 `ws:` 前缀归桶记 `lastLibView / lastWsView`——`ui.leftMode` 从不回写，分段选择器与侧栏树停留在旧模式。
- **落点硬编码**：TabAddButton「+」恒 `addTab("quick:all")`，不区分当前停留在库还是工作空间。

## 修复（纯前端三处）

- `App.vue` sidebarSelected watch：归桶记录的同时回写 `ui.leftMode`（`ws:` → workspace，其余 → library）——单写点覆盖切标签页 / 分屏激活 / 跨视图导航全部路径；手动切分段原路径（onModeChange → openView → watch 回写同值）无环。
- `stores/tabs.ts`：新增 `addTabAtHome(referenceGroupId)` 命令——参照组当前视口定种（`ws:` → 根视图 `"ws:"`，否则 → `"quick:all"`），参照组取不到回退激活 panel；分屏下各组 + 钮跟随本组视口不串台。关空补默认 / 布局恢复等内部路径仍走 `addTab` 显式 key。
- `TabAddButton.vue`：+ 钮改调 `tabs.addTabAtHome(group.id)`（决策收命令层，UI 不承载业务）。
