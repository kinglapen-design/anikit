# 同资产同文件夹多位置：选择域独立化（2026-10-11）

用户实机报「同一个文件的原始和链接，还是会被同时选中，我记得修过一次」——截图实证：同文件夹内 origin（★）+ 两条链接同选同亮。记得的那次 = 2026-09-19 BUG 3，但那次修的是**选择模式 picker 域**（isPicked/togglePick 按 assetId 联动），**主选择域从未修过**（归档《实机走查.md》「选择文件时，所有链接文件都会被设为选中态，请改为独立选择」一项目此前实际未落地）。

## 根因

主选择域 key = `${assetId}|${folderId}` 二元组。链接常规住不同文件夹时不撞，2026-08-13 放开「同文件夹允许重复链接」后，origin 与链接（乃至多条链接）同夹共址即撞键：点任一卡 `selected.add(同 key)`，全部同键卡齐亮。且不止选中视觉——Vue `:key` / data-key / 范围选 / 框选 / 拖拽间隙 / 预览定位同链全撞；命令层三元组 `find_placement` 首条命中，即使选中分开，删/改重复链接也会打错行。

## 修法：撞键后缀 + name 精确到行

**前端**（选择键单写点 `content.placementKey`）：基底 `${assetId}|${folderId}` 不动；仅当该基底在全库 placements 撞键（content 新增 `dupPlacementKeys` getter）时追加 `|{origin?1:0}|{name}` 后缀精确到行。撞键集按全库计算与视口无关 → 同一 Placement 跨视图同键；ws 合成键 / 回收站键永不撞（不属 content.placements）原样得基底——**非撞键项 key 与今日完全一致，漏改的旧点位只退化成今日同选行为、不破其他**。selection.keyOf 代理之；`content.placementRef` 对撞键行在命令入参附 `name`；网格 :key / data-key / 点击三态 / 范围选序 / 框选命中 / 拖拽（dragView.assetKeys 快照 + dropAssetsGap 按键精确）/ 预览 assetKey / 链接跳转（jumpToAssetPlacement 加 origin/name 行提示）/ 详情 / 菜单 / F2 全量换口径（约 20 文件）。

**后端**：`PlacementRef` 补第四字段 `#[serde(default)] name: Option<String>`，`find_placement` 见名即走原 find_placement_named 语义（旧调用方零变化）；`RenameItem` 补 `old_name`（origin None + oldName 唯一命中时 resolve_origin 按行消歧），MCP rename_placements 同吃；单条 rename_placement 命令加 oldName 参。prompt.rs 提示词源文档回收的「三元组相同逐轮重收」写法顺势改单轮精确删除（注释坟场标记）。新增测试 2 件（同夹重复链接指名删除只中该行 / 批量改名 oldName 各中各行 + 陈旧名失败不错伤）。

**顺手补选择模式同族残留**：picker pickKey 三元组（09-19 BUG 3）对同夹重复链接仍撞——补第 4 维 name（archive 恒 `archive|{id}` 不变）；picker exit 恢复发起项选中、link 用途确认入参同换精确口径。

已知边界（边缘可接受）：撞键行改名后选择丢失（key 含名，prune 剔除旧键）；剪贴板持有撞键行后改名再粘贴会因名陈旧跳过该项。

## 验证

`cargo test` 615 全绿（+2）；`pnpm typecheck` 0 错；`pnpm build` 绿。待用户实机走查：同夹 origin + 多链接独立点选 / Ctrl 加选 / 框选 / Shift 范围选不串行；删 / 移 / 改名单指该行；拖拽排序与跨组约束不回归。
