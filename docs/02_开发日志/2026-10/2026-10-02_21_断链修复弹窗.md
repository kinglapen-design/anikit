# 断链修复弹窗（选中断链即弹，2026-10-02）

链接走查三连报：用户删掉链接目标后，选择 / 双击断链目录**没有任何提示**——用户视角就是 UI 卡住了，对 MKLINK 没概念的人更无从理解（资源管理器反而会弹「位置不可用」）。用户定稿交互：**选中断链即弹修复窗，主按钮 重新定位，次按钮 删除链接，X 掉窗口 = 先不管**。

## 定稿与实现

**弹窗** = ConfirmModal brand 三钮（`secondaryLabel` 扩位首例，复用纪律不新建）：主钮「重新定位…」（系统目录选择器重挂同 rel，复用菜单 `retargetLinkFlow`）/ 次钮「删除链接」（弹窗本身即提示，不再二次确认直删——门进系统回收站可找回）/ 取消「先不管」（弹窗族无 X 钮，取消即「先不管」语义，已向用户说明）。状态 = `selection.brokenLinkPrompt`，宿主 App.vue。

**三触发源按 rel 去重**：①单选断链（App.vue watch 选择域——卡片单击、树行 plain click 选中即弹）；②导航拦截（`tabs.openView` ws 守卫：缓存已知断链 → 弹窗不导航，替代当日早些时候的 toast 方案）；③幽灵回退（缓存陈旧「说没断」实际已断——loadDir Err 回退路径改弹窗，普通目录没了仍 toast「目录已不存在或已被移动」）。

**陈旧徽章一并修**：目标被删（尤其空目录）零 watcher 事件，徽章停在选择时的挂链态——回退路径顺带 `refreshAround` 重扫父级，linkOk 随列举翻正；回退目标改为「先爬开断链 / 缺失父级再回退」（断链父级会被 openView 守卫拦截，否则连环回退卡死）。

**术语统一**：菜单「重新指向… / 移除链接」→「重新定位… / 删除链接」（以弹窗用户用词为准），菜单删除链接两段确认文案同步。
