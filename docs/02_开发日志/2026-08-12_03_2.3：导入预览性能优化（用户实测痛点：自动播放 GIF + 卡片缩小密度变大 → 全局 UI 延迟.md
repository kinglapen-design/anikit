**2.3：导入预览性能优化（用户实测痛点：自动播放 GIF + 卡片缩小密度变大 → 全局 UI 延迟，hover 目录树滞后；feat/new-ui）**。**根因**——① 自动播放无数量闸无视口闸：小卡片时虚拟滚动窗口内 200+ 卡片同时逐帧解码，负载随密度倍增；② 卡片动图播放 = `<img>` 直指原尺寸 GIF 源文件（1080p GIF 在 100px 卡片上按原尺寸解码）。**方案定案（用户选）**：数量闸 + info 小动画缓存；自研解码器仍归阶段四（闸门是调度层与其互补不浪费，小动画是缓存层把解码成本从每次播放转移到导入一次）。**① 数量闸（前端）**——新 `lib/autoplayGate.ts`（上限 16，满员排队 FIFO 唤醒；悬停播放直通不走闸）；AssetCard 三处自动播放接线（动图 img 替换 / HoverVideoLayer / HoverSequenceLayer 共用一卡一名额，销毁/关开关即释放）。**② 小动画缓存（后端）**——`paths.rs anim_preview_file`（`{stem}_anim.webp` 推导唯一出口）+ `adapters/ffmpeg.rs transcode_anim_preview`（sidecar 转短边 320 animated webp：scale 条件式短边 320 不放大、`-fps_mode passthrough` 保原 pts 时长无变速、`-loop 0`；实测踩点：临时文件必须显式 `-f webp`）+ `services/anim_preview.rs ensure_anim_preview`（新鲜判定 mtime ≥ origin、`.tmp`+rename 防半文件、失败返 None 不打扰）——挂解包队列同管线（导入后异步生成，解包成败不影响）；`get_asset_file_path` 返回加 `animPreview`（动图命中给路径、未命中提交懒生成返回 None；非动图恒 None）。前端 loadAnim 源改 `animPreview ?? path`（存量旧动图首次回退源文件、懒生成后命中）。**CDP 探针实证**（tools/cdp-autoplay-gate-probe.py：桩 40 动图卡 + autoPlayGif 开）——初始/滚底两态均 21 挂载 16 播放 0 源文件泄漏：闸门上限成立、播放源全走小动画、滚动释放唤醒正常。**探针基建教训**：@tauri-apps/api 2.11 convertFileSrc 改调 `__TAURI_INTERNALS__.convertFileSrc`，桩需补；dev server 随 VSCode 关闭会断（探针前 curl 确认）。vue-tsc / build / cargo test 259 全绿。PRD 04 §自动播放补性能口径、PRD 01 info 内容与 07 接口文档同步（后端子代理落）。
