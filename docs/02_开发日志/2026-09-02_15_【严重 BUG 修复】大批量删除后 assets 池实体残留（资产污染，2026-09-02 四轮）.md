## 【严重 BUG 修复】大批量删除后 assets 池实体残留（资产污染，2026-09-02 四轮）

**真因（purge 半途失败缺陷，两条物理删除路径同构）**：

- `purge.rs::delete_assets_permanently`（素材直接彻底删除）旧序 = **先数据段后物理段**：先 retain 清全部目标 Placement + 落盘，再逐个 remove_dir_all；半途失败只同步已成功项 → **未删资产 Placement 已清、index/recent 保留、info 残留 = 孤儿**（与 6 个残留现场 100% 吻合；CEP 测试期 Animate 占用 fla 是触发器）。
- `recycle.rs::delete_recycle` 物理段首个失败即中断，且 partial_sync 把 **target_set 全集**回收站条目清除 → 失败/未尝试项丢重试入口（回收站已空、物理残留）。空壳链条完全吻合。

**修复四件**：

1. **purge.rs 两函数（delete_assets_permanently / delete_folder permanent）+ recycle.rs delete_recycle 全改先物理后数据**：物理段逐个删 info、失败收集名单**不中断**；数据段只清成功项；失败项 Placement / index / recent / 回收站条目**原样保留**（文件夹 permanent 分支的失败项挪未分类，节点照删），报错含名单 + 「关闭占用程序后重试」。崩溃窗口由既有 prune_missing_placements 兜底。
2. **sync_after_purge 级联回收无主 hidden 伴生**（09 待办既定方向，缺陷仍真实）：被删资产 thumb_asset_id 候选须 hidden==true 且不在删除集 + 剩余存活资产引用计数为零 → 物理删 + Placement/index/recycle/recent/pins 统一收尾；深度恒 1（防套娃护栏既有）；级联失败仅 log 跳过（自检兜底）。
3. **开库自检扫无主 info**（library.rs `scan_orphan_infos`，用户定形态）：空壳（无 metadata.json）= 半截残骸**自动物理删** + log；孤儿（metadata 在，folders ∪ recycle 无引用）= **log 清单不自动删**（可能是用户数据唯一副本）。
4. **import.rs build_asset_with_id 半截清理**：建目录后任何失败 remove_dir_all 自建壳（document.rs 同款口径），堵空壳源头。
