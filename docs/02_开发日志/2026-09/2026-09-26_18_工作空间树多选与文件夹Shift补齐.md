# 工作空间树多选与文件夹Shift补齐（2026-09-26）

## 起因

用户实机走查 _17 轮后两报：ws 视口里文件夹卡片 Shift 范围选不生效（只能 Ctrl 一个个加选）；ws 侧栏树行没有 Ctrl/Shift 多选（库侧目录树有，ws 树保持纯导航 + 单选）。

## 缺口 1 查实：文件夹卡片 Shift——代码在且生效，实机症状唯一相容机制 = 新旧模块混合态

先静态追链：FolderStrip 的 ws 分流（`onSelect`）调 `selection.clickItem` 时已显式传 `order`（条带序的 ws 合成键组），`clickItem` 的 order 参与锚点逻辑完整，`wsCardKey` 键形 `ws:{rel}|ws:{所在目录rel}` 在点击、order 数组、`:selected` 绑定三处同源计算——链路无断点。

再实证：新探针 `tools/cdp-ws-multisel-probe.py`（桩根目录四文件夹 + 两文件，CDP `Input.dispatchMouseEvent` 真实派发带 Shift/Ctrl 修饰位的鼠标事件）：点甲 → Shift 点丙 = 甲乙丙按条带序整段选中 PASS；Ctrl 点甲减选、Shift 点丁从锚点甲延伸整段全 PASS。**当前工作区代码下，用户场景完全生效，无需代码改动。**

唯一与「Shift 恒不生效 + Ctrl 正常」相容的机制：实机会话跑的是「新 FolderStrip（ws 分流传 order）+ 旧 `selection.ts`（clickItem 无 order 参）」的混合模块态——旧签名丢弃第三参，shift 分支退回 `visiblePlacements`（只含文件 Placement）查文件夹键，`indexOf` 恒 -1 **静默 return 且永不自愈**；Ctrl 分支不读 order 故正常。_17 改动未提交经 HMR 上场，pinia store 无 `acceptHMRUpdate` 正常应触发整页刷新，但实机若遇 HMR 通道断开 / 页面未刷新即残留此混合态。**整页刷新或重启 dev 即自愈**；本探针已把该场景锁进回归网，防后续轮次真回归。

边界行为记档（素材范围选同规则，非缺陷）：锚点落在文件键 / 树行键上时 Shift 点文件夹卡片 = 锚不在条带序内退化单选（清空后单选项并置锚），再 Shift 一次即成段——锚点自愈；文件夹段序 = 条带序、文件段序 = 网格序，两段各自独立，不跨段强行连号。

## 缺口 2 落地：ws 树行 Ctrl/Shift 多选（对齐库 FolderTree 三态）

`WsTreeRows` 行点击改三态分发 `onRowClick`：**plain = 导航 + nextTick 单选入域**（_17 既有行为不变，导航与选中并存）；**Ctrl = 加选/减选不导航**（此前修饰键点击会误导航进目录，一并消除）；**Shift = 同级范围选**，范围序 = 本层已加载同级行序（`subDirs` 映射 rowKey）。懒加载边界记档：两锚点须同父级且均已加载才成段——跨父级 / 锚点间未加载的段落天然不含在 order 内（行未渲染即不在 `subDirs` 缓存），锚点失配退化单选，与素材范围选同规则。选择模式（picker）下树仅导航（库 FolderTree 同口径）。

同域联动零新代码：树行键 `ws:{rel}|ws:{父rel}` 与视口在父目录时 FolderStrip 卡键同构——树里 Ctrl 选丙，网格卡丙出 `.kc-sel` 蓝环、树行丙出既有灰底（domain-selected；速查 §41 树选中无描边口径不动，零新样式）。键盘链随之自动受理：Del / Ctrl+C·X 读 `selectedRefs()` 对树行选中整批生效。

树行右键两块补齐：未选中项先单选入域（FolderStrip ws 卡片同口径；picker 模式不入域直接出菜单）；`wsTreeRowSpec` 补**批量分流**（同 wsFolderSpec / wsCardSpec 口径：触发行在选择域内且多选 → 复制 / 剪切 / 删除 N 项作用于整批，文件与文件夹可混合）——原「树行保持轻量」系树行不入选择域时期的定案，多选落地后按本轮任务口径补齐。pin 行（常用区块）复用本 spec：纯导航行永不在选择域，分流天然不命中，退化为对 pin 目录自身的单项管理操作。
