## 结构三件 = 首批 _op 范式复用

`create_folder_op` / `move_placements_op` / `link_placements_op` 从 commands/operations.rs 命令体整段抽出（锁 library → 锁 undo → begin/record_file → 服务调用 → commit / fail()），原 #[tauri::command] 改一行委托，MCP 侧同调——三个都**进撤销**（整体单撤销步，APP 内 Ctrl+Z 可撤），锁序与磁盘快照纪律单一实现。move 的 root → 非 root 摘 importedFrom 标（metadata 快照随撤销步）也随 _op 一同复用。MCP 入参本地化：PlacementRef 三元组（assetId / folderId / origin）重声明带 schemars 中文注释（services 层结构无 JsonSchema derive，同首批 RenameItem 处理）；link 的 names 缺省 = 全部用源名，给了就校验与 items 等长。

## import_paths = 逐文件同步直调既有管线（方案一冲突策略）

读穿 commands/import.rs + services/import_task.rs 后的接入选择：**不另造导入管线，也不包 spawn_import**（那是 Channel 事件 + 任务注册表的 APP 异步形态），而是逐文件同步直调 `run_import`（四阶段并行流水线：并行 sha256 → 一次短锁查重 → 锁外建档缩略图 → 串行注册 + folders.json 节流落盘——单写点纪律不破），on_event 闭包自用捕获 Asset 事件。逐文件驱动换来逐文件精确对账（Asset 事件不带源路径，批量调用无法把回包映回入参路径）；同请求内重复给同一文件，第二次自然落进管线查重 = skippedDuplicate。

方案一映射（管线产出 → MCP 报告）：hash 完全相同 = 管线 ConflictItem → `skippedDuplicate` + 已有资产 id 与名字回给 Agent（查重白送）；同名不同内容 = add_placement 既有同名单一化（**`-序号` 后缀**，core::library::unique_name 口径——PRD 泛称「 (n)」，实际后缀形态以库内既有口径为准）→ `renamed` + finalName；管线失败（路径不存在 / 读不了 / 目标文件夹没了）→ `failed` + reason。**撤销口径：不进撤销**——APP 导入管线本就不接 UndoManager（撤销体系覆盖库结构操作、不覆盖资产池新增），MCP 同口径不硬接，工具描述与文档如实写。文件夹入参拒收（只收文件路径，防一次展开整棵树的意外）。导入对 APP 无害：事件闭包无人订阅（APP 前端 Channel 是另一条链路），库文件无监听（watcher 只管收件箱），UI 随用户切视图自然刷新。

## 顺手结论：场次 groups = 规则组（不需要 assign_group 工具）

读当前库 folders.json：`漫剧_穿越异世界/04_分镜/第六集/场_01` 等场次的 groups 全是**规则组**（GroupDef.rules，无 members）——「提示词」组 = ext md，「P1 / P2…」组 = ext mp4 + name 含 Pn。规则组按扩展名 / 关键字自动归组，导入 / 改名即归组，**assign_group（自由组成员归组）对这些场次无用**，余量批不必带它。全库 11 个有 groups 的文件夹均为规则组。
