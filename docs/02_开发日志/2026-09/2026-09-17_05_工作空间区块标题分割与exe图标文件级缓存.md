# 2026-09-17_05_工作空间 · 常用/目录树区块标题分割 + exe 图标改文件级缓存（用户两条）

## 要做什么

用户实机两条：① 固定后的常用文件夹和目录树挤在一起——要截图那样的区块标题分割（「项目 / 2」「文件夹 / 3」样式）；② exe 图标串味根治口径——「exe 可以单独走文件缓存，其他的还是按格式缓存」。

## 区块标题分割

WorkspaceTree 根层加两个 SectionTitle block 区块标题：「常用 / N」（pin 数，无 pin 不渲染）+「文件夹 / N」（根直接子目录数），间距 = 标题 padding-top 8（首个不吃双份），items 仍 gap 2。**改 04 轮「无区块标题直接列表」初判**（那是沿用库快速访问先例的自作主张——库快速访问是无标题先例，但用户要的是区块分割）——PRD 常用固定交互段同步改定。

交互沿用 FolderStrip / ArchiveStrip 先例：hover 出展开钮、点击折叠区块（组件级 ref 默认开）；空态（workspace 目录缺失）不随折叠隐藏。子层递归无标题。

## exe 文件级图标缓存

根因：不可解码类型回退系统格式图标按扩展名缓存 `.anikit/thumbs/{ext}.webp`——exe 同扩展名各程序图标不同，首个提取的 exe 图标被所有 exe 复用（用户实机「缓存了我打开的第一个 exe，之后所有的软件都变成一模一样」）。

修：exe 走文件级缓存 `{url-safe(rel)}-{mtime}-{size}.icon.webp`（内容缩略图键 + `.icon` 中缀防撞名，purge_stale 同源顺清旧缓存），现场 shell 提取**该文件自身**图标；mtime+size 变化即失效重提。其余类型（txt/zip/fla 等）维持按扩展名缓存。thumbKind 仍 = FormatIcon，前端零改动。库侧（cache/thumbs/{ext}.webp，import / resolve / inbox 同链路）同病未修——本轮只修用户实机痛点（工作空间），库侧待用户发话。

测试：`exe_icons_cache_per_file`（两 exe 缓存互不相同 + 源变化旧缓存被清、邻文件不受影响）；既有 format_icon 回退测试改断言 exe 走 `.icon.webp` 非 `exe.webp`。

## 验证与遗留

`cargo test --lib` 绿（13 workspace 测）；`pnpm typecheck` 0 错。遗留：库侧 exe 图标按扩展名缓存同病未修——用户定「库重构时再弄，那边一般放资产，不会把 exe 导进去」（2026-09-17）；移动已开标签目录后旧 viewKey 显空；树内无「移回根」落点。

## 同日补笔二轮：区块间距改 LibraryView 同口径

用户实机间距仍不对（「不是都是现成的组件吗？看看库里怎么写的」）。根因：初版平铺 + 标题 padding 补丁，与库结构不同——库 LibraryView 是**段容器**写法：`.block.tree` = padding 8 12 / 容器内**标题↔内容 gap 8** / 行 items gap 2 / 段间距 8（.library-view gap 8）。

改：WorkspaceTree 根层照抄段容器结构——`.ws-section`（gap 8）= SectionTitle + 行列表容器 `.ws-rows`（gap 2），根容器 `.ws-tree.root` = 段间距 8 + padding 8 12 共享，padding 补丁全撤。行模板（含递归展开）抽成 `WsTreeRows.vue` 根/子层共用（否则根段容器与非根平铺两处重复），pin 行右键取消固定随抽取补挂（@contextmenu 在 WorkspaceTree 的 pin 行包装 div）。
