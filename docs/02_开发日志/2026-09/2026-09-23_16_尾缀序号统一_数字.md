# 2026-09-23_16 尾缀序号统一 `_数字`（含导入自动加序号；存量不迁移）

2026-09-23

## 需求

用户定：所有尾缀序号统一为 `_数字`，包括导入时自动加的序号也要调整。此前 PRD 01 边界规则 7 定的是 `-序号`（2026-08-04「不使用括号」定案的延续），库内实际还混着 `名 (2)`（工作空间）与 `名称01`（批量重命名序号模式）两种异类。

## 定案

**序号格式统一 `_序号`，存量名称不迁移，只统一新生成。** PRD 先改（8 处：01 规则 7 与序列帧归一条、02-14 批量重命名、05 导入两条、07-03 插件冲突、08-06 MCP 冲突策略、01-02 工作空间冲突口径），代码随后。

## 落地（生成点 8 处 + 解析点 3 处）

后端生成点全改 `_`：

- `core/library.rs unique_name`（同文件夹显示名唯一化单写点——导入 / 移动 / 链接粘贴 / 副本 / 克隆「xx 副本」/ 新建文档 / 解散序列帧包建档 / 冲突决策 link 全走它）；
- `services/asset_menu.rs dedupe_path`（导出文件与文件夹重名）；
- `services/cep_export.rs unique_beside`（CEP 仅缩略图未命中，WebP 挪 fla 旁边）；
- `services/sequence.rs frame_name`（序列帧入库归一名 `标题_序号.扩展名`）；
- `services/workspace.rs unique_target`（ws 移动/粘贴重名 `名_n`，n 从 2——**`名 (n)` 括号式废除**，序号统一的最后一处异类）；
- `commands/import.rs clipboard_temp_name`（剪贴板导入临时文件重名）。

解析点兼容存量（关键，漏了会出真 BUG）：

- `services/sequence.rs restem_frame`（序列帧资产改词干）与 `operations/sequence.rs parse_normalized`（重排序号）原只认 `-` 分隔——存量 `-` 帧与新 `_` 帧都要解析，改 `rfind(['-', '_'])`；改名/重排产出一律 `_` 新格式（存量 `-` 帧重排序号时自然迁入，PRD 已写明）。`parse_frame_name`（导入检测）本就四形态兼容不动。
- 前端 `DetailNotes.vue` 笔记 key 帧号解析正则 `-(\d+)` 改 `[-_](\d+)`——否则新 `_` 帧名笔记标签显示全名不显示帧号。`preview.ts animCoverIndex` 不动（只服务存量动图解包帧名，动图已不持久化解包，永不新增）。

前端批量重命名序号模式同步：`BatchRenameDialog.vue` 序号模式 `名称01` → `名称_01`（位宽规则不变）。

**不动的**：`font.rs -anikit[-{i}]`（临时目录内部文件，语义后缀非纯序号，用户不可见）；`backup.rs 备份目录`（`-1` 是数据版本号、重名 `.{n}` 皆内部机制）；`剪贴板-yyyyMMdd-HHmm` 时间戳连接符非序号；`library.rs 存量扶正测试`夹具保留 `-`（模拟历史存量语义）。

MCP 面同步：mod.rs instructions 与 tools/import.rs 描述「自动加 -序号 后缀」改 `_序号`；接口文档 7 处（MCP通道 / MCP使用指南 / 03_导入 / 08_export_assets / WebSocket通道 / 20_工作空间 / 02_系统 / 18_逐帧笔记 key 示例）同改。
