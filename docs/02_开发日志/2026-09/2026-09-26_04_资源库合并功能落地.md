# 资源库合并功能落地（阶段二 2.1 收尾项，2026-09-26）

## 起因

PRD 01_储存空间 3.2「多个资源库允许合并为一个」始终只有一句话；合并弹窗 UI 在 2026-09-08 纯样式轮已按 18 稿建好（确认钮不接动作、容量列无数据源、多选语义待定，见 [2026-09-08_06](2026-09-08_06_阶段七%20·%20创建与合并资源库弹窗换新稿（BaseModal）.md)）。本轮补齐业务本体：**多选定案 = 勾选项并入当前打开库**，容量列接真数据，确认接真合并。

## 定案（合并口径，已回补 PRD 01_储存空间 3.2）

- 合并目标恒 = 当前打开库；弹窗多选，勾选项一并将入，源库目录随后删除（space::delete_library 复用，delete_orphans = false——引用已归目标库，无孤儿产生）。
- 素材实体不迁（空间级 assets 池多库共享，合并 = 数据层归拢）：源库 folders / recycle / recent / pins / archives 五文件全量并入；**tags.json 不并**（标签体系已取消、无写点，源库标签定义随目录删除废弃）。
- id 撞车才重生成（F/B + 时间戳 + 随机，理论撞），引用全同步（parent / block / Placement.folder / archives.folderId / pins.target / 空间级 relations.json 档案端点 / 档案封面文件名前缀）；默认区块「dir」两库同一个，跳过不重复并。
- **同名不去重**（库本就允许同名，2026-08-14 同类口径）；仅完全重复（同资产 + 同文件夹 + 同名）的 Placement 跳过，origin 转移给已存在条。
- **origin 治理**：目标库已有 origin（folders ∪ 目标回收站 origin 快照 ∪ 本批已并入）的资产，源 origin 降级为链接——库内 origin 恒 ≤ 1（开库自检 fix_missing_origins 同口径）。
- 回收站同资产条目并成一条（placements 按 (folder,name) 取并集、deletedAt 取早）；最近使用同资产保留最新 viewedAt、倒序截 500；pins 按 target 去重。
- 档案封面跨库拷贝进目标 cache/covers/（文件名随新 folderId 改前缀；legacy 原名保留路径撞名唯一化并回写 avatar.file）。
- 目标库合并前**强制备份**（失败即取消，PRD 06-04 备份门禁）；合并后**清撤销栈**（栈内快照绑定合并前状态，撤销会把并入内容从盘上抹掉）；relations.json 指向源库的端点 lib 改写为目标库。
- 2.1 遗留①（待办 2026-08-12）随本立项定案：**开库索引收窄不做**，维持池级索引（合并不依赖收窄，assetCount 口径维持实况）。

## 落地

后端：

- `core/merge.rs`（新模块）：read_source 读源库五文件（archives 缺省空表，版本门禁随 read_json）+ merge_into 纯数据并入（MergeTarget = 五文件可变引用组，剥离 Library 壳便于单测；MergeOutcome = id 重映射表 + 封面迁移清单 + 统计）。id 生成器 new_folder_id / new_block_id 上移 core::models（core 不反向依赖 services，同 ROOT_FOLDER_ID 先例；services 两处转接，口径不变）。
- `core/space.rs`：library_size——引用资产集（folders ∪ recycle，口径同孤儿判定）的 metadata.size 求和，弹窗容量列数据源；按 ID 推导读 metadata，不枚举 assets/（热路径纪律）。
- `core/relations.rs`：rewrite_lib_refs——端点 lib 改写 + 档案端点 id 重映射（资产端点 id 不动）。
- `commands/library.rs`：list_merge_candidates（排除当前库、libraryOrder 序、容量失败按 0 计）+ merge_libraries 编排——校验（空选择 / 并入自己 / 源库不存在中文报错）→ 备份门禁 → 逐源并入 + 封面迁移 → 五文件单写点落盘（任一失败 reload 对齐盘面后报错）→ 内存索引重建 → relations 改写（失败记日志不阻断）→ 删源目录 + libraryOrder 更新（删除失败容忍：数据已并入，残留可再删）→ 清撤销栈 → 返回目标库最新 LibraryInfo。

前端：

- `libraryOps.ts`：mergeLibraryModalState.names → items（MergeCandidate = { name, sizeBytes }）；requestMergeLibrary 走 list_merge_candidates；新增 confirmMergeLibraries（成功 toast 带音 + content.refresh 全量刷新，失败 toast 留弹窗）。
- `MergeLibraryModal.vue`：容量列渲染（数字-大 13/18 三级档，formatSize）+ 确认接线（空选择不响应，§24 口径）；多选语义注释定案化。
- 菜单「合并资源库」disabled 补「空间内不足两库」条件；预览页 mock 换 items。
