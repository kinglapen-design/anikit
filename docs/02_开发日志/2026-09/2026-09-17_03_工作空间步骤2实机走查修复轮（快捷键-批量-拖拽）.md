# 2026-09-17_03_工作空间 · 步骤 2 实机走查修复轮（快捷键 / 批量 / 拖拽三修）

## 要做什么

步骤 2 落地后用户实机走查三条：① 复制剪切快捷键在 ws 视口弹出「当前视口不允许导入」错误弹窗；② 文件只能一个个操作，没有批量；③ 拖拽完全没反应。

## 根因与修法

**快捷键弹窗**：`onPaste`（系统剪贴板导入处理器）不认 ws 视图——Ctrl+V 在 ws 内剪贴板为空时落系统导入，isNoImportView 命中弹拒入窗。修：ws 视图在 onPaste 静默让位（系统文件导入进工作空间未立项，不弹窗）；同时 `onOperationKeys` 的步骤 1 一刀切禁用（`isWorkspaceView 直接 return`）改为 ws 分支——F2 重命名（单选）、Del 直接进回收站（同库口径不两段确认）、Ctrl+C/X 写 ws 剪贴板、Ctrl+V 粘贴到当前视口目录；其余库快捷键（D/Y/J/L/E）继续禁用（合成假 id 严禁进 assetId 命令）。

**无批量**：右键菜单只作用于被右键的单项。修：wsCardSpec 接库 3.4 同款批量分流——触发项在选择域内且多选 → 复制 / 剪切 / 删除（菜单项标 `N 项`，删除确认文案「已选中的 N 个文件」）作用于整个选中集；重命名单项语义，多选不出现。拖拽批量本来就走 selection.selectedRefs（引擎通用），dropWsAssetsInto 过滤 ws 项即可，无需改。

**拖拽无反应**：`gridPointerDown` 的虚拟视图禁拖守卫（2026-09-09 入口收窄：全部 / 最近使用 / 缩略图不是位置）步骤 1 把 ws 也挂进 isVirtualView 档 → 卡片按下直接放行，拖拽手势永不启动。修：`isVirtualView && !isWorkspaceView` 才禁——ws 是真实磁盘位置，步骤 2 起放行拖拽（落点走 dragOperation ws 分支，间隙排序 / 库回收站行 / 拖出窗口三处守卫上轮已就位）。

**顺手修**：ws store.move 剔除「目标 = 自身所在目录」的条目——拖拽落到当前目录行 / 向所在目录粘贴不造 `名 (2)` 副本（paste 已有同 guard，move 补齐）。
