# 工作空间树选中与展开箭头修复（2026-09-26）

## 起因

用户实机两报（均在工作空间 ws 视口）：点侧栏树的文件夹行 / 视口网格的文件夹卡片没有选中反馈——预期的「蓝色边框」不出现，当前目录行只有灰色底；目录树里无子文件夹的行仍显示展开箭头，双击展开一次箭头才消失。

## 排查结论

**问题 1 不是 _12~_16 未提交轮引入的回归**（那五轮 diff 只涉卡片内容变体与缩略图性能，未碰选择链），而是 2026-09-17 文件夹进网格轮（020e6fd2）留下的暂缓闸：FolderStrip 里 `isWs` 早退 + `:selected` 恒 false，注释写明「文件夹选择域不接合成 id（写操作归步骤 2）」——彼时步骤 2 磁盘写操作未落地，选中无意义；步骤 2 同日落地后此闸无人回访，遗留成缺口。

两个定位细节先查实：其一，树行侧其实工作正常——当前目录行命中 TreeRowItem `.selected`（半透明-2 底 + 立体感-通用），口径速查 §41「树选中无描边」是用户确认过的定案，树选中本就没有蓝框；用户口中的「蓝色边框」是卡片族选中环（cards.css `.kc-sel` 2px 品牌描边，selection 体系驱动），ws 文件夹卡片从未接通所以不出现。其二，库侧同位置行为 = 文件夹卡片点击 clickFolder 进文件夹选择域出蓝环、树行 plain click 导航外还 nextTick 入域（FolderTree），本次以此为对齐基准。

**问题 2** 在 WsTreeRows 的 `expandable`：旧逻辑「未加载乐观当有天，已加载按实际子目录数」——未加载目录一律先出箭头，双击展开触发懒加载后才发现没有子级才消。

## 落地

### 问题 1：ws 文件夹选中链接通（对齐库侧）

ws 文件夹进**素材选择域**（clickItem，键形 `ws:{rel}|ws:{所在目录rel}` 与 ws 文件卡同构），不进库侧文件夹域——ws 写操作全按路径（removeEntries / setClip / paste 对文件与文件夹混合集无差别受理），而库文件夹域的消费方全是库命令（deleteFoldersFlow / move_folders / cutFolders），进那个域反而要逐处加 ws 守卫。改动：

- FolderStrip：onSelect ws 分流 clickItem（Ctrl 加选 / Shift 按条带顺序锚点范围选，三态同口径；clickItem 补可选 order 参——文件夹不是 Placement 不在 visiblePlacements，缺省行为不变）；`:selected` 接通即得既有蓝环（无新样式、无新口径）；右键未选中项先单选（库侧同口径）。
- WsTreeRows：plain click 导航 + nextTick 单选入域（FolderTree 同口径，sidebarSelected watch 的 pre-flush 清选择让过，同 tick 已切走不入的守卫照搬）；行补 domain-selected 联动绑定（选择域成员灰底，当前目录优先）。pin 行保持纯导航（库快速访问行同口径）。
- selection store：selectedRefs 对 `ws:` 文件夹键兜底按形合成（文件夹不是 Placement 原查不到会被丢弃；ws 键只在 ws 视口产生、切视图即清空，库命令路径收不到）；prune 存活键补目录条目（原只保文件键，库 refresh 会把文件夹选中连带清掉）。
- 操作链随之自动接通：Del 混合删除 / Ctrl+C·X 混合写 ws 剪贴板 / 拖拽混合移动（startDrag 读 selectedRefs）；F2 单选为文件夹键时路由 namingFolderCardId 卡片命名态（renamingKey 只有素材卡消费；仅当前视口条带内可命名——树行选中的是当前目录自身不在条带，保持无响应，右键菜单 / 名称双击仍可改）。
- wsFolderSpec 批量分流（同 wsCardSpec / 库 3.4 口径）：触发项在选择域内且多选 → 复制 / 剪切 / 删除带数量作用于整批（可文件 + 文件夹混合），重命名单项不出现。
- 详情面板：DetailPanel wsTarget 目录缓存直达本就兼容目录条目；WsDetail 补文件夹形态——名称原名直出（displayName 会误去目录名里的点后缀）、类型行 = 文件夹，size / 日期后端恒 0 不出行（磁盘实况无递归统计口径）。

偏离库侧一处记档：库 = 文件夹域与素材域互斥不可混选；ws = 单域可混选（Explorer 式，ws 命令混合受理天然支持，混选后 Del / 复制 / 剪切 / 拖拽移动均整批生效）。

### 问题 2：WsEntry 补 hasSubDir

后端 `entry()` 对目录条目顺带单次 read_dir 提前退出扫描：发现任一非 .anikit 子目录即 true（与 list_dir 同口径只滤缓存目录，隐藏 / 系统目录照常计入；读取失败按 false——扫不出就不出箭头），开销可忽略；文件恒 false。serde camelCase 出 `hasSubDir`。

前端 wsOps 的 WsEntry 类型字段可选（缺省宽容）；WsTreeRows 展开钮显隐改按条目 hasSubDir——列目录即得真实信息，不再乐观显示；旧缓存缺字段回退旧判定。库侧 FolderTree 不受影响（全量树本就知道 children.length）。

## 验证

`cargo test` 548 绿（新增 `list_dir_fills_has_sub_dir`：有 / 无子目录、.anikit 不计、文件恒 false、逐层各自判定不递归）；`cargo clippy --lib` 零告警；`pnpm typecheck` 0 错。实机走查交用户：ws 文件夹卡片点击出蓝框 / Ctrl·Shift 多选 / 右键批量 / F2 重命名 / 树行点击详情联动 / 无子目录行不再出箭头。
