# 2026-09-17_11_实机走查第 4 步 · 标签分屏后文件跨分屏拖拽

## 要做什么

走查「标签分屏后，文件要能跨分屏拖拽」——分屏的收益 = 高效整理：一边开着目标目录，另一边找文件拖过去。

## 旧模型为什么不行

网格 resolver 是「激活 panel 单例」（2026-09-13 提示线出盒修复的同一机制）——非激活 pane 的网格本体不是落点，只能落文件夹卡片（属性命中天然跨 pane）。跨分屏拖到目标目录的卡片区 = 无落点。

## 改造（dragOperation + AssetGrid）

- **注册表单例 → 全可见网格注册表**：`Map<token, GridRegistration>`（resolve / visibleKeys / scroll / layer / dropFolder）；AssetGrid 挂载即注册（**不再 panelActive 门控**——dockview 隐藏标签页层 rect 全零，命中判定天然不中），卸载按 token 清自己。
- **落点分流**（updateDropTarget 新增 pane 分支，在 gap 排序前）：
  - 目标文件夹 ≠ 当前 = **并入移动**（`dropAssetsInto`：移动 / Ctrl 建链接，与文件夹卡同语义）+ **pane 级高亮**（grid-viewport.pane-drop = 并入同款品牌/半透明 + 2px 品牌 inset 描边）；
  - 目标 = 回收站视口 = 丢回收站；ws 视口 = ws 素材按路径移动（库素材不落）；虚拟视图（全部/最近使用/缩略图）不出落点（位置级不成立）；
  - 目标 = 当前文件夹（含同视口两分屏）= 落下方 gap 排序同语义（组约束照旧）。
- **间隙提示线归属**：`dragView.gapGrid = token`——提示线只渲染在归属网格（替代 panelActive 门控，跨 pane 同文件夹场景目标 pane 也画线）；边缘自动滚动同按 token 驱动目标网格；`dropAssetsGap` 的可见序改按归属网格带入。

## 验证与遗留

`pnpm typecheck` 0 错（纯前端改造，无后端变动）。待用户实机走查：左右分屏互拖（不同文件夹 = 移动高亮 / 同文件夹 = 间隙排序）/ Ctrl 建链接 / 回收站与 ws 落点 / 虚拟视图不出落点 / 提示线归属与边缘滚动。遗留：并入移动落点位置不参与排序（move 语义落尾，与文件夹卡落点同口径——gap 精确落序仅同文件夹 reorder 保留）。
