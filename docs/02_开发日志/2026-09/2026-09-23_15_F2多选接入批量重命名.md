## 需求

## 现状

F2 此前只在单选生效（`useGlobalKeys.ts`：素材卡片就地重命名 / 文件夹域卡片·树命名态分流），多选素材无分支；批量重命名弹窗（37 稿，`selection.renameDraft` 驱动）入口只有右键菜单。右键菜单（assetCard spec）早已按选中数分流 label「重命名 / 批量重命名」并标 F2 快捷键——快捷键名不副实。

## 落地

- `src/lib/useGlobalKeys.ts` F2 分支补多选：`selectedFolders.size === 0 && count > 1` → `selection.renameDraft = selection.selectedRefs()` 开批量重命名弹窗。回收站只读不触发（既有 `isRecycleView` 拦截覆盖）；虚拟视图与单选同口径放行（速查 §35 重命名 = 所见即所得资产级操作）；工作空间视口不动（ws 段已先行 return，ws 无批量改名）。
- `src/lib/menuSpecs/editMenu.ts` 同步放开（§27 定案「编辑菜单 = useGlobalKeys 快捷键的菜单面，分流/禁用同口径」）：`canRename` 增素材域多选、`renameFlow` 增 `renameDraft` 分支、label 多选显示「批量重命名」（右键菜单同口径）。多选分支显式排除工作空间视口——`ws:` 合成假 id 严禁落 `rename_placements` 等 assetId 类命令（F2 侧由 ws 段先行 return 天然免疫，菜单侧需自守）。
- PRD `02_文件整理/14_批量编辑.md` 触发方式更新：「多选时右键「批量重命名」/ F2 触发」（原写 Ctrl+R——该键位 2026-08-18 已废除，文档滞后一并修正）。
