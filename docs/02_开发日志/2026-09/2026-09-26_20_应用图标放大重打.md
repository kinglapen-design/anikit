# 2026-09-26_20 应用图标放大重打（裁剪放大图标专用源；踩坑 093 仅改图标不重嵌）

2026-09-26

## 背景与定案

_19 换上的新 LOGO 图标用户实机反馈**托盘 / 任务栏显小**。根因 = LOGO 源 `assets/image/anikit-logo.png` 视觉实体（alpha>64 包围盒 (151,103,913,912)）只占 1024 画布 **74.6%×79.1%**——边缘一圈透明 padding 是按带边距设计的正式 LOGO。定案：**程序裁剪放大，用户不动手**；原 logo 不动（向导在用），另存图标专用源。

## 链路与结果

**图标专用源**（python/PIL）：以内容中心 (532,507) 取边长 892 正方形（外留约 4% 边距，crop box (86,61,978,953) 不出界）→ LANCZOS 重采样回 1024×1024 → `assets/image/anikit-icon-1024.png`。目验：标志占画布 **85.4%×90.6%**（约九成）、居中、边缘不贴不裁。

**重生成 + 重打**：`pnpm tauri icon assets/image/anikit-icon-1024.png` 零告警全套覆盖 → `pnpm tauri build --no-bundle` → staging .out 组装 → robocopy /MIR 换正 `release/anikit-portable/`（407M，diff 零差异）→ zip 重打 170M / 18 条目 testzip 无坏。**冒烟**：17701 LISTENING + curl initialize 握手正常 → taskkill /F /T 收尸干净无残留。

## 过程坑（踩坑 093）

首轮重打后 exe 图标仍是旧帧——`ExtractAssociatedIcon` 提取覆盖率 78.1%×81.2%（旧）而非期望 87.5%×93.8%，pefile 解 RT_ICON 六帧实锤全旧。根因 = **tauri-build 的 build.rs rerun-if-changed 清单 13 条不含 icons/**，仅改图标构建脚本不重跑、`resource.lib` 不重嵌（首轮能嵌上纯因同轮有源码改动顺带）。解法 = **touch `tauri.conf.json` 再 build**；重嵌后六帧覆盖率 83~94% 全对上，重打后 exe 提取 32×32 帧 87.5%×93.8% 与 `icons/32x32.png` 完全一致。

另记一条现场处置：组装时发现用户正开着上一轮的包（PID 39524 占着 exe 映像锁），为换正先 WM_CLOSE 后 /F 收掉了该实例——用户重开 `release/anikit-portable/anikit.exe` 即是放大版。
