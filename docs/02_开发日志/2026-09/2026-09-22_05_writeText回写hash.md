# 2026-09-22_05 write_text_asset 回写 hash（哈希漂移治理第 1 层）

> 用户在 docx 预览轮提出架构问题：外部编辑会改 origin 内容，但库内 metadata.hash 不变——再导入旧版会撞旧 hash 误报「内容相同」，「保留两个」后扫重还会把不同内容并一组。查实后定三层方案（[待办 2026-09-22](../../03_项目进度/待办细节清单/2026-09-22.md)），本条 = 第 1 层顺手做。

## 查实结论

hash = 建档一次性快照，全库无任何更新路径——连 APP 自己的 `write_text_asset`（txt 编辑保存）都只回写 size / modifiedAt 不动 hash。导入查重仅 hash 判等（size / mtime 纯展示不参与）；冲突四选项（用已存 / 保留两个 / 关联 / 跳过）均无「替换」，编辑成果不会被覆盖——真实风险点 = 「保留两个」后同 hash 不同内容被扫重并组。库对 origin 内容漂移零感知（assets 池无监听、开库无校验、读取触点不回写）。

## 改动（第 1 层：APP 内编辑自己认账）

`services/import.rs` 加 `sha256_bytes`（内存版，与 `sha256_file` 同输出格式）；`commands/text.rs` `write_text` 保存后同笔回写 `meta.hash`（先落盘再同步索引口径不变）。MCP 写工具同函数自动获得。单测扩展：编辑后 disk / 索引 hash = 新内容 sha256 且 ≠ 导入时旧值。`cargo test` 482 绿。

## 留待立项

第 2 层 = 读取触点自愈（预览 / 详情 / 默认应用打开时 size / mtime 不符 → 重算回写，模式抄 media.rs fps 自愈）；第 3 层 = 查重弹窗加「库内文件已被外部修改」提示 + 扫重分组加 size 一致性校验。口径决策点已记待办。
