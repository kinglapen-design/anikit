# AI 外接通道一期：进程内嵌只读 MCP server（2026-09-19，PRD 08-06 落地）

外部 Agent 工具（Kimi Code / Claude Code 等）经 MCP 协议直连 APP 读素材库——「大量看资产写提示词」流程的通道底座。一期只读先行，写入闸二期。

## 选型与架构

按 PRD 定案引入官方 Rust SDK **rmcp 3.4.0**（≥1.4.0 内置 Host 头校验防 DNS rebinding，CVE-2026-42559；默认 allowedHosts 即 localhost / 127.0.0.1 / ::1）+ **axum 0.8** `nest_service("/mcp", …)` 挂载其 Streamable HTTP Tower 服务。协议握手 / 会话 / 工具 schema 协商全由 SDK 承担，不手写 JSON-RPC。服务形态照 plugin_ws 范式：127.0.0.1 动态端口 + 端口文件（`%APPDATA%/AniKit/mcp-server.port`，每次启动覆写）+ 复用 Tauri tokio 运行时 + `cfg(not(test))` 门控（踩坑 014）。

## 工具注册表（一类一文件 + 一行注册）

`server/mcp/mod.rs` 持 `AnikitMcp { app: AppHandle, tool_router }`；`tools/` 按域分六文件，各文件一个 `#[tool_router(router = xxx_router, vis = "pub")] impl AnikitMcp`（宏生成关联函数），`new()` 里 `Self::library_router() + Self::search_router() + …` 合并。加工具 = 加一个文件 + 注册处一行。本注册表未来复用为插件 API 注册表（PRD 定的结构红线兑现）。

公共骨架 `with_lib`：取库锁 → 未开库回「请先打开素材库」工具级错误（isError=true，不静默空表）→ 业务闭包 → `json_result` 回包（content 文本 pretty JSON + structuredContent 双带）。域错误一律工具级错误带中文原因，协议级 McpError 只留序列化失败等内部异常。

## 一期只读白名单（8 个，薄壳转发既有命令/服务层，全部 readOnlyHint）

get_current_library（空间+库状态）/ search_assets（范围参数面向 Agent 简化：不传 folderId = 全库，传 = 限定文件夹，recursive 缺省 true）/ list_folder_tree / list_placements / get_asset_detail / get_asset_origin_path（thumbAssetId 伴生代理复用 views::placement_view 口径，不自拼词干）/ read_text_asset / list_archives。

纪律落地两条值得记：**get_asset_detail 走纯读**——直接调 `archive::asset_detail`，不过命令层的 `ensure_asset_colors` 懒回填（维护性写副作用，存量资产 colors 可能为空，文档已注明）；有副作用的准只读命令（转码 / 后台生成队列类）全不进白名单。命令层为复用做的微调：`space_info` / `to_info` / `placement_views` 提 pub(crate)，`list_archives` 命令抽出 `archive_list_items` 公共组装。

## 验证

`cargo test` 471 过 0 挂；`cargo build` 通过。端到端 curl 走真库（动画资产，654 资产）：initialize（serverInfo anikit 0.1.0、session 头）→ initialized 202 → tools/list 八工具齐、schema 与 readOnlyHint 正确 → tools/call 逐个真戳——搜索「走」命中 2 条；get_asset_origin_path 验证 thumbAssetId 代理生效（fla 资产的 thumbPath 指向伴生 hidden 资产的 webp）；read_text_asset 对 fla 正确回「不是文本资源」。接口文档 `docs/05_接口文档/MCP通道.md` 同步。
