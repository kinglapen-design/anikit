## 杂项 · 副本 origin 标记修复（用户实机报 BUG）

用户实机测出：创建副本后删除这个文件（丢回收站 → 回收站彻底清除），`assets/{新ID}.info` 物理目录还在，数据层记录已清，成无主孤儿。

**根因**（排查读 duplicate / delete / recycle 全链 + PRD 01 边界规则）：`duplicate_placements` 把副本的唯一 Placement 标为 `origin: false`（链接语义——模块头注释自述 "duplicate = info 目录整体复制 + 新 ID + 链接 Placement"），但 PRD 定义副本 = 物理复制为全新资源（新 ID、独立 info），**从此完全独立**，落点理应是 origin Placement。回收站彻底清除按「快照含 origin = 资产本体在站」判定物理删除（2026-08-19 位置级模型），副本被当「纯位置记录」只删记录、不动磁盘 → info 永久残留。同管线导入建档（import.rs）/ 克隆文件夹（clone.rs）都正确挂 origin=true，只有创建副本标错。同根因连带三处暗伤：① 单位置副本不满足「设为原始文件」菜单条件（`!origin && liveCount > 1`），用户无自救入口；② 重命名副本走链接语义只改显示名、磁盘 originName 不同步；③ 副本刻意保留源 hash 利于导入查重命中，但查重选「用已存入文件导入」找不到 origin 报「资源数据异常：缺少原始位置记录」（resolve.rs use_existing）。

**修法**（用户拍板 = 扶正 + 存量自愈，弃选「改回收站判定」——不动 2026-08-19 定的位置级模型口径）：

- **新建扶正**（duplicate.rs）：同文件夹紧随原件 / 跨文件夹段首前插两分支 origin 改 true，与导入 / 克隆同口径——副本删除随本体物理清除、重命名走 origin 磁盘段改名（originName + 词干缩略图同步）、查重可「用已存入文件导入」。单位置无角标（规则 = 活位置 > 1 才上角标），UI 无感。
- **存量自愈**（library.rs `fix_missing_origins`，接入打开自检 prune 之后）：库内有活位置无 origin、且回收站无其 origin 快照的资产，items 序首条位置置 origin——排除「origin 在站、全链接存活」合法过渡态（PRD 01 规则 8）；一资产只扶正首条保库内 origin 恒 ≤ 1；计入 folders_changed 备份门禁（备份失败仅内存清理不落盘）。覆盖「链接管理 removes 删 origin 行」产生的同类无 origin 态（已告知用户并接受——该类资产本来也无法物理删除，属同一漏洞面）。已产生的磁盘孤儿 info 不批量物理删，维持无主 info 扫描警告、用户处置的既有口径。

**验证**：`cargo test` **446 绿 0 失败**（+2 新测试：副本删除 → 回收站彻底清除 → 副本 info 物理删、源 info 与索引不动闭环 / 开库扶正三态——存量副本扶正落盘一致、过渡态不动、已有 origin 不多置）；`pnpm typecheck` 0 错。文档同步：PRD 01 边界规则 6（副本 / 克隆独立本体同口径一句）+ 02-10 副本条 / 接口 08 duplicate_placements / 踩坑 070（预防：复制类管线先分「链接指向 vs 独立本体」；挂物理生命周期判定的标记，新管线要把下游消费者逐一过）/ 当前状态 2026-09-08_01。**行为变化交实机走查：重命名副本现同步改磁盘文件名（与导入文件一致）；存量副本开库自动扶正后删除可物理清除。**
