# 阶段七 · 实机走查第一批：标签栏与拆分条五条（稿 = 用户当场供稿口径 + 归档走查第一批 4/5/6/8/9 条）

## 任务

继续 UI 重构。用户从归档的 `实机走查.md` 第一批里圈出标签栏 / 拆分条相关的五条（搜索框条 7 明确排除），其中拆分条样式由用户当场供稿。

## 五条与修法

**条 4 · 左栏拆分条旧 token**——`SplitBar.vue` 悬停高亮用旧 `--brand-border`（青绿）。用户供稿：左栏拆分条 = **渐变线，沿条长两头亮色/四级 0%、中间 50%**。落地为 2px 圆角线的垂直 `linear-gradient`，中间档用 `color-mix(in srgb, var(--n-l4) 50%, transparent)` 走 token 派生不硬编码；常态即显示（不再常态透明），悬停 / 拖拽不再变色（用户未供 hover 态，不自创）。

**条 5 · 右栏拆分条**——「不需要悬停效果，做简约一点，只需要鼠标指针有提示」。右栏 `side="right"` 时模板不渲染 `.line`：零绘制、无悬停，仅 `cursor: col-resize`。

**条 6 · 标签分屏分割线 + 圆角**——「标签左右分屏，不需要分割线，面板本身就自带边框。除了第一列的分屏，其他列不需要左上角的圆角效果，不然非常丑」。两笔：

1. dockview-theme 里分屏静态分割线整套删除（原 `.dv-view:not(:first-child)::before` 1.5px 常态线，横向纵向两规则 + `--dv-separator-border` 一并透明化）；sash 悬停 / 拖拽指示线保留，`--brand-border` → `--n-brand`（行为不变，只换品牌蓝）。
2. 左上 16px 圆角 + 左缘线的选择器末端从**后代选择器**改**直达子链**（`> .dv-view > .dv-groupview > .dv-content-container`）——原写法把第一列内嵌套分屏的内层容器一并圆角化，正是用户报的「其他列圆角非常丑」。链路三级全部读 dockview-core 源码实证（splitview 包 `.dv-view`、组元素挂 `.dv-groupview`、内容容器为其直接子）。

**条 8 · 拖拽插入提示旧色**——dockview 的 `--dv-drag-over-background-color` / `--dv-drag-over-border-color` 还是旧品牌色。用户定：和框选样式统一。换成框选同款三变量：`--n-brand-50` 填充 + `--n-brand` 1px 描边（`--dv-drag-over-border` 也补上，全矩形落点才有描边），与 `AssetGrid .marquee` 完全同色系同粗细。

**条 9 · 单标签拖拽分屏 no-op**——「只有一个标签拖拽时插入分屏实际没有成功，右键菜单左右 / 上下分屏都没问题」。读 dockview-core `moveTo` 源码定性：单 panel 组拖自己内容区边缘时，dockview 走「单 tab = 移组」优化——源 / 目标同分支时 `gridview.moveView` 移动的是它自己 = no-op，分屏永不发生。修法：**拦组级 `model.onWillDrop`**（该事件可 `preventDefault`，dockview 随即放弃默认处理）：`kind === 'content'` + 四边缘位置 + 落点组 === 源组 + 源组只剩 1 panel 时拦下，改走 `tabs.splitTab` 同语义——同视口复制到新组（与右键菜单分屏一致；单标签拖走必然源组销毁布局回弹，复制是该场景唯一有效结果）。两个工程细节：组件级 `@will-drop` 在无 advancedDnD 模块时不转发组级事件，必须逐组订阅（`api.groups` + `api.onDidAddGroup` 补挂，Set 幂等防移组重挂）；willDrop 的 position 词汇是 top/bottom，addPanel 的 direction 词汇是 above/below，需映射。
