# 2026-09-25_13 架构包容性评估与 7.3 扩展点立项

2026-09-25，feat/new-ui。用户三问：现在架构对未来未知功能（待办、天气卡片等）的包容性怎么样；大版本迭代与 UI 换代会不会伤筋动骨；视频向量加入动大不大。并当场给四个留门点定案。评估方式 = 三路并行实证探查（后端 / 前端 / 债务与换代减震），结论全部带文件行号，本文件记定案与关键数据。

## 现状实证（关键数据）

**后端**：114 文件 35k 行，services 占 58%、commands 18%——「命令薄服务厚」成立，151 命令注册表无漏。数据层单一写点大体成立，破口两处：metadata.json 写点散见 6 处（路径单点在、写点收敛不在）、tags.json 无写点死占位。MCP「一类一文件 + 一行注册」实测属实（最小工具 25 行）。迁移机制空转：`MIGRATIONS` 空表（migrate.rs:21）+ `DATA_VERSION` 恒 1，结构演进全堆开库自检链 9 段（library.rs:236-305）——library.rs 1391 行成全项目最大文件的主因。plugin_ws 实为 CEP 单租户通道：cepOutDir / pasteFla / flaAssetId 泄漏通用协议层，server 反向依赖 commands（plugin_ws.rs:279 自承）。AppState 以库为中心（lib.rs:109-116），撤销绑死库（commands/undo.rs:16）。

**前端**：149 组件 = 新 72 / 业务 75 / legacy 0 / 休眠 2；组件直调 invoke 仅 8 处；注册表四件（previewSpecs / cardSpecs / barSpecs / menuSpecs）实证有效（docx 先例）。新功能域的短板在挂载点：dock 面板只有 ContentArea 一种且内部是素材域 if 链；左栏三段 / 右栏 picker-detail / 详情三 tab 全是硬编码联合类型。最大单体 content.ts 1064 行。

**换代减震**：组件内 legacy token 三周 473→0；硬编码 hex 真实残留 5 处；legacy 块只剩向导 `--space-48` ×8 一个定案解锁删块。结论 = UI 换代不伤筋动骨，成本已从全量肉眼走查降为台账驱动 + 逐面板烧减。

## 四个真实缺口（7.3 立项依据）

1. **验证网腐烂**（最危险）：过期探针 ≥6 枚全红、clippy 48 处、vite HMR 失真四咬（踩坑 029/041/064/081）——大改动时验证网有洞是迭代保险丝烧断。
2. **WS 协议 CEP 化**（09-04 待审项坐实）：第二个软件插件接入前必须泛化。
3. **迁移机制空转 + 自检链线性膨胀**：版本发得越多 open() 链越长。
4. **AppState 库中心化**：非库功能域（待办 / 天气）状态层无家可归、无撤销。

死代码与补丁面反而不是大问题：后端 TODO/FIXME 为零，死代码 = 休眠组件 2 件 + 后端死命令 2 个，全部在台账有名有姓；补丁感最强处 = 自检链与 loadAsset if 链（preview.ts:229-337），已点名。

## 留门四定案（用户定）

一、**详情第三 tab = 自定义卡片容器**（直方图 / 项目待办 / 其他效率功能），提示词挪基础信息下方区块（用户截图红框区）。留门 = detailTabSpecs 注册表（TAB_OPTIONS 已是数组，半步已迈；内容区改动态组件分发），「信息查看管理」钮为排序 / 显隐 / 挂接的管理入口。

二、**中间面板自定义页面**：启动页（负一屏——卡片排列、一眼看到今日工作与组合信息）等自定义页面，另可接 3D / 电子书等新预览。留门 = pageSpecs 注册表（viewKey 前缀 → 页面组件，ContentArea 顶层分发查表化；标签 / 分屏 / 布局持久化白捡），widget 卡片走 cardSpecs 同范式；新预览走 previewSpecs 现成门。

三、**多功能悬浮栏按钮扩展**：show 数组 + PlayGroup 单点收口够用（barSpecs/types.ts:9-17），不提前泛化；真泛化 = 按钮描述对象数组（id/icon/tip/action），等真实需求再做。

四、**左栏 Obsidian 式自定义**（自定义图标 + 自增快速访问 item）：分段注册表化 + 库快速访问 pin 泛化（ws pinned 先例：ws_pin/ws_unpin）+ 图标网格体系复用（3.3 已有）。

## 视频向量预研（用户问「动大不大」）

**定案结论：动得整齐，对现有代码零侵入；唯一新大件 = 推理引擎，收 adapter 层可替换。**

- V1 存储检索底座：向量 = 可重建派生数据（cache 级，不进 JSON 写点体系、不进备份），SQLite 单文件（rusqlite）+ 暴力 topK（万级素材毫秒级，十万级再评 hnsw）+ semantic_search 命令。
- V2 provider adapter：embedding 提供方抽象收 adapters/ 层（ffmpeg 同先例）——外部 API 与本地 onnx/candle 可互换，选型可后换。
- V3 导入挂接：import_task 任务队列 + 进度事件范式复用，导入后异步 embedding；视频 = 抽帧（ffmpeg sidecar / 自研解码器现成）+ 帧向量平均池化，不上专用视频模型。
- V4 UI = 搜索栏语义模式（悬浮栏模式切换范式现成）；V5 = MCP 暴露（工作台语境下语义检索是 agent 的关键能力，薄壳 25 行级先例）。
