## 杂项 · 视频卡片悬停 scrub 同日二轮（进度条回弹 / 闪烁修复）

一轮（2026-09-08_20，seek 串行化合流）落地后用户实机复验：画面卡死已解，但**进度条还是不跟手，停下来后还会闪烁或者回弹**。录屏证据：鼠标匀速右滑，帧号却不单调——3968→2615→1289 反复回落。

**根因**：一轮只让 `onScrub` 直写 UI（`currentTime.value = t`），漏了 `onTimeUpdate` 的覆盖——该处理器 4Hz 触发，`currentTime.value = v.currentTime` 用 video 实际播放位置刷新 UI。长片源 seek 串行化后实际落点本就滞后于鼠标目标（这正是合流的代价与目的），每次 timeupdate 都把进度条 / 帧号拉回滞后位置，pointermove 再推回——来回拉扯 = 不跟手 + 闪烁；鼠标停下后最后一次 timeupdate 覆盖 = 回弹定格。

**修法**（`src/components/HoverVideoLayer.vue` onTimeUpdate）：**scrub 期间不写 UI**——`v.seeking` 在飞或 `scrubTarget` 有待发目标时直接 return（范围循环检查保留，语义不变）；seek 落定（无在飞、无待发）后 timeupdate 恢复同步，正常播放路径不受影响。scrub 期间 UI 完全由鼠标位置主导，与解码节奏解耦。

**验证**：`pnpm typecheck` 0 错、`pnpm build` 通过。**行为变化交实机走查：悬停长视频横扫鼠标，帧号 / 进度条应单调跟随鼠标不再回落，停下后定格在最终位置不回弹。**
