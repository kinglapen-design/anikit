# MCP 写入热刷新 + 写工具描述收窄（2026-09-19，用户实测两连）

用户实测便携版提两条，同日修完。

## ① agent 新建文件夹不热刷新，要重启软件

根因：库数据文件**本来就没有监听**（watcher 只管收件箱）——命令层写操作是前端自己 invoke 后自己刷新，而 MCP 写工具从后端直入 `state.library`，前端完全不知情。修法照 CEP 导入热刷新（`cep-imported` → 全量对齐）的既有范式：后端 `server/mcp` 加 `emit_library_changed(what)`，八个写工具成功路径广播 `mcp-library-changed`（import_paths 有真实入库才发，全 skippedDuplicate/failed 不打扰前端）；前端 content store 加 `initMcpListener`——**去抖 300ms 合并**（Agent 批量写连发，一拍全量对齐）后 `refresh()`，不带 CEP 的成功提示音（那是给「视口停在 Animate」场景的听觉兜底，MCP 场景不需要）。App.vue onMounted 挂载。

## ② Codex 指出工具描述有重复浪费（省 token 续轮）

Codex 实测后建议：每个写工具描述重复背着「需在偏好设置开启写入 / 进撤销 Ctrl+Z 可撤回」等通用说明，应收窄到只写本工具特有信息。采纳——八个写工具描述各砍 30~60 字（开关门禁、通用撤销口径只在握手 instructions 里说一次；write_text_asset 的「先备份」与 import_paths 的方案一冲突策略属工具特有，保留）。读工具描述本来就没有通用段，不动。

验证：cargo check 零警告 + 471 测绿 + typecheck 0 错；release 重编后便携包刷新（热刷新 UI 实效待用户重新启动便携版后目验——agent 建文件夹应即时出现在侧栏）。文档：MCP通道.md 写入闸段补热刷新口径；日志 _12 遗留的「新 exe 待刷新」随本轮一并闭环。
