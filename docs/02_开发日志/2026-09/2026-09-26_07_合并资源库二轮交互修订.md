# 合并资源库二轮交互修订（全库展示 + 勾选 ≥2，2026-09-26）

## 起因

用户实机走查功能轮（2026-09-26_04）：「合并资产库的操作逻辑不对，要同时展示所有资产库，勾选两个以上才能合并」。一轮口径 = 列表排除当前库、勾选项并入当前打开库——用户不认识"并入看不见的当前库"这个隐含目标。

## 定案

- 弹窗列表 = 当前空间**全部**资源库（libraryOrder 序，**含当前库**），勾选 **≥2** 才可合并（不足确认钮禁用——控件族通用禁用口径 30% 透明度，§39②）。
- **目标库 = 勾选集中 libraryOrder 最靠前者**，其余并入它；合并完成即打开目标库（目标非当前库时表现为切库，activate 统一出口：停帧流 / 清撤销 / 记最近 / 无主资产 emit）。
- 底行提示双态：未满两勾 = 「找到 N 个资源库」（稿原样）；够两勾 = 「并入「目标库名」」（稿未画此态，功能必需就近正文加粗档）。
- 菜单「合并资源库」disabled 条件收窄为「空间内不足两库」（不再要求当前库）。

## 落地

- 后端：`list_merge_candidates` 不再排除当前库；`merge_libraries` 重构——names = 勾选集（≥2 校验），目标 = order 最前勾选者；目标非当前库时 `library::open` 打开目标（库全部写操作即时落盘，源库虽正开着也内存态 == 磁盘态，读盘无分叉），合并后交 `activate` 统一收尾。失败路径：目标是当前库时 reload 放回 state 不留空档；非当前库直接丢（未激活无副作用）。`merge_sources_into` 数据段独立（备份门禁 / 并入 / 落盘 / 索引）。
- 前端：弹窗确认钮接 disabled（§39② 通用口径，淘汰一轮"稿未画仅不响应"）；底行双态提示；`confirmMergeLibraries` 按返回库名分流——同库 refresh / 异库 afterOpen（切库）。
