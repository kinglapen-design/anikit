# 阶段七 · 只读视口导入入口封堵（最近使用 / 自动导入 / 缩略图 / 回收站）

## 任务

2026-09-05 走查收窄右键菜单后（quick:recent / inbox / thumbnail 只给扫描两项、回收站专属空白菜单，导入项全撤），用户定：**这四个视口不允许额外导入，所有导入入口彻底封堵**——拖拽直接拒绝弹错误弹窗；同日续排查全量入口再堵两处漏网。

## 入口排查（全量）

已封堵 / 不漏：网格空白右键（scanOnlySpec / recycleBlankSpec 无导入项）；空态导入双钮 EmptyFolderState（四视口不出，范围 = folder: + quick:all）；侧栏「新增」按钮与 Ctrl+N（7.1 十八轮已撤，入口不存在）；内部剪贴板粘贴（非导入，pasteTarget 快速访问一律 toast 拦）；收件箱磁盘区「导入」（条目入库既有功能，非外部导入）；CEP 导出入库 / 收件箱自动入库（后台通道）。

漏网两处（本轮堵上）：**菜单栏「文件 ▸ 导入文件 / 导入文件夹」**（appMenu，全局可用无视口分流，落点 currentFolderId=null → 未分类）；**Ctrl+V 系统剪贴板导入**（useGlobalKeys onPaste → startImportClipboard(null) 同落未分类，无拦截）。

另发现菜单栏「文件 ▸ 新建」三级（新建文档七项）在四视口下也可用——同属 09-05 收窄口径（"新建文档在这里污染很严重"）的漏网，本轮未动，待用户定夺。

## 做法

统一判定入 store：`content.isNoImportView` getter（isRecycleView 旁）——四视口 key 命中即禁导入，五处同判定：

1. **拖拽**：`App.vue` `onDrop` 前置守卫直接 return（不走 classify_paths / importDraft），置 `ui.importRejectOpen` 弹窗；
2. **菜单栏**：appMenu 文件菜单「导入文件 / 导入文件夹」+「**新建 / 新建文件夹 / 新建档案**」整组 `disabled: content.isNoImportView`（项保留置灰不消失，同「新建子文件夹」先例；新建组整组置灰 = 同日用户追加：四视口 = 数据自动维护，与全部/未分类不同——新建子文件夹/转换为档案本随 folderId 禁用不重复接）；
3. **Ctrl+V**：useGlobalKeys onPaste 守卫，同弹拒入弹窗；
4. **兜底**：`pickImportPaths` 函数级守卫——任何调用方触达都弹窗，防未来新增入口漏判；
5. 右键收窄 = 既有 09-05 成果，同判定语义不重写。

拒入弹窗 = 新弹窗定稿件 `modals/ConfirmModal`（**kind=danger**，状态/禁止钮——520 宽竖排：标题 18/26 + 正文 13/18 + 按钮行 120×38 次左主右）：标题「当前视口不允许导入」，正文列四视口名 + 引导切文件夹视口，主钮「知道了」次钮「取消」同义纯关闭。开关 `ui.importRejectOpen`（onDrop 与 onPaste 分处 App.vue / useGlobalKeys，lib 无权触达组件本地态故入 store，同 blockManageOpen 惯例）。

首版误用旧体系 `AppConfirm alert: "error"`（48 徽章横排待退役件），用户当场指正——新弹窗定稿在 preview 页 PreviewModals 展区（技能第 3 节第 4 条：新旧并存期拿不准用哪套时查 preview 展区 import），已改回 ConfirmModal。

判定按激活视口 key、不看落点：拖拽命中文件树 item 也一并拒绝，彻底堵死——要导入请先切文件夹视口。
