# MCP 通道改固定端口 17701 优先（2026-09-19，Codex 实测后用户定）

MCP 一期落地当天，用户拿 Codex 接真实流程验收：搜「走路」命中「雪牧_走路.fla」全链路跑通。验收过程暴露一个机制错配——一期照 plugin_ws 范式用了动态端口 + 端口文件发现，但 plugin_ws 的客户端（CEP 面板）会自己读端口文件，而 Codex 这类 Agent 工具只读静态 `config.toml`（沙箱还读不到 `%APPDATA%` 下的端口文件），APP 每重启端口一变配置就失效。

**定案：固定端口 17701 优先**——`server/mcp/mod.rs` serve 一处改：`TcpListener::bind(("127.0.0.1", 17701))` 先行，被占（双开 / 他占）回退 `127.0.0.1:0` 动态，`mcp-server.port` 端口文件恒写实际端口兜底。plugin_ws 维持动态不动（其客户端读端口文件，无此问题）。

顺带记一个协议常识（用户当日问到）：裸浏览器 / 无头 curl 访问 `/mcp` 回「406 Not Acceptable: Client must accept text/event-stream」是规范行为——Streamable HTTP 要求客户端 `Accept` 头双带 `application/json, text/event-stream`，不是故障。

PRD 08-06、接口文档 MCP通道.md、当前状态 _05 条目同步改口径。cargo check 过；起服后经 17701 真机 curl initialize 验证（见会话记录）。
