# 2026-09-25_10_预览绑定发起面板——新标签抢预览 / 分屏丢预览 / 双面板左右跳三报根治

## 任务

用户实机演示三报（附视频）：1) 预览中点「+」新标签，预览没退出还飘进了新标签（新标签应是干净列表，还得手退一次）；2) 预览中分屏，预览「自己丢失」回到文件列表；3) 想左右两面各预览一张图对比，双击后预览左右跳——问「是同文件夹的原因还是只能开一个预览的原因」。

## 根因

答案 = **只能开一个预览**（全局单例 `preview.assetKey`），且显示判定是「谁激活谁显示」（ContentArea `previewActive = assetKey && 本 panel 激活`）——预览没有属主概念，跟着 dockview 激活面板飘。三现象同根：新标签激活 = 飘进新标签；分屏新 panel 激活 = 原标签「丢」给它；轮流双击 = 左右跳。与文件夹无关。

## 修复（ownerPanelId 绑定）

- `preview store` 加 `panelId`：`open()` 时记 `useTabsStore().activeTabId`（options store 运行时解析，tabs ↔ preview 模块级循环安全），`close()` 清。
- `ContentArea.previewActive` 改「assetKey 非空且本 panel 是属主」；panelId 空（布局恢复等早期路径）回退旧激活判定。
- `tabs.syncMirror` 清理：属主 panel 已关闭 → `preview.close()`（不挂僵尸预览）。

修后行为：① 预览中「+」新标签 = 新标签干净列表，预览留原标签（切回还在）；② 分屏 = 属主预览保留，新分屏是列表（用户要的「左预览右列表」起步态）；③ B 面板双击 = 预览**明确**归 B（可预测，不再莫名飘）。**真双预览对比 = per-panel 预览实例，独立立项**（评估已写进待办细节清单 2026-09-25）。

## 验证

- 新探针 `tools/cdp-preview-owner-probe.py`：先复现红四场景（新标签抢 / 分屏抢 / 左右跳 / 关属主僵尸），修复后全绿（S1 新标签列表+原标签保留 / S2 `[属主T, 新分屏F]` / S3 B 双击归 B / S4 属主关即退）；md 编辑器探针 16 段回归无影响；`pnpm typecheck` 绿。
- 探针坑三记（已入踩坑 089）：dockview 只渲染激活 panel（快照须逐 tab 激活读）；**tab 激活走 pointerdown**（合成 click 无效，pinia state 实证——`#app.__vue_app__...$pinia.state.value` 直读状态是对不上时最快诊断）；多组时各组渲染各自激活 tab（`querySelector` 拿首元素必误读，断言按组序数组）。
