# 两个持久化：库 / 工作空间切换视口记忆 + 详情面板 tab 全局记忆（2026-09-19，feat/new-ui）

用户实机报的两条状态丢失，同属"切走再切回没记住"，一轮改完并各自废了旧口径。

## 一、库 / 工作空间切换：中间容器停留在对方目录

旧口径（7.1 十八轮起）：左侧分段模式是会话级本地 ref，切到 workspace 仅在"尚无 ws: 标签页"时 `openView("ws:")` 开根视口，切回库则完全不动中间容器——于是从工作空间切回库，中间容器还停在工作空间的目录，用户得自己再点回库内视口。

新口径（用户定）：**库 / 工作空间各记各的停留视口，切分段即恢复**。落法三件——

- ui store 新增持久化三键：`leftMode`（分段模式本体，library / workspace / ai）+ `lastLibView` / `lastWsView`（两模式各自停留视口，默认 quick:all / ws:），走 settings.ui 既有写回通道；
- App.vue 的 sidebarSelected watch 顺带按 `ws:` 前缀归桶持续记录（比切换时刻现读稳——程序化导航、激活其他标签页等路径全覆盖）；
- SidebarLeft `onModeChange` 改为 `openView(对端记忆视口)`：同视口早退不重复导航，锁定页按既有 Eagle 语义新开标签页，AI 占位段不动中间容器。

启动路径不变：中间容器仍由 tabLayout 恢复，本组只管侧栏模式与切换基点——重启后侧栏分段与中间容器不再互相错位（旧版恒回 library 段、中间却可能是 ws: 视口）。

## 二、详情面板 tab：链接文件成功后自动回基础信息

旧口径（2026-08-31 用户定）：tab = 组件内 ref，会话级记忆、换选中回 basic、不写设置存储。用户的痛点场景：链接关系 tab 里发起「链接文件」，链接成功后面板弹回基础信息 tab，得再点一次。两层根因——

1. 选择模式（picker）期间右栏整体替换为备选区，DetailSections 卸载，本地 tab ref 销毁，退出重挂恒回 basic；
2. 组件内 `watch(targetKey)` 在选中对象身份变化时强制重置 basic（picker 退出恢复 origin 选中也会踩到）。

新口径（用户定）：**tab 全局记忆 + 持久化**——`ui.detailTab`（basic / links / prompt）入 PERSIST_KEYS，DetailSections 改 computed 代理读写；targetKey 重置 watch 整段删除。换选中、选择模式往返、重启应用都不再丢当前 tab。探针 `cdp-sidebar-right-probe.py` R12 断言随行为反转改写（links 态换选中 → 仍 links，末尾补回 basic 供后续档案形态断言）。
