# 三个小 BUG 修复：新建文件夹视口落点 / 粘贴仲裁竞态 / 选择模式联动选中（2026-09-19，feat/new-ui）

用户前一日记录的三个小 BUG（排期在 BUG 4 与链接音频之后），纯前端一轮修完。

## BUG 1：文件夹视口内新建文件夹跑到根目录

根因 = 菜单「新建文件夹」入口（addMenu / appMenu 两处）恒 `createAndName(null, …)` 建到默认区块根级——2026-08-14 区块子系统"保持原语义"的旧口径，与文件夹视口的用户心智（文件管理器"在这里新建"）直接冲突。修法 = 视口感知：`currentFolderId` 非空（文件夹视口）建到当前文件夹，其余视口保持根级原口径（区块折叠先强制展开不变）。appMenu 的「新建子文件夹」（Ctrl+Shift+Alt+N）语义自然重叠，保留不动。

## BUG 2：Ctrl+V / Ctrl+Shift+V 链接粘贴不触发

根因 = **2026-09-17 新上的粘贴仲裁存在竞态**：`copySelection` 里「读系统剪贴板序号」与「写系统剪贴板」两个 invoke 并发发出，读几乎恒先返回——`clipboardSeq` 记下的是写入**前**的旧序号，写完成后系统序号已推进。于是每次 APP 内复制后按 Ctrl+V，`internalClipboardLive()` 比对都失败、误判"外部覆盖"，让位系统剪贴板导入——**链接粘贴 100% 不触发**，还连锁把"导入 APP 自己的文件"喂给当时的假冲突链（与 BUG 4 部分场景同源）。Ctrl+Shift+V 不触发则是连带：第一次 Ctrl+V 误判弹出的冲突弹窗 / 导入浮层触发 `.modal-mask` 守卫，后续快捷键被静默拦截，形成"两键全灭"观感。修法 = **先写完系统剪贴板、再读序号**（copySelection 改 async，调用点补 void）。

## BUG 3：选择文件时同资产所有链接位置联动选中

根因 = 选择模式 `picker.isPicked / togglePick` 按 `kind + assetId` 匹配——同一资产的多条链接 Placement 共享 assetId：任一位置入备选，同资产全部位置卡片都亮大勾压暗；再点另一条位置反被误判"取消"。修法 = 匹配键升级 **三元组** `kind + id + folderId`（pickKey），Placement 级独立选择；`confirm` 时 relation / voice 按资产 id 折叠首条（资产级关系不重复建）；link 用途入参本就是三元组，天然正确。发起资产自身的禁选联动（pickerSelf）语义正确，保留。

## 验证

`pnpm typecheck` 0 错（无 Rust 改动）。实机待验：文件夹视口新建落当前文件夹；Ctrl+C → Ctrl+V 链接粘贴、Ctrl+Shift+V 副本；选择模式点选链接位置只亮被点卡片。
