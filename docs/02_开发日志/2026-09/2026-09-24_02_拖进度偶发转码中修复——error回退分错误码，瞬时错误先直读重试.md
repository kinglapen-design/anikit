# 修复：拖进度偶发「转码中…」——error 回退分错误码，瞬时错误先直读重试（2026-09-24，feat/new-ui，用户实机报）

## 用户报告

预览普通 MP4 看视频，拖进度条到开头，偶发播放条显「转码中…」又要等几十秒。用户质疑：正常的 mp4 应该不需要转码。

## 根因

质疑成立。「转码中…」在直读优先链路（2026-09-13 定案，踩坑 075）下只在一处出现：`<video>` 元素触发 error 事件后前端带 forceTranscode 回退、后端 ffmpeg 软编码整段重编码的等待期。问题出在回退链**不读 MediaError.code**——seek / 硬解管线的瞬时错误（快速连续 seek、seek 到边界、ended 回绕瞬间管线复位偶发失败，MEDIA_ERR_DECODE / MEDIA_ERR_NETWORK，Chromium 硬解已知脆点）与「格式真不支持」（MEDIA_ERR_SRC_NOT_SUPPORTED）一视同仁，全部送整段转码。瞬时错误同源重载即可恢复，转码纯白等（踩坑 086）。

## 修法

error 回退分两级，四个播放点（previewMedia / HoverVideoLayer / HoverAudioLayer / TabLinks）同口径：

- **非 SRC_NOT_SUPPORTED 且本素材未重试过** → 同源 `load()` 重载直读重试一次，loadedmetadata 后恢复原播放位置续播（previewMedia 抽 `retryDirect()`；转码提示 300ms 防闪不变，重试全程不出「转码中…」）；
- **重试仍 error / SRC_NOT_SUPPORTED**（真格式不支持，首装即报）→ 落原转码兜底，每素材一次不变。

真不能播的格式（无 OS 解码器的 HEVC、mov/wma 等）首装即报 SRC_NOT_SUPPORTED，直落转码不白试——2026-09-13 定案能力不变。

## 验证

`pnpm typecheck` 绿、`pnpm build` 绿。纯前端改动无 cargo 涉及。瞬时 error 为实机偶发，复验点交用户：同片反复拖进度到开头，不再出「转码中…」；真不可播格式（mov/无解码器 HEVC）照旧转码兜底可播。
