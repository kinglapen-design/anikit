# MCP 回包省 token 两刀（2026-09-19，用户实测额度后立项）

用户用 Codex 做一次搜索测试掉了约 2% 额度，排查后定位 MCP 进上下文的三个开销点并逐刀优化。

**第一刀：砍掉 structuredContent 重复副本**。一期为了兼容性，每个回包同时带 `content`（pretty JSON 文本）和 `structuredContent`（同一份数据结构化副本）双带。Kimi Code 会查重只留一份，Codex 这类不查重的客户端会把两份都喂进上下文——回包直接翻倍。改为仅 `content` 文本（未声明 outputSchema 时 structuredContent 本就可选，Agent 解析文本 JSON 无门槛）。

**第二刀：pretty JSON 改紧凑 JSON**。`serde_json::to_string_pretty` → `to_string`，空白缩进零开销（大清单回包省一成以上）。

**第三刀（使用侧，写进文档与握手 instructions）**：省 token 口径——先 `search_assets` 缩小范围再按需取详情，避免无 folderId 的全库 `list_placements`；看图读 thumbPath 缩略图而非源图；Kimi Code 侧可在 mcp.json 加 `deferred: true` 按需加载工具 schema（每会话固定开销再省）。

改动一处收口：`server/mcp/mod.rs` 的 `json_result`（全工具统一回包点）。验证：cargo check 过；真机 curl tools/call 实证回包只剩单行紧凑 JSON、无 structuredContent 字段。文档：MCP通道.md 回包口径 + MCP使用指南.md 新增「省 token」节同步。
