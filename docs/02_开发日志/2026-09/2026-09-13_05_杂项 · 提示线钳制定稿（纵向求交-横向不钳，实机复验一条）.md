# 杂项 · 提示线钳制定稿：纵向求交、横向不钳（2026-09-13，实机复验一条）

用户实机复验："之前左侧的插入提示和右侧一样在边距处，现在覆盖在卡片上"。

## 根因与定稿

左边距并非网格布局的 PAD（PAD.left=0），而是**宿主「列表容器」的 `padding: 12 0 0 12`**（ContentArea，grid-viewport 在常规流中被它内推 12px）。行首间隙 g.left=-12 经 layer rect 换算后恰好落在那条留白带里——用户看到的"在边距处"即此。我的钳制二轮（求交）把它判空、三轮（平移进视口）把它钉到首卡上盖住卡片，两轮都错在没认出这条留白带是设计内区域。

定稿口径：**纵向求交、横向不钳**（gapClient / gapBar 同）。纵向必须求交——Teleport 到 body 无 overflow 裁剪，滚出视口的间隙行会把竖块画到工具栏/标签栏上；横向不钳——行首落宿主留白带与右侧 PAD.right=12 对称，本就是设计位置。提示线出盒（窗口左上）由 panelActive 门控保证，不靠钳制。

## 验证

pnpm typecheck 绿（纯前端坐标逻辑，无后端改动）。口径速查 07 已按定稿改写钳制条目。**实机复验点**：行首插入提示线回到首卡左侧留白带（不盖卡片、不丢），行滚出视口时提示线不出现在工具栏上。
