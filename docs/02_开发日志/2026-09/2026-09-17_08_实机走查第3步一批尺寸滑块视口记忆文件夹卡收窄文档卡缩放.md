# 2026-09-17_08_实机走查第 3 步一批 · 尺寸滑块按视口记忆 + 文件夹卡收窄 + 文档卡跟随缩放

## 要做什么

走查「缩略图」节前三条：① 尺寸滑块需要记住每个视口的数据——每个视口文件类型都不一样，不要统一应用；② 文件夹卡片太宽（一排能放四个放三个显宽）；③ 文档卡片需要跟随尺寸缩放。

## ① 尺寸滑块按视口记忆

旧模型 = 单一全局 `ui.targetRowHeight`（持久化），任何视口动滑块全库跟着变。新模型 = **全局默认 + 按视口覆盖**：`ui.viewRowHeights: Record<viewKey, number>`（持久化），有效行高 = `rowHeightFor(viewKey)`（覆盖值 ?? 全局默认）；滑块（ContentTitleBar）与 Ctrl+滚轮（AssetGrid）只写本视口覆盖值，不动全局默认。消费端同按 viewKey 取效：useGridLayout（重排 + watch 双路）、SequencePackView 卡片宽（`seq:{assetId}` 键）。工作空间 / 回收站 / 缩略图 / 序列帧包各视口经 ContentTitleBar 同一滑块自动生效。

## ② 文件夹卡片收窄

FolderStrip 网格 `minmax(220,1fr)` → **`minmax(180,1fr)`**（唯一卡限宽同改 180）——220 下一排能放四个只放三个、拉伸显宽（用户实机）。定高 122 不变；不跟随滑块缩放的定案不动。走查待复验（不合适再调档）。§22 已同步。

## ③ 文档卡片跟随尺寸缩放

txt-md 卡此前盒随布局缩放但**内容恒 13px 不缩放**——卡片放大后小字贴角落。改 = **内容随卡宽 cqw 等比缩放**：`.fc-root` 挂 `container-type: inline-size`，稿基准 300 宽换算——标题 18px=6cqw、正文 13px≈4.34cqw、内边距 12px=4cqw、gap 8px≈2.67cqw（行高保持稿比例）。滚动胶囊加 ResizeObserver 同步重算（缩放后滚动量随动）。纯 CSS 零 JS 依赖（WebView2 容器查询原生支持）。§16 已同步。
