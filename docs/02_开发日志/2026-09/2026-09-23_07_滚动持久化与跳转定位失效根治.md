# 2026-09-23_07 滚动持久化与跳转定位失效根治（watch 顺序反转，flush:sync）

2026-09-23

## 需求

用户实机两报（录屏两条）：① 视口滚动持久化没生效——「人物」滚到中部切「音色」再切回必回顶端；② 链接文件跳转定位不准——详情链接行点「项目 / 场_01 俊仔.png」，目标卡在首屏外时视图停顶端（俊仔在首屏的场_05/场_04 看似成功实为巧合）。

## 排查（探针铁证，推理三次被证伪后上探针）

先读 `%APPDATA%/AniKit/config.json`：`scrollPositions` 写盘成功但几乎全 0（恢复失败 → 停 0 → 再切走以 0 覆盖，第一现场被抹）。新建最小复现探针 `tools/cdp-scroll-restore-probe.py`（桩 fa 40 项/fb 3 项，页面内 `JSON.stringify` 读 pinia state——CDP `returnByValue` 序列化 reactive Proxy 得 `{}` 空壳，首轮读数被它误导），逐环插桩：

- 间谍：`setScrollPos("folder:fa", 0)`——保存被调但值为 0（transform 同期 -1155px）；
- `__grid` 暴露 ref 真值：切走前 pos=1155、watch 保存时 pos=0；
- `__vkLog` 流水铁证：**items watch 先跑（relayout 把 pos 夹到 fb 的 0），viewKey watch 后跑**——与代码注释「注册序 = 触发序」的假设相反。根因：两 watch 依赖不同 props（`:items` 先于 `:view-key` patch），触发序跟 patch 序不跟注册序。

连锁三症同根：保存污染（持久化失效）/ restorePos 迟到（本轮恢复失效）/ restorePos 悬着（reveal 定位被下次 relayout 拉回 0——录屏 ②）。

## 落地

`src/lib/useGridLayout.ts` 的 viewKey watch 改 **`flush:"sync"`**：props patch 赋值瞬间同步执行，保存拿到未污染 pos、restorePos 先于一切排队 relayout 就位——一修同治三症（含 reveal 恢复位与定位同 relayout 内「恢复先、reveal 覆盖」的正确次序）。

## 验证

探针 S1-S5 全 PASS：保存值 1155 未污染 / 切回 pos=1155 恢复 / 同视口 reveal 消费 / 跨视口 reveal（fa 恢复位 1189 → reveal a20 覆盖到 478.4）/ 各视口按 key 保存。TEMP-DEBUG 插桩已删净，`pnpm typecheck` 绿。重启后跨会话恢复与真实链接跳转手感待用户实机复验。
