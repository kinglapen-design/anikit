# 杂项 · 视频卡片悬停 scrub 卡顿修复（连发 seek 解码器饿死）
## 杂项 · 视频卡片悬停 scrub 卡顿修复（连发 seek 解码器饿死）

用户实机报：视频卡片悬停播放时滑动鼠标快进快退特别卡，有时甚至没反应。录屏证据：帧号跟手跳变（1047→3068→1734…），画面却长时间卡住不动（同一帧停 2 秒多），之后才偶发恢复。

**根因**：`HoverVideoLayer.onScrub` 自 2026-08-22 起是 pointermove 直接设 `video.currentTime`（当时实机数据：单点 seek 5-40ms、浏览器自身合并跟不上的 seek，结论「无需合帧 / 门控」）。该结论对长片源不成立——用户这条 3:03 的 MP4 GOP 大、单次 seek 成本高，pointermove 高频率连发 seek，每个新 seek 取消未完成的前一个，解码器陷入**取消-重启循环出不了帧**（饿死），即「卡 + 有时没反应」；帧号是 UI 状态同步直写所以照常跟手，与画面脱节。

**修法**（`src/components/HoverVideoLayer.vue`，仅悬停模式 scrub 路径）：UI 状态（帧号 / 进度条）保持同步写目标值立即跟手不变；**video seek 改串行化合流**——`v.seeking` 空闲直发、在飞只记最新目标 `scrubTarget`，`seeked` 事件补发（死区 0.04s ≈ 一帧，落点已在附近不重复 seek）；直发分支同步清账，防陈旧目标在后续 seeked 误补发回跳。解码器任意时刻至多一个在飞 seek，不再取消-重启。音频卡片 seek 廉价不受影响，不动；2026-08-22 头注释旧口径已同步改写。

**验证**：`pnpm typecheck` 0 错、`pnpm build` 通过。**行为变化交实机走查：悬停长视频卡片快速横扫鼠标，画面应跟随鼠标位置逐段落点、不再卡死；鼠标停下后画面落到最终位置。**
