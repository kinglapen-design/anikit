# 2026-09-17_14_复验收尾 · 空白点击状态机补完（聚焦与取消选择各司其职）

## 问题

复验收尾用户再报：「空白处无法取消选择」——上一版 `onRootPointerdown` 只要真空白就调 setActive，**已聚焦 pane 的空白 click 也被激活链重渲染吞掉**，取消选择全灭。用户定逻辑：已聚焦 = 空白取消选择；未聚焦 = 第一击先聚焦、之后就绪。

## 修复（ContentArea 一处）

`onRootPointerdown` 改状态机 + **capture 先拦**：

- `panelApi.isActive` = true → **直接返回不调 setActive**——空白 click 走框选原语义 = 取消选择（激活链不再介入）；
- false（未聚焦）→ `setActive()` + `stopImmediatePropagation()`——本击**只聚焦不清空**（capture 阶段拦下框选手势；下一击即按已聚焦走清空语义）；
- 交互件（卡片/树行/按钮/输入框/菜单/分组标题/滚动条等）上永不激活（复验石锤的根因防线保留）。

## 实机验证（鼠标自动化 + 截图）

场景文件夹选中 WAV 卡 → 点空白：第一击环保留（只聚焦）→ 再点：环消失（取消选择）——与用户定案逐字吻合。`pnpm typecheck` 0 错。
