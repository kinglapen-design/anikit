# MCP 二期首批：写入闸形态 A + 三个写工具 + 偏好设置弹窗（2026-09-19，PRD 08-06）

一期只读通道落地同日，二期首批跟上：写入闸（确认闸形态 A = 全局写入开关 + 撤销兜底，用户当场定案）+ 首批三个写工具 + 偏好设置弹窗承载开关。撤销兜底为定案的一部分：create_document / rename_placements 进撤销（用户 Ctrl+Z 可撤），write_text_asset 不进撤销（与 APP 内文本编辑同口径，2026-08-23 定——库操作撤销体系不覆盖内容编辑，此点写进工具描述告知 Agent）。

## 写入闸（server/mcp write_gate）

开关持久化在全局 config.json `settings.ui.mcpWriteEnabled`（默认 false）。**逐次检查**：每个写工具入口先过 `write_gate()`——直读 `core::config::ui_settings()`（该函数本就每次读盘、无内存缓存，低频门禁调用直读可接受，也带来一个测试红利：端到端验证时可直接改文件开关闸），关态 / 读取失败一律回工具级错误「MCP 写入未开启（偏好设置里可开启）」（isError=true，与一期「请先打开素材库」同口径，Agent 可见原因）。不做逐笔弹窗：首批全是 L2 可逆操作，批量场景弹窗不可行。

## 三个写工具（tools/write.rs，注册表加一行 `+ Self::write_router()`）

**复用范式 = 命令整段抽出 `_op` 函数**：`create_document` / `rename_placements` 命令体（锁 library → 锁 undo → begin/record_file → 服务调用 → record_disk_op → commit，出错 `fail()`）原样抽成 `commands::operations::create_document_op(state: &AppState, …)` / `rename_placements_op`，原 #[tauri::command] 改一行委托，MCP 侧同调——锁序、撤销登记、磁盘逆操作对全部单一实现，不存在 APP 与 MCP 两套行为（先例 = 一期 archive_list_items / placement_views / space_info 的 pub(crate) 复用）。`write_text_asset` 走新加的 `with_lib_mut` 骨架（with_lib 的可变版）+ `commands::text::write_text` 提 pub(crate)。

工具全部 `annotations(read_only_hint = false)`（rmcp 3.4 宏写法同一期，布尔直写），描述中文写清后果（write_text_asset 明写「不进撤销、先 read_text_asset 备份」）。rename_placements 空数组拦一道「items 至少 1 项」（否则会压一个空撤销步）。回包照一期 json_result 双带惯例。
