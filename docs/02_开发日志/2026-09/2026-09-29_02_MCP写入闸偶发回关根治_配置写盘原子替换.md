# 2026-09-29_02 MCP 写入闸偶发回关根治：配置写盘原子替换

用户报「MCP 允许写入开关不知道怎么就自己关了」——非每次，重启电脑后 / 重编译换包后可见，其余设置无损。

## 根因

`json_io::write_text_atomic` 原实现 = 写 .tmp → `remove_file(目标)` → `rename`（Windows fs::rename 不覆盖已存在文件，先删后换）。**删-换间隙被杀 = config.json 永久丢失** → 启动按默认重建。ui/窗口几何有前端内存态快照启动随即写回（用户无感），**唯 settings.mcp / pluginServer 无快照子树静默回默认**——「只丢开关不丢别的」谜底。排障会话的 Stop-Process 强杀当场复现了一次。

## 修法（json_io 全局写点 + config 读侧兜底）

- `write_text_atomic`：删-换改 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)` 原子替换无窗口期；非 Windows 保持 fs::rename（POSIX 原子覆盖）。**全数据文件共用此写点，库文件同类风险一并断根**。
- `config::load_from`：目标缺失但 .tmp 完整可解析 → 恢复当次写入成果并转正（半截 tmp 弃用）——兜旧代码已造成的现场。

## 验证

551 测绿（+3：覆盖已存在目标 / tmp 残留恢复转正 / 半截 tmp 回默认）+ clippy 净；release 换正 portable，冒烟 = 进程起 + MCP initialize 握手通 + config.json writeEnabled:true 保留。踩坑 095 新立。
