## 杂项 · alt+` 呼出改最上层判定（实机走查第 19 条）

实机走查第一批第 19 条：alt+` 呼出的逻辑还是有问题，最小化解决了（2026-09-02 修），但大部分的时候没有最小化，只是被其他 APP 遮挡到了后面——希望判定的逻辑是 APP 是否显示在最上层，不是就呼出到最上层。

**根因**：旧判定（`lib.rs` 热键回调）是 `visible && focused && !minimized` → hide 进托盘，否则呼出——用 `is_focused()` 近似"在前台"。但窗口被其他 APP 遮挡在后、焦点又未移走（`is_focused` 仍 true）时，旧判定误命中 hide 分支把窗口收进托盘，与用户"按一下就呼出到眼前"的预期正好相反。

**修法**：`lib.rs` 新 `is_main_foreground()`——Win32 `GetForegroundWindow()` 拿系统前台窗口句柄与主窗口 HWND 比对（windows 0.62 crate 已在依赖、`Win32_UI_WindowsAndMessaging` feature 已启用，零新依赖）；非 Windows / 取句柄失败回退 `is_focused` 近似。热键判定改为：可见 && 是最上层 && 未最小化 → hide（toggle 语义不变）；其余一律 `show_main_window`（unminimize + show + set_focus + 通知前端恢复播放）呼出到最上层。托盘菜单 / 托盘左键 / 单实例三处唤醒路径本就走 show_main_window，不受影响。

**验证**：`cargo test` 446 绿 / `cargo clippy` 净。交实机复验：窗口被其他 APP 遮挡（未最小化）时按 alt+` 直接提到最上层，不再误收托盘。接口文档 `命令/17_预览/12_主窗口显隐事件.md` 同步，当前状态同步 2026-09-08_04。
