# 收件箱 recover 问题改"编辑中门禁"（用户新方案，替代同日早些时候的"维持现状"定案）

**收件箱 recover 问题改"编辑中门禁"（用户新方案，替代同日早些时候的"维持现状"定案）**：命名过滤被否的根本原因——各软件临时/恢复文件千奇百怪（AN 的 RECOVER_*、Blender 的 .blend1……）永远筛不完。新语义：inbox 内任一文件处于占用编辑状态 → 整批按住不动（可移走的文件也不放行）；AN 正常关闭时 RECOVER 自动消失（exists 检查丢弃，不入库），真实 fla 放手后入库；软件崩溃致恢复文件残留的，随真实文件一并入库——反而保住用户崩溃恢复数据。新增门禁集成测试（占用期整批零回调、放手后收齐），cargo test 62 过零警告。
