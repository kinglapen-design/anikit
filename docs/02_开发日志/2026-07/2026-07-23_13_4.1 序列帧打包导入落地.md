# 4.1 序列帧打包导入落地

**4.1 序列帧打包导入落地**（分支 feat/stage3-import，用户 2026-07-22 定案交互与文案）：
	- 后端 `services/sequence.rs`：宽容检测（仅同目录兄弟文件成组，按"基础名 + 扩展名 + 序号位宽"分组，`标题001` / `标题 (1)` / `标题_001` / `标题-001` 四形态，基础名可含其他文字、序号在末尾；仅图片格式 png/jpg/jpeg/gif/webp/bmp = 缩略图管线支持集）；连续判定量化 PRD 未定的"少量缺帧"为 **缺帧 ≤ max(2, 跨度/10)**（取 2 保底：3 帧小序列缺 1 帧仍算序列；跨度大时按比例收紧），同组同号（`标题 (1)` 与 `标题1` 撞号）不判；组 hash = 各帧 sha256 按序号升序串联后再 sha256；打包建档 = `{ID}.info/frames/` 归一重命名 `标题-序号.扩展名`（序号补齐位宽），metadata 记 fps（默认 24）/ frameCount / thumbFrame（**改为 String 记封面帧文件名**，默认首帧，用户定案），缩略图复用图片管线取 thumbFrame。
	- 管线改造（import_task）：导入单元化（Unit = 单文件 | 序列帧组），四阶段并行流水线语义不变——帧照常并行 sha256（组 hash 由帧 hash 串联，不增加读盘遍数），started.total 按单元计（散文件 + 组数），撞组 hash 整组挂起一个冲突（ConflictItem 新增 `sequence` 组信息字段，显示名 = `标题.扩展名`，sourcePath 取首帧供弹窗预览）；resolve_conflicts 的"保留两个"按前端原样回传的 sequence 重新打包（重算组 hash、新 ID 新实体）；复制/剪切对整组生效。有帧读取失败的组整组不进管线，其余帧逐个记 failed（不吞文件）。
	- 命令：`detect_sequences`（新，检测摘要供弹窗）+ `import_paths` 增加 `sequenceMode: "pack" | "scatter"`（07 已同步）；剪贴板 / 收件箱恒 scatter（收件箱不自动打包为留待）。
	- 前端：SequenceDialog（12_序列帧弹窗，样式复用 09 规格，文案用户原话：标题「监测到序列帧」+ 提示 + 打包导入预览 默认 / 分散图片导入，取消 = 放弃整个导入）；09 确认后先 detect_sequences，命中追加弹窗否则按现状直入；DuplicateDialog 决策透传 sequence。
	- 测试：sequence 10 用例（四形态解析 / 拒绝形态 / ≥3 与连续 / 缺帧容忍与过稀 / 撞号 / 目录·扩展名·位宽分组隔离 / 组 hash 有序性 / 打包归一与 metadata / copy 保留源）+ import_task 6 用例（整组单 Asset / 缺帧打包与短组散入 / 剪切整组移走 / 组 hash 冲突挂起 / keep 落末级 / 分散现状）+ resolve 1 用例（保留两个重新打包）+ 命令层 1 用例（detect_sequences）；cargo test 83 过零警告，tsc --noEmit 全绿。
	- **序列帧显示约定（用户定：一眼可辨）**：PlacementView 补 `frameCount`（仅序列帧非 null，契约测试同步）；卡片格式角标 / 列表"格式"列显示「序列帧」，名称显示为 `标题.序列帧`（Placement 名称去原扩展名加 `.序列帧`）——纯显示层转换，数据与 frames/ 真实帧名不动；12_序列帧弹窗文档补"卡片 / 列表显示约定"节。cargo test 83 过零警告，tsc 全绿。
