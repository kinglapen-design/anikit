**3.4 八轮 · 删除组两项化 + 回收站链接警示 + 重命名唯一化拆除（feat/new-ui，用户当日三连定案）**：
  - **删除组两项化**：03 稿"从文件夹中移除文件链接"独立项废除——删除组恒两项：「从文件夹中移除」Shift+Delete（`delete_placements` lastAction="uncategorized"，最后一条 origin 改挂未分类）/「丢到回收站」Delete（"recycle"）。链接 Placement 两种操作都只移除记录（不进回收站不去未分类——不变量：资产最后一条必为 origin，origin 转移机制保证，链接永不滞留成孤儿）。快速访问视图同口径支持（用户定：护栏全拆，不过度设计）。后端撤销标签分流「丢到回收站 N 个项目 / 从文件夹中移除 N 个项目」；`deletePlacements` 加 action 参数，键盘 Shift+Delete 分流（回收站视口不认 Shift）。
  - **回收站彻底清除链接警示**：`DeleteRecycleReport` 加 `linkRefs`（快照内 origin=false 链接数）——delete_recycle / clear_recycle 未确认段在 segmentRefs>0 **或 linkRefs>0** 时拦截；RecycleConfirmDialog 文案补"其关联的 N 条链接将一并清除"。（注意：删除语义下回收站条目必无活链接，linkRefs 统计的是快照内记录——清除即不可恢复；用户场景"保留链接文件"归阶段六「将此文件设为原始文件」手动 origin 转移，09 待办已记。）
  - **重命名唯一化拆除**（用户问"单条重命名唯一化是什么"后定"护栏全拆"）：rename_placement 与批量 rename_placements 统一**撞名不唯一化**（显示名放开 PRD 01 规则 7 全对齐——原单条"同文件夹自动追加 -1"废除；rename_impl 开关参数删除，单条函数恢复全量实现）；原始 Placement 磁盘撞名属物理约束（rename_origin 失败中文报错回滚）。旧测试断言改写（"原图-1.png"→"原图.png"）。
