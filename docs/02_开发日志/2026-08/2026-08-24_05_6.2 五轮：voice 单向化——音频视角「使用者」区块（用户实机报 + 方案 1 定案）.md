# 6.2 五轮：voice 单向化——音频视角「使用者」区块（用户实机报 + 方案 1 定案）


**背景**：用户实机报"音频文件点添加，选择模式不是只筛选音频、正好反过来排除音频"——根因非代码写反：**在音频文件上点音频区块添加钮**时，filterAudio 仍按"选音频"过滤，但该场景用户要选的是**使用者**（非音频），过滤方向与意图正好相反。用户指出"音频的标题就不是音频了，而是使用者"，给三方案——① 音频侧砍添加钮只展示/跳转；② 废音频区块全走关系手动称谓；③ 双向添加（音频侧排除音频防递归）。我方倾向①（voice 恒单向语义最干净、改动只动 SectionAudio 一处、不丢 02 稿播放/波形 UI；③ 的 picker 三态过滤 + 确认反向写入复杂度全为保一个低频入口；② 推翻已定稿设计），用户定案方案 1。

**改动**：
- `SectionAudio`：当前目标 = 音频文件（file + isAudioExt）→ 标题「使用者」+ **无添加钮**（只展示使用方文件卡 + 跳转，× 删除保留）；非音频目标维持「音频」+ 添加钮现状不变。
- 后端 `add_batch` voice 分支补 from 校验：**from 不得为音频 asset**（"「X」是音频文件，不能作为使用方"）——单向语义固化到数据层（前端入口砍了仍双保险）；测试 +1 断言（音频作 from 报错）。
- models.rs / commands/relations.rs 注释同步单向口径。

**探针**：`cdp-link-manage-probe.py` V1 补使用方视角断言（标题「音频」+ 有添加钮）、V2 补音频视角断言（标题「使用者」+ 无添加钮）。**坑**：① check 文案嵌英文直引号撞 Python 字符串定界 SyntaxError——探针文案引号一律「」/『』；② W5 悬停浮层时序 flake（固定 0.7s sleep 等不到浮层渲染，三连 FAIL 后同代码一轮过）——浮层出现改轮询（重复 dispatch mouseenter + 查 .link-pop，openLinkList 幂等，上限 8×0.4s）。
