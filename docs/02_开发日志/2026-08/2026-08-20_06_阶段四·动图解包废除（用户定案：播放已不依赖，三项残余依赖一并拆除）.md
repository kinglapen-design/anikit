# 阶段四·动图解包废除（用户定案：播放已不依赖，三项残余依赖一并拆除）


预览对接帧流后用户追问"三项禁用是不是还要解包才行"，确认方案后定案：**frames/ 导入解包整体废除**——播放（帧流）、设封面 / 帧条小图 / 逐帧笔记全部改对 origin 运行时解码，导入零解包等待、磁盘大减。

- **废除**：import_task 解包挂钩摘除（register_one 的 assets_dir 死参同删）；`services/anim_unpack.rs` + `services/unpack_queue.rs` 两文件删除（lib.rs init / library.rs 两处 clear_pending / mod.rs 清理）；`anim-unpacked` / `anim-unpack-failed` 事件消亡；frames.json 从备份清单移除（INFO_DATA_FILES）；`list_sequence_frames` 动图分支删除（报"动图无序列帧清单"，unpacking / delayMs 字段随删——存量 frames/ 目录不再被误当序列帧返回，回归用例钉）。
- **设封面（set_thumb_frame 动图分支）**：frameName 改 `f:{帧索引0起}`（如 f:41）→ `anim::decode_frame` 单帧抽解码 → cache/tmp 临时 png 走同管线重生成缩略图（视频分支同款套路），thumbFrame 同格式记录；存量帧名值前端按尾号兼容解析（`{标题}-00042.webp` → 41）。
- **帧条小图**：preview_queue 新任务 `AnimStrips`——origin 单趟流式 `decode_frames` 逐帧缩 128 落 `cache/frames/{id}/f-{索引5位}.webp`（会话级，已缓存跳过幂等；逐帧查代际可中断，8 帧一批经同一 `preview-strips-ready` 事件渐进）；`thumbnail::generate_frame_strip_mem` 内存版。新命令 `prepare_anim_strips`：立即返回已缓存清单（扫目录非按 frameCount 推导——探测帧数与实际可能出入）+ 提交队列补齐。前端 PreviewFrameStrip 动图分支改帧索引渲染（`f:{i}` key，animStrips 渐进填充）。
- **逐帧笔记**：key 改 `f:{帧索引}`（前端 currentKey/jump/帧条圆点）；`get_notes` 对动图资产附带旧帧名 key 一次性迁移（`{标题}-00042.webp` → `f:41`，尾段 5 位数字防标题连字符误判，冲突保留 updatedAt 较新者，`core::notes::replace_all` 全量写保留原文本时间）；`get_note_thumb` 动图分支 `f:` → decode_frame 抽帧 → cache/note-thumbs 幂等（视频分支同款）。
- **前端 preview store**：loadAnim 删帧清单拉取（unpacking 状态消亡）——帧流播放 + prepare_anim_strips 帧条 + 笔记恒可用（PlayBarFrames 禁用解除）；封面帧定位改读 PlacementView.thumbFrame（f: / 旧帧名尾号双解析）。HoverZoomOverlay 零改动（动图本就 `<img>` 播 origin）。
- **验证**：cargo test 345 绿（解包相关删除 10+ / 新增：导入不解包断言、动图拒绝帧清单、prepare_anim_strips 全流程——首调空缓存 + 队列补齐 f-0000N + 二次命中 + 幂等 mtime + 非动图报错、set_thumb_frame 抽帧分支；两处断言教训：帧索引 0 起（f-00000 非 f-00001）、anim3.gif 64×48 短边不足 128 不放大）；typecheck / build 绿；预览探针改写全项 PASS（帧条 24 块 / 设封面 f:12 / 禁用钮 0 / 播放四件套不回归）。**坑：用户 dev server 的 vite watcher 漏文件变更**——探针拿到旧版 SFC 编译产物（PreviewFrameStrip 旧 `v-if="preview.seq"` 不渲染），touch 触发失效后复跑才过；涉多文件改动时探针前宜批量 touch 或重启 dev。
