# 5.4 一轮：「复制缩略图」点亮（用户两轮定口径）


- **背景**：5.4 自定义缩略图设置开工复核——「自定义缩略图 - 从剪贴板 / 选择文件」两项 6.3（2026-07-29）已落地、新 UI 菜单接线保留，端到端链路完整（菜单 → placementOps → 命令 → asset_menu 服务），非本轮新写；本轮点亮同组「复制缩略图」。
- **口径（用户两轮定案）**：① 初定"shell 图标 / 音频波形没必要复制、动图放文件"，用户随即推翻——**全类型统一复制各自缩略图位图**（静态图 / 视频封面 / 序列帧封面 / 动图首帧 / 音频波形），shell 格式图标也放开："复制缩略图的最大用处 = 把库里缩略图复制进剪贴板，经「自定义缩略图 - 从剪贴板」改其他文件的缩略图；有的用户想用 shell 的缩略图定义其他文件，那也是用户自己的事"。② 用户追问"剪贴板能直接粘动图进 info 当缩略图的话，「转换为缩略图链接并复制」是不是重复了"——定案**不重复、本轮不做**：动图作工程预览 = 动态缩略图业务（缩略图管线现为静态 webp，粘动图也只会取首帧），链接引用路线是 PRD 02-15 hidden 资产机制的既定方向，「转换为缩略图链接并复制」「将「xx」设置为缩略图」两项归 8.2 伴生缩略图阶段；拷贝进 info 路线与 hidden 设计冲突，不并行。
- **后端**：`asset_menu::copy_thumbnail_to_clipboard`——源定位拆 `thumbnail_source`（info 缩略图优先；`meta.thumbnail = None` 回退 `thumbnail::ensure_format_icon` 幂等现场 shell 提取 cache/thumbs/{ext}.webp）→ `image::open` 解码 RGBA → arboard `set_image`；纯读操作 `&Library` 不改库数据。命令同名注册。
- **前端**：placementOps `copyThumb`（invoke + toast；纯读不 refresh——menuOps 文件头"命令调用一律走 placementOps"约定，初稿误放 menuOps 已纠正）；assetCard spec 点亮（disabled = 多选，与同组既有两项同口径）。
- **测试**：新用例 `copy_thumbnail_source_locates_thumb_and_format_icon`（info 缩略图命中 / 缩略图文件缺失报错提示刷新 / fla 格式图标现场提取 / 资产不存在报错），`#[cfg(windows)]`（shell 依赖）；arboard 写入薄壳不测——防测试污染用户剪贴板。cargo test **364** 绿（+1）/ typecheck / build 全绿。
- **同步**：PRD 04-03 新增条 5（缩略图操作 + 同组三项归属）/ 07 接口（copy_thumbnail_to_clipboard 条）/ 09 待办（2026-07-23 行闭环——该笔 6.3 即落地、本轮复核连带划掉）。
- **待用户实机复验**：复制缩略图 → 设给另一资产的闭环手感（含 shell 图标 / 波形图 / 动图首帧各类型）。
