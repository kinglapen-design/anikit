## 二十一轮八轮修订（用户实机再验：投影像矢量图一层层硬边，中间深色 = 第一层）

- **物理定性**：投影台阶非实现 bug——#171717（亮度 23）到投影最深 ≈18 仅 5 级亮度，8-bit 输出下 20px 模糊必呈 3-4 层硬边；figma 稿图自身同位置同为 3 级（19→21→23），缩小显示被降采样平均才显柔和。多层叠加/换 SVG filter 同限（输出整数亮度级数不变），唯一出路是抖动（CSS 无）。
- **"中间深色块"根因**：SVG 内嵌 `<g opacity="0.6">` 时 drop-shadow 源是半透明像素——阴影在本体后**透过 0.6 图标显现**（中心层 = 用户看到的"深色正方形"），外缘 3-4 层 = 上述色带。
- **定案（用户提方案）**：SVG 节点**不透明导出** + CSS 管 opacity 0.6——CSS filter 先于 opacity 应用：drop-shadow 以不透明本体为源被挡住不透出，随后图标+投影整体乘 0.6 = 稿观感（投影剩外缘 3-4 层，与稿图自身台阶一致）。两份 SVG 手删 `<g opacity="0.6">`（docs 源 + assets 引用）；.ef-icon CSS 加回 opacity 0.6（七轮"删 CSS opacity"修法被本方案取代）。
- **导出约定（速查 §22）**：装饰插画类整体透明度不烘 SVG，统一 CSS 管；日后 figma 重导带回 `<g opacity>` 须删。
- 探针：T17a 断言改「CSS opacity=0.6 + filter 含 drop-shadow」；复跑 ALL PASS；vue-tsc 绿。
