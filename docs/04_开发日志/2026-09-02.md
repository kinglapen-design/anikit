**定案**：比例基准 = **高度跟随当前文档，宽 = 高 × 比例**（四舍五入取整；用户拍板，弃内容包围盒 / 固定长边两案）；「自动」= 跟随文档原尺寸（现状行为保留）。

**落地**（plugins/animate-cep/，APP 侧与 WS 协议零改动）：

- `index.html`：静/动分段下加比例区分段（自动 | 16:9 | 4:3 | 1:1 | 3:4 | 9:16）+ 自定义比例输入框（placeholder「自定义比例 宽:高（如 2:3）」），样式全复用 seg / input 既有控件。
- `panel.js`：分段与自定义框**互斥**——点分段清自定义框；自定义框输入合法比例（`宽:高`，支持 `:：x×/` 分隔符）即生效、分段去选中；清空自定义框回「自动」；非法输入标红框（`.input.err` → `--n-danger`）沿用上一生效值。选择经 localStorage（key `cepRatio`）记忆，面板重开恢复。导出调用 `exportSelection` 追加 ratioW/ratioH 两参。
- `host.jsx`：`exportSelection(name, outDir, dynamic, maxFrames, ratioW, ratioH)`——比例档生效时 `W = Math.max(1, Math.round(H × ratioW / ratioH))`，高度恒随文档；缺参（旧面板）自动回退跟随文档，向后兼容。内容缩放居中（短边 90%）逻辑不变自动适配。

## 阶段八 CEP 补场景 · 修复轮：导出中断卡死（用户实机报：导出时退出 APP → 卡「等待入库」无提示无重试）

**根因三层**：① 面板单选路径断连时 onWsDead 只复位不提示（批量才有提示）——状态区停在「等待入库」像卡死；② WS 在 CLOSED 态 `send` **静默丢弃**（规范如此）——导出中 APP 退出时消息可能根本没发出，面板无从知晓；③ 无重试机制——产物（fla/PNG）已在 cep-out 却无人入库，重连后也无人重发。连带坑：APP 重开未开库时面板停「未开库」永不刷新（welcome 只在连接建立时发一次）。

**修复**（panel.js，纯面板侧零后端改动）：

- **pending 单条续传**：导出消息发送即登记 `pending`（localStorage `cepPending` 持久化——面板重开也不丢，产物在 cep-out 等重发）；收到回执（importDone/Error、thumbDone/thumbError）清除；`sendPayload` 统一入口——发送前必查 readyState（CLOSED 静默丢坑根治），send 异常 try 兜住。
- **断连明确提示**：onWsDead 三分支——批量中止（已入库有效、剩余重导）/ 有 pending =「连接中断，导出未完成——产物已保留，重连开库后自动重发」/ 无 pending = 导出中止。
- **welcome 自动重发**：libReady 且有 pending（且非批量/导出中）→ 重发 + 等回执期间禁新导出（防 pending 覆盖后旧回执误清）。
- **重复重发免疫**：APP 退出时机在 commit 后回执前 → 重发撞「产物不存在」（已清场）→ 不计错误，温和提示「产物已入库或已清理，无需重发」。
- **未开库自动跟上**：welcome 时 libReady=false → 5s 轮询重发 hello（单链不叠加），开库后面板自动点亮 + 自动重发 pending。
- 批量 send 前同查 readyState（断连即计失败，onWsDead 随后复位）。

**遗留**：用户那笔卡单（雪牧_自动）发生在修复前，localStorage 无 pending 记录不会自动重发——重新导出一次即可（产物覆盖）；cep-out 残留属 temp 语义可手动清。批量中断不做自动重发（部分入库状态不明，提示重导剩余项）。**8.2 可评估「启动扫描 cep-out 孤儿产物继续入库」兜底**（记 09 待办）。

**验证**：node --check 过；panel.js 已同步 extensions（重开面板生效）。

**文档**：04 本日志；05 当前状态。

**根因**：阶段四帧流卡片层三重 CPU 链——① N 卡 = N 个 Rust 解码线程**全尺寸循环重解** origin（1080p GIF/WebP 每趟重解码再缩 320，永不缓存）；② RGBA 裸帧 WS 传输（320p 帧 ~400KB × 25fps × N 卡）；③ 前端主线程 `putImageData` 光栅化（CPU 路径，阻 GPU 合成）。spike 验收基线「50 路 17%」为 32 核机数据（2026-08-20），与用户实机不符——口径错位当时已埋下。

**修（用户定方向 = 对齐 Eagle）**：AnimCanvasLayer 退役 → 新 `AnimImgLayer.vue`——`getAssetFilePath(playAssetId ?? assetId)` 直读 origin + convertFileSrc，`<img>` 原生循环，解码/合成全走 webview 优化路径；透明帧 g2 衬底（2026-09-01 修复语义）沿用；播放源 watch 热切换 / 进入延迟分档（悬停 300 / 自动播放 100）/ 主窗口隐藏卸载-恢复 / 解析失败回退静态封面全保持。**帧流收窄预览窗口专用**（播放条/逐帧/倍速/帧条需帧级控制）；数量闸（anim 池 50 + 可见性联动）与 fla 伴生播放代理不变；后端 frame_stream 零改动。

**决策佐证**（翻旧账）：文档从未论证 `<img>` 播动图在 WebView2 有功能性障碍——2.3 前 `<img>` 直播原尺寸 GIF 的唯一问题是原尺寸解码贵（Eagle 同级成本，可接受）；2.3 小动画缓存被废理由是"导入提速 + 磁盘大减"非不好用；PRD 对卡片动图无帧级控制需求（悬停即播放原生循环）。重影修复（cep_export 全帧组包）在编码端，不受播放路径影响。

**验证**：vue-tsc 0 错 / build 绿。**下一步：用户实机复验（视口动图卡 CPU/风扇回归 Eagle 同级）**。

**文档**：PRD 04 卡片口径（阶段四口径删除线 + 回滚定案）/ 07 帧流段（收窄预览专用）/ 05 当前状态 / 09 待办（cdp-anim-stream-probe 过时登记）。

## 修复：小动画卡片残影（2026-09-02 八轮，用户实机报「所有帧都重叠，仅卡片预览；空格/双击预览与帧图正常」）

**定性**（证据链逐环排除）：① Pillow 规范合成已生成的 `_anim.webp`（ffmpeg sidecar 转码产物）第 4 帧起即带残影 → **产物帧本身就错**（排除 Chromium 播放缺陷）；② ffmpeg 解码 origin（CEP 自产全帧组包 webp）输出 PNG 干净 → 解码无恙；③ 坐实 = **ffmpeg libwebp 动画编码差分帧生成错误**（矩形裁剪 + blend/dispose 组合，大透明区动画必发；GIF 不透明全帧不触发，故 2.3 时代未暴露）。帧流/帧条正常是因为它们走 image-webp 解 origin（全帧组包）。2026-09-01「image-webp 画布合成缺陷」定性只是差分帧危害链一环——不合规差分产物在任何解码端都可能叠影（踩坑 068）。

**修法（转码链整体换纯 Rust，编解自洽）**：`anim_preview::ensure_anim_preview` 弃 ffmpeg sidecar → `anim::decode_frames`（完整画布帧）→ `shrink_to_edge` 短边 320 → `anim::encode_webp_anim` 全帧组包（blend=0 全画布矩形；组包函数从 cep_export 收编 anim 域共用，CEP 导出改调同函数）。`ffmpeg::transcode_anim_preview` 删除；sidecar 依赖摘除。**存量坏缓存自动翻新**：`is_fresh` 加 `is_full_frame_pack` 结构判定（逐 ANMF 校验全画布矩形 + flags bit1=1，读失败/非 RIFF 同判陈旧）——旧 ffmpeg 产物下次播放即触懒生成重生成 + 前端热切换，用户无感。

**验证**：真实伴生 webp（雪牧_开枪跑，125 帧 1024×576）走新链重生成 → Pillow 合成第 4/9 帧干净无残影 ✓；cargo test **448** 全绿（+2：全帧组包判定 ×篡改三态 + 差分陈旧重生成闭环；复跑三次稳定——首次删临时验证测试后曾现 2 failed 未捕获测试名，疑增量编译态偶发）；vue-tsc 0 错 / build 绿。**下一步：用户实机复验（卡片残影消失 + CPU 仍低）**。

**文档**：06 踩坑 068 / PRD 04（小动画转码实现改纯 Rust）/ 07 接口（animPreview 段）/ 05 当前状态 / 本日志。

## alt+` 最小化呼出修复（走查第一批 · 末条）

**现象**（用户实机）：窗口最小化挂任务栏时按 alt+\` 呼出无效，要先挂托盘再按才呼出。

**根因**：热键回调与托盘/单实例共 4 处"显示主窗口"全是裸 `show() + set_focus()`——Windows 上最小化窗口 `is_visible()` 仍 true、`is_focused()` false，走显示分支；但 `show()` 底层 SW_SHOW 对最小化窗口**不还原**（须 SW_RESTORE 语义），表现为按键没反应。

**修法**：lib.rs 新统一出口 `show_main_window(w, emit_shown)`——`is_minimized()` 先 `unminimize()` 再 show + set_focus；emit_shown 保持各调用点原语义（托盘路径恒通知前端恢复播放；单实例唤起不通知；热键 else 分支恒通知）。热键 toggle 判定（visible && focused 才 hide）不动。

**验证**：cargo test 449 全绿（复跑稳定；首跑 1 failed 为增量编译态偶发，同族前例已记）/ 前端零改动。窗口管理运行时行为无自动化覆盖，**下一步：用户实机复验（最小化 → alt+\` 直接呼出聚焦；托盘/单实例路径同验）**。
