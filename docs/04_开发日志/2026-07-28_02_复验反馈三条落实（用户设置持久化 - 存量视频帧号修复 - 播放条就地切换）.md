# 复验反馈三条落实（用户设置持久化 / 存量视频帧号修复 / 播放条就地切换）

**复验反馈三条落实（用户设置持久化 / 存量视频帧号修复 / 播放条就地切换）**：① **UI 设置持久化**（用户原话："用户设置要持久化，包括窗口大小，位置"）——ui store 19 个字段（查看方式 / 开关组 / 侧栏 / targetRowHeight / alwaysOnTop / 左右视图 / timeDisplay）存全局 config.json settings.ui 子树（core/config.rs 加 ui_settings / save_ui_settings / window_state / save_window_state 四个写点函数 + 3 单测）：启动 get_ui_settings 拉取（类型对照默认值校验防手改 config 污染），$subscribe 防抖 500ms 整体写回；新命令 get_ui_settings / save_ui_settings / save_window_state（commands/settings.rs）。**窗口几何自实现，放弃 tauri-plugin-window-state**——三条理由：a) 主窗口无边框 decorations:false + shadow:true，该插件在 Windows 无边框窗口有位置恢复漂移已知问题（阴影 inset 偏移）；b) 预览子窗口按资产动态建标签，插件静态 allow/denylist 无法排除；c) 插件自写 .window-state.json，绕开 core/config.rs 单一写点（UI 设置本来就落 config.json，两份状态文件没必要）。**依赖四问结论：本轮零新依赖**（评估对象 tauri-plugin-window-state 用途=窗口几何持久化、许可 MIT/Apache、维护活跃，但"有无重复轮子"一问不过——config.rs 既有写点 + 30 行自实现即可，且避免上述冲突）。实现：主窗口 resize/move 防抖 500ms 提交（最大化时后端 merge 只刷标志位、几何保留还原尺寸——merge_window_state 纯函数单测），启动 setup 恢复（tauri.conf 改 `visible: false` 先隐后显防跳变；available_monitors 判坐标落空只恢复尺寸；预览子窗口不记录不恢复，App.vue 监听按 previewParam 门控）。② **存量视频帧号不显示**（用户："卡片预览和预览界面只有一两个视频显示帧，新窗口打开才有"）——根因 = 上轮自愈只写后端 metadata + 内存索引，前端 content store 的 PlacementView.fps 仍是开库旧快照 null（新窗口重拉数据所以正常）。修：MediaSource 响应加 fps（自愈后准确值，previewMedia 优先用响应值——播放条/笔记立即正确）+ 自愈写回成功广播 `video-fps-healed { assetId, fps }`（content store initFpsHealListener 同步该资产全部 Placement——HoverVideoLayer 胶囊 / DetailNotes 随之正确；同一资产自愈后 fps 非空不再命中，天然不刷屏；序列帧 metadata.fps 早有值，自愈条件 fps.is_none() 不命中，零污染）。③ **播放条时间码悬停就地切换**（用户："和速率的样式差不多"）——新 TimeDisplayControl.vue（复刻 RateControl：悬停竖排弹窗 / 4px 桥接 / 未选中 60% 选中实色），「帧数」「时间码」选中即切 ui.timeDisplay（与查看方式菜单同一值双向联动）；PlayBarVideo 时间文本换为该控件（.time-text 样式随控件迁出），PreviewWindow 经 PreviewPlayBar 复用 PlayBarVideo 天然覆盖新窗口。cargo test 170 过零警告、clippy -D warnings 清零、tsc / build 全绿；07 接口 / 05 进度 / PRD 04 / PRD 06 / 13_预览窗口 已同步。
