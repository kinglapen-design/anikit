## 5.3 终版后修复轮：托盘恢复播放 + 设封面范围即时跟随（用户实机两报）

**背景**：5.3 终版（视频回 `<video>` 直读，651d5ed）用户复验通过后报两个预览相关问题。

### ① 关闭到托盘再打开：自动播放 / 悬停播放不恢复（要滚出视口或切文件夹才活）

- **根因**：`main-window-hidden` 只有暂停路径——hoverPreview 注册表只注册 pause 回调，窗口重新显示（热键 / 托盘菜单 / 托盘左键）无任何事件，被 pause 的播放层没人唤醒；鼠标未移动时 Chromium 不重发 hover 事件，悬停态也不重建。
- **修法**：后端三条 show 路径（热键 else 分支 / 托盘菜单「显示」/ 托盘左键单击）补 emit `main-window-shown`；hoverPreview 注册表升级 pause+resume 双回调；useHoverPlayer 加 `resume` 必传参；四层各自实现——HoverVideoLayer（ready 则 play）/ HoverAudioLayer（play）/ HoverSequenceLayer（fps 存组件级，start() 抽取复用重启轮播）/ AnimCanvasLayer（pause 是停会话省 CPU，resume = `!session` 则重建）。**预览单例（previewMedia）不受理 shown**——保持"重新显示后手动再播"（2026-07-27 用户定案）不动。

### ② 设封面后：静态封面生效，但自动播放范围要重启 APP 才生效

- **根因**：`set_video_thumb` 后端把 thumbFrame（`t:{秒}`）落盘 + 同步内存索引，但返回结构只有 `{thumbPath, modifiedAt}`——前端只热换了缩略图（版本戳），`PlacementView.thumbFrame` 没同步；HoverVideoLayer 自动播放 rangeStart 读的还是旧值，重启重拉才新。
- **修法**：`SetThumbResult` 加 `thumb_frame` 字段（set_thumb_frame 同结构同字段），前端 previewMedia.setVideoThumb 写回 `target.thumbFrame`。

### 验证与同步

cargo test 363 绿 / typecheck / build 绿；cdp-preview-anim + cdp-playbar 复跑 PASS（干净 vite 实例）。07 接口（main-window-shown 事件条 + set_video_thumb 返回字段）同步。**待用户实机复验两条修复**。

## 同日三轮：卡片滚回视口恢复播放提速（自动播放进入延迟 300→100ms，用户实机报）

- **症状**：视口外卡片滚回视口后停顿约半秒才开始播放，每次滚动都要等。
- **根因**：恢复耗时链 = IntersectionObserver 回调（~30ms）→ 名额申请 → 播放层组件挂载 → **useHoverPlayer 固定 300ms 进入延迟** → 源加载到 canplay 起播（~100-300ms）。300ms 是悬停语义（防鼠标快速划过误加载），对自动播放路径（可见性驱动，本身即意图信号）是纯等待，占总耗时一半以上。
- **修法**：useHoverPlayer 加 `enterDelay` 参数（缺省 `HOVER_ENTER_DELAY=300` 悬停语义不变），新增 `AUTOPLAY_ENTER_DELAY=100`——100ms 足以滤掉飞速滚过（一屏瞬时穿过的卡不触发加载），比悬停档砍 200ms 纯等待。HoverVideoLayer 本有 `auto` prop 直接分档；AnimCanvasLayer / HoverSequenceLayer 新加 `auto?: boolean`，AssetCard 模板传 `:auto="!hoverActive"`。挂载瞬间 auto 已定型（悬停接管只切 prop 不重建组件），延迟仅挂载时用一次，两档语义不串。
- **边界（不做，用户定"现在够用了"）**：剩余 ~200-400ms 是浏览器 canplay 起播时间；若还要更接近 Eagle 无感需视口外预加载（rootMargin 宽 IO 提前挂载起播），改动更大，本轮不启。
- **验证**：typecheck 绿；用户实机复验"够用了"。探针 = cdp-anim-stream-probe 干净 vite 实例（5374）：场景①通过（可见 9 卡全出帧 / img 不换源 / starts 9——100ms 档核心链路正常）；滚底 / 尺寸跟随两轮吊死在滚轮注入段未覆盖——探针 frame_server 单线程事件循环推流与 CDP recv 互饿的已知结构瓶颈（探针注释在册，2026-08-20），100ms 档滚动连接变密 + 本机 dev 全套在跑放大触发，降帧率/滚速重跑未救回；该两场景代码本轮零触碰、实机等价物（用户滚动复验）已过，不硬磕（踩坑 049⑤）。误跑过时 cdp-autoplay-gate-probe 一轮（09 待办 2026-08-22⑤ 在册：断言 2.3 img 换源旧口径，帧流后既红，删/改待用户）。
