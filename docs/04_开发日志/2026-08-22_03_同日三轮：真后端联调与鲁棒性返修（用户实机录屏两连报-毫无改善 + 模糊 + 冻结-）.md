# 同日三轮：真后端联调与鲁棒性返修（用户实机录屏两连报"毫无改善 + 模糊 + 冻结"）


用户提供了问题录屏（AniKit 侧）与 Eagle 对照录屏（`assets/video/`）。看录屏定症：预览打开后画面**模糊**，播放条数帧后**永久冻结**（停 624/4725），音频仍在放。真后端单元压测（4K120 带音录屏样本）解码/seek 健康（120fps 满节奏、seek 52ms）——问题在交付链与鲁棒性，逐项修：

- **模糊 = 出帧尺寸未计 DPR**：streamEdge 只按 CSS 像素，4K/150% 屏 1.5 倍欠采样。修 = 帧短边 × devicePixelRatio（>2 不追），预览档上限同步收紧 4096→2048（大源高帧率下 WS 吞吐 / putImageData 主线程预算有限）。
- **永久冻结两候选通道全堵**：① seek 后 `flush` 控制消息经广播通道 Lag 丢失 → 前端 videoSeeking 丢帧标记永久卡死——serve_ws Lagged 分支合成 flush 强制重同步 + 前端 1.5s 看门狗自清；② 会话线程解码错误即死、前端无任何信号——新增 `error` 控制消息 + Session.die()（通知前端 + 自清会话表），预览降级报错（播放条禁用）、卡片回退静态封面。
- **高帧率洪泛**：源 >60fps 时隔帧发布（4K120 录屏全量推流 = webview 主线程被 putImageData 压垮的假冻结诱因）；暂停/逐帧定位帧恒发布。
- **音频钟异常自愈**：无头环境（假音频设备 currentTime 跳变）实测帧等钟卡 1s 级间隙——待渲帧等钟加 120ms 墙钟上限，超时强渲，音画偏差封顶。
- **真后端探针 `cdp-video-real-probe.py` + 测试内 harness**（video_stream_harness，#[ignore] 手动）：真 Rust 后端解码真实视频 + WS 推流，探针桩仅替换命令路由（start_video_stream 指 harness 会话；seek/playing/rate/loop/size 经命令文件转发真执行）。实测：连续出帧 66 次/3s 无 >100ms 间隙（不冻结）、seek 90% 端到端 737ms（含 ~100ms 命令轮询与无头环境损耗；后端本体 52ms）、seek 后续播、暂停恢复命令直达真后端。踩坑：探针后台协程并发 evaluate 同 CDP 连接会互吃响应（改主流程同步转发）；harness/探针共享状态文件的删除竞态（先清再启）。
- 附带基建修正：serve_ws / frame_bytes / audio_bytes 摘除 cfg(not(test))（纯 tokio/tungstenite 无 AppHandle——踩坑 014 门控只罩 init），测试/harness 可用真 WS 服务。
