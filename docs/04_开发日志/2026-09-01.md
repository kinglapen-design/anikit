## 阶段八 8.1 二轮 2a 复验二修：WebP 黑底（透明丢失）修复（用户实机报）

**现象**：重导的 fla 卡片黑底（应透明透出卡片灰底）。**根因两环**：

1. **组包丢 ALPH**（初版 `extract_vp8_chunk` 只提 VP8/VP8L chunk）——webp crate 有损编码对含 alpha 输入自动产 ALPH 伴随块（libwebp use_argb=1），初版提取把它丢了 → 帧无 alpha 不透明、透明区 RGB(0,0,0) 落成黑底。修法 = `extract_image_chunks` 按序保留 ALPH+VP8/VP8L 全部图像 chunk。webp 0.3.1 自带的 AnimEncoder（官方 libwebp 动画编码封装）评估弃用——它自动差分裁剪帧矩形，与重影根治的"全帧组包"路线冲突。

## 阶段八 8.1 二轮 2a 复验三修：组包 flags 语义反转修复（用户实机报"还有重影"）

**现象**：修复重导后播放仍脚部残影。**根因**：组包 ANMF flags 语义写反——初版写 `0`（bit1=0 = **alpha 混合**），透明区混合 = 保留画布旧内容 → 角色移动后旧脚位残影；python 解析确认新文件已是全帧矩形（组包路线对）但 flags 错。**终版 = bit1=1（do not blend）**：源像素**含透明区**直接替换画布，每帧画布即该帧完整内容。ffmpeg 差分帧坑（矩形外残留）与本坑（透明区残留）合并根治。

**教训**：webp ANMF flags 语义——bit0 = dispose to background；**bit1 = 0 才是 alpha 混合、1 是源覆盖**（与直觉的"blend=1=混合"相反）。

**验证**：cargo test **423** 全绿（+1：`webp_anim_no_ghost_with_translucent_move` 残影回归钉——透明底移动色块，帧 2 在帧 1 色块位必须恢复透明；前两个回归钉（不透明全异色块 / 黑底 alpha）未覆盖透明区移动场景，本钉补齐）；既有 `frame_strips_generate_products` 并行竞态 flake 一次（单跑复跑均过，历史前科 TEST_LOCK 族，留意不阻断）。

## 阶段八 8.1 二轮 2a 复验四修：播放 canvas 透明区透下层首帧（用户实机报"第一帧永远在后面"）

**现象**：flags 修正版组包播放仍见第一帧残留（底部静止鞋）。**根因 = 前端双层叠加**：播放 canvas（v-show=hasFrame 后可见）叠在静态缩略图 img（恒显示）之上，**帧透明像素（alpha=0）透出下层首帧静态图**——GIF 等不透明帧像素全覆盖从未暴露，CEP 伴生 WebP（角色仅占画布小部、大透明区）首曝。**解码链路本身已正确**（flags=0b10 组包经 image-webp 整帧源覆盖，画布 = 当前帧完整内容含透明区）。

**修法**：播放 canvas 衬底色——`.anim-canvas` 背景 = `--n-g2`（卡片壳底色，`AnimCanvasLayer`）/ `.stream-stage` 背景 = `--n-g1`（预览区底色，`PreviewStreamCanvas`）——canvas CSS 背景被不透明像素覆盖、透明像素处显底色，下层首帧完全遮挡；不透明帧零视觉变化，停止播放（v-show false）回静态封面。vite 热更新即生效，**flags 修正版文件无需重导**。

**验证**：vue-tsc 0 错 + build 绿。**文档**：04 日志 / 00 状态同步。


## 阶段八 8.1 二轮 2a 复验五修：fla 预览静帧无播放条（用户实机报）

**现象**：fla 双击预览 = 静帧，无播放条/帧条。**根因**：播放代理初版把 `loadAnim(p.playAssetId ?? p.assetId)` 直接传了伴生资产 id，而 loadAnim 内部的"await 期间已切走"守卫按 `current.assetId !== assetId` 判定——current 是 fla、入参是 webp，**守卫误判切走把帧流会话当场停掉**（prepareAnimStrips 同被拦，故帧条也无）。

**修法**：代理收进 loadAnim 内部——开流源 `sourceId = current.playAssetId ?? assetId`（开流 / 帧条 / 失败回退图源全走伴生资产），切走守卫恒按预览目标（fla）判定；调用点恢复传预览目标自身。顺手把「当前帧设为预览图」同代理（invoke assetId = playAssetId 优先——设封面 = 改伴生 hidden 资产的封面帧，fla 卡片经视图代理同步换图；target 版本戳/布局尺寸仍按 fla 定位刷新）。

**验证**：vue-tsc 0 错 + build 绿。**下一步：用户实机复验（fla 预览 = 播伴生动画 + 播放条 + 帧条渐进 + 设封面生效）**。


## 阶段八 8.1 二轮 2a 复验六修：fla 预览帧条不加载 + 标题栏缺默认应用打开（用户实机两报）

**① 帧条不加载（开 webp 预览一遍后才有）**——根因同五修同族：`preview-strips-ready` 渐进事件按 `current.assetId !== e.assetId` 过滤，fla 预览时事件 assetId = 伴生 webp id 被丢弃（prepareAnimStrips 首次返回空、渐进度全丢）；开 webp 预览后缓存生成 + current 匹配故出现。修法 = 事件过滤放行 `playAssetId`（伴生 id 同样接收）。

**② 标题栏缺「默认应用打开」**——fla 预览按伴生 WebP 显示为 anim kind（图片工具栏），而 anim/video 旧口径无此钮；但 fla 本质是工程文件，预览确定后需要入口打开 fla 本身（用户定）。修法 = 显示条件加 `current.playAssetId`（代理资产恒显示）；`openDefaultApp` 本就对预览目标（fla）调用，打开 fla 本身无需改。

**验证**：vue-tsc 0 错 + build 绿。**下一步：用户实机复验（fla 预览帧条渐进 + 默认应用打开 fla）；其后 2b = CEP 正式面板 + 一键安装 + 设置页**。
