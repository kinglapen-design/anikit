## 十八轮十二轮 · 主窗口角部 1px 缝实机像素级排障（用户复验：边框与线条圆角不一致、角上空出一个像素点）

- **排障过程**（DWM 层 headless 探针截不到的破法，mss + PIL + ctypes 实机直查）：①原生文件资源管理器（云母）角部 8x 放大干净 → 非系统固有，是 AniKit 架构问题；②读 tao 0.35.3 源码确认 undecorated shadow 的 insets 机制（GPUI 系：窗口矩形 = 客户区 + 左/右/下 SM_CXSIZEFRAME+SM_CXPADDEDBORDER、上 round(dpi/96)，WM_NCCALCSIZE 返回 0）；③ctypes 枚举窗口 + `DwmSetWindowAttribute(BORDER_COLOR)` 染纯红实验：**S_OK 且即时生效**——DWM 染色链路与 hwnd 无误（`DwmGetWindowAttribute` 读 BORDER_COLOR 返回 E_INVALIDARG 是该属性只写的正常行为，勿误判）；④EnumWindows + GetProcessTimes 反查：app.exe 16:58 重启（tauri dev 自动重编正常），实机跑的就是最新代码。
- **根因坐实**：角上"像素点" = DWM 边框线弧与前端框线弧（或裁切弧）~1 物理 px 的圆心/半径差——异色时分离显形成缝/双层，**同色重叠则错位隐形**。
- **同色容错实机验证**：手动 ctypes 染 DWM 边框品牌青（选择模式中），8x 放大角部 = DWM 线与 ::after 融合为单层整圈，角部只剩 1-2 个暗像素点（两弧分叉带，transparent+NCCALCSIZE0+云母架构的物理极限）。三轮架构（b061f55：DWM 画线 + picking 切染同色 + 圆角 DWM 独裁）经实验证明正确，本轮无行为变更。
- 切色链路加可观测性：`set_main_border_picking` 失败 log::warn + 成功 info（原静默吞返回，"切色有没有发生"零信号）；前端 .catch 改 console.warn。
- 常态角部观感留用户复验：若 1-2 暗像素点仍在意，候选 = 常态 ::before 也画 #333 同色双画（代价边框变 ~2px），留待定夺。
