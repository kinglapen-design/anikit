## 阶段五 5.2 一轮：序列帧包内视图 + 解散导入 + 动图预览复核

用户开工四问：① 复核动图各预览是否接入自研解码器；② 点亮「打开序列帧包 / 解散序列帧包导入」两个右键菜单（解散 = 每帧单独存成 info 素材，危险操作要警告窗口）；③ 打开序列帧包 = 视图变成正常卡片列表展示全部帧；④ 抽删帧序号断开会不会影响播放、有什么方案。

### 动图预览复核结论（explore 全链路盘点）

- **已接入自研解码器**：网格卡（WS 帧流 AnimCanvasLayer）/ 预览窗口（PreviewAnimCanvas）/ 帧条（prepare_anim_strips）/ 设封面（set_thumb_frame `f:{索引}` 抽帧）/ 逐帧笔记（get_note_thumb 抽帧）/ 后端六命令；无 animPreview 消费方、无 anim_unpack / 动图 frames/ 残留。
- **有意未接**：HoverZoomOverlay 空格放大浮层 = img 播源文件（阶段四"零改动"定案；切不切帧流记 09 待办待用户）；列表行 / 详情 pinned = 静态缩略图（本就无播放设计）。
- **4 个解包废除漏适配已修**（preview.seq 对动图恒 null 的分支）：DetailNotes 点动图笔记**跳帧失效**（改 `f:{索引}` 直接 setFrame，与 previewNotes store jump 同口径——组件内是旧拷贝）、DetailNotes / PreviewNotes 列表项原样显示 `f:41`（改帧号）、PreviewNotes 头部"帧 x/y"空串（改 animTotal/frame 驱动）。

### 抽帧断号问题的答案（进 PRD 04 口径）

**不影响播放**——list_sequence_frames 扫 frames/ 按文件名排序（序号只是帧名字符，不推导连续性），每帧时长均匀 1000/fps；抽删后顺序不变、帧数变少 = 节奏加快（正是抽帧目的）。位宽统一由入库归一保证。方案 = 包内视图提供删帧 + 重排序号（整洁性，非播放前提）。

### 包内视图（用户定案操作集）

- **视口**：viewKey = `seq:{assetId}`（ContentArea 分流 SequencePackView；viewTitle = 包名；标签页/面包屑历史/新标签页全免费获得）。打开 action 内 `selection.clear()`——包内无素材卡片，残留选中会让全局 Delete 误删素材域（实机级坑，防线先行）。
- **帧卡片**：素材卡 14 稿紧凑形态视觉（简介区 36 / aspect-ratio 260:199 折算），缩略图 = cache/frames 帧条小图（与预览帧条同缓存，preview-strips-ready 渐进填；未缓存原图兜底），封面帧名称行右侧"封面"标记（标签档）。本地选择集（click 单选 / ctrl 切换 / shift 范围 / 空白清空），帧不是 Placement 不进全局选择域。
- **操作**：双击 / 右键「打开预览」= 退回包所在文件夹视口 + preview.open + setFrame 定位（导航历史入栈，面包屑后退回包内）；右键「重排序号 / 删除此张序列图」（多选 = 删除 N 张，Delete 键同径）；空白右键 = 重排序号。重排图标 = clear-cache-reload（用户定：切换资源库"清除缓存并重新加载"同款刷新图标，要换再说）。
- **热刷新**：watch 目标资产 modifiedAt（ops / undo-redo 后 content.refresh 带入）→ 重拉清单并剔除已消失选中帧；资产消失（已解散）落空态文案。

### 后端三命令（commands/sequence + services/operations/sequence）

- **`dissolve_sequence`（危险，不进 undo）**：每帧移动（Source::Move）出库建档（复用 build_asset_with_id 单文件管线：逐帧 sha256 + 缩略图），落点 = 原包 origin 所在文件夹（无 origin 取首条、无 Placement 兜底未分类），段首前插保帧序；成功后原包 placements 清除 + info 目录物理删除（逐帧笔记随删）+ 该资产 cache/frames 与 seq-trash 清理。任一帧失败整体回滚（帧移回 + 已建 info 删 + 索引/placement 清），落盘失败命令层 reload 对齐。
- **`delete_sequence_frames`（可撤销）**：帧移 `cache/seq-trash/{id}/` 暂存（**开库清空名单新增 seq-trash** = 会话结束真删；DiskOp::Rename 双向恒不撞名——暂存区与 frames/ 互斥）；封面帧被删改指剩余首帧 + 重建缩略图；笔记 key 清除 + noteCount 同步（0 记 None）；**至少保留 1 帧**护栏；0 删除不留空 undo 事务（前端 toast 撤销按钮防误关联历史操作）。
- **`renumber_sequence_frames`（可撤销）**：连续化 `词干-001..N`（位宽只增不减）；**两段改名防撞**（`~anikit-renumber-` 临时名过渡）；undo/redo 磁盘序列由服务层按 apply_disk 逆序语义折算（0 起序号 old_i < new_i 场景单向序列必撞——测试 `renumber_undo_redo_sequences_are_two_phase_safe` 钉死）；笔记 key 映射迁移（replace_all 保时间文本）；帧条缓存整清。
- 前端 ops 层三函数（placementOps 序列帧包段）：删帧 / 重排不走 runOp——0 操作时后端无 undo 事务，runOp 恒带撤销按钮会误关联（注释钉了口径）；解散走 runHardDelete（无撤销按钮）。menuOps.dissolveSequenceFlow = alert warning 弹窗（帧数 / 笔记数按 noteCount 条件拼接 / 明示不可撤销，主左「解散导入」）。
