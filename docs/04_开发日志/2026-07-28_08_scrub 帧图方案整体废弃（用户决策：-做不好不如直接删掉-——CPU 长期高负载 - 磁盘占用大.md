**scrub 帧图方案整体废弃（用户决策："做不好不如直接删掉"——CPU 长期高负载 / 磁盘占用大 / 载入慢）**。同日迭代链回顾：video seek 卡顿 → 改预生成帧图（Eagle 手感来源误判为"导入期抽帧"）→ 修单帧 bug（.webp 默认原生单帧编码器覆盖，显式 libwebp）→ skip_frame 提速 → 帧数分档加密 + 导入期预抽 + 持久化 → 用户实测 Eagle 毫秒导入立即可滑（**Eagle 是自研播放器实时解码 seek，解码器常驻，并非预生成帧**）——webview + sidecar 架构下 Chromium video seek 有硬限制，帧图路径的成本（全片解码 CPU / 每视频数 MB 磁盘 / 首次载入等待）不可接受，决策废弃。拆除：list_video_scrub_frames 命令、services/scrub_frames.rs、unpack_queue QueueTask::Scrub 与 import_task 预抽挂钩、ffmpeg.rs video_scrub_frames、library.rs scrub 持久化改动、前端帧图层与双缓冲——回退 HoverVideoLayer 精简版（video seek + rAF 合帧 + 66ms 门控，保留双模式 / 范围循环 / 音量胶囊）。保留的沉淀：GPU 硬解实测结论（d3d11va 帧回拷贝反慢于 CPU，抽帧场景无优势）、.webp 默认原生单帧编码器序列输出覆盖坑。cargo test 166 过零失败、clippy 清零、tsc / build 全绿；07 接口条目删除、05 进度与 PRD 04 同步。
