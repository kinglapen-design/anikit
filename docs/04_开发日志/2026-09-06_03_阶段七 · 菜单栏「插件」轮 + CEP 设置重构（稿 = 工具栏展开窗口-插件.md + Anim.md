### 同日七轮（用户实机走查一条修订）

**子窗口打开后首次悬停滚轮不显、要先点一下**——根因 = ScrollThumb 的 hover 显隐仅由 `mouseenter/mouseleave` 驱动，**WebView2 新窗未激活态首次 mouseenter 丢失**（点击 = 激活窗口，之后事件链才恢复，所以"点一下就好了"）。修法 = 加 `window` 级 `mousemove`（capture + passive）**兜底校正**：不依赖「进入」语义，鼠标一动即按 `wrap.contains(e.target)` 实时置 hover；mouseenter/leave 保留为快速路径（leave 防鼠标离窗后 hover 滞留）。组件层落地，主窗口各滚动区同类首悬停场景同愈。

**验证**：`pnpm typecheck` 0 错；探针 41 项回归全 PASS。**交实机走查**：子窗口打开后首次悬停即显滚轮（不再要点击）。

### 同日八轮（用户复验：七轮修法无效，真根因不在 hover）

**滚轮不显真根因 = `thumb.show` 观测盲区**（用户：「点击也不行，非要滚轮滚一下才能调出滚动条」）——子窗口首帧「路径」组短文本（`读取中…`/`未开库`）刚好不溢出，`sync()` 算 `show=false`；IPC 返回后换长路径折行内容变溢出，但变化在**第三 section 内部文本节点**：`RO(el)`（容器高不变）/ `RO(firstElementChild)`（变的是第三个）/ `MutationObserver childList`（文本属 characterData）三路全捕不到 → show 恒 false；「滚一下」= scroll 事件触发 sync 才置 true（之后一切正常）。修法 = **MO 补 `characterData: true, subtree: true`**（useSideThumb 层，全局「异步数据返回后内容变高」滚动区同愈）。七轮的 mousemove 兜底保留（新窗未激活 hover 丢失的防御，但非本案根因）。**教训已记速查：悬停显隐 bug 先分 `show` / `hover` 两条腿查，勿单边定论。**

**验证**：`pnpm typecheck` 0 错；探针 41 项回归全 PASS。**交实机走查**：子窗口打开后首次悬停即显滚轮（不点不滚）。
