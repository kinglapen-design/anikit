## 修复：小动画卡片残影（2026-09-02 八轮，用户实机报「所有帧都重叠，仅卡片预览；空格/双击预览与帧图正常」）

**定性**（证据链逐环排除）：① Pillow 规范合成已生成的 `_anim.webp`（ffmpeg sidecar 转码产物）第 4 帧起即带残影 → **产物帧本身就错**（排除 Chromium 播放缺陷）；② ffmpeg 解码 origin（CEP 自产全帧组包 webp）输出 PNG 干净 → 解码无恙；③ 坐实 = **ffmpeg libwebp 动画编码差分帧生成错误**（矩形裁剪 + blend/dispose 组合，大透明区动画必发；GIF 不透明全帧不触发，故 2.3 时代未暴露）。帧流/帧条正常是因为它们走 image-webp 解 origin（全帧组包）。2026-09-01「image-webp 画布合成缺陷」定性只是差分帧危害链一环——不合规差分产物在任何解码端都可能叠影（踩坑 068）。

**修法（转码链整体换纯 Rust，编解自洽）**：`anim_preview::ensure_anim_preview` 弃 ffmpeg sidecar → `anim::decode_frames`（完整画布帧）→ `shrink_to_edge` 短边 320 → `anim::encode_webp_anim` 全帧组包（blend=0 全画布矩形；组包函数从 cep_export 收编 anim 域共用，CEP 导出改调同函数）。`ffmpeg::transcode_anim_preview` 删除；sidecar 依赖摘除。**存量坏缓存自动翻新**：`is_fresh` 加 `is_full_frame_pack` 结构判定（逐 ANMF 校验全画布矩形 + flags bit1=1，读失败/非 RIFF 同判陈旧）——旧 ffmpeg 产物下次播放即触懒生成重生成 + 前端热切换，用户无感。

**验证**：真实伴生 webp（雪牧_开枪跑，125 帧 1024×576）走新链重生成 → Pillow 合成第 4/9 帧干净无残影 ✓；cargo test **448** 全绿（+2：全帧组包判定 ×篡改三态 + 差分陈旧重生成闭环；复跑三次稳定——首次删临时验证测试后曾现 2 failed 未捕获测试名，疑增量编译态偶发）；vue-tsc 0 错 / build 绿。**下一步：用户实机复验（卡片残影消失 + CPU 仍低）**。
