# 02_文件整理讨论定案（用户草稿同目录 02_文件整理.md + mockup 截图迭代）

**02_文件整理讨论定案（用户草稿同目录 02_文件整理.md + mockup 截图迭代）**：
	- 档案 = 复盘"节点"的落地：文件夹 + 详细数据；管线（剧本/设定/角色…）不硬编码，由用户用档案结构自由拼出，一套机制同服资源库与项目。
	- **弹性层级**：档案馆限深 4，但分类/分组不再区分（mockup 中用户自己摆反证明语义太接近）——合并为"集合 > 中间层 0~2 层（用户自定）> 档案"，角色库可用 3 层、项目可用满 4 层。
	- **chips = 纯筛选器不是层级**：题材维度（古装/军人/通用）横跨各分组，是"标签融管线"中"词"的落地（2026-07-29 用户选 2：打词下沉为节点属性，不建独立标签体系）；chips 只能选不能建，零管理操作。
	- **交互统一（本轮定案）**：集合/中间层/目录树统一"单击 = 选中看内容"（集合 = 全部档案递归平铺、中间层 = 其下档案、目录文件夹 = 其下文件与子文件夹）+ 箭头展开；集合抓手图标删除（类型图标已够区分）；"集合/中间层不作文件落点"是落点约束与单击语义无关；**目录树保留不删**——轻量素材（散图/参考/收件箱落点）不配四层仪式，全档案化只会重新发明"未分类档案"。
	- **项目视图 = 工作空间的档案层**：工作空间 = 实况模式（磁盘树热刷新）+ 项目模式（档案四层）；档案引用两类实体共存——链接图标 = 资源库资产（ID 寻址零拷贝，统一池支撑），五角星 = workspace 磁盘文件（相对路径寻址，原始文件本体）；项目文件（fla/提示词/输出）直接落 workspace 磁盘，**不入 assets 池**（Animate 另存为不该面对 info 路径）；沉淀时才右键导入资源库；断链兜底 = 丢失态 + 重新定位（仅"用户在资源管理器直接动 workspace 文件"一种场景）。
	- **五角星语义（用户澄清）**：素材被链接至其他档案后源文件出现的"我被引用了"标识，无链接不显示——现有 origin Placement 角标演化，反查 Placement 零新成本。
	- **高级重命名**（男人→张三）：现有 Placement 显示名按条独立天然支持，项目档案内链接批量替换显示名即可，不碰资产本体；hover 展示全部链接 = 已关联文件夹反查扩展。
	- **素材级链接落盘（硬链接）**：虚拟节点混工作空间目录与实况索引相冲（热刷新口子/资源管理器黑箱/操作特判），改物理落盘——文件 = NTFS 硬链接（同卷免权限，workspace 与 assets 同空间天然同卷），UI 比对 fileIndex 识别链接打图标；档案文件夹整体物化不推荐（双向同步高耦合），档案视图纯数据层管整理查看，需要时提供"物化到磁盘"动作批量落硬链接。此即 links 稳定层第二用途。
