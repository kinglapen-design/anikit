# 收件箱 RECOVER 撞 hash 终局：自动合并（用户实测后定案 A）

**收件箱 RECOVER 撞 hash 终局：自动合并（用户实测后定案 A）**：RECOVER 是 AN 保存时刻的同内容快照（hash 必然相同）且永远先到——真实文件后入必撞冲突弹窗，选"用已存在"还会让 RECOVER 反客为主成正式资产名。方案：metadata 新增 `importedFrom` 渠道字段（PRD 01/05 已更，"inbox" 标记收件箱资产；segment 的 source 字段语义独立不复用）；inbox 导入撞 hash 且已有资产同渠道 → **静默合并**——内容不重复存，已有资产改名为真实名（磁盘 originName + 词干缩略图 + metadata + origin Placement 唯一化，4.1 重命名语义提前落地），新文件作为重复丢弃，合并发 Asset 事件照常流入收件箱视图；同名纯重复静默丢弃无事件；正式资产（非 inbox）与反向（常规导入撞 inbox 资产）照常弹窗，绝不被自动改名。同批次 twin 不自动合并（顺序不定可能改反方向，留冲突询问——崩溃残留同批到达，少见）。新增 5 用例（合并改名 / 纯重复 / 正式资产门禁 / 反向门禁 / 缩略图联动改名），cargo test 67 过零警告。
