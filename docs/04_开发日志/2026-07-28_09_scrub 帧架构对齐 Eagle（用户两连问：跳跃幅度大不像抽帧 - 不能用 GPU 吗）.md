# scrub 帧架构对齐 Eagle（用户两连问：跳跃幅度大不像抽帧 / 不能用 GPU 吗）

**scrub 帧架构对齐 Eagle（用户两连问：跳跃幅度大不像抽帧 / 不能用 GPU 吗）**：① **GPU 硬解实测否决**——d3d11va 5.2s 反慢于 CPU 全片 3.8s（185s/303MB 实测）：硬解帧在显存，逐帧回拷贝（~16GB）给 scale/编码，一次性抽帧场景无优势，坚持 CPU 全片真解码（关键帧复制无信息增量，跳跃感根源）。② **帧数分档加密**（对齐 Eagle 连贯度）：≤30s 按 4fps、>30s 按 0.5fps（2 秒一帧），8~150 帧封顶（185s → 93 帧，卡片 ~3px/帧）；解码 `-threads 8` 限流防风扇猛转。③ **导入期异步预抽**（Eagle 毫秒级手感的真相 = 帧图提前就绪）：新 `services/scrub_frames.rs`（抽帧核心 + 帧数分档 + 源戳幂等 + running 防重，自 commands/media.rs 迁出）；unpack_queue 扩展 `QueueTask::Scrub`（动图解包与视频预抽共用单 worker 串行，dedup 按类型+资产），import_task register_one 视频（VIDEO_EXTS）挂钩 submit_scrub——解码成本摊到导入期，悬停命中缓存毫秒级；list_video_scrub_frames 改薄壳（ensure：命中直给 / 未命中同步补抽存量与预抽失败 / 重入 pending）。④ 测试：scrub_frame_count 分档（含 185×0.5=92.5 半进 93 断言修正）、cached 戳判定、ensure 防重 pending、队列 dedup 类型区分；命令层 reentrant 用例移服务层。cargo test 170 过零失败、clippy 清零、tsc / build 全绿。
