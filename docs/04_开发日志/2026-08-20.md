### 解码吞吐（CLI，1080p→320p RGBA，50 路 = 卡片并发上限场景）

| 源 | 1 路 | 16 路 | 50 路 |
|---|---|---|---|
| GIF | 170 fps | 1920 fps | 3110 fps（每路 62） |
| H264 | 780 fps | 6600 fps | 7740 fps（每路 155） |

后端解码能力远超 50 卡 × 30fps = 1500fps 需求，瓶颈不在解码。

### 通道对比（Tauri 壳 + canvas，16 路全速）

| 通道 | 总 fps | CPU（32 核机，单核倍数） |
|---|---|---|
| **本地 WS 推（定案）** | **1686** | 1812% |
| invoke 拉（ipc::Response 二进制） | 876 | 1974% |
| custom protocol 拉 | 924 | 2018% |

50 路 WS 全速 GIF：总 2400fps、每路 48fps——50 卡按 30fps 需求仍有 1.6 倍余量。

### 生产语义（pace=1 按源帧率播放，50 路 1080p→320p）

| 场景 | CPU | 每路送达 |
|---|---|---|
| 50 路 GIF（10fps 源） | **17%**（5.3 核） | 9.1/10 fps |
| 50 路 H264（30fps 源） | **29%**（9.2 核） | 25.6/30 fps |

H264 每路顶不满 30 = Windows `std::thread::sleep` 默认粒度 15.6ms（33ms 睡眠实际 ~48ms）。铺量对策：`timeBeginPeriod(1)` 提精度，或节奏权交消费端（帧槽恒持最新帧 + 前端 rAF 取帧）。卡片预览 25.6fps 观感已流畅。

### 边界（铺量须知）

- **动图 webp 不进 ffmpeg 管线**：BtbN lgpl 构建 libwebp 只开 encoder（无 libwebp/libwebp_anim decoder），原生 webp decoder 不认 ANIM/ANMF（demuxer probe 即败）。webp 动图归主线既有 **image-webp** 纯 Rust 解码（services/anim.rs 生产在跑）。ffmpeg 管线管 GIF / 视频 / 其余格式。
- CDP 探针 `spike/decode-proto/cdp-probe.py`：真实 Tauri 壳（WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS 开 CDP 端口）+ psutil 采 CPU；页面 origin 加载完成前是 "null"，须轮询等待再注入参数。

## 阶段四二轮小项：动图卡出帧尺寸跟随卡片显示尺寸（用户定案"随实际大小跟随"）

用户实机走查后定：缩小时视口几十张动图、更小渲染更省；放大后视口动图个位数、跟随放大要清晰。原恒 320 档废除。

- **口径修正（本轮揪出的旧账）**：帧流两桥原实现是"假短边真长边 + 小源放大"——decoder 与 webp 桥都把**长边**钉到 short_edge（注释却写短边），且小尺寸源（如 64×48 gif）会被放大到 320，webp 桥反而缩到 48×36，两桥行为互相矛盾、与缩略图 `shrink_to_edge`（真短边 + 不足不放大）都不一致。本轮三处统一为 `shrink_to_edge` 语义：decoder 缩放公式重写（每帧算目标尺寸），webp 桥直接复用（`shrink_to_edge` 转 pub(crate)，单一实现）。
- **热更新机制（不重启解码、不回第一帧）**：会话级 `AtomicU32` 目标短边——`decode_once` 签名改传 `&AtomicU32` 每帧读取（尺寸变 → scaler 与输出帧重建；**坑：rgb 输出帧旧 buffer 尺寸不符会让 sws_scale 报错丢帧**，重建 scaler 必须一并重置输出帧）；webp 桥每帧读取。新命令 `set_anim_stream_size(session, shortEdge)`（幂等同 stop）；`start_anim_stream` 加 `shortEdge` 参数，clamp [16,1024]。
- **前端**：AnimCanvasLayer 开流时读 `.thumb` 实测短边（canvas 未出帧 display:none 读不到自身尺寸，读父元素；0 兜底 320）；ResizeObserver 监听 `.thumb`，防抖 150ms → `session.setSize()`（缩放布局时跟随）。
- **验证**：cargo test 348 绿（+2：decoder 不足不放大 + 运行期改尺寸、frame_stream set_size 热更新；会话类测试共享全局 sessions 表——stop_all/is_empty 互踩 race，加 TEST_LOCK 串行）；typecheck / build 绿；CDP 探针补场景⑤ PASS（改 7 张可见卡 .thumb 高度 → 7 次 set_anim_stream_size 调用）。07 接口 / PRD 04 同步。
