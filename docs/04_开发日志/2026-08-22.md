### 后端

- **`adapters/decoder.rs`**：`decode_video_once`——视频 AV 同趟解码：**真 seek**（`start_secs>0` → `ictx.seek`（AV_TIME_BASE 微秒，关键帧落点）+ 前向丢帧，帧区间 [pts, pts+delay) 整体在起点前才丢 = 跨点帧精确命中，任意方向同径）；帧 pts = best_effort_timestamp；音轨 best Audio → `resampling::Context` 重采样 48k 立体声 f32 packed → 攒 1024 帧/块回调（块 pts 锚定首样本、按块长累加）。`DecodedFrame` 加 `pts_ms`（gif 桥填趟内累计 delay）。缩放抽 `scale_frame` 共用（gif 老路不动）。坑两枚：`timestamp()` 不回落 pts（单测手造帧须 set_pts，生产解码器恒有 best_effort，代码已加 pts 回落兜底）；**`frame.plane::<f32>()` 长度 = samples() 不含声道数**（ffmpeg-next 语义）——立体声交错只拿到一半，改 `data(0)` + 手工切片（`f32_plane` 助手钉注释）。

## 同日二轮：5.3 性能返修（用户实机四报）

用户实机：① 悬停 scrub 非常卡顿甚至不如以前；② 预览播放画面动不动就卡住、音频还在放；③ 快进/跳进后画面放了 1、2 秒音频才出声；④ 上下帧也差不多等 1 秒。

**根因 = 一轮的视频 seek 是"中止本趟 + 重开整个文件"**（每次 seek/逐帧/循环都要 `format::input` + find_stream_info + 解码器初始化 + 从关键帧前向丢帧解码，长 GOP 视频单次 ~1s 量级）；循环重开同路径 = 周期性接缝卡顿；WS 写路径 MB 级视频帧堵住后续音频块 = 音画错位。

**修法**：
- **decoder 重构为持久 `VideoDecoder`**（open / seek / continue_to / read_frame 拉取模型）：seek = `ictx.seek` + 两解码器 flush + 重采样器重建，**不重开文件**；**相邻前跳 ≤2 帧 = continue_to 续解免 seek**（逐帧步进即时落帧， Decoder 位置 pos_pts_ms 跟踪）；**循环重开 = 就地 seek(0)**；丢帧阶段逐帧可查 interrupt（scrub 拖动不被旧目标拖住，Pull::Interrupted 回顶即处理）。旧 `decode_video_once` 改薄封装收窄 `#[cfg(test)]`（测试继续覆盖同一路径）。
- **frame_stream 视频会话改持久驱动**：run_video_session 持有解码器全程；seek/续解/循环全就地。
- **WS serve_ws 加 biased select**：音频/控制优先于视频帧写（16KB 快写先走，视频帧 watch 语义丢得起）。
- **streamAudio：AudioContext 手势恢复**——无手势创建的 ctx 起步 suspended（独立预览窗口直开即此场景），挂一次性 pointerdown/keydown 捕获监听 resume，恢复前丢块不积压。
- 坑：pull_audio 初版借用冲突（adec 借用横跨 emit_audio_chunk）→ 吃帧限域借用、处理走自由函数 `resample_into` + `emit_chunk`（单测直测）。

**验证**：cargo test **364**（+1：video_decoder_inplace_seek_and_continue——就地 seek/续解/Eof 重开全程）/ typecheck / build 全绿；四探针复跑全 PASS（video-stream / anim-stream / preview-anim / playbar）。07 接口帧流条同步（就地 seek 语义 + biased 音频优先 + VideoDecoder 路由名）。

## 同日三轮：真后端联调与鲁棒性返修（用户实机录屏两连报"毫无改善 + 模糊 + 冻结"）

用户提供了问题录屏（AniKit 侧）与 Eagle 对照录屏（`assets/video/`）。看录屏定症：预览打开后画面**模糊**，播放条数帧后**永久冻结**（停 624/4725），音频仍在放。真后端单元压测（4K120 带音录屏样本）解码/seek 健康（120fps 满节奏、seek 52ms）——问题在交付链与鲁棒性，逐项修：

- **模糊 = 出帧尺寸未计 DPR**：streamEdge 只按 CSS 像素，4K/150% 屏 1.5 倍欠采样。修 = 帧短边 × devicePixelRatio（>2 不追），预览档上限同步收紧 4096→2048（大源高帧率下 WS 吞吐 / putImageData 主线程预算有限）。
- **永久冻结两候选通道全堵**：① seek 后 `flush` 控制消息经广播通道 Lag 丢失 → 前端 videoSeeking 丢帧标记永久卡死——serve_ws Lagged 分支合成 flush 强制重同步 + 前端 1.5s 看门狗自清；② 会话线程解码错误即死、前端无任何信号——新增 `error` 控制消息 + Session.die()（通知前端 + 自清会话表），预览降级报错（播放条禁用）、卡片回退静态封面。
- **高帧率洪泛**：源 >60fps 时隔帧发布（4K120 录屏全量推流 = webview 主线程被 putImageData 压垮的假冻结诱因）；暂停/逐帧定位帧恒发布。
- **音频钟异常自愈**：无头环境（假音频设备 currentTime 跳变）实测帧等钟卡 1s 级间隙——待渲帧等钟加 120ms 墙钟上限，超时强渲，音画偏差封顶。
- **真后端探针 `cdp-video-real-probe.py` + 测试内 harness**（video_stream_harness，#[ignore] 手动）：真 Rust 后端解码真实视频 + WS 推流，探针桩仅替换命令路由（start_video_stream 指 harness 会话；seek/playing/rate/loop/size 经命令文件转发真执行）。实测：连续出帧 66 次/3s 无 >100ms 间隙（不冻结）、seek 90% 端到端 737ms（含 ~100ms 命令轮询与无头环境损耗；后端本体 52ms）、seek 后续播、暂停恢复命令直达真后端。踩坑：探针后台协程并发 evaluate 同 CDP 连接会互吃响应（改主流程同步转发）；harness/探针共享状态文件的删除竞态（先清再启）。
- 附带基建修正：serve_ws / frame_bytes / audio_bytes 摘除 cfg(not(test))（纯 tokio/tungstenite 无 AppHandle——踩坑 014 门控只罩 init），测试/harness 可用真 WS 服务。
