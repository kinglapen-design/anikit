- **3.4 复核一轮 + 批量删除文件夹 BUG 修复（feat/new-ui，用户报"批量删除文件夹只删除一个"）**：
  - **根因**：右键菜单「删除文件夹」只传被右键的一项（folderCardSpec / treeItemSpec / archiveCardSpec → `deleteFolderFlow(folder.id)`），完全不看文件夹多选域 `selectedFolders`；Delete 键只接素材域（`useGlobalKeys` 读 `selectedRefs()`），多选文件夹按 Delete 无反应；后端只有单个 `delete_folder` 命令。
  - **后端**：`purge::delete_folders`（仅非 permanent 形态）——存在性过滤 + 保序去重 → **祖先同批入选的后代剔除**（parent 链上溯命中集合即后代）→ 并集子树一趟改完只 `finish` 一次；陈旧 id 容错，全部不存在才报错；`delete_folder` 非 permanent 分支委托同函数（单例 = 批量特例，永久分支不动）。命令 `delete_folders(folderIds)` 接撤销三步——**单撤销步**，标签 1 个 = "删除文件夹 {name}" / 多个 = "删除 N 个文件夹"。
  - **前端**：`placementOps.deleteFolders`（报告聚合 toast 同单删口径）；`menuOps.deleteFolderFlow` 批量分流（触发项在多选域且 size>1 → `deleteFoldersFlow(orderedSelectedFolderIds())`，确认文案"已选中的 N 个文件夹将被删除…"）+ 新 `deleteFoldersFlow`（键盘入口统一走它，单元素回退单删文案）；`useGlobalKeys` Delete 加文件夹域分流（优先于素材域，两域互斥）。菜单 spec 零改动（分流在流程层）。
