# 同日二轮：5.3 性能返修（用户实机四报）


用户实机：① 悬停 scrub 非常卡顿甚至不如以前；② 预览播放画面动不动就卡住、音频还在放；③ 快进/跳进后画面放了 1、2 秒音频才出声；④ 上下帧也差不多等 1 秒。

**根因 = 一轮的视频 seek 是"中止本趟 + 重开整个文件"**（每次 seek/逐帧/循环都要 `format::input` + find_stream_info + 解码器初始化 + 从关键帧前向丢帧解码，长 GOP 视频单次 ~1s 量级）；循环重开同路径 = 周期性接缝卡顿；WS 写路径 MB 级视频帧堵住后续音频块 = 音画错位。

**修法**：
- **decoder 重构为持久 `VideoDecoder`**（open / seek / continue_to / read_frame 拉取模型）：seek = `ictx.seek` + 两解码器 flush + 重采样器重建，**不重开文件**；**相邻前跳 ≤2 帧 = continue_to 续解免 seek**（逐帧步进即时落帧， Decoder 位置 pos_pts_ms 跟踪）；**循环重开 = 就地 seek(0)**；丢帧阶段逐帧可查 interrupt（scrub 拖动不被旧目标拖住，Pull::Interrupted 回顶即处理）。旧 `decode_video_once` 改薄封装收窄 `#[cfg(test)]`（测试继续覆盖同一路径）。
- **frame_stream 视频会话改持久驱动**：run_video_session 持有解码器全程；seek/续解/循环全就地。
- **WS serve_ws 加 biased select**：音频/控制优先于视频帧写（16KB 快写先走，视频帧 watch 语义丢得起）。
- **streamAudio：AudioContext 手势恢复**——无手势创建的 ctx 起步 suspended（独立预览窗口直开即此场景），挂一次性 pointerdown/keydown 捕获监听 resume，恢复前丢块不积压。
- 坑：pull_audio 初版借用冲突（adec 借用横跨 emit_audio_chunk）→ 吃帧限域借用、处理走自由函数 `resample_into` + `emit_chunk`（单测直测）。

**验证**：cargo test **364**（+1：video_decoder_inplace_seek_and_continue——就地 seek/续解/Eof 重开全程）/ typecheck / build 全绿；四探针复跑全 PASS（video-stream / anim-stream / preview-anim / playbar）。07 接口帧流条同步（就地 seek 语义 + biased 音频优先 + VideoDecoder 路由名）。
