# 5.4 二轮：布局跟缩略图走 + 假扩展名解码修复（用户实机两报）


- **报①**：选择文件 / 剪贴板新设的缩略图被卡片旧比例 cover 裁剪——布局比例数据源是 meta.width/height（源文件尺寸），自定义缩略图后不跟随。
  - **口径（用户定）**：自定义缩略图要符合自适应布局和瀑布流，**但元数据尺寸不动**（width/height 恒为源文件尺寸，详情显示与排序语义不变）；「刷新缩略图」即可回退（从 origin 重生成 → 尺寸字段回到 origin 比例）。
  - **修法**：AssetMeta 加 `thumb_width/thumb_height`（serde default + skip_none 不升 DATA_VERSION）——缩略图实际像素尺寸，布局比例专用；`thumbnail::generate` 改返回 `ThumbOut{name,width,height}`，五处生成点全刷新（导入 / 设封面帧 thumb_frame / 缩略图三件套 asset_menu / 序列帧打包 sequence / 删帧封面重建 operations/sequence）。前端 PlacementView 加 thumbW/thumbH（views.rs 装配），useGridLayout 回退链 `thumbW → w → 300`（存量数据 null → 回退源尺寸，比例一致无感知）；set_thumb_frame / set_video_thumb 返回加 thumbWidth/thumbHeight，preview.ts / previewMedia.ts 局部同步（布局即时跟随，与 modifiedAt 版本戳同径）；三件套走 content.refresh() 全量无需返回。
- **报②**："有的 PNG 格式不支持"——样本 `【哲风壁纸】动漫-小黑猫-治愈.png` 魔数 FFD8FF 实为 JPEG（壁纸站假扩展名）。image crate 0.25 按扩展名预设解码格式 → InvalidSignature（踩坑 052）。`thumbnail::probe` / `load_origin` 改**按内容魔数识别**（probe_by_signature / decode_by_signature），导入与缩略图三件套同愈。
- **验证**：回归用例 `fake_extension_decodes_by_content_signature`（JPEG 内容 + .png 扩展名）+ ThumbOut 尺寸断言改写三处；**用户真实样本实测通过**（4096×2304 → 568×320，一次性探针跑完即删）。cargo test 365 绿（+1）/ typecheck / build 绿。
- **事故自省**：排障中临时探针用 python `open(p,"wb")` 先截断后写抛错，致 thumbnail.rs 被清空——git show 恢复 HEAD 版 + 重放全部改动救回；教训 = python 写文件先内存构造完整内容再一次落盘（07 接口文档本轮同步已按此执行）。
- **同步**：PRD 04-03 条 5 补布局口径 + 解码口径 / 07 接口（PlacementView.thumbW/thumbH、三件套尺寸刷新、SetThumbResult 尺寸字段）/ 踩坑 052。
- **待用户实机复验**：自定义缩略图（含该假 PNG）→ 卡片比例即时自适应；刷新缩略图 → 比例回退。
