# 阶段五前 BUG 补修："全部"视图导入后中间插入（用户实机报）


- **根因**：`add_placement_impl` 写存储序（folders.json items）时按**目标文件夹段首 + 批内偏移**定位——文件夹视图读 `placements_by_folder` 索引（段首前插，语义正确）不受影响；但"全部"视图直接按 `folders.items` 顺序展示（`placement_views` None 分支），目标文件夹段不在 items 头部时，新项插到段首 = 全部视图中间。流式期间前端 importAnchor=0 前插正常，finished 后 refresh 全量对齐即被拉回段位。
- **修法（import.rs，一处）**：items 插入位改**全局前插** = 本批此前已插总数（`front_anchor.values().sum()`——异文件夹混批也按到达序从头部依次后移，单用 per-folder 锚点会同位点反复插入致批内翻转）；`placements_by_folder` 索引维持锚点前插，文件夹视图语义不变。新批次锚点清零、整批排在旧批次之前。新建文档 / 链接 / 冲突"保留两个"等同走 add_placement 的路径一并受益。
- **回归测试**：新增 `add_placement_all_view_front_regardless_of_segment_position`（段在中间场景：批1 FY → 批2 FX 挤后 → 批3 FY 应排全部视图最前 + 混批全局保序）；既有 `add_placement_inserts_front_with_batch_order` 断言不受影响。
- **回收站显示名口径（用户定）**：不做 origin 优先等特殊对待——回收站只是普通视口，被删位置叫什么名就显示什么名（链接进回收站即显示链接名）。`list_recycle_desc_and_pseudo_fields` 断言适配新顺序（快照按 items 正序收集，第一条 = 全局前插后的头部项），实现不动。PRD 02-13 补此条。
- **环境两坑**：① 用户 dev 起不来 = cargo 增量缓存错乱 LNK2019（anon 符号对不上，疑 cargo test 与 dev watcher 并发踩踏 target）——`rm -rf target/debug/incremental` 45s 重编即过（踩坑 033 补录轻量解法）；② 重跑 dev 报 5373 占用 = 上次失败退出后 vite 孤儿残留——netstat/taskkill 清理（新踩坑 045）。
- **验证**：cargo test --lib 348 全绿（+1 新用例）。
- **文档**：PRD 04-06 新增区条文补"存储序前插修订" / PRD 02-13 回收站显示名口径 / 踩坑 033 补 + 045 新增。
