	- `list_recycle() -> RecycleEntryView[]` —— 回收站视图，deletedAt 倒序；`RecycleEntryView = PlacementView（flatten，name 取 placements[0].name 或资产名，folderId 恒 "recycle" 伪值、origin 恒 false）+ deletedAt + placementCount`
	- `restore_recycle(assetIds: string[]) -> number` —— 还原：Placement 写回 folders.json（目标文件夹已删挂 root、**显示名原样写回不唯一化**——2026-08-19 撞名放开、段尾追加 order 重写连续）+ 回收站条目移除。撤销标签"还原 N 个项目"
	- `delete_recycle(assetIds: string[], confirmed: boolean) -> { needConfirm, segmentRefs, linkRefs, deleted }` —— 彻底删除两段式（**2026-08-19 位置级模型分级**）：**快照含 origin 的条目 = 资产本体在回收站** → 物理删 `{ID}.info` + 库内该资产全部活位置（含链接）随清 + index / recycle / recent / pins 同步；**纯链接位置记录（无 origin 快照）= 只删回收站条目**，物理不动、无需确认。needConfirm 拦截条件 = 本体将删且有虚拟片段引用（segmentRefs）**或有库内活链接（linkRefs，提示"其关联的 N 条链接将一并清除"）**；确认前 backup_library 兜底。**半途失败口径（2026-09-02 资产污染修复）**：物理删除逐个执行、失败收集名单不中断——失败项回收站条目**保留**（可关闭占用程序后重试），成功项照常同步，报错含名单。**无撤销（不可逆）**
	- `clear_recycle(confirmed: boolean) -> 同上` —— 清空回收站（等价全量 delete_recycle，segmentRefs / linkRefs 汇总）
