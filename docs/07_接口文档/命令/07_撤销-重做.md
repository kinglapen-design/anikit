# 撤销 / 重做（6.0 地基，2026-07-28 落地）：

**撤销 / 重做（6.0 地基，2026-07-28 落地）：** 会话级双栈（core/undo.rs，上限 50 步，库切换清空，不持久化——与 Eagle 一致）；UndoEntry = 操作标签 + 受影响数据文件操作前 / 后快照 + 磁盘逆操作清单（DiskOp 枚举成对：撤销 / 重做，随 6.1 各命令接入）；**快照注入点 = 各数据文件单一写点**——写操作命令按 `begin(标签)` → 写点前 `record_file(路径)`（同路径去重记首次）→ `commit()`（抓 after 快照入栈、清空 redo）三步接入；回滚 = 磁盘逆操作（逆序）+ 快照原子写回（json_io::write_text_atomic，version 随原文恢复门禁天然合法），随后 library::reload 重读全部数据文件 + 重建内存索引（盘上是事实来源，前端全量 refresh）
	- `undo() -> string` —— 撤销一步，返回操作标签（通知条文案用）；回滚成功才出栈（失败栈不动）；空栈报错"没有可撤销的操作"
	- `redo() -> string` —— 重做一步；空栈报错"没有可重做的操作"
	- `get_undo_state() -> UndoState` —— 栈状态（菜单置灰用）；`UndoState = { canUndo, canRedo, undoLabel, redoLabel }`，未打开库 = 双空
	- 前端：Ctrl+Z / Ctrl+Shift+Z（输入框 / textarea / contentEditable 内不拦截，保留文本编辑自身撤销）；结果经**通知条**（ToastStack，样式见 figma-css 01_组件/07_通知栏）反馈"已撤销 / 已重做：{标签}"并带反向动作按钮；库切换经 activate 清空双栈
	- **6.1 配套扩展（2026-07-28）**：apply_disk 支持目录递归——DiskOp::Delete 对目录走 remove_dir_all、Copy 递归复制整目录（duplicate 副本撤销 / 重做需要整 info 目录粒度）；core/library.rs 新增 save_recycle 写点（recycle.json，删除两段式"移入回收站"落点）
