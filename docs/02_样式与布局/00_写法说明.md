# 00_写法说明（格式参考）

> 给写文档的人看的格式约定。照着写，我就能机械地转成 tokens.json + CSS 变量。

## 1. 分工（组件该不该写在这里）

- **01_样式 token.md**：颜色、文字、线框、间距、圆角、图标 + **通用组件的样式规则**（按钮、item 这类到处复用的"零件"）。
- **02_组件布局.md**：具体窗口/面板的容器布局（尺寸、内边距、子项间距）。
- **Figma 已画好的页面以 Figma 为准**，md 里不用重画细节，只写 Figma 里没有的规则。

## 2. 基础 token（01-06 节）——照现在的写法就行

一行一个：`名称：值（用途）`，无需改动。

## 3. 组件写法：常态写全，状态只写差异（不要嵌套层级）

每个组件一段，**常态写完整，其他状态只写和常态不一样的属性**，一行一个状态：

``` text
#### 图标按钮-无底色（示例）

- 常态：图标 c4-70 / 底色 无 / 边框 无 / 圆角 6 / 内边距 6（图标大=28×28）或 4（图标小=24×24）
- 悬停：底色 c4-07
- 点击：底色 c4-15
```

嵌套容器（如文件树 item）也只写每层的关键属性，状态同样只写差异：

``` text
#### 文件树 item（示例）

- 结构：展开按钮(图标 8px, c4-40) + 内容容器(内边距 4, 圆角 6, 子项间距自适应最小 6) → 基础 item + 数量标签(副文本, c4-40)
- 悬停：内容容器底色 c4-07
- 选中：内容容器底色 c4-15；装饰图标线条 c4-100；数量标签 c4-100
```

## 4. 颜色速记（写 md 用左边，我转 JSON 用右边）

| 你的写法 | 代码变量 |
| --- | --- |
| 通用色-1 | `--c1` |
| 通用色-2 | `--c2` |
| 通用色-3 | `--c3` |
| 通用色-4 | `--c4` |
| 通用色-4：70% 透明度 | `--c4-70`（即 c4 的 70% 不透明） |
| 品牌色-1 | `--brand-1` |

md 里继续写"通用色-4：70% 透明度"也行，我会按同一规则转换；图省事直接写 c4-70 也行。

## 5. 布局文件写法

每个容器一段，属性一行写完：

``` text
## 左侧边栏
- 尺寸：250 × 填充拉伸（拆分条调宽）
- 圆角 6 / 内边距 4 / 子项间距 0 / 颜色 c3 / 边框 1px c4-15
- 结构备注：文件树展开图标竖向对齐，子项左边距统一留位
```

## 6. 间距约定（设计与工程一致）

**一律使用内边距 + 子项间距（gap），不使用外边距（margin）。** Figma 无外边距的设计方式与现代 CSS 工程实践一致：组件不带 margin，间距由父容器用 gap / 内边距统一控制，避免 margin 塌陷与组件间间距污染。

**四边边距的写法顺序：上、右、下、左**（从上面开始顺时针，与 CSS `padding: 上 右 下 左` 一致，转换零翻译）。能简写就简写：四边相同写一个数（`内边距 8`）；上下、左右分别相同写两个（`内边距 上下8 左右12`）；都不一样才写四个。

需要由我翻译的设计↔工程差异（会个案记录在开发日志）：填充可拉伸 → flex/grid 弹性、绝对定位元素（滚动条、角标）、文字行高的字体渲染差异。

## 7. 图标 SVG 约定

- **Figma 导出时线条保持"描边"属性，不要轮廓化（Outline stroke）**——轮廓化后 SVG 全是 fill，CSS 无法区分线条与填充。
- 本项目的图标配色均为"同色不同透明度"（如线条 c4-40、填充 c4-07），统一做法：SVG 内使用 `currentColor`，透明度烘死在 SVG 属性里（线条 `stroke-opacity`、填充 `fill-opacity`）；CSS 只控制 `color` 一个变量，常态 / 悬停 / 选中改 color 即可，图标文件不动。
- 若未来需要真正的双色图标（如品牌色），退回用属性选择器 `[stroke]` / `[fill]` 分别控制。
- 需要换配色的 SVG（如文件夹卡片）：颜色写 CSS 变量（`var(--folder-card-back)` 等），且**必须内联使用**（`<img>` 引入的 SVG 读不到页面变量）。
- SVG 文件名可用中文命名，交付后由我统一改为英文 kebab-case，并维护中英文对照表。
