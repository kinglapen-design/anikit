## 01. 区块

允许用户自定义新增、删除区块，为区块命名，设置区块文件夹的默认图标。点击菜单栏的区块管理图标进入区块管理界面：

- 允许上下排序，且允许在侧边栏视图里拖拽排序。
- 允许自定义区块名称。
- 允许自定义区块默认图标——影响新建文件夹时 item 的默认图标，后续用户可对单个文件夹更改图标。
- **默认区块为「目录」，不允许删除、名称与图标不可改（可参与排序，2026-08-14 用户定）**：当用户停留在档案、全部、未分类等无法导入文件夹的视图时，选择导入文件夹并保留层级后，「目录」就是自动存放该导入文件夹的地方。
- 删除区块时，若区块内有文件夹则弹出警告窗口（26 稿 alert warning）；**确认后区块内顶级文件夹带子树移入「目录」区块根级（2026-08-14 用户定）**——不摧毁用户层级；原"文件去到未分类"文案作废。
- **数据口径（2026-08-14 落地）**：区块表存 folders.json `blocks`（`{id, name, icon, order}`，默认区块 id = "dir"）；顶级文件夹以 `Folder.block` 归属区块（None = 「目录」），`Folder.icon` 记新建时继承的区块默认图标（单文件夹改图标 / 颜色随 3.3）；未分类（Placement 根级）语义上属「目录」区块根级，无数据变化。区块管理弹窗（30 稿）= 草稿式一次提交（`apply_block_changes`，一步撤销）；侧栏区块标题可拖拽排序（`reorder_blocks`）、文件夹拖到区块标题 = 移入该区块根级。

导出资源库到本地时，不同区块物化为平行的兄弟文件夹：

``` text
- 项目
	- 吃鸡天赋树
- 档案
	- 角色
		- 男主角
		- ...
	- 场景
	- ...
- 目录
	- 男人
	- ...
```

## 02. 文件树整理

通过修改数据文件实现文件的层级和信息管理等，而非频繁的真实移动文件。

- **自定义排序：** 支持拖拽排序文件夹与文件，顺序写入 folders.json 的 order 字段，仅改数据不动磁盘，保证响应流畅。
- **区块根目录视觉（2026-08-04 定）：** 区块根目录下的父级文件夹用底色区分，未自定义颜色时默认灰色；文件夹从其他层级拖至区块根目录下时，自动变为带灰色底色的默认 item；父级被设置颜色后，其子项全部变为父级颜色的 10% 作为底色；设置父级 item 图标时，允许勾选影响范围至全部子级，统一换图标。
- **自定义图标颜色：** 文件夹可自定义图标颜色用于分类识别，一处改色多处生效——文件树的图标、缩进线、右侧详情面板的关联文件夹列表；颜色值存于 folders.json 对应节点。
- **封闭式专属：** 文件树整理、区块、档案、分组、标注、多文件夹关联均为封闭式资源库专属功能（注释 / 描述降级后置见 06，评分移出 MVP 见 08）；索引式工作空间仅按真实磁盘结构显示，不支持自定义排序，磁盘与 UI 双向热刷新。

## 03. 档案文件夹

档案 = 文件夹 + 详细数据（数据项见 [[03_数据链接]]），是复盘"节点式管理"的落地形态。对文件夹右键可转换为档案，也可直接新建档案；档案享有和文件一样的数据配置；档案徽标可自定义设置或隐藏。

- **层级约束：** 档案文件夹内不允许出现子级文件夹；右键转换时若文件夹内有子级，提醒用户剔除层级导入。
- **树内形态：** 档案 item 可在目录树内出现，但无展开箭头、下无子级，图标强制切换为档案专属图标 + 品牌紫色圆圈装饰。
- **拖拽规则：** 目录树拖拽文件夹时，档案不允许作为父级并入，仅支持排序；仅纯文件（多选时不包含文件夹）才允许拖入档案。
- **中间面板：** 展示分为文件夹 / 档案 / 文件三个区域。
- **回收站语义（档案当单个文件看待）：** 档案删除移入回收站时保持档案状态（剔除层级是对常规文件夹的处理），允许一键恢复；被删除的文件夹内包含档案时，档案同样保持封装状态。注：序列帧移入回收站时同样保持封装打包状态（既有实现天然满足）。
- **卡片：** 固定长宽比，缩略图默认索引子项第一张图片网格填充铺满；用户可在档案里设置头像——头像即档案封面，二者同步（见 [[03_数据链接]] 03）。
- **档案内视图：** 进入档案后，在中间面板与左侧边栏之间插入二级侧边栏显示档案数据；右侧正常显示文件。

## 04. 分组

档案与普通文件夹通用的内容区组织能力（功能来源参考 Windows 资源管理器分组，支持自定义），工具栏分组图标点击进入分组设置。

- **未分组：** 新拖入的文件默认放入未分组；设置自动分组后，进入的文件按规则自动归组（如开启扩展名分组，fla 文件默认进 FLA 组）。
- **自定义规则：** 扩展名（检测全部扩展名供多选）/ 类型（文本 / 图片 / 文档 / 视频，供多选）/ 名称（输入分词，AND 逻辑）/ 添加日期 / 修改日期（日期分档互斥：今天 / 昨天 / 本周早些时候 / 上周 / 本月早些时候 / 更早——一个文件只出现一次，2026-08-04 定）。
- **规则冲突处理（2026-08-04 定）：**
	1. 两个组规则与范围完全相同时，弹出报错，禁止保存；
	2. 单规则组之间互斥——组二选择已被组一占用的扩展名 / 类型 / 日期时，该项自动从组一转移至组二，并 toast 明确告知（确认前取消则全部恢复）；
	3. 多规则组合允许重叠，文件优先进入命中条件更多的组（如组一 = fla、组二 = fla + 名称"雪牧"，则含"雪牧"的 fla 归组二）；命中数相同的平局按分组定义顺序，先建者优先。
- **AI 写规则：** 后续版本可指派 AI 生成规则，解放手动输入（见 11）。

用户可对文件夹添加描述，可对文件进行注释。

- **数据归属：** 文件夹描述存 folders.json 的 note 字段，文件注释存 metadata.json 的 note 字段；功能就位后纳入分词搜索范围。

## 07. 标注

这是一个对于动画师来说比较重要的功能，让用户可以在图片、动图、视频上创建多个画框来进行标注。

示例1：用户在一张打篮球的图片上，创建画框框选住篮球，然后为画框取名为篮球。
示例2：用户在动图或者视频上创建画框，逐帧绘制视频内运动对象的轨迹和压缩与拉伸的状态，来观察动画，方便动画师参考和创作，允许用户额外保存一份记录了标注的副本，导入至动画软件进行绘制参考。

- **数据归属：** 标注存于资源 info 文件夹内独立的 annotation.json，每条标注 = 帧号/时间戳 + 画框坐标 + 名称，随资源一并删除与备份。
- **搜索：** 标注名称纳入分词搜索范围，搜"篮球"可命中对应图片。
- **版本规划：** 静态图片的单帧标注进入 MVP；动图、视频的逐帧标注（轨迹、压缩与拉伸的关键帧绘制）列为后续版本。

## 09. 链接

可为素材添加链接，点击链接可打开浏览器跳转，允许添加 ID 路径：`anikit://item/{ID}`，来进行点击后软件内跳转。

ID 寻址还允许添加给外部软件使用，如给 Obsidian 等软件作为图片附件，点击后打开 AniKit 跳转至图片界面。

- **数据归属：** 链接列表存于 metadata.json 的 links 数组，纳入分词搜索范围（匹配前 URL decode，见 [[03_查找文件]]）。
- **技术前提：** `anikit://` 需在安装时向系统注册协议处理（Windows 注册表 / macOS Info.plist）；软件未启动时点击协议链接，先启动再跳转至对应资源。

## 10. 多文件夹关联

允许同一文件以不同名称出现在多个文件夹，提供两种选项：

- **链接：** 同一资源 ID 出现在多个文件夹，各文件夹内可自定义显示名称，零磁盘开销，重新生成缩略图等操作处处生效。
- **副本：** 物理复制为全新资源（新 ID），从此完全独立，互不影响。
- **导入查重：** 导入与已有资源 hash 相同的文件时，弹窗询问"建立链接 / 仍导入副本"。

数据规则（改名作用域、删除语义、反查关联、链接寻址、搜索命中）详见 [[01_资源与数据]]。被链接引用的源文件在卡片上显示标识（五角星），hover 展示该文件的全部链接位置。

## 11. AI 智能分类

允许用户配置规则或者直接与大模型对话，让大模型进行资产分类，这项功能的前提是，将 AniKit 的功能，包括基础操作都抽象成接口，让 AI 能从底层操控软件。还需要向量库的帮助，让 AI 可以搭配向量数据，进行文件分类，减少 token 消耗。分组规则同样可由 AI 生成（见 04）。

## 13. 基础操作

#### 封闭式资源库（仅改数据，不动磁盘）

- **撤销 / 重做（Ctrl+Z / Ctrl+Shift+Z）：** 一切写操作可逆——会话级双栈（上限 50 步，切库清空，不持久化），每步记录受影响数据文件的操作前快照与磁盘逆操作，逐步撤销逐步重做（机制见 [[05_项目进度]] 阶段 6.0）。
- **拖拽排序：** 拖拽调整顺序，写入 Placement 的 order 字段。落点视觉统一为品牌色-1（2026-07-28 定）：文件树 item 高度三等分——上下 1/3 判定为排序（显示插入线 + item hover 背景），中间 1/3 判定为并入（item 底 = 品牌色-1 12% 填充 + 1px 边框）；卡片排序落点 = 品牌色-1 12% 填充 + 1px 边框的**圆角竖向矩形色块填满卡片间距**，拖到文件夹卡片上 = 并入（刚好覆盖缩略图区域的方形覆盖，同配色）。**文件夹卡片与素材卡片排序不混排。**
- **拖拽移动 / 剪切（Ctrl+X）+ 粘贴（Ctrl+V）：** 移动 Placement 至目标文件夹；**素材、档案、文件夹均支持剪切粘贴（2026-08-04 修订——剪切 = 移动，三种实体全通；原"剪贴板移动仅素材"作废）**，文件夹剪切粘贴复用 move_folders 护栏（禁止移入自身或子文件夹、粘贴时源失效则 toast 提示）；剪切期间源项半透明（--opacity-cut）。快速访问项是数据自动分类视图，**不可作为拖拽落点与粘贴目标**；档案不接收文件夹（无子文件夹约束）。
- **粘贴三键（2026-08-04 定案，取代原"Ctrl+C/V 必弹关联窗"）：** **Ctrl+V = 作为链接粘贴**（静默执行，显示名默认取源名；同文件夹重复链接放开，显示名自动唯一化——2026-08-13 用户定：不替用户做整理决定，原"同资产同文件夹只允许一条链接 + 重复粘贴去重 toast"作废）；**Ctrl+Shift+V = 作为链接粘贴并重命名**——弹「选择性粘贴」清单弹窗（沿用 2026-07-28 草图）：每行一个素材，源（缩略图 + 所在文件夹 + 文件名）→ 目标（目标文件夹 + 文件名输入框，默认填源文件名全选态）；行尾「关联 / 副本」互斥单选（默认关联）+ ×（踢出该行）；确认一次执行，取消全部放弃，多选不逐个弹窗；**Ctrl+Alt+V = 作为副本粘贴**——物理复制生成新 ID，不弹窗直接执行，名称与源一致。**Ctrl + 拖拽落文件夹 = 直接建链接不弹窗**（与 Ctrl+V 同语义）。右键菜单露出三个粘贴项。
- **新建文件夹（2026-07-28 定）：** 侧栏「文件夹」副标题添加按钮 = 新建当前选中文件夹的兄弟（插到其下一行；侧栏恒有选中项，选中快速访问项时插到根级最底部）；右键菜单「新建同级文件夹 / 新建子文件夹」——均不用模态框，直接创建并进入名称输入态；对 item 触发插到其下一行，空白处触发建到最底部。
- **重命名（F2 / 右键菜单）：** 非模态——标题就地变为输入框（卡片与文件树 item 同）；重命名**原始 Placement** 时，同步将磁盘上的 originName（含词干缩略图等伴生文件）一并改名，失败中文报错并整体回滚（2026-07-28 修订为同步语义——配合撤销机制天然可逆；原"先改显示名、后台空闲时异步执行 + 启动自愈"队列方案降级留待，日后遇 Animate 占用致改名失败场景再评估）；重命名**链接 Placement** 仅改显示名（数据规则详见 [[01_资源与数据]]）。
- **克隆文件夹：** 弹窗提供两个选项——**链接克隆：** 仅克隆文件夹节点与全部 Placement（链接指向原资源），零磁盘开销；**复制克隆：** 同时物理复制全部资源（各自生成新 ID）。均命名为"xx 副本"。
- **创建副本（Ctrl+D）：** 就地创建副本（当前位置生成新 ID），完全独立。
- **复制 base64（右键菜单"复制数据"）：** 静态图片（png / jpg / jpeg / bmp / webp / gif）复制原文件字节 base64（≤10MB）；**psd / psb / svg 复制解码后 PNG 的 base64（2026-08-14 用户定）**——合成图解码 → 长边 ≤4096（复用全尺寸预览口径）→ PNG 编码 ≤10MB，贴给 AI / 网页可用（原字节 PSD 对方不认，且 123MB 级文件编码无意义）；其余格式不支持（toast 提示）。返回纯 base64，不带 data: 前缀。
- **删除（Del）：** 删除当前 Placement；最后一条 Placement 被删除时直接移入回收站（不询问，2026-07-29 用户修订，详见 [[01_资源与数据]]）。**菜单文案按语义分流（2026-08-04 定）：** 存在多条 Placement 时仅显示「从文件夹中移除」（仅删当前位置记录，可撤销），仅剩最后一条时显示「丢到回收站」；删除链接不进回收站（资产本体未动），撤销可找回。

#### 索引式工作空间（真实磁盘操作）

- 复制、剪切、粘贴、重命名直接操作磁盘文件，配合双向热刷新。
- 不支持拖拽排序、克隆文件夹、建立链接（无 Placement 数据）。

## 14. 批量编辑

多选后，基础操作自动转为批量执行，是快速移动整理文件的手段：

- **批量复制 / 剪切 / 粘贴：** 对多个 Placement 批量执行，语义同 13（粘贴可选链接或副本）。
- **批量创建副本：** 批量物理复制，各自生成新 ID。
- **批量克隆文件夹：** 多选文件夹时可用，同样提供"链接克隆 / 复制克隆"选项。
- **批量重命名：** 单个「批量重命名」弹窗（2026-08-04 设计定稿，查找替换不单设入口）：底部分段选择器切换模式（**序号命名** / **替换命名**，同一时刻只显示当前模式的一行输入；后续扩展规则——前后缀、去括号等——加页签）——序号命名 = 名称 + 起始编号，位宽自动按选中数量决定（<100 两位、≥100 三位）；替换命名 = 查找文本 + 替换为（纯文本，MVP 不做正则）。规则只作用**词干**，扩展名不动。新名称列 = **实时预览**（只读，输入即刷新，无"应用"按钮；逐行手动微调不做，确认后单独 F2）。撞名不拦截（显示名放开，见 [[01_资源与数据]] 边界规则 7）。执行 = 逐条改名（链接仅改显示名 / 原始同步改磁盘 originName），**失败项（如被动画软件占用）跳过并在结果中汇总报告，不整体回滚**。
- **批量删除：** 删除语义同 10。

## 15. 快速访问视图（2026-08-04 定案）

全部 / 未分类 / 最近使用 / 自动导入 / 缩略图 / 回收站统称**快速访问**——数据自动归类的只读视图，不可作为拖拽落点与粘贴目标。

- ~~资产级去重~~（**2026-08-13 用户定案废除**：不替用户做整理决定——快速访问视图按实际 Placement 显示，链接不再隐藏，侧栏计数同口径；原"按资产显示一次只显原始 Placement"作废）。
- **候车区（未分类 / 自动导入）：** 只是临时落点，**不做内容限制**（2026-08-13 用户定案）——链接允许从任意资产发起、允许落在未分类，同文件夹允许重复链接；怎么整理是用户的事。原"只收原始文件 + 发起端/落点双护栏 + 文件夹选择弹窗无未分类项 + 开库剔除 root 链接"整体废除；"移出根目录即摘标"、"快速访问不作拖拽落点与粘贴目标"的交互规则不变。
- **删除文件夹时的链接去向（2026-08-12 定案）：** 删除文件夹时子树原始 Placement 回未分类（不变），链接 Placement 随文件夹直接删除——链接删除不进回收站，链接存在时资产必有原始 Placement 在别处或同批回未分类，不会凭空丢资产。
- **缩略图视图（hidden 资产）：** 图片被设为工程 / 档案的缩略图后打 hidden 标记——**不复制、不搬迁、不删链接**：所有视图统一过滤 hidden 资产，其在各文件夹的链接位置自动从视图消失；缩略图视图按资产显示一次并标注绑定的工程；**一个资产可绑定多个工程**（thumbAssetId 引用不受 hidden 影响）；「还原为素材」取消 hidden 后所有链接位置原样恢复。工程更换缩略图后，旧缩略图资产可「解除缩略图」（回未分类）或删除。
