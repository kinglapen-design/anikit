## 01. 导入素材

很多用户吐槽 eagle 的原因是，他们自己整理好的素材拖入到 eagle 就被打乱了，虽然 eagle 有导入文件夹的选项，但功能藏得很深。还有 eagle 会强制复制一份，增加磁盘压力。

我们提供导入文件、导入文件夹两个选项，均支持菜单触发与拖拽触发。

- **导入位置：** 导入文件直接导入至当前视口停留的目录；导入文件夹直接导入至根目录；拖拽至文件树某个文件夹上时，导入至该文件夹。
- **导入弹窗：** 两组选项 + 确认，而非四个互斥按钮——
	- 结构（仅导入文件夹时）：保留层级 / 剔除层级递归导入；
	- 来源：复制 / 剪切。
- **剪切导入：** 物理移动文件进 info 文件夹，源位置不再保留，弹窗文案必须明示"源文件将被移走"。
- **剪贴板导入：** 支持直接粘贴剪贴板内容导入（如截图），无需先保存到本地再拖入；默认存为 PNG，以时间戳自动命名（如 剪贴板-20260717-1718.png），重名追加 -序号。
- **收件箱 Inbox（工作中素材/模板快速入口）：** 库内设独立 Inbox 目录，解决封闭库"先存磁盘、再拖入、再删源文件"的繁琐。**2026-07-25 修订：Inbox 不是工程收纳器，不再对一切文件自动过境**——工程文件（fla / aep 等，含"一段表演单独存下来"的素材模板工程）不支持自动导入；自动入库对象收窄为**白名单可视素材格式**（当前 = 4.2 可出缩略图口径 + 视频 mp4 / mov / avi / mpeg4 / m4v + 音频 mp3 / wav / wma：png / jpg / jpeg / bmp / webp / gif / psd / psb / svg / ai / mp4 / mov / avi / mpeg4 / m4v / mp3 / wav / wma；音频于 5.1 波形/元数据就位后扩入，2026-07-26）。**不反向枚举工程格式**（枚举不完）；白名单以外一律不自动导入，只作磁盘实况展示。工程文件自动转移有两条硬伤：占用期物理上移不动；后台移动会改掉动画软件"最近打开"的路径语义（恢复文件如 RECOVER/.blend1 也要求留在原目录原位）。
	- **盘符入口：** Windows 用内置 `subst` 命令把 Inbox 挂载为盘符（如 A:），另存为对话框直接可见；启动时挂载、退出卸载，托盘提供挂载开关（用户可手动卸，启动时重挂）；mac 无 subst，用符号链接 + Finder 收藏替代（适配时补）。
	- **监听管线：** `notify`（Rust，Windows 走 ReadDirectoryChangesW 增量事件，非轮询、常驻零 CPU）监听 Inbox；媒体类新文件先做**写入完成检测**（大小连续 N 秒稳定且可打开，防止写到一半被移走），再触发导入管线；文件被占用时延迟重试。
	- **两个区块（2026-07-25 与用户定案）：** ① **工程文件**——直接扫描 Inbox 磁盘实况展示，不建档、不写库数据、不建持久状态；热刷新必须准确，新增 / 删除 / 重命名 / 占用变化都不能丢失实际文件显示（防黑箱）。区块提醒文案写死："工程文件不支持自动导入，请手动导入"。右键只给轻量文件操作（打开 / 重命名 / 删除）与手动导入；**手动导入 = 移走入库（剪切语义）**，入口必须明示"源文件将从收件箱移走"（复用剪切导入警示）——不用复制入口：复制会让磁盘实况与库内资产在 UI 上长期并存两份，用户困惑。导入后工程文件从"工程文件"区块消失，"已导入"区块出现对应资产；后续用户整理到何处是用户自己的事。② **已导入**——写入库数据的资产：媒体类自动导入与工程文件手动导入后都进入这里。
	- **过境语义（仅媒体类）：** 可自动入库的媒体类仍只作过境，导入后即移走；工程文件不适用过境语义（不自动移走）。重名与 hash 冲突走"导入即建档"既有规则；**撞 hash 自动合并**（已有资产同为 inbox 渠道时静默改名为真实名）随工程不自动导入收窄为只服务自动入库的媒体类——AN 的 RECOVER 快照属工程文件，不再自动入库，原"RECOVER 与真实文件 hash 相同"场景随之消解；工程文件手动导入撞 hash 走正常"重复添加提示"（2026-07-25 修订）。
	- **伴生缩略图候选（规则前置，实现归 8.2）：** 不做"扫描同名 gif/png 并过滤出 UI"的隐式规则（会误伤真正需要同名的工程 + 图片两个文件）；同基础名工程与图片/动图只做**双向候选提示**，且**工程未入库不参与判定**——图片/动图入库时查库内已入库的同基础名工程；工程手动入库时再查库内已入库的同基础名图片/动图，命中同一条候选，工程先进还是伴生图先进都无所谓。候选只提示不过滤，用户确认"设为预览图"后才把媒体收进该工程 info 作 cover/sidecar 并撤掉其独立 Placement，选"两者都要"则保持两个独立资产。候选不建持久状态文件，基于库索引即时比对（磁盘实况里的未入库工程不算）；确认绑定才写数据。
- **序列帧打包：** 导入检测到序列帧时，弹窗提示"检测到 N 组序列帧"并提供打包开关（默认开启）；误打包可在素材上右键解散为独立文件，漏检可多选后右键手动打包。

> 保留层级，不代表我们真的保留层级，而是将用户的层级关系直接写入数据（按原结构创建文件夹节点与 Placement），让素材导入进来就保持原有层级；剔除层级则是全部平铺进目标文件夹。

导入即建档：按 [[01_资源与数据]] 的流程生成 ID、metadata、hash 查重、缩略图；**hash 冲突不即时打断**——冲突项挂起收集、其余文件照常导入，全部完成后逐个弹窗询问（设计 10_重复添加提示）：**用已存入文件导入**（已有资源的原始 Placement 移至当前目录，源文件保留）/ **保留两个**（创建副本）/ **关联文件夹**（建立链接，可自定义名称；开"全部应用"可按起始序号批量命名）；右上角关闭 = 跳过当前项（不导入，源文件保留）；fla 等无缩略图的文件走 7.1 插件补图。

## 02. 打开素材

- 右键菜单常驻"用默认应用打开"，Shift + Enter 同效。
- 双击行为支持用户设置：软件内预览（默认）/ 用默认应用打开。
- 支持跨窗口拖拽至其他软件内打开，支持拖拽至软件图标打开，比如任务栏里的快捷方式。

> 技术前提：拖入 UI 使用 webview 自带的文件拖放事件即可；拖出到其他软件时，HTML5 拖拽无法离开窗口边界，需要原生层发起系统级拖拽（Windows 为 CF_HDROP，Tauri 生态有现成拖拽插件，也可自写原生模块），架构阶段需先行验证。拖至任务栏图标走系统"打开方式"机制：程序接收文件路径参数 + 单实例转发。

## 03. 导出素材

右键菜单常驻导出，支持导出文件，文件夹，整个素材库。

- 导出文件夹和整个素材库时，按照 folders.json 记录的层级 + Placement 显示名重建目录结构，千万不可导出我们的实际路径（ID.info 结构）。
- 同一素材以链接形式存在于多个文件夹时，导出后每个位置均为真实副本。
- 导出仅为拷出，不改动库内任何数据。
- 索引式工作空间无需导出功能，文件本来就在磁盘上。
