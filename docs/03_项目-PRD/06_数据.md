## 01. 存放目录

1. **素材库目录（封闭式资源库）：** 数据文件与缓存均保留在素材库目录内，重装软件和系统时不丢失；内部路径全部相对化、链接按 ID 寻址，整个目录可整体搬迁、换盘符不影响使用。
2. **工作空间目录（索引式）：** 在用户选择的文件夹根目录建立 `.anikit` 隐藏文件夹，只存缩略图、波形、系统格式缩略图等缓存，整个文件夹可随时删除（缓存可重建）。
3. **全局配置：** 存于系统配置目录（Windows：`%APPDATA%\AniKit`；macOS：`~/Library/Application Support/AniKit`），内容为 config.json：资源库列表（名称、路径、最近打开时间）、工作空间列表、全局设置（热键、双击行为、布局默认值等）。**UI 设置与主窗口几何持久化（2026-07-28 用户定）**：`settings.ui` 子树存界面设置（查看方式、自动播放与显示开关、侧栏宽高与折叠、目标行高、时间显示等，前端变更防抖 500ms 整体写回，启动拉取覆盖）；`settings.window` 子树存主窗口大小 / 位置 / 最大化标志（resize/move 防抖写回，最大化时只刷标志位、几何保留还原尺寸；预览子窗口不记录）。安装目录是普通权限不可写的，不要往安装目录写数据；若后续提供便携（绿色）模式，则优先读写软件所在目录。

素材库目录结构总览：

``` text
素材库（用户命名）
├── asstes/                素材实体
│   └── {ID}.info/         每个资源一个文件夹
│        ├── metadata.json
│        ├── {标题}.{拓展名}
│        ├── {标题}_thumbnail.{拓展名}
│        ├── {标题}_waveform.png     音频波形图
│        ├── annotation.json         标注数据（如有）
│        └── frames/                 序列帧（如有）
├── backup/                数据备份（滚动 10 份）
├── cache/                 系统格式缩略图等可重建缓存
├── vectors/               向量数据与视频分段索引（派生，供向量语义搜索与 AI，可重建）
├── inbox/                 收件箱（工作中素材/模板快速入口：媒体类自动过境、常态为空；工程文件仅磁盘实况展示、不自动导入，subst 挂载与监听见 [[05_导入与导出]] 5.1）
├── folders.json           文件夹树 + Placement（含 origin、分组规则、排序）
├── tags.json              标签定义与群组
├── pins.json              快捷入口
└── recycle.json           回收站记录（资源 ID、原 Placement、删除时间）
```

## 02. 数据文件总览

| 文件 | 位置 | 内容 | 性质 |
| --- | --- | --- | --- |
| metadata.json | asstes/{ID}.info/ | 单资源元数据：名称、originName、hash、标签、注释、评分、链接、宽高、时长等 | 用户数据，需备份 |
| 缩略图 / 波形图 | asstes/{ID}.info/ | 预览图（含封面帧）、音频波形 | 缓存，可重建 |
| annotation.json | asstes/{ID}.info/ | 标注：帧号/时间戳 + 画框 + 名称 | 用户数据，需备份 |
| notes.json | asstes/{ID}.info/ | 逐帧笔记（序列帧 = 帧名 / 动图 = `f:{帧索引}` / 视频 = `t:{秒}`，5.2） | 用户数据，需备份 |
| frames/ | asstes/{ID}.info/ | 序列帧全部帧文件（**动图不持久化解包**——播放/设封面/帧条对 origin 运行时解码，2026-08-20 解包废除） | 素材实体 |
| folders.json | 素材库根 | 文件夹树、全部 Placement、分组规则 | 用户数据，需备份 |
| tags.json | 素材库根 | 标签与群组 | 用户数据，需备份 |
| pins.json | 素材库根 | 快捷入口（ID 引用） | 用户数据，需备份 |
| recycle.json | 素材库根 | 回收站记录：资源 ID、原 Placement、删除时间 | 用户数据，需备份 |
| recent.json | 素材库根 | 最近使用记录（ID + 访问时间，上限 500 条） | 用户数据，需备份 |
| .anikit/workspace.json | 工作空间 .anikit | 置顶、常用等视图状态 | 轻量状态，丢失成本低 |
| vectors/ | 素材库根 | 文件信息向量与视频分段索引（素材 ID + 起止时间 + 类型 + 向量 / 台词文本），供向量语义搜索与 AI（避免 AI 逐个读取 JSON） | 派生数据，可重建 |
| backup/ | 素材库根 | 数据文件备份文件夹，滚动 10 份 | 备份 |
| cache/、.anikit/ | 素材库根 / 工作空间根 | 系统格式缩略图等 | 缓存，可重建 |
| config.json | 全局配置目录 | 资源库与工作空间列表、全局设置（含 settings.ui 界面设置与 settings.window 主窗口几何，2026-07-28） | 全局唯一 |

所有 JSON 文件都必须携带 `"version"` 字段（见 05）。

## 03. 存储方案

- **权威数据一律使用 JSON 文件**：人类可读、单文件损坏不扩散、用户可用记事本等工具自行救急，与整体"数据可自救"的设计哲学一致。
- **启动时加载进内存建立索引**（资源 ↔ Placement 反查、搜索索引等），运行期查询全部走内存，写操作先落盘再更新内存。
- **打开自检（2026-07-25 补）：** 用户可能在软件外直接删除 `asstes/{ID}.info`；打开库时剔除 folders.json 中指向缺失 info 的 Placement（内存索引与磁盘同清，数量统计随之正确），落盘前先强制备份一份含脏数据的快照，备份失败则不写盘（仅本会话内存清理）。
- **SQLite 仅作为可选的索引缓存**：后续数据量大、启动加载变慢时再引入，定位为"可删除重建的加速层"，JSON 永远是权威来源，SQLite 损坏或删除后从 JSON 重建即可。
- **向量库是派生数据**：从 JSON 中提取文件信息生成，供向量语义搜索与 AI 使用（AI 查找素材不必逐个读取 JSON），损坏或删除后重新提取即可。

## 04. 备份与恢复

- **备份对象：** folders.json、tags.json、pins.json、recycle.json 及全部 metadata.json、annotation.json；缓存与向量库不备份（可重建）。
- **备份形式：** 以文件夹形式存放（如 `backup/2026.0717.17.38-1.12/`），直接存放数据文件副本，仅复制自上次备份后有变动的文件；不使用压缩包，避免回滚时还要内置解压。
- **备份时机：** 启动时（距上次备份超过 24 小时）、大批量写操作前（批量导入、批量删除、数据迁移）。
- **回滚方式：** 不让用户手动动文件夹——软件菜单内提供版本回滚，列出各备份时间，一键恢复；恢复前先将当前数据另存为一份新备份，以便反悔。
- **损坏检测：** 启动时校验 JSON 可解析性与版本字段，发现损坏提示用户回滚至最近备份。

## 05. 数据版本与迁移

- 每个 JSON 文件带 `"version": N`，软件内记录当前支持的最新版本。
- **旧版本升级：** 启动时检测，低于当前版本则逐级迁移（v1→v2→v3），迁移前自动备份一次。
- **高版本降级：** 检测到大版本高于当前软件（新版软件写过的库用旧版打开），提示用户升级软件，禁止写入，防止数据被破坏。

## 06. 回收站

- **移入回收站不做物理移动（2026-08-19 位置级模型修订）：** 「丢到回收站」= 该位置从 folders.json 移除并在 recycle.json 记录（资源 ID、位置记录、删除时间）——**任一位置（origin / 链接一视同仁）可独立进回收站**，原"删除最后一条 Placement 才移入、移除全部 Placement"口径废除；recycle.json 按资产聚合条目（同资产多次删除追加进同一条目）。info 文件夹保留原位不动，省去文件剪切。
- **回收站视图：** 回收中的资源在正常视图隐藏，仅在回收站视图展示；本体（origin 位置）在回收站的资产，其库内活链接照常显示在原文件夹（链接与原始文件同等待遇）。
- **彻底删除（2026-08-19 分级）：** 条目含 origin 快照 = 资产本体在回收站——彻底删除才物理删除 info 文件夹，并清除关联数据（pins 引用、内存索引、**库内该资产的全部活链接**；确认窗提示虚拟片段引用数与"关联的 N 条链接将一并清除"）；纯位置记录条目（无 origin 快照）彻底删除只删记录，物理不动、无需确认。
- **还原：** 按 recycle.json 记录恢复全部 Placement；原文件夹已不存在的，还原至根目录；撞名放开不追加序号（2026-08-19）。
- **保留策略：** 永久保留，不自动清理，由用户自行担责与手动清空。
- 索引式工作空间的删除直接走**系统回收站**（真实磁盘文件，调用系统 API），不进入库内回收站。

## 07. 缓存清理

- 设置页展示各类缓存占用大小（系统格式缩略图、波形图、.anikit 等），提供一键清理。
- 所有缓存均可重建，清理不影响任何用户数据。
