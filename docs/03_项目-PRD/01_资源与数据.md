## 01. 数据式资源库

类似 eagle 的封闭式管理方式，通过修改数据文件实现文件的层级和信息管理等，而非频繁的真实移动文件。

用户初次开打软件弹出窗口：**创建资源库** ，**打开资源库** ，**稍后** 。

#### 1. 资源库结构

- **素材库** （用户命名）
	- **backup（文件夹）：** 数据文件备份文件夹，软件定时备份，方便数据损坏、丢失时回滚，最多备份十份数据文件。
	- **asstes（文件夹）：** 存放素材的地方。
		- **ID.info：** 将每份素材单独建立 info 文件夹，并自动命名唯一 ID，通过随即生成，或者用一些固定的格式。
			- **metadata.json：** 元数据文件
			- **标题.拓展名：** 原始素材
			- **标题_thumbnail.拓展名：** 缩略图文件（如：PNG，WEBP 等）
			- **标题_anim.webp（阶段四一轮起停止生成，2026-08-20）：** 动图小动画播放缓存（仅动图资产；短边 320 animated webp，2.3）——已随自研解码帧流退役，存量文件留盘待清理口径
	- **数据文件：** 为层级，标签，向量，时间戳，文件夹信息等等单独创建数据文件。

#### 2. 数据格式

1. ID 不承载语义（语义全部放在 metadata 中），采用 `AN` + 时间戳 + 随机字符，保证唯一且时间有序，如：

``` text
AN2607171718-X7K2Q

AN：AniKit
2607171718：26 年 7 月 17 日 17:18
X7K2Q：随机字符，防止同一秒冲突
```

2. 备份数据文件可在标题前面加上时间戳和版本号，如：

``` text
2026.0717.17.38-1.12-metadata.json
```

3. 核心模型：**资源（Asset）与放置位置（Placement）分离**。一份物理文件永远只有一个 ID、一个 info 文件夹、一份 metadata.json；多文件夹、多名称通过 Placement 实现。真实路径不存绝对路径，由 ID 推导：`asstes/{ID}.info/{原始文件名}`。

单个文件的元数据（`{ID}.info/metadata.json`），只存资源固有属性：

``` json
{
  "version": 1,
  "id": "AN2607171718-X7K2Q",
  "name": "人物",
  "originName": "人物.fla",
  "ext": "fla",
  "size": 1234567,
  "hash": "sha256:xxxx",
  "width": null,
  "height": null,
  "duration": null,
  "bpm": null,
  "rating": 0,
  "links": [],
  "importedAt": "2026-07-17T17:18:00+08:00",
  "importedFrom": null,
  "modifiedAt": "2026-07-17T17:18:00+08:00",
  "tags": ["男人", "走路"],
  "note": "注释与描述",
  "noteCount": null,
  "thumbnail": "人物_thumbnail.webp"
}
```

> 图片、视频、音频导入时提取 `width`、`height`、`duration`，用于比例与时长筛选，fla 等工程文件为 null；音频另提取 `bpm`——**只读内嵌标签（TBPM/bpm），不做自动节拍检测**（2026-07-26 用户定），无标签为 null；视频另提取 `fps`（素材自身帧率——**5.3 帧化改造，2026-07-28 用户定"帧数优先"**：播放条 / 悬停胶囊 / 笔记按帧号显示；ffprobe 首个视频流 `avg_frame_rate` 分数解析，"0/0" / 缺失回退 `r_frame_rate`，再缺为 null；字段与序列帧 `fps` 共用，5.3 前入库的存量视频播放时自愈补写）；`rating` 为 0-5 星评分，`links` 为链接数组（见 [[02_文件整理]]）；`importedFrom` 为导入渠道标记（`"inbox"` = 收件箱渠道，常规导入为 null），服务快速访问"已导入"区块口径与摘标语义（移动出根目录即摘标转正）；**撞 hash 一律走"重复添加提示"冲突挂起，不分渠道**——同渠道静默合并 2026-08-13 用户定案废除（该方案原为 AN 工程恢复文件 RECOVER 不停自动导入准备，工程文件已不自动导入，场景随之消解，见 [[05_导入与导出]] 5.1）。`noteCount` 为逐帧笔记条数冗余（5.2 展示层：卡片角标 / 详情区块免读 notes.json），`set_note` 命令同步维护，无笔记记 null 不写字段。

4. 文件夹树与放置位置（`folders.json`），每条 Placement 记录"哪个资源、在哪个文件夹、显示什么名称、排在第几"：

``` json
{
  "version": 1,
  "folders": [
    { "id": "F01", "name": "人物",   "parent": null, "order": 0 },
    { "id": "F02", "name": "动画01", "parent": null, "order": 1 }
  ],
  "items": [
    { "asset": "AN2607171718-X7K2Q", "folder": "F01", "name": "男人.fla", "order": 0, "origin": true },
    { "asset": "AN2607171718-X7K2Q", "folder": "F02", "name": "张三.fla", "order": 0 }
  ]
}
```

5. 序列帧：**一个序列帧包 = 一个资源**（一个 ID、一个 info 文件夹），内部以 `frames/` 子文件夹存放全部帧，metadata 记录 `fps`、`frameCount`、`thumbFrame`（封面帧），设置某一帧为预览图时重新生成缩略图并更新 `thumbFrame`。链接、副本、Placement 语义与普通资源一致。
	- **检测：** 外部命名格式不一（Adobe 导出为 `标题001`，Windows 复制为 `标题 (1)`，另有常见的 `标题_001`、`标题-001`），检测需宽容：按"基础名 + 扩展名 + 序号位宽"分组，序号连续（允许少量缺帧）且数量 ≥ 3 判定为序列帧。
	- **入库归一：** 打包时帧文件在 `frames/` 内统一重命名为 `标题-序号`（序号补齐位宽），库内只维护这一种格式，不使用括号。
	- **实现定案（2026-07-22 与用户）：** 交互 = 09 导入弹窗确认后后端检测，命中则追加弹「监测到序列帧」弹窗（[[12_序列帧弹窗]]：打包导入预览 默认 / 分散图片导入，取消 = 放弃整个导入）；检测仅同目录兄弟文件成组、仅图片格式（缩略图管线支持的格式），缺帧容忍量化为 缺帧 ≤ max(2, 跨度/10)、同组同号不判；`fps` 默认 24、`thumbFrame` 记封面帧文件名（默认首帧）、资产标题 = 基础名；组 hash = 各帧 sha256 按序号升序串联后再 sha256，撞 hash 走既有冲突挂起 + 逐个"重复添加提示"流程（显示名用序列帧标题，"保留两个"按冲突项回传的组信息重新打包）；复制/剪切来源语义对整组生效。收件箱自动导入无弹窗，维持逐文件导入不自动打包（留待）。
	- **动图共用字段（2026-07-26，5.1）：** GIF / WEBP 动图导入时 metadata 同写 `frameCount`（帧数）与 `duration`（单循环总时长，秒）；`fps` 仍为序列帧专属（动图逐帧 delay 可变，平均 fps 无意义）；**`thumbFrame` 动图 = `f:{帧索引0起}`**（如 f:41——设封面时 origin 运行时解码抽帧，2026-08-20 定案；存量帧名值按尾号兼容解析）。**帧数据最终定案（2026-08-20 用户定，解包废除）：** 动图**不持久化解包**（无 info/frames/ 与 frames.json，导入零等待）——播放 = 自研解码帧流（WS 推帧 canvas）、设封面 / 笔记帧画面 = origin 单帧抽解码、帧条小图 = origin 按需解码存 cache/frames 会话级；逐帧笔记 key = `f:{帧索引}`。原"导入期解包持久化"定案（2026-07-26）与更早"cache 会话级"定案（2026-07-25）均废止。

6. 视频片段（虚拟素材）：动态素材的某段时间可沉淀为虚拟片段——仍建立 info 文件夹（metadata + 缩略图，缩略图取自该区间），仅无独立实体文件；metadata 记录 `"type": "segment"`、`source`（来源资源 ID）、`start`、`end`；Placement、链接、标签等语义与普通资源一致。来源资源被彻底删除时，其虚拟片段一并失效，彻底删除前需提示"该资源被 N 个虚拟片段引用"。物理截取（ffmpeg）则生成普通新资源。

#### 3. 多文件夹关联（副本与链接）

对应 [[00_功能总览]] 2.7，允许同一文件以不同名称出现在多个文件夹：

- **链接：** 新增一条 Placement，可自定义显示名称。零磁盘开销，改标签、重新生成缩略图等操作处处生效。
- **副本：** 物理复制 info 文件夹，生成新 ID、新 metadata、新 Placement，从此完全独立。
- **导入查重：** 导入时 hash 与已有资源相同不打断导入，挂起收集、全部导入完成后逐个询问（[[05_导入与导出]] 01，设计 10_重复添加提示）：用已存入文件导入（原始 Placement 移至当前目录）/ 保留两个（副本）/ 关联文件夹（链接，可改名）；关闭 = 跳过当前。

边界规则：

1. **改名作用域：** 修改显示名只影响对应 Placement。重命名分两步：先改显示名保证 UI 即时响应，后台空闲时再异步执行磁盘改名——重命名**原始 Placement** 时，异步将磁盘上的 originName（含缩略图等伴生文件）一并改名，保证软件出 BUG 时用户可用 Everything 等工具按记忆中的名称搜索救急；**序列帧资产 = frames/ 内全部帧文件同步改词干**（保留序号尾与扩展名，thumbFrame / originName 跟随封面帧，2026-08-14 用户定）；重命名**链接 Placement** 仅改显示名。异步改名经任务队列执行，异常退出后启动时校验 metadata.originName 与 info 文件夹内实际文件名，自动恢复一致。
2. **删除语义（2026-08-19 位置级模型修订）：** 删除 Placement ≠ 删除文件；**任一位置（origin / 链接一视同仁）都可独立删除**——「丢到回收站」= 该位置进回收站（recycle.json 按资产聚合记录，物理不动）；「从文件夹中移除」= 该位置挪未分类（不删记录）。原"最后一条 Placement 被删除时移入回收站"判定废除（回收站条目可以是纯链接位置记录）；**回收站条目含 origin 快照 = 资产本体在回收站**，彻底删除它才物理删 info 并连带清除库内该资产的全部活链接（确认窗提示"关联的 N 条链接将一并清除"）；纯位置记录的彻底清除只删记录、物理不动、无需确认。还原 = 快照位置写回原文件夹（文件夹缺失挂未分类，撞名放开不追加序号）。
3. **反查关联：** 详情面板的"已关联文件夹"通过资源 ID 反查 Placement 实现，加载时建立内存索引，metadata 中不冗余存储。
4. **链接寻址：** 软件内链接统一使用 ID 寻址 `anikit://item/{ID}`，不使用名称寻址，避免改名后死链。
5. **搜索命中：** 分词搜索同时命中资源的 name 与所有 Placement 的 name。
6. **原始 Placement：** 导入时创建的第一条 Placement 为原始文件，在 folders.json 中标记 `"origin": true`；素材卡片上以角标区分链接与原始 Placement。
7. **显示名放开（2026-08-04 修订，取代原"显示名唯一"）：** 同一文件夹内允许相同显示名——唯一名规则是贴 Windows 习惯的保守决策，库内显示名是纯数据，物理唯一性由 originName（磁盘文件名单一写点）承载，不受影响；~~同资产同文件夹仍只允许一条链接~~（**2026-08-13 用户定案废除**：链接不做任何数量 / 落点限制，怎么整理是用户的事；同文件夹重复链接显示名自动唯一化区分）；自动生成的默认名仍给区分序号（如 新建文件夹-2、剪贴板-时间戳），但不拦截、不强制追加；**导入冲突"保留两个"不自动加序号**（2026-08-14 用户定：库本就允许同名文件存在，需要什么名字用户自己改）；**重命名撞名不追加序号**（2026-08-18 用户定"护栏全拆"：单条 rename_placement 与批量 rename_placements 统一不唯一化；原始 Placement 磁盘改名撞名属物理约束，失败中文报错回滚）；序号格式统一为 `-序号`，不使用括号（括号在部分软件与脚本中易出问题）。
8. **origin 不主动转移（2026-08-19 修订，取代原"origin 自动转移"）：** 删除原始 Placement 时 `origin: true` 随记录走（删除/进回收站即随之消失），**不再自动转给剩余链接**——原始文件标识的空缺由用户自主决定（阶段六右键「将此文件设为原始文件」手动转移）。资产可以暂时没有 origin 位置（全链接存活），物理实体由 info 目录承载不受影响；原"删到最后一条 = 资产进回收站"判定随删除位置级化废除（任一位置都可独立丢回收站）。

## 02. 索引式工作空间

在工作中，我们需要频繁切换操作系统自带的资源管理器来管理项目，素材软件来查找素材，我们需要做一个简易的本地索引，来实现软件内即可完成工作。

用户首次打开软件弹出窗口：**创建工作空间**， **打开工作空间**， **稍后**。

工作空间无标签，自定义排序，评分，注释，描述，批注等等附加数据，只缓存缩略图便于快速加载浏览，保证双向热刷新。

#### 1. 资源库结构

与本地磁盘双向同步，UI 热刷新，在工作空间根目录创建 .anikit 文件夹，保存缩略图缓存。
