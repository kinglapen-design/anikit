## 01. 数据式资源库

类似 eagle 的封闭式管理方式，通过修改数据文件实现文件的层级和信息管理等，而非频繁的真实移动文件。

用户初次开打软件弹出窗口：**创建资源库** ，**打开资源库** ，**稍后** 。

#### 1. 资源库结构

- **素材库** （用户命名）
	- **backup（文件夹）：** 数据文件备份文件夹，软件定时备份，方便数据损坏、丢失时回滚，最多备份十份数据文件。
	- **asstes（文件夹）：** 存放素材的地方。
		- **ID.info：** 将每份素材单独建立 info 文件夹，并自动命名唯一 ID，通过随即生成，或者用一些固定的格式。
			- **metadata.json：** 元数据文件
			- **标题.拓展名：** 原始素材
			- **标题_thumbnail.拓展名：** 缩略图文件（如：PNG，WEBP 等）
	- **数据文件：** 为层级，标签，向量，时间戳，文件夹信息等等单独创建数据文件。

#### 2. 数据格式

1. ID 不承载语义（语义全部放在 metadata 中），采用 `AN` + 时间戳 + 随机字符，保证唯一且时间有序，如：

``` text
AN2607171718-X7K2Q

AN：AniKit
2607171718：26 年 7 月 17 日 17:18
X7K2Q：随机字符，防止同一秒冲突
```

2. 备份数据文件可在标题前面加上时间戳和版本号，如：

``` text
2026.0717.17.38-1.12-metadata.json
```

3. 核心模型：**资源（Asset）与放置位置（Placement）分离**。一份物理文件永远只有一个 ID、一个 info 文件夹、一份 metadata.json；多文件夹、多名称通过 Placement 实现。真实路径不存绝对路径，由 ID 推导：`asstes/{ID}.info/{原始文件名}`。

单个文件的元数据（`{ID}.info/metadata.json`），只存资源固有属性：

``` json
{
  "version": 1,
  "id": "AN2607171718-X7K2Q",
  "name": "人物",
  "originName": "人物.fla",
  "ext": "fla",
  "size": 1234567,
  "hash": "sha256:xxxx",
  "width": null,
  "height": null,
  "duration": null,
  "rating": 0,
  "links": [],
  "importedAt": "2026-07-17T17:18:00+08:00",
  "modifiedAt": "2026-07-17T17:18:00+08:00",
  "tags": ["男人", "走路"],
  "note": "注释与描述",
  "thumbnail": "人物_thumbnail.webp"
}
```

> 图片、视频、音频导入时提取 `width`、`height`、`duration`，用于比例与时长筛选，fla 等工程文件为 null；`rating` 为 0-5 星评分，`links` 为链接数组（见 [[02_文件整理]]）。

4. 文件夹树与放置位置（`folders.json`），每条 Placement 记录"哪个资源、在哪个文件夹、显示什么名称、排在第几"：

``` json
{
  "version": 1,
  "folders": [
    { "id": "F01", "name": "人物",   "parent": null, "order": 0 },
    { "id": "F02", "name": "动画01", "parent": null, "order": 1 }
  ],
  "items": [
    { "asset": "AN2607171718-X7K2Q", "folder": "F01", "name": "男人.fla", "order": 0, "origin": true },
    { "asset": "AN2607171718-X7K2Q", "folder": "F02", "name": "张三.fla", "order": 0 }
  ]
}
```

5. 序列帧：**一个序列帧包 = 一个资源**（一个 ID、一个 info 文件夹），内部以 `frames/` 子文件夹存放全部帧，metadata 记录 `fps`、`frameCount`、`thumbFrame`（封面帧），设置某一帧为预览图时重新生成缩略图并更新 `thumbFrame`。链接、副本、Placement 语义与普通资源一致。
	- **检测：** 外部命名格式不一（Adobe 导出为 `标题001`，Windows 复制为 `标题 (1)`，另有常见的 `标题_001`、`标题-001`），检测需宽容：按"基础名 + 扩展名 + 序号位宽"分组，序号连续（允许少量缺帧）且数量 ≥ 3 判定为序列帧。
	- **入库归一：** 打包时帧文件在 `frames/` 内统一重命名为 `标题-序号`（序号补齐位宽），库内只维护这一种格式，不使用括号。

6. 视频片段（虚拟素材）：动态素材的某段时间可沉淀为虚拟片段——仍建立 info 文件夹（metadata + 缩略图，缩略图取自该区间），仅无独立实体文件；metadata 记录 `"type": "segment"`、`source`（来源资源 ID）、`start`、`end`；Placement、链接、标签等语义与普通资源一致。来源资源被彻底删除时，其虚拟片段一并失效，彻底删除前需提示"该资源被 N 个虚拟片段引用"。物理截取（ffmpeg）则生成普通新资源。

#### 3. 多文件夹关联（副本与链接）

对应 [[00_功能总览]] 2.7，允许同一文件以不同名称出现在多个文件夹：

- **链接：** 新增一条 Placement，可自定义显示名称。零磁盘开销，改标签、重新生成缩略图等操作处处生效。
- **副本：** 物理复制 info 文件夹，生成新 ID、新 metadata、新 Placement，从此完全独立。
- **导入查重：** 导入时 hash 与已有资源相同，弹窗询问"建立链接 / 仍导入副本"。

边界规则：

1. **改名作用域：** 修改显示名只影响对应 Placement。重命名分两步：先改显示名保证 UI 即时响应，后台空闲时再异步执行磁盘改名——重命名**原始 Placement** 时，异步将磁盘上的 originName（含缩略图等伴生文件）一并改名，保证软件出 BUG 时用户可用 Everything 等工具按记忆中的名称搜索救急；重命名**链接 Placement** 仅改显示名。异步改名经任务队列执行，异常退出后启动时校验 metadata.originName 与 info 文件夹内实际文件名，自动恢复一致。
2. **删除语义：** 删除 Placement ≠ 删除文件；最后一条 Placement 被删除时，询问"移入回收站 / 保留为未分类"。
3. **反查关联：** 详情面板的"已关联文件夹"通过资源 ID 反查 Placement 实现，加载时建立内存索引，metadata 中不冗余存储。
4. **链接寻址：** 软件内链接统一使用 ID 寻址 `anikit://item/{ID}`，不使用名称寻址，避免改名后死链。
5. **搜索命中：** 分词搜索同时命中资源的 name 与所有 Placement 的 name。
6. **原始 Placement：** 导入时创建的第一条 Placement 为原始文件，在 folders.json 中标记 `"origin": true`；素材卡片上以角标区分链接与原始 Placement。
7. **显示名唯一：** 同一文件夹内显示名唯一，冲突时自动追加 `-序号`（如 男人-1.fla）；全库序列格式统一为 `-序号`，不使用括号（括号在部分软件与脚本中易出问题）。

## 02. 索引式工作空间

在工作中，我们需要频繁切换操作系统自带的资源管理器来管理项目，素材软件来查找素材，我们需要做一个简易的本地索引，来实现软件内即可完成工作。

用户首次打开软件弹出窗口：**创建工作空间**， **打开工作空间**， **稍后**。

工作空间无标签，自定义排序，评分，注释，描述，批注等等附加数据，只缓存缩略图便于快速加载浏览，保证双向热刷新。

#### 1. 资源库结构

与本地磁盘双向同步，UI 热刷新，在工作空间根目录创建 .anikit 文件夹，保存缩略图缓存。
