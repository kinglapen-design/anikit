> 2026-08-04 定稿（依据 `docs/00_修改与需求/01_新PRD/01_储存空间.md` 与讨论定案）。本文定义库的外层——储存空间；库内数据模型（Asset / Placement / metadata / folders.json）仍以 [[01_资源与数据]] 为准。

## 01. 概述

AniKit 分为库式资产管理和索引式工作空间，两个模式之间涉及频发的互相导入；动画制作与后期合成中涉及大量素材链接，**路径稳定性优先级最高**：素材能不做实质物理迁移就不做，数据变更才是核心管理模式。多素材库同样遵守这一理念——所有素材封存在统一 assets 池，多资源库用不同的数据文件记录和区分。

## 02. 空间结构

assets、各资源库、工作空间统一放在 AniKit 储存空间下；整体搬迁时，所有相对路径维持以储存空间根为锚点的稳定状态：

``` text
AniKit（储存空间）
├── assets/        统一素材池：所有资源库的素材平铺为 {ID}.info，跨库投递零物理迁移
├── 资源库-1/      库 = 纯数据（folders.json 等数据文件 + backup）
├── 资源库-2/
├── ...
└── workspace/     索引式工作空间（唯一）
```

- 回收站、最近使用等记录为库级数据；删除判定升级为**跨库引用计数**——资产仍被任一库引用时，其他库的删除不动物理 info。
- 全局配置（储存空间、资源库列表与设置）仍存系统配置目录（见 [[06_数据]]）。

## 03. 入口

### 3.1 初次打开

欢迎界面四步设置（每步可直接下一步跳过）：

1. **指定储存空间**：打开已存在或新建；所选文件夹非 AniKit 空间结构时弹出报错。
2. **创建资源库、开启工作空间**：工作空间也可后续在设置中开启。
3. **安装浏览器扩展**（见 [[09_浏览器插件]]，后续版本）。
4. **安装桥接插件**（动画软件桥接，见 07 动画软件通信，后续版本）。

### 3.2 资源库管理

- 切换资源库的二级菜单中可新建、切换资源库。
- 储存空间可创建多个，不同空间内资源**完全独立、不互通不共享**；跨空间互通走导出素材包 `.anikit` 导入合并（后续版本）。
- 每个储存空间内允许建立多个资源库，多个资源库允许合并为一个。
- 工作空间默认唯一 `workspace` 文件夹，用户按习惯和项目自建层级；可在设置中将其以目录联接（junction，Windows 免管理员权限）映射至其他路径，供用户在资源管理器内直接操作（不考虑散落在各处的既有项目文件夹——用户经 UI 导入或在 UI 内创建项目）。

### 3.3 扩展 / 插件

浏览器扩展经汉堡菜单 → 设置安装；动画软件桥接插件经设置或工具栏插件面板安装与卸载。

## 04. 工作空间链接落盘（2026-08-02 讨论定案）

素材从资源库链接至工作空间目录时，**链接真实落在磁盘上**，而非 UI 虚拟节点（虚拟节点与索引式"磁盘实况"相冲：热刷新要开口子、资源管理器所见不一致、操作需特判）：

- 文件级 = NTFS **硬链接**（同卷免权限；workspace 与 assets 同处一个空间，天然同卷）。链接文件就是真实文件：动画软件可打开、资源管理器可见、外部引用路径稳定；文件改名不影响链接目录项的名称（如库内"男人_走路"、链接处"张三_走路"）。
- UI 识别：扫描时比对 NTFS fileIndex（文件索引号），相同即同一文件的两个目录项——自动打链接标识，hover 展示该文件的全部链接位置。
- 文件夹 / 档案整体不物化（避免数据层与磁盘双向同步的高耦合）；需要时提供"物化到磁盘"动作，批量落成硬链接。
- 删除链接仅删目录项，库内素材数据不受影响。
