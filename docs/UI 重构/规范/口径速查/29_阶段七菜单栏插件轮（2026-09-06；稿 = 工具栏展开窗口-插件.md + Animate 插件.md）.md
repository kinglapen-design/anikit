- **同日四轮（用户实机走查三条修订）**：① **子窗口拖拽带通栏 62px**——原标题行 26px 太小（用户：「拖拽范围太小了」）；`.pw-dragband` 负 margin 三向扩（上 24 吃进根 padding 顶、左右到窗口边、margin-bottom -12 与 padding-bottom 12 对消保持首组间距 24 贴稿）；滚动区/按钮行不挂。**子窗口/弹窗拖拽区一律通栏带，不只挂标题文字行**。② **滚轮色档改定 = 通用/四级常态、通用/六级 hover**（用户引实机走查第一批末项口径——旧 C4/C5 在 g3 底几乎不可见，「说错了，是通用/四级和通用/六级」）；ScrollThumb 组件层落地全局生效；**滚轮贴窗口右缘手法 = 包裹层负 margin 扩边 + 滚动容器 padding 补回内容原位**（首例本子窗口，全场景整改归走查项）。③ **CEP 面板高度 = manifest 760 兜底，不再追记忆**（用户定「估计 Animate 不让这么干，swf 插件可以。算了，不折腾了」——resizeContent 重试保留无害，浮动面板仍有效）。
- **同日五轮（用户实机走查三条修订）**：① **Tauri v2 `data-tauri-drag-region` 只认元素自身命中**（e.target 须为挂属性元素，**后代不冒泡**——主窗口菜单栏按钮在拖拽区里可点正因此）：四轮拖拽带容器单挂 → 标题文字（h1 后代）不可拖「只剩顶部 padding 能拖」；修法 = **容器与文字行双挂**（h1 另清 UA margin-block，尺寸链才精确）。写拖拽区一律照此。② **滚轮拖动期间禁窗口拉伸**（用户：拖滚轮与系统边缘拉伸热区重叠「小心翼翼生怕丢失滚动条」）——`useSideThumb` onThumbDown `setResizable(false)` / onUp 恢复（**pointercancel / blur / 组件卸载三路兜底**防永禁；capabilities 补 `core:window:allow-set-resizable`）；invoke 失败（桩/无权限）静默不阻断。组件层落地全局生效。③ **子窗口边框 = 亮色/半透明-1**（用户问 token 来源：云母 = **非 token**，主窗口 DWM 染 #333（lib.rs DWMWA_BORDER_COLOR）、子窗口未染 = 系统默认色；实色 = --n-g6，均非老 token）：plugin 窗 = 后端 `DWMWA_COLOR_NONE` 抑制 DWM 默认边框 + 前端 `.window.plugin-win::before` l-a1 自绘（云母特例恢复自绘、radius 8 同路径；主窗口不动——用户准备把主窗口也换半透明边框，另立项翻新 §19 六轮定稿）。**「DWM 关边框 + CSS 独绘」组合实机观感待用户验证**（六轮只否过「双画并集」，此组合未试过）。
- **同日六轮（用户实机走查两条修订）**：① **滚轮拖拽锁改禁「拉伸的指针」**（用户澄清：不是窗口拖拽，是拉伸的指针）——根因 = 前端自制拉伸热区 `.resize-zone`（absolute z-100，边缘 8px、**右缘收窄 3px**（2026-08-13 详情面板滚轮同款坑的既有避让），各带 `*-resize` 光标）：滚轮贴窗口右缘后与热区重叠，拖滚轮时 e-resize 光标与 `startResizeDragging` 抢走。**`setResizable(false)` 只管 OS 级 WS_THICKFRAME/tao 物理判定，前端热区是 JS 层须另行禁**——`useSideThumb` 拖拽锁同步挂 `.thumb-scroll-lock` 类（documentElement，lock/unlock 计数同帧）→ base.css 规则 `.thumb-scroll-lock .resize-zone { pointer-events:none !important; cursor:default !important; }`（事件落下层滚轮、光标归默认）。横向滚动条 `.kit-scroll-x` 色档同步改 g4/g6（行 42「应用至所有」口径的另一半）。② **窗口边框全窗 = DWM 默认半透明**（用户：「DWM 原生就是半透明就可以直接把边框交给 DWM，主窗口也是」）——**五轮 l-a1 CSS 方案整体撤销**（plugin.rs COLOR_NONE 块 / App.vue `.plugin-win` 样式与类）；**主窗口 #333 实心染色撤销**（lib.rs 不再调 DWMWA_BORDER_COLOR；`set_main_border_picking` 常态 #333 → `COLOR_NONE` 恢复默认，picking 品牌色 #0F89EC 不动）。实色模式（Win10 DWM 无默认边框）前端 ::before g6 自绘保留。§19 口径已翻修。
- **同日七轮（用户实机走查一条修订，八轮根因更正）**：**子窗口打开后首次悬停滚轮不显、要点一下**——初判 = ScrollThumb hover 仅由 `mouseenter/mouseleave` 驱动、WebView2 新窗未激活态首次 mouseenter 丢失，修法 = 加 `window` 级 `mousemove`（capture + passive）兜底校正（contains 实时置 hover；mouseleave 防离窗滞留）。**该兜底保留**（对新窗未激活 hover 丢失仍是有效防御），但用户复验「点击也不行、非要滚轮滚一下才调出」证明**真根因不在 hover**（见下条八轮）。
- **同日八轮（用户复验逼出真根因）**：**滚轮不显的真根因 = `thumb.show` 观测盲区**——子窗口首帧「路径」组是短文本（`读取中…`/`未开库`），内容刚好不溢出 → `sync()` 算 `show=false`；`onMounted` 的 IPC（get_cep_install_status / get_current_library）返回后换长路径**折行**（`.pw-path` overflow-wrap），内容变溢出——但变化发生在**第三 section 内部文本节点**：`RO(el)`（容器高不变）/ `RO(firstElementChild)`（变的是第三个）/ `MutationObserver childList`（文本属 characterData）**三路全捕不到** → show 恒 false；「滚一下」= scroll 事件触发 sync 才置 true。**修法 = MO 补 `characterData: true, subtree: true`**（useSideThumb 层，全局「数据异步返回后内容变高」的滚动区同愈——sync 成本微秒级，高频触发无碍；同值 reactive 写入不触发重渲染）。**教训：悬停显隐类 bug 先分两条腿查——`visible = show && hover`，show 侧（观测覆盖）与 hover 侧（事件链）都可能断，勿单边定论。**
