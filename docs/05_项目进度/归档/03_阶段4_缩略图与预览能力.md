# 阶段 4 · 缩略图与预览能力（目标：任何入库格式都"看得见"）

- **4.1 序列帧打包（✅ 验收通过 2026-07-26，PRD 01-2.5）：**
	- 宽容检测：按"基础名 + 扩展名 + 序号位宽"分组（`标题001` / `标题 (1)` / `标题_001` / `标题-001`），序号连续（允许少量缺帧，量化为 缺帧 ≤ max(2, 跨度/10)，同组同号不判）且 ≥ 3 判定为序列帧；仅同目录兄弟文件成组、仅图片格式；后端为唯一事实来源（`detect_sequences` 命令）。
	- 交互（2026-07-22 用户定案）：09 导入弹窗确认后后端检测，命中追加弹「监测到序列帧」弹窗（12_序列帧弹窗：打包导入预览 默认 / 分散图片导入，取消 = 放弃整个导入），确认后后台流式导入；无序列帧时流程与现状一致。
	- 入库归一：`frames/` 子文件夹统一重命名为 `标题-序号`（序号补齐位宽，库内只维护这一种格式），metadata 记 fps（默认 24）/ frameCount / thumbFrame（首帧文件名）；thumbFrame 缩略图复用图片缩略图管线，本任务验证到卡片级；组 hash = 各帧 sha256 按序串联再 sha256，撞 hash 走既有冲突挂起 + 逐个"重复添加提示"（显示名 = 序列帧标题，"保留两个"重新打包）；复制/剪切对整组生效。
	- 留待：收件箱自动导入无弹窗，维持逐文件导入不自动打包；逐帧/动画预览归 4.3/5.x；右键解散 / 多选手动打包归 6.3。
