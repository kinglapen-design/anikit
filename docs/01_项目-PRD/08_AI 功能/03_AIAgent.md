## 03. AI Agent

> **定案（2026-09-20 用户定，见 [[07_工作台转型]]）：内置 agent 排期放很后，职责收窄为只干简单的活——整理、命名、打标签，不参与生产**。理由：正面做 agent 不如大公司成熟产品（自带生图 / 更大权限 / 能调终端），且安全 / 拦截 / 场景 prompt 是「判断对错」的责任链而非代码活——能工程化的部分（红线 = 工具面白名单、拦截 = 写入闸 + 撤销、场景 prompt = 项目说明书）已在 MCP 外接通道（[[06_AI外接通道MCP]]）先行落地。真到排期日，内置 agent = 内置模型 + 现有工具面 + 现成红线层，与外部 agent 各吃一段。以下 L1~L4 框架与场景清单为原稿，职责范围以收窄定案为准（L2 / L3 的整理杂活）。

Agent 在素材管理软件中具体能起到什么作用，是值得探讨的。前提是全部基础操作 API 化（前后端解耦），Agent 按**分级授权**调用：

- **L1 只读（搜索、分析、体检报告）：** 自由执行。
- **L2 低风险可逆（标签、评分、注释、描述）：** 可配置为自动执行；AI 生成的内容统一打标记，可一键清除；后台任务队列批量运行，不打扰前台。
- **L3 结构性（移动、新建文件夹、批量重命名）：** AI 先出方案（变更预览），用户确认后才执行。
- **L4 删除：** 永远需要人工确认，回收站兜底。

典型场景：

1. 整理素材（L3，先出方案再执行）。
2. 自动标签、描述、注释（L2，后台批量跑）。
3. 监测到无缩略图的动画工程文件，自动调出插件执行（此类定时任务由规则引擎直接做即可，不必经过大模型）。
4. 定期体检：重复文件、死链、未分类资源、缺失伴生图。
5. 自然语言指令："把上周导入的走路素材移到 人物/走路 并打上标签"。
6. 联网搜索素材：列为后续探讨。

Token 控制：向量检索预筛候选集，再交给大模型处理（见 [[02_文件整理]] 08）。
