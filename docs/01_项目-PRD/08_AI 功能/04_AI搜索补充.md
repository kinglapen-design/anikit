## 04. 关于 AI 搜索的补充

### 产品边界（2026-10-24 用户定稿）

AniKit 提供**内置轻量画面语义能力 + 外接高阶视频理解能力**。内置部分必须离线可用、无需独显，不能因为用户没有配置 AI 服务就变成空壳；高阶部分只提供 provider 接口，不把 LLM、Ollama、PyTorch / CUDA 推理环境或大型视频模型打包进 APP。

基础模型采用中文图文对齐的 CLIP 级双塔，不使用英文 CLIP 直接承担中文查询，也不跨模型随意组合文本塔与图像塔。模型按固定 revision 下载并校验，另提供离线模型包；下载完成后，基础分析和搜索均可离线运行。权重许可与 notices 是发布前置条件，技术验证通过不等于可以直接再分发。

**模型选型（2026-10-25 同集对照定稿）：** 文本塔 = `sentence-transformers/clip-ViT-B-32-multilingual-v1`（Apache-2.0，revision `58edf8cada9e398793dca955574a48cbb7f18be2`）；图像塔 = 其训练时对齐的 `openai/clip-vit-base-patch32`（OpenAI 官方 MIT 路径，revision `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`）。两塔必须作为同一模型组合使用，输出 512 维。Chinese-CLIP 因权重许可未确认不进入产品；SigLIP 2 在同一质量集上质量下降且成本更高，不采用。

同一 50 轨迹 / 150 帧 / 17 常规查询基线上，选定组合 Top1 35.29%、Top5 52.94%、Top10 64.71%、MRR 42.36%。这只证明基础画面检索可用，**动作与开关状态识别仍有静态场景偏置**，详细动作、事件和因果候选必须由外部 provider 补强，不得把 CLIP 排名当成稳定动作识别准确率。

### 内置基础分析

- **设备：** CPU 默认，GPU 由用户主动选择。Windows 首选 ONNX Runtime + DirectML，同一份 FP32 ONNX 支持两种后端；不为 GPU 引入 CUDA 环境。GPU 不可用时明确提示并回退 CPU，界面和任务进度显示真实后端，禁止把静默回退伪报为 GPU 加速。
- **运行隔离：** 推理在独立 worker 中执行，默认单任务、小批次；主界面不加载视频分析模型。搜索只使用轻量文本塔，模型空闲后卸载。设备切换在下一批任务生效。
- **静态画面语义：** 对视频、GIF / 动态 WebP、APNG 和序列帧包抽帧，分别提取图像向量。保留分段和每帧向量，不把整段视频所有帧平均成一个向量，避免短暂动作被稀释。
- **手动触发：** 用户选中素材或文件夹后点击分析。未分析素材不参与语义搜索，普通分词搜索和素材管理不受影响；不沿旧预研在导入后自动全库 embedding。

### 外接详细分析

详细分析用于动作描述、连续事件、候选精排和可选因果推测。provider 支持 OpenAI 兼容服务与 Ollama 原生 API，但 AniKit 不安装、不启动、不管理 Ollama，也不假设 provider 支持原生视频输入。

默认输入是**带真实时间戳的多帧图片 + 分段上下文**，输出为中文结构化描述与事件。事件必须引用输入中的证据帧，时间段经过校验；稀疏采样只能提供“基于采样帧的理解”，不能包装成模型看见了全部连续画面。API key 存操作系统安全凭据存储，配置与日志不得回显密钥。

外部返回的原始描述、事件、provider、模型名、prompt / schema 版本和原始帧时间戳均需保留。描述与事件文本再由**本地同一 CLIP 文本塔**编码，因此详细分析完成后，日常语义搜索不需要继续调用外部 embedding，也不必重复消耗 provider 额度。

### 分段语义索引与时间定位

- **覆盖范围：** 视频、GIF / APNG / 动态 WebP、序列帧包，以及 2026-11-07 用户定补入的静态 PNG / JPG / JPEG / WebP / BMP。视频按场景变化辅助切镜，长镜头再分短窗并保留必要重叠；动图与序列帧按真实帧时间轴分段。静态图直接读取原图，只生成一个 `visual` 向量，起止时间为 0、帧索引为空，不增加分析版本；命中后保留原卡图并正常打开预览，不显示时间徽标，不开放详细事件分析或虚拟 / 物理片段创建。既有媒体索引继续有效。
- **索引条目：** 素材 ID + 起止毫秒 + 可选起止帧索引 + 类型（画面 / 描述 / 台词 / 事件）+ 文本 + 向量 + 模型 revision + 源指纹，属派生数据、可重建，存库根 `vectors/semantic.sqlite3`。
- **时间换算：** 视频使用真实 PTS；GIF / WebP 累计每帧 delay；序列帧按实际帧清单与 fps。动图和序列帧同时保存帧索引，禁止用平均帧率猜变 delay 动图的落点。
- **索引失效：** 源内容、序列帧有序帧清单、模型 revision、预处理或分段配置变化后旧索引标陈旧，不混用不同模型空间的向量。序列帧删帧即使未重算组 hash，也必须能被帧清单指纹发现。
- **检索结果：** 每个 Placement 只展示最佳命中段和命中数，不为多个时间段复制卡片；其他片段可经菜单选择。原始相似度只用于通道内排序，不冒充识别或因果置信度。
- **分通道融合（2026-11-07 用户定）：** `visual` 与文本类片段分别按原始余弦相似度排名，使用等权 RRF（k=60）把通道内名次转换为可融合的相关度，同分优先 `visual`。每个素材不累加多段得分，以最高融合分片段参与素材排序并作为 `best`；返回的 `score` 仍是该片段原始余弦相似度，不作跨通道比较。单通道结果顺序保持原样。定位按融合后的片段顺序跳过 `description`，不再固定优先 `event`。

### 连续动作与因果边界

短动作和有序事件链可以检索：各事件带时间，查询可要求它们属于同一素材且先后有序。**先后发生不等于因果成立**。只有“洗碗之后碗碎裂”这类可观察关系能作为事实索引；“因为洗碗导致碗碎”只能作为 provider 的推测，必须标注不确定性和证据，不作为通用因果识别承诺。

### 任务与台词

分析任务支持暂停、恢复、取消、失败重试和重启后续跑，逐段或逐资产提交检查点；推理、HTTP 与 ffmpeg 进程不得持库锁。任务显示真实设备与进度，外部服务慢或失败不能卡住主界面。基础或详细分析完成后，所有打开面板中的语义结果必须按当前视口重新查询并更新 segmentId，不能把重分析前的陈旧命中用于创建片段；刷新监听在应用启动时注册，覆盖 MCP 启动的任务。

台词优先解析外挂字幕和内封字幕轨；无字幕时的 ASR 只走外部 provider，不在 APP 内置 Whisper。台词按起止时间写入同一分段索引。烧进画面的硬字幕不做 OCR。

命中的优秀片段可沉淀为**虚拟片段**（metadata 记录来源 ID 与起止时间，见 [[01_资源与数据]] 数据格式第 6 条）或经 ffmpeg 物理截取为普通新资源，完成“找到 → 定位 → 剪下 → 归档”的闭环。

### 命中片段闭环

统一命令 / MCP `create_semantic_segment` 消费已检索到的 `assetId + segmentId`，`physical=false` 创建虚拟片段，`true` 创建物理片段。`targetFolderId` 缺省为未分类，创建与撤销沿用普通入库操作；MCP 逐次过写入闸并广播库变更。创建前校验基础索引的模型 / 分析版本与源指纹，不消费陈旧命中，也不允许从虚拟片段继续嵌套。

虚拟片段只建 info 中的 metadata 与区间缩略图，不复制媒体实体。播放解析沿 `source` 找源资产，视频按真实 PTS 限界，动图 / 序列帧按保存的原始帧索引限界。来源已删除、嵌套引用或帧索引缺失时明确报错，不能静默播放整个源文件。

物理片段是独立普通资产。视频重编码截取，避免按关键帧粗略落点；动图按原始帧和逐帧 delay 截取，序列帧按实际帧清单截取，二者输出 GIF。`source / start / end` 只保留来源与时间证据，物理片段不再是 `type=segment` 的引用资产。ffmpeg 和哈希 / 缩略图重活不得持库锁。命中时间角标与完整任务控制面板另行供稿，不在本轮自创样式。
