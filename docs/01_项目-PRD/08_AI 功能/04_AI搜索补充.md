## 04. 关于 AI 搜索的补充

CLIP 类向量只记录静态画面（"是什么"，不含运动信息）。我们垂直是动画师，动态语义需要补充两条路线，推荐组合使用：

1. **抽帧静态向量：** 动图、视频、序列帧抽取关键帧分别提取 CLIP 向量，聚合入库，覆盖画面内容。
2. **运动描述文本化：** 用视频理解模型为动态素材生成运动描述文本（如"火焰从中心向外扩散"），作为文本入向量库——用户搜"爆炸特效"时命中的正是运动描述。
3. 时空向量模型（InternVideo / X-CLIP 等）确实存在，但模型重、需要本地 GPU，列为技术观察，不进主线。

#### 分段语义索引（时间轴定位）

- **覆盖范围：** 视频、动图（GIF / APNG / 动态 WEBP）、序列帧包。
- **手动触发：** 用户选中素材或文件夹后点击"分析"，分析过的素材才纳入语义搜索（未分析素材的分词搜索不受影响）。
- **两档分析：**
	1. 粗略分析（快）：镜头切分（场景检测，动图与序列帧可按帧段细分）+ 抽帧提取 CLIP 向量，本地完成、无大模型调用，画面内容可搜。
	2. 详细分析（慢）：在粗略基础上，每段送视频理解模型生成动作与内容描述，并进行台词提取。可 API 或本地模型，后台队列、断点续跑。
- **台词定位：** 优先解析字幕——外挂字幕（srt / ass）直接读取，内封字幕轨用 ffmpeg 提取，零成本最可靠；无字幕时走 ASR 语音识别（whisper / faster-whisper，本地可跑、自带时间戳）；烧进画面的硬字幕不做 OCR（成本高、准确率低）。台词按"起止时间 + 文本"入索引，搜台词即可定位时间轴。
- **索引结构：** 分段索引条目 = 素材 ID + 起止时间 + 类型（画面 / 台词）+ 向量 / 文本，属派生数据、可重建。
- 命中的优秀片段可一键沉淀为新素材：**虚拟片段**（metadata 记录来源 ID 与起止时间，零磁盘开销，见 [[01_资源与数据]] 数据格式第 6 条）或 ffmpeg 物理截取为普通新资源，完成"找到 → 定位 → 剪下 → 归档"的参考库闭环。
