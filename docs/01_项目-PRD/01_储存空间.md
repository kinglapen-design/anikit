> 2026-08-04 定稿（依据 `docs/归档/00_修改与需求/01_新PRD/01_储存空间.md` 与讨论定案）。本文定义库的外层——储存空间；库内数据模型（Asset / Placement / metadata / folders.json）仍以 [[01_资源与数据]] 为准。

## 01. 概述

AniKit 分为库式资产管理和索引式工作空间，两个模式之间涉及频发的互相导入；动画制作与后期合成中涉及大量素材链接，**路径稳定性优先级最高**：素材能不做实质物理迁移就不做，数据变更才是核心管理模式。多素材库同样遵守这一理念——所有素材封存在统一 assets 池，多资源库用不同的数据文件记录和区分。

## 02. 空间结构

assets、各资源库、工作空间统一放在 AniKit 储存空间下；整体搬迁时，所有相对路径维持以储存空间根为锚点的稳定状态：

``` text
AniKit（储存空间）
├── space.json     空间标志与元数据：{version, name, createdAt, autoImport, libraryOrder}；校验 = 可解析 + assets/ 存在（缺失自愈补建）
├── assets/        统一素材池：所有资源库的素材平铺为 {ID}.info，跨库投递零物理迁移
├── 自动导入/     收件箱（空间级共用，2026-08-12 用户定）：盘符挂载恒定指向它、不随切库变化；自动导入目标 = 当前打开的库。注：盘符显示名继承目标卷卷标（subst 机制，免管理员不可按映射改名），与目录名无关
├── inbox_blocked.json  自动导入搁置清单（2026-08-13 用户定案）：取消冲突 / 失败过的条目不再自动重试（按 条目名+大小+mtime 标识），只能"工程文件"区块右键手动入库
├── 资源库-1/      库 = 纯数据：folders.json 等 5 数据文件 + backup/（cache/、vectors/ 同为库级）
├── 资源库-2/
├── ...
└── workspace/     索引式工作空间（唯一，创建空间时建空目录，功能阶段九接）
```

- 回收站、最近使用等记录为库级数据；删除判定升级为**跨库引用计数**——资产仍被任一库引用时，其他库的删除不动物理 info。
- 全局配置（储存空间、资源库列表与设置）仍存系统配置目录（见 [[06_数据]]）。

### assets 池访问纪律（2026-08-12 讨论定案）

多库共池意味着 assets/ 承载全空间去重后的全部 info 文件夹，量级按十万级设计。NTFS 单目录条目上限约 43 亿，容量无虞（Eagle 素材池同为 `{ID}.info` 平铺结构，十万级实证可用）；性能关键在于**按名访问走 B+ 树索引 O(log N)，与目录大小无关；全目录枚举 O(N)，随规模劣化**。由此定三条：

1. 热路径**禁止枚举 assets/ 根目录**，一律按 ID 推导路径直接访问；必须全量遍历的维护操作（一致性校验、孤儿 info 清理）分批后台执行。
2. `ID → info 文件夹路径`的推导在代码中**收敛为单一函数**，所有调用点只经此函数——为未来可能的分桶（按 ID 随机段分一层子目录）留单点改造口，当前不做分桶。
3. assets/ 对用户是黑盒：资源管理器直接打开十万级目录会卡死，文档与安装建议中引导用户将杀毒 / 备份工具排除该目录。

## 03. 入口

### 3.1 初次打开

欢迎界面（设计稿 38_向导，主窗口内全屏层）：入口帧「新建储存空间 / 打开储存空间」+ 四步设置（每步可直接下一步跳过）：

1. **配置储存空间**：输入空间名称 + 选择保存路径（新建）；「打开储存空间」选已有目录——所选文件夹非 AniKit 空间结构时弹出报错（校验依据 space.json + assets/，见 02 节）。
2. **创建资源库、开启自动导入**（2026-08-12 修订：原"开启工作空间"改为自动导入开关，按 38 稿；工作空间开启留阶段九在设置中开启）。**自动导入 = 空间级设置**（space.json，2026-08-12 用户定：inbox 空间级共用；菜单"新建资源库"16 稿弹窗因此无此开关）。关闭时：不挂载收件箱盘符、不监听；点击快速访问「自动导入」弹确认窗，确认即开启并进入视图（2026-08-12 用户定）。
3. **安装浏览器扩展**（见 [[09_浏览器插件]]，后续版本，向导中占位）。
4. **安装桥接插件**（动画软件桥接，见 07 动画软件通信，后续版本，向导中占位）。

打开已有空间后：空间内有库 → 打开该空间最近使用的库进入主界面；无库 → 直接进入第 2 步创建首个库。存量旧版库结构（库根自含 asstes/）不迁移，打开时报错引导新建（2026-08-12 定）。向导期间主窗口不显示（遮罩纯色不透明）；未配置完成（无空间无库）时关闭向导 = 直接退出程序（2026-08-12 用户定：没完成连储存空间都没有，打开软件也没意义）。落盘时机：前两步"下一步"仅校验暂存，第四步"完成"才真正 create_space → create_library——中途退出零落盘，重启必再弹向导（2026-08-12 用户走查定案）。

### 3.2 资源库管理

- 切换资源库的二级菜单中可新建、切换资源库。
- 库列表 item（08 稿）：移动抓手 + 品牌徽章 + 库名（标题档）+ 当前库对勾 + 删除×；**抓手拖动排序**（拖动时其他 item 跟随移动动画，松手即到位），自定义顺序持久化于 space.json `libraryOrder`（新库排尾，列表按此排序返回）；**删除×** = 删除资源库（确认弹窗：库内数据文件删除不可恢复），删除当前打开的库时自动切到剩余第一个库、无剩余则回第二步创建（2026-08-12 定）。**孤儿素材清理**（2026-08-12 用户定案，统一池保留 + 引用计数）：弹窗统计"仅该库引用的素材数"（引用口径 = 各库 folders.json ∪ recycle.json），复选框默认勾选"同时删除 N 个仅该库引用的素材文件"——确认后这些 info 实体从 assets 池一并删除，跨库共享的保留；不勾则全部留池。
- 储存空间可创建多个，不同空间内资源**完全独立、不互通不共享**；跨空间互通走导出素材包 `.anikit` 导入合并（后续版本）。
- 每个储存空间内允许建立多个资源库，多个资源库允许合并为一个。**合并资源库（2026-09-26 功能轮定案，稿 = 布局/模态窗口/合并资源库）**：菜单「仓库 ▸ 资源库 ▸ 合并资源库」（无当前库 / 空间内不足两库不可点）弹 498 宽弹窗，列表 = 当前空间其余库（libraryOrder 序）+ 容量列（该库引用资产 metadata.size 求和——资产实体在空间级 assets 池共享，"库容量"= 引用合计），行级对勾多选，确认后勾选库**并入当前打开库**、源库目录删除。合并口径：素材实体不动（池共享）；源库 folders.json（区块 / 文件夹 / Placement）/ recycle.json / recent.json / pins.json / archives.json 全量并入——文件夹 / 区块 id 撞车才重生成并同步改全部引用（parent / block / Placement.folder / archives.folderId / pins.target / 空间级 relations.json 档案端点 + 档案封面文件名前缀），默认区块「dir」两库同一个不重复并；同名不去重（库允许同名同类口径），仅完全重复（同资产 + 同文件夹 + 同名）的 Placement 跳过（origin 转移给已存在条）；一资产库内 origin 恒 ≤ 1——目标库已有 origin（含回收站快照）的资产，源 origin 降级为链接；回收站同资产条目并成一条（placements 取并集、deletedAt 取早）；最近使用同资产保留最新截 500；档案封面文件跨库拷入目标 cache/covers/；tags.json 不并（标签体系已取消）。目标库合并前强制备份（失败即取消），合并后清撤销栈（栈内快照绑定合并前状态）；relations.json 中指向源库的端点 lib 改写为目标库。
- 工作空间默认唯一 `workspace` 文件夹，用户按习惯和项目自建层级；可在设置中将其以目录联接（junction，Windows 免管理员权限）映射至其他路径，供用户在资源管理器内直接操作（不考虑散落在各处的既有项目文件夹——用户经 UI 导入或在 UI 内创建项目）。

### 3.3 扩展 / 插件

浏览器扩展经汉堡菜单 → 设置安装；动画软件桥接插件经设置或工具栏插件面板安装与卸载。

## 04. 工作空间链接落盘（2026-08-02 讨论定案）

素材从资源库链接至工作空间目录时，**链接真实落在磁盘上**，而非 UI 虚拟节点（虚拟节点与索引式"磁盘实况"相冲：热刷新要开口子、资源管理器所见不一致、操作需特判）：

- 文件级 = NTFS **硬链接**（同卷免权限；workspace 与 assets 同处一个空间，天然同卷）。链接文件就是真实文件：动画软件可打开、资源管理器可见、外部引用路径稳定；文件改名不影响链接目录项的名称（如库内"男人_走路"、链接处"张三_走路"）。**跨卷约束（2026-08-14 用户确认）：硬链接不能跨盘符——junction 映射到异盘时链接落盘失效，回退口径（复制 or 拒绝提示）随阶段九工作空间一并定；硬链接功能（原 2.9）同因挪阶段九实施。**
- UI 识别：扫描时比对 NTFS fileIndex（文件索引号），相同即同一文件的两个目录项——自动打链接标识，hover 展示该文件的全部链接位置。
- 文件夹 / 档案整体不物化（避免数据层与磁盘双向同步的高耦合）；需要时提供"物化到磁盘"动作，批量落成硬链接。
- 删除链接仅删目录项，库内素材数据不受影响。

**不用工作空间的直接引用路径（2026-08-14 用户场景确认）：** 素材机械盘冷存、工程固态盘求打开速度、不开工作空间的用户，可直接引用 info 池真实路径（右键"复制文件路径"）；库内改名后磁盘名同步（含序列帧帧文件），旧路径失效 → 库里复制新路径去软件重新链接即可。纪律：assets 池只许库内操作，用户不手动动池内文件。
