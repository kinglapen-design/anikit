## 01. 导入素材

很多用户吐槽 eagle 的原因是，他们自己整理好的素材拖入到 eagle 就被打乱了，虽然 eagle 有导入文件夹的选项，但功能藏得很深。还有 eagle 会强制复制一份，增加磁盘压力。

我们提供导入文件、导入文件夹两个选项，均支持菜单触发与拖拽触发。

- **导入位置：** 导入文件直接导入至当前视口停留的目录；导入文件夹直接导入至根目录；拖拽至文件树某个文件夹上时，导入至该文件夹。
- **导入弹窗（27_导入 稿，2026-08-12 落地）：** 320 宽纯标题弹窗，两组选项 + 确认，而非四个互斥按钮；组序按稿——来源组在上（双组时带下分隔线），结构组在下。
	- 来源：复制（默认）/ 剪切；
	- 结构（仅导入文件夹时）：保留层级（默认）/ 剔除层级递归导入。
- **剪切导入：** 物理移动文件进 info 文件夹，源位置不再保留，弹窗文案必须明示风险（稿定文案"剪切导入有风险，谨慎选择"，2026-08-12 取代原"源文件将被移走"）。
- **剪贴板导入：** 支持直接粘贴剪贴板内容导入（如截图），无需先保存到本地再拖入；默认存为 PNG，以时间戳自动命名（如 剪贴板-20260717-1718.png），重名追加 _序号。图片格式识别 = PNG / CF_DIBV5 / **CF_DIB 兜底**（2026-09-17 实机走查修订：QQ·微信截图等只写 CF_DIB 的软件此前读不到，已补直读；「自定义缩略图 - 从剪贴板」同链路生效）。**2026-08-14 扩：base64 文本（data URI / 裸 base64）也纳入剪贴板导入**——解码后按文件魔数定扩展名（psd / psb / png / jpg / gif / bmp / webp / wav / mp3 / mp4 / mov / svg），魔数不在表内一律不认（普通文本可能是合法 base64 字符集，防误判入库）；命名同时间戳口径（如 剪贴板-20260814-1359.psd）；单文件上限 512MB，超出提示先存成文件再导入。
- **导入失败提示（2026-08-14 用户定）：** 导入结束有失败项时弹 alert 错误模板弹窗（48 错误徽章 + 侵入式提示音），描述只列失败文件名（多个依次竖排、间距 8px）；主按钮"重试"= 按原导入参数重投失败项，次按钮"退出" = 纯关闭。
- **收件箱 Inbox（工作中素材/模板快速入口）：** 库内设独立 Inbox 目录，解决封闭库"先存磁盘、再拖入、再删源文件"的繁琐。**2026-07-25 修订：Inbox 不是工程收纳器，不再对一切文件自动过境**——工程文件（fla / aep 等，含"一段表演单独存下来"的素材模板工程）不支持自动导入；自动入库对象收窄为**白名单可视素材格式**（当前 = 4.2 可出缩略图口径 + 视频 mp4 / mov / avi / mpeg4 / m4v + 音频 mp3 / wav / wma：png / jpg / jpeg / bmp / webp / gif / psd / psb / svg / ai / mp4 / mov / avi / mpeg4 / m4v / mp3 / wav / wma；音频于 5.1 波形/元数据就位后扩入，2026-07-26）。**不反向枚举工程格式**（枚举不完）；白名单以外一律不自动导入，只作磁盘实况展示。工程文件自动转移有两条硬伤：占用期物理上移不动；后台移动会改掉动画软件"最近打开"的路径语义（恢复文件如 RECOVER/.blend1 也要求留在原目录原位）。
	- **盘符入口：** Windows 用内置 `subst` 命令把 Inbox 挂载为盘符（如 A:），另存为对话框直接可见；启动时挂载、退出卸载，托盘提供挂载开关（用户可手动卸，启动时重挂）；mac 无 subst，用符号链接 + Finder 收藏替代（适配时补）。
	- **监听管线：** `notify`（Rust，Windows 走 ReadDirectoryChangesW 增量事件，非轮询、常驻零 CPU）监听 Inbox；媒体类新文件先做**写入完成检测**（大小连续 N 秒稳定且可打开，防止写到一半被移走），再触发导入管线；文件被占用时延迟重试。
	- **两个区块（2026-07-25 与用户定案）：** ① **工程文件**——直接扫描 Inbox 磁盘实况展示，不建档、不写库数据、不建持久状态；热刷新必须准确，新增 / 删除 / 重命名 / 占用变化都不能丢失实际文件显示（防黑箱）。区块提醒文案写死："工程文件不支持自动导入，请手动导入"。右键只给轻量文件操作（打开 / 重命名 / 删除）与手动导入；**手动导入 = 移走入库（剪切语义）**，入口必须明示"源文件将从收件箱移走"（复用剪切导入警示）——不用复制入口：复制会让磁盘实况与库内资产在 UI 上长期并存两份，用户困惑。导入后工程文件从"工程文件"区块消失，"已导入"区块出现对应资产；后续用户整理到何处是用户自己的事。② **已导入**——写入库数据的资产：媒体类自动导入与工程文件手动导入后都进入这里。
	- **过境语义（仅媒体类）：** 可自动入库的媒体类仍只作过境，导入后即移走；工程文件不适用过境语义（不自动移走）。重名与 hash 冲突走"导入即建档"既有规则——**撞 hash 一律走"重复添加提示"（冲突挂起弹窗），含自动导入，不再区分渠道**（2026-08-13 用户定案：废除同渠道静默合并；该方案原为 AN 工程恢复文件 RECOVER 不停自动导入准备，工程文件已不自动导入，场景随之消解）。**取消冲突 / 导入失败不再自动重试（2026-08-13 用户定案，二轮）**：跑过一次导入管线的条目记入空间级搁置清单（`inbox_blocked.json`，按 条目名 + 大小 + 修改时间 标识"那个文件对象"），重启存量清点、改名 / 内容变化等事件都不得再次触发自动导入——搁置条目留在"工程文件"区块，由用户右键手动入库；改名保持拦截（记录随名平移）、删除清记录、同名新文件（mtime 不同）视为新条目照常自动导入。
	- **伴生缩略图候选（规则前置，实现归 8.2）：** 不做"扫描同名 gif/png 并过滤出 UI"的隐式规则（会误伤真正需要同名的工程 + 图片两个文件）；同基础名工程与图片/动图只做**双向候选提示**，且**工程未入库不参与判定**——图片/动图入库时查库内已入库的同基础名工程；工程手动入库时再查库内已入库的同基础名图片/动图，命中同一条候选，工程先进还是伴生图先进都无所谓。候选只提示不过滤，用户确认"设为预览图"后才把媒体收进该工程 info 作 cover/sidecar 并撤掉其独立 Placement，选"两者都要"则保持两个独立资产。候选不建持久状态文件，基于库索引即时比对（磁盘实况里的未入库工程不算）；确认绑定才写数据。
	- **编辑器贴图直链（2026-10-23 用户定，插件面板「编辑器贴图直链」条目）：** Typora / Obsidian 的粘贴图片动作经小工具（Typora 自定义上传命令 = `anikit-paste.exe` / Obsidian 粘贴插件）**直接拷入收件箱**（唯一时间戳名 `贴图-yyyyMMdd-HHmmss-fff`），走既有自动导入管线（move 语义、写入完成检测、撞 hash 冲突挂起、白名单口径全继承），文档当场拿到 by-name 链接（解析形态见 [[09_链接]]）——附件入封闭式素材库、md 链接稳定不死，"附件目录指 Z 盘被移走丢链接"的用法由此替代。AniKit 未开时文件躺收件箱（盘符卸载不影响真实目录），下次启动存量导入后链接即活。Typora 受其自定义上传命令能力边界只回 http 图片形态；Obsidian 插件写双形态（http 渲染 + anikit:// 点击拉起）。小工具经 `%APPDATA%\AniKit\config.json` 的 spaces[0] 推收件箱真实目录、读 `mcp-server.port` 取实际端口。
- **序列帧打包（27_导入 稿 §3，2026-08-12 落地）：** 导入检测到序列帧时追加弹窗"检测到序列帧"，提供打包导入（默认）/ 分散导入单选（来源已在导入弹窗选过，本窗不重复）；误打包可在素材上右键解散为独立文件，漏检可多选后右键手动打包。**解散序列帧包导入（2026-08-20 用户定，5.2 落地）：** 素材卡片右键「解散序列帧包导入」→ **alert warning 危险弹窗**明示后执行——每帧**移动**出库建档为独立素材（新 ID、独立 info、逐帧 sha256 与缩略图，落点 = 原包 origin 所在文件夹、段首前插保持帧序、显示名唯一化），原序列帧包整体删除（info 目录物理删除，**逐帧笔记随之一并删除**，原包全部 Placement 清除）；**不可撤销**（不进 undo，与回收站彻底清除同级），任一帧建档失败整体回滚（已移帧移回、已建 info 清除）。

> 保留层级，不代表我们真的保留层级，而是将用户的层级关系直接写入数据（按原结构创建文件夹节点与 Placement），让素材导入进来就保持原有层级；剔除层级则是全部平铺进目标文件夹。

导入即建档：按 [[01_资源与数据]] 的流程生成 ID、metadata、hash 查重、缩略图；**hash 冲突不即时打断**——冲突项挂起收集、其余文件照常导入，全部完成后逐个弹窗询问（「重复文件提示」，2026-08-04 设计定稿，取代原 10_重复添加提示交互）：每行左右对照（已存在文件 vs 新的文件：缩略图 / 名称 / 大小 / 所在位置标签）+ **radio 三选一**（作为新链接导入 = 关联文件夹，默认 / 作为新文件导入 = 保留两个副本 / 用已存在文件导入 = 已有资源的原始 Placement 移至当前目录；落点不设限——含未分类，2026-08-13 用户定"不替用户做整理决定"，原"候车区收窄只留作为新文件导入"作废）+ 行尾**导入/跳过开关**（可逆切换，跳过行压暗标记）+ **「全部跟随」开关**（默认开：改一行决策全部行跟随；关掉后逐行精调）；**确认 = 按各行决策执行；取消 / 关闭 = 全部跳过**（源文件保留）。~~底部内嵌批量重命名~~（**2026-08-13 用户定：过度设计废除**——"导入就是导入，只选择怎么导入；要命名导进来再说"，批量重命名归独立弹窗，见 [[02_文件整理]] 14）。fla 等无缩略图的文件走 7.1 插件补图。
