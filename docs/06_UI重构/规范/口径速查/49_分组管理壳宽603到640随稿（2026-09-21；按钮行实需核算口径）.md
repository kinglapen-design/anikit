# 49 分组管理壳宽 603 → 640 随稿（2026-09-21；按钮行实需核算口径）

> 用户实机报分组管理底栏「按钮都挤在一起了，重新计算面板宽度，保证按钮间距是常规的规矩」。

## 账与定案

底栏四钮（宽自适应 + 左右 48 口径）：添加分组 160 / 添加空组 160（稿外件 2026-09-17 增——稿底栏只画三钮）/ 取消 128 / 确认 128 = 576，加 gap 8×3 = 600；603 壳底栏内宽仅 579（603-2 边-24 padding）——**超 21px，四钮挤满贴边**。这不是按钮罩失效（48 自适应一直生效），是壳宽装不下按钮行。

**定案：壳 603 → 640 随稿**（02_样式标注稿值，§42「稿 640 未随」待办勾销）——640 内宽 616，四钮 600 余 16 从容。GroupEditDialog 保持 603（底栏两钮 264 无挤压；与分组管理的统一在组卡片语境，宽度各随各稿不强行拉齐）。

## 口径（模态窗宽度核算）

模态窗定宽须过一遍按钮行实需：**Σ(按钮内容宽 + 96) + gap×(n-1) + 壳 padding ≤ 壳内宽**。不足时随稿加宽或重排，**禁止靠挤压消化**（挤到贴边 = 按钮行已超宽的信号，先核算再交付）。后续新增底栏按钮（尤其稿外件）要重算一次——本次病灶正是稿外「添加空组」增钮后没人重算壳宽。
