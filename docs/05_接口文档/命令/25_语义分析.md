# 25 语义分析

本文记录本地语义分析、检索与外部详细分析的命令接口。基础画面检索离线运行，外部详细分析只在用户配置 provider 后执行；应用不安装或管理 Ollama，也不内置 LLM。

## 模型与运行环境

`get_semantic_settings` 返回 `{ device: "cpu" | "gpu", modelDir: string | null }`，`save_semantic_settings` 接收 `{ settings }`。默认 CPU；GPU 使用 DirectML，初始化或推理失败回退 CPU，并在同一模型 revision 内复用回退结果，不逐帧重复初始化 GPU。运行中的任务固定启动时的模型与设备，设置变更在下一任务生效。

`test_semantic_runtime` 返回 `requestedBackend / actualBackend / modelDir / runtimeDir / dimension`。`actualBackend` 是实际执行后端，不是用户选择的设备；模型为 512 维 multilingual-v1 文本塔与配套 CLIP ViT-B/32 图像塔。`modelDir` 可指向离线模型包，清单固定 revision、权重 SHA-256 和 512 维；公开发布下载源尚未定稿，不能将 spike 目录当正式模型包。活动分析任务期间拒绝测试新配置，提示先完成当前任务，避免把旧任务的实际后端误报为新配置的回退结果。

worker 是独立 `semantic-worker.exe`，主进程经 NDJSON 调用，不加载 Python/PyTorch。每次响应最多等待 180 秒，取消会终止对应子进程；文本塔最后使用超过 120 秒会卸载。CPU 与 DirectML 的私有运行时 DLL 随便携包携带。

## 基础分析任务

`start_semantic_analysis` 接收 `{ request: { assetIds?: string[], folderId?: string, recursive: boolean } }`，返回 taskId。视频、GIF / 动态 WebP / APNG、序列帧按 4 秒窗、3 秒步长采样，每窗最多首中末三帧，场景切分点辅助切镜。视频记录真实 PTS；动图累计 delay 并保留帧索引；序列帧按实际帧清单和 fps 保存时间与帧索引。APNG 由真实文件内容判定，不与 PNG 序列帧混淆。

2026-11-07 起静态 PNG / JPG / JPEG / WebP / BMP 也可进行基础分析：直接读取原图，每张只写一个 `visual` 向量，起止时间为 0、帧索引为空，`analysis_version` 保持 1。静态图可参与语义搜索和正常预览，但不显示时间徽标，不开放详细事件分析或虚拟 / 物理片段创建；既有媒体索引不失效。

任务查询与控制：

- `get_semantic_analysis_task` / `list_semantic_analysis_tasks`：读取当前库任务及逐项错误，其他库的任务不可见。
- `pause_semantic_analysis` / `resume_semantic_analysis`：暂停与恢复。恢复中断任务可能创建新 taskId，因此 resume 返回 String，而非 void。
- `cancel_semantic_analysis`：取消当前任务，已取消的未完成项可重试。
- `retry_semantic_analysis`：重试失败和未完成素材，返回新 taskId。

`TaskSnapshot` 包含 `libraryRoot / assetsDir / device / mode / actualBackend / status / total / completed / errors`，其中 `mode` 为 `basic` 或 `detailed`。事件 `semantic-analysis-progress` 另含 `taskId / currentAssetId / error`。默认同时只有一个活动任务，异常退出会注销运行态并允许失败重试；恢复和重试保持原分析模式。取消幂等，迟到的单项完成不会把已取消任务翻转为完成。任务完成后，前端按各面板当前视口重新执行语义查询，更新 segmentId 后再允许创建片段；监听在 App 初始化时注册，覆盖 MCP 启动的任务。

索引位于库根 `vectors/semantic.sqlite3`，属于可重建派生数据。`analysis_version = 1`，数据库 schema = 4；旧版本任务表会迁移真实后端字段，已有任务的模式默认为 `basic`。失败的基础分析会移除旧画面向量，外部增强失败只记录错误，不删除已可用的基础结果。

## 资产分析状态

`get_semantic_asset_status` 接收 `{ assetId }`，返回 `{ analyzable, segmentCount, detailedCount }`。`analyzable` 与基础分析目标同口径（视频 / 动图 / 序列帧 / 常见静态图，排除 hidden 与虚拟片段）；`segmentCount` 为当前模型版本与 `analysis_version` 下的有效分段数；`detailedCount` 为 `semantic_documents` 中 description / event 文档数。只读不写；模型目录未配置或索引不可读时两计数按 0 返回（`analyzable` 不受影响）。APP 详情面板「基础信息」基本数据区块末位据此行式展示（未分析 / 基础 N 段 / 基础 N 段 + 详细 M 条），分析任务完成后自动刷新。

## 语义检索

`semantic_search` 接收 `{ query, scope, limit? }`。`scope` 与 `search_assets` 相同，沿用视口、递归、全局、回收站、hidden 和筛选语义。未分析素材不自动加入索引，也不会在查询时触发分析。

范围查询性能口径（2026-11-03）：先用候选 assetId 集检查当前模型版本的有效片段，范围内没有片段时在模型清单加载与文本推理前直接返回，`actualBackend = "unknown"`。非全局查询在读取向量二进制与相似度计算前过滤范围外资产，并在范围内排序截取 Top N；不再先取全库 Top N 再过滤。全局查询维持原全库扫描路径。

返回 `{ hits, actualBackend, modelRevision }`。每个 asset 的 `best` 是分通道融合后排在首位的片段，`segments` 按同一顺序最多返回 8 个片段，`matchCount` 是该 asset 当前模型版本的片段总数。`placements` 保留原 Placement 范围，不按多个片段复制卡片。静态图只有 1 个无时间轴片段。

2026-11-07 起，`visual` 与文本类片段分别按原始余弦相似度排名，再以等权 RRF（k=60）融合，同分优先 `visual`。每个素材以最高融合分片段参与排序，不累加同素材多段；只有一个通道时顺序不变。`score` 仍是该片段的原始余弦相似度，只用于通道内排序，不得跨通道比较，也不代表识别或因果置信度。

`SegmentHit` 包含 `segmentId / assetId / startMs / endMs / startFrame / endFrame / score / kind / text`，详细事件另有可选 `certainty`（`observed` 或 `hypothesis`）。预览用 `startMs / 1000` 定位视频，动图和序列帧使用 `startFrame`，禁止按平均 fps 猜变 delay 动图的落点。`best` 为融合首位，但 `description` 段覆盖近全片、起点恒近 0，无定位价值——凡「定位」语义的消费（预览跳转 / 卡片徽标 / 创建片段 / 卡片起播点）统一按 `pickLocateSegment` 在融合顺序中取首个非 `description` 窄段；2026-11-07 起不再固定优先 `event`。

## 外部详细分析

`start_detailed_semantic_analysis` 接收 `{ assetIds }`，要求先有同模型版本的基础分析和一致的源指纹。外部输入最多 24 张真实证据帧，长边不超过 768，保留真实时间戳和原始帧索引；稀疏采样不代表看完整段视频。

provider 配置：

- `get_semantic_provider_settings`：返回 `{ settings, hasKey }`，不返回密钥。
- `save_semantic_provider_settings`：保存 `kind / endpoint / model / timeoutSecs`；`kind` 为 `openai-compatible` 或 `ollama`。endpoint 和 model 同时留空表示未配置；对外服务使用 HTTPS，HTTP 仅本机回环地址。
- `set_semantic_provider_key` / `clear_semantic_provider_key`：写入或清除 Windows 钥匙串，清除不存在项也成功。密钥不进入 config.json、日志或接口回包。
- `test_semantic_provider`：返回 `{ ok, message, latencyMs }`。OpenAI 兼容服务优先 `/models`，Ollama 优先 `/api/tags`，只访问用户配置的地址，不启动外部进程。

详细分析使用 OpenAI `/chat/completions` 或 Ollama `/api/chat`，不混用接口格式，也不假设原生视频输入。输出 description 与有序 events，事件必须引用输入证据帧，且时间区间覆盖至少一个证据帧。observed 仅表示可观察的连续事件；hypothesis 表示不确定的候选因果，不能将先后关系写成确定因果。**不合规事件逐个丢弃不入库，不再整单失败（2026-11-02 容错口径）**——模型对单个事件编出落空区间属随机失误，description 与其余合规事件保留；description 缺失或帧数校验失败仍整单失败。任务固定启动时的 provider 配置，避免同一批素材混用不同服务；重启恢复或失败重试读取当时的 provider 配置。前端入口为素材右键「AI 工具集 → 详细语义分析（外部服务）」，与基础分析共用任务进度。

外部描述、事件、provider、模型、prompt 版本、源 JSON 与证据帧时间戳存 `semantic_documents`。文本随后由本地同一 CLIP 文本塔编码，因此详细分析完成后可离线搜索。基础重分析或源指纹变化会清除旧的外部文档；provider 调用或校验失败不删除既有基础结果。

## 命中片段

`create_semantic_segment` 接收 `{ request: { assetId, segmentId, targetFolderId?, physical? } }`，`physical` 缺省为 `false`。`assetId + segmentId` 必须来自当前模型版本和源指纹一致的索引；不允许嵌套虚拟片段。应用内创建前会重新查询当前面板，避免分析完成事件与点击之间的竞态。`targetFolderId` 缺省为未分类，创建进入普通撤销事务，MCP 另逐次检查写入闸并广播 `mcp-library-changed`。

虚拟片段沿用 `AssetMeta.type = "segment"` 与 `source / start / end`，start / end 为来源时间轴秒数；动图和序列帧另有 `startFrame / endFrame` 原始索引（0 起、含端点）。info 只保存 metadata 与区间缩略图，不复制媒体实体。`get_media_source`、`list_sequence_frames` 和 `start_anim_stream` 在虚拟片段返回可选 `segment`，范围与 `SegmentRange` 同构。预览以源 PTS 或原始帧索引限界；来源失效或缺索引明确报错，不静默播放完整源文件。

物理片段经 ffmpeg 重编码为独立普通资产，可脱离源文件播放。视频输出 MP4，动图按原始帧及逐帧 delay 导出，序列帧按实际帧清单导出 GIF；后者在容器时间精度内保持顺序和时长。`source / start / end` 及可用的原始帧索引仅保留来源证据，`type` 为空，不依赖源引用。ffmpeg、哈希与缩略图生成在库锁外完成，提交 Placement 时才加锁。

## 验证边界

基础媒体分析、中文检索、CPU / DirectML、取消、APNG 与真实末帧 PTS 已做真实验证。外部 provider 已通过本地回环完整闭环：真实 GIF 基础片段 → OpenAI 兼容假服务 → observed / hypothesis 与证据时间落库 → 中文离线检索；基础画面向量保留、源指纹不一致拒绝，dummy Windows 凭据写入 / 读取 / 清除通过，未使用真实配置、密钥或额度。

真实界面已完成搜索菜单、相关度顺序 / 计数、三类媒体定位、右键创建片段、三类虚拟范围播放与物理单帧验收；MCP 32 工具实调通过。重分析后命中会刷新，创建前再次重查。独立便携包在不覆盖模型 / worker / 运行时路径时，包内 CPU、检索、片段、ffmpeg sidecar、ORT / DirectML 和 MCP 全链通过，ZIP 完整性通过。最终全量后端 703 项通过、0 失败。千帧耐久与真实第三方 provider 联网验收未做，不据此承诺动作 / 因果识别准确率。
