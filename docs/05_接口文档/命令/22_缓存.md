# 缓存（设置面板缓存页后端，2026-10-13 落地；PRD `06_数据` §07）

设置页缓存区块的数据源：分组占用统计 + 按类别一键清理。覆盖对象全部是**可重建缓存**，清理不动任何用户数据。红线两条：工作空间侧 `.anikit/workspace.json`（常用固定 + junction 台账）绝不可删；库侧缩略图只删 metadata 引用与按规则推导的文件，不按文件名后缀盲扫（用户原始文件可能恰好叫「xx_thumbnail.png」，Eagle 导出惯例）。

## 命令

- `get_cache_overview() -> CacheOverview`：分组统计。`CacheOverview = { groups: [{ id, label, items: [{ id, label, bytes, files }] }] }`——资源库组（id `library`）与工作空间组（id `workspace`）恒在、各类条目恒在，前端布局稳定。**降级口径：未打开资源库 → 资源库组各项 0；未打开空间或 workspace/ 目录不存在 → 工作空间组各项 0**（条目不省略）。async + spawn_blocking（目录树遍历不占 tokio worker）。
- `clear_cache(category: string) -> ClearOutcome`：按类别 id 清理。`ClearOutcome = { category, freedBytes, removedFiles, failedFiles, rebuildingThumbs }`——`freedBytes/removedFiles` 只计删除成功项；被占用等删除失败文件跳过并计入 `failedFiles`（播放器持有中的转码产物属此类，不报错不阻断）。**未知类别 id 拒绝**（「未知的缓存类别：xx」，只删枚举内目录，不给任意路径开口）；库类需已开库、工作空间类需已开空间，否则中文报错。async + spawn_blocking。

## 类别 id 与落点对照

| id | 组 | 内容 | 落点 |
| --- | --- | --- | --- |
| `lib-thumbs` | 资源库 | 缩略图与动图 | `assets/{ID}.info/` 内 metadata 引用的 `{stem}_thumbnail.webp/png` + 推导的 `{stem}_anim.webp` |
| `lib-previews` | 资源库 | 预览与帧缓存 | `库根/cache/{previews, frames, note-thumbs, tmp}`（会话级，开库本就会清） |
| `lib-media` | 资源库 | 音视频转码与波形 | `库根/cache/{media, peaks}` + 旧遗留 `waveforms`（已无写入方，一并清） |
| `lib-icons` | 资源库 | 系统格式图标 | `库根/cache/thumbs`（按扩展名） |
| `ws-thumbs` | 工作空间 | 缩略图与图标 | `workspace/.anikit/thumbs`（含按扩展名图标与 exe 文件级图标） |
| `ws-media` | 工作空间 | 音视频转码与波形 | `workspace/.anikit/{media, peaks}` |
| `ws-probe` | 工作空间 | 探测缓存 | `workspace/.anikit/probe.json`（单文件删除） |

`lib-thumbs` 覆盖的是**空间级 assets 池**的全部资产（多库共池，不按库切分）。`.anikit/cache_v2`（缓存命名版本标志）与 `workspace.json` 不在任何类别名单内；库侧 `cache/covers`（档案封面，无自动重建管线）与 `cache/seq-trash` / `cache/covers-trash`（会话内撤销暂存）刻意不纳入统计与清理。

## 清理后的重建口径

- **lib-thumbs → 触发全库缩略图后台重建**（`rebuildingThumbs = true`）：视图层 `views::thumb_path` 只拼路径不判存在，删后不重建 = 卡片破图。后台线程逐资产重建「metadata 有引用但文件已缺失」的缩略图（复用导入同款 `thumbnail::generate` 管线；序列帧从 `frames/` 封面帧取源）；源缺失 / 解码失败回退格式图标（清 thumbnail 引用 + 尺寸/主色，落盘与索引一致，同 origin_sync 手动刷新回退口径）；维护性写不刷 modifiedAt（同主色懒回填先例）。完成时 emit 事件 **`library-thumbs-rebuilt`**（负载 `{ rebuilt, fallback }`），前端可据此刷新列表。**已知代价：自定义缩略图（set_thumbnail_custom 等设的图）重建后回退为 origin 派生图**——自定义图只存为缩略图文件本身，删除即不可复原，清理前 UI 应如实提示。动图播放缓存（`_anim.webp`）不主动重建：卡片播放链懒生成补提交（`anim_preview::ensure_anim_preview` 幂等）。
- **lib-icons → 即时重提**：格式图标无懒生成兜底（仅导入 / 开库两个建立点），清完按在库资产实际扩展名集逐格式 ensure 重提并同步内存 `format_icons`，卡片无 blank 窗口。
- **ws-thumbs**：与 `ws_thumb_queue` 的失败记忆 / 去重键天然兼容——键内嵌 rel+mtime+size，清理不动源文件则键不变；`fresh_thumb_path` 按当前实况重算期望文件名查存在，文件被删即失鲜，下次 `list_dir` 自动重新入队重建，无需额外同步（清理前 `clear_pending()` 摘掉排队任务，在跑任务落盘幂等无害）。
- **lib-previews 注意**：`cache/tmp` 内含「有冲突挂起的剪贴板导入源文件」，清理会使进行中的冲突决策回读不到源（报「文件读取失败」，重新复制粘贴即可）——属用户显式操作的罕见交叠，保留清理能力。
