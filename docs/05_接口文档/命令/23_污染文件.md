# 23_污染文件

> 污染文件业务（2026-10-16，1.0 收尾第 5 项，PRD 03_数据链接 02「污染文件」——6.2 工程恢复文件同物）：资产 info 文件夹内不属于 AniKit 已知文件集的磁盘条目对详情「链接关系」tab 可见。实现 = services/pollution.rs + commands/pollution.rs。

- `list_pollution_files(asset_id: string) -> PollutionItem[]` —— 污染清单（详情区块数据源）：info 单层 read_dir 过滤**已知集**（字段驱动 + 写死名，**禁后缀盲扫**——cache.rs 红线：用户 origin 可能恰叫 xx_thumbnail.png / xx_anim.webp）：
  - 写死名 `metadata.json` / `notes.json` / `annotation.json`（备份清单同口径）；
  - origin 实体（`metadata.originName`）、缩略图（`metadata.thumbnail`）——字段引用做组件级纯文件名校验（拦 `../` 形态）；
  - 动图小动画缓存推导名 `{origin词干}_anim.webp`（paths::anim_preview_file 单点；改名同步改名已随本轮堵增量，存量旧词干缓存会判污染由用户清）；
  - `frames/` 目录仅序列帧形态已知（origin 不在 info 根 + frames/ 存在，sequence::frames_dir_if_sequence 同口径）——其余资产冒出 frames/ 算异物；
  - `PollutionItem { name, path, isDir }`（camelCase）：path = 完整路径（reveal 直传），isDir 分流导入 kind；按名字典序；info 目录缺失返回空（空壳/孤儿治理 = 开库自检另管）；资产不存在报错。
- `trash_pollution_file(asset_id: string, name: string) -> ()` —— 污染条目丢系统回收站（无确认弹窗，工作空间删除同口径，回收站即兜底）：三层校验 = 纯文件名单组件 + 确实不在已知集（永不误删库管文件）+ 存在（不存在报「条目已不存在（可能刚被移动或删除）」），再交 `adapters::recycle_bin::delete_to_recycle`。**不进撤销**（系统回收站即恢复通道）。
- 「打开资源管理器」复用 `reveal_orphan_info`（见 [01_库管理](01_库管理.md)，池内路径校验对文件/目录同适用）；「导入」零新命令——前端走既有 `import_paths`（经 `probeSequences`，`source: "move"` = 导入即清污，落点 = 当前查看位置所在文件夹，序列帧检测 / 冲突挂起 / 进度条 / 失败重试全继承）。
- `scan_pollution() -> PollutionAssetView[]`（2026-10-16 立项，PRD 03_查找文件-05，扫描污染文件弹窗数据源）——全库污染扫描，两段短锁 + spawn_blocking：锁 1 快照 assets 池目录 + 有活 Placement 的资产 meta 集（回收站 / 无位置记录不扫），锁外逐资产 `list_pollution`（判定唯一出处，与详情区块零分叉；单资产 read_dir 失败记 log 跳过不拖垮全扫），锁 2 命中资产装卡片视图。`PollutionAssetView { asset, infoPath, items }`（camelCase）：asset = 复用扫描重复文件 `DupAssetView` 全字段（见 [10_扫描重复文件](10_扫描重复文件.md)），infoPath = info 目录完整路径（「打开资源管理器」直传 reveal_orphan_info），items 同详情区块；排序 = 条目数降序，平手按显示名 + assetId。无主 info（孤儿 / 他库资产）不在此列——开库自检另管。
