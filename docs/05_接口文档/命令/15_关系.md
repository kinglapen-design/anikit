**关系（6.2 一轮，2026-08-23 落地，PRD 03_数据链接 02/06 + figma 02_主窗口选择模式 / 03_数据 item §4）：** 文件与档案之间的关系（kind = `free` 自由关系 / `voice` 音色——voice 随 6.2 三轮链接音频接入；**voice 无称谓**——PRD 音色双向显示『使用的音频 / 在哪些文件里使用过』，label 恒存空串、reverseLabel 恒 None）；数据 = **空间级 relations.json**（关系可跨库——ref 携库名 + 显示名快照，跨库目标未打开 / 目标失效时快照兜底显示；core::relations 单一写点，缺文件按空表加载同 archives 口径）：`RelationsFile = { version, relations: Relation[] }`，`Relation = { id, from, to, kind, label, reverseLabel? }`（**label = to 对 from 的称谓**——雪牧.from 发起选雪天.to 输入"父亲" → 雪牧详情显示"雪天是父亲"；**reverseLabel = from 对 to 的称谓，选择模式备选区右框手动填写**——2026-08-23 用户定不做词典推导，空规整 None 不写字段，反向显示回退 label），`RelationRef = { lib, kind: "asset"|"archive", id, name }`；**开库自检** prune_relations：剔除端点指向本库已失效目标的关系（跨库端点无法校验保留），有改动直接原子写回（空间级文件不在库备份清单）；写命令撤销三步（锁序 library → space → undo——本组为三者同持唯一处，record_file 快照空间级文件天然支持）；服务无改动返回 false 取消事务不进撤销栈
	- `list_relations() -> Relation[]` —— 关系清单（只读；空间级全量返回，前端按当前库过滤显示）
	- `add_relations(fromKind, fromId, kind?, items: NewRelationInput[]) -> Relation[]` —— **批量建立关系**（选择模式确认；2026-08-24 二轮用户定多选累积，替代单条 add_relation）：`NewRelationInput = { toKind, toId, label, reverseLabel? }`；from = 发起文件/档案（kind = asset/archive，archive 的 id = folderId）；**kind 缺省 free**：label trim 必填、to ≠ from、目标存在校验（archive 须 kind="archive" 文件夹）；**kind = voice（6.2 三轮链接音频）**：无称谓不校验 label（恒存空串 + reverseLabel 恒 None），**to 必须是音频 asset（mp3/wav/wma，扩展名小写比较），from 可是 asset / archive**（档案也能链音频，区块体系共用），**from 不得为音频 asset**（2026-08-24 方案 1：voice 恒单向 使用者→音频防递归——音频侧区块 = 标题「使用者」只展示/跳转、无添加钮，报错"「X」是音频文件，不能作为使用方"）；**任一失败全不写**（批量原子）；返回完整记录组（含生成 id `RL` 前缀与显示名快照，前端就地插入免重拉）。撤销标签 free 1 条 = "添加关系"、多条 = "添加 N 条关系"；voice = "链接音频" / "链接 N 条音频"
	- `update_relation(id, label, reverseLabel?) -> void` —— 编辑关系称谓（详情关系 item 点称谓框二次修改，§4 稿注；**换绑 2026-08-24 用户定废除**——"要换就重新再添加"，newTo/newFrom 参数已移除）。撤销标签"编辑关系"
	- `remove_relation(id) -> void` —— 删除关系（详情关系 item ×）。撤销标签"删除关系"
