# 工作空间缓存文件名超长修复（2026-09-26，feat/new-ui）

纯后端缓存命名修复（无 UI 改动）。用户实机报 ws 中文长路径音频 / 视频缩略图必败：根因 = 缓存文件名用整条 URL 编码相对路径，中文每字符 ×9 膨胀，实锤案例编码后 257 字符超 NTFS 255 单组件上限（`\\?\` 前缀也绕不过组件级限制），写盘 Invalid argument → 静默记失败记忆落回格式图标。

- **有界命名**：`job_key` = `{截断≤80的 encode_rel 前缀}-{fnv64hex(rel)}-{mtime_ms}-{size}`——前缀只截完整 %XX 边界保可读，FNV-1a 64bit（手写不加依赖，不用 DefaultHasher）保唯一，mtime+size 内嵌判新鲜，全长 ≤160；缩略图 / exe 图标 / peaks / 失败记忆 / 队列去重共口径，`encode_rel` 收为私有原语。
- **purge_stale 改按 hash 段 `-{fnv64hex(rel)}-` 匹配**（截断前缀不再唯一）；peaks（card_peaks_by_path）同换 job_key。
- **存量迁移**：`.anikit/cache_v2` 标志——开空间时无标志则清空 thumbs/ 与 peaks/ 后落标志（纯缓存可重建，其余内容不动，失败记忆进程级无需迁移）。

验证：cargo test **547 绿**（新增 6 测：FNV 已知向量 / 257 字符场景复现 + 新名有界 / 深中文 rel 生成-命中-purge 全链 / purge 不撞 / 迁移幂等 / peaks 深中文命名有界）+ clippy 零告警；踩坑 092。**待实机复验**：原失败条目缩略图与波形生成。
