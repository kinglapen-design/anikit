# MCP 写入闸偶发回关根治：配置写盘原子替换（2026-09-29，feat/new-ui）

用户报「MCP 允许写入开关自己关掉」（偶发，重启电脑 / 换包后可见，其余设置无损）。根因 = `json_io::write_text_atomic` 旧「先删目标再 rename」实现：删-换间隙进程被杀（强杀/关机）→ config.json 永久丢失 → 启动按默认重建；ui/窗口几何有前端快照随即写回无感，唯 `settings.mcp` / `settings.pluginServer` 等无快照子树静默回默认——「只丢开关」谜底。

- **写点断根**：删-换改 `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 原子替换（无窗口期 + 写穿落盘）；非 Windows 保持 fs::rename。json_io 为全局数据文件共用写点，库文件同类风险一并断根。
- **读侧兜底**：`config::load_from` 目标缺失 + .tmp 完整可解析 → 恢复并转正（半截弃用）。

验证：**551 测绿**（+3：覆盖已存在目标 / tmp 残留恢复转正 / 半截 tmp 回默认）+ clippy 净；release 已换正 portable，冒烟 = 进程起 + MCP initialize 握手通 + config.json `writeEnabled:true` 保留。踩坑 095。待用户日常使用观察开关是否再掉。
