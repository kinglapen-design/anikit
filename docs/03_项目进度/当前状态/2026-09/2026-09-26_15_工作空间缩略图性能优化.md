# 工作空间缩略图性能优化（2026-09-26，feat/new-ui）

纯性能优化（无 UI 样式改动；不换解码库 / 不加依赖 / 不动库侧导入·预览链路）。ws 缩略图链路六根热埂（全尺寸解码 / 每 invoke 裸 spawn 串行线程 / 前端无视口裁剪 / ffmpeg 逐文件串行 / 列举占 tokio worker / 失败无记忆无限重试）按 A/B/C 落地：

- **A 并发 + 去重 + 失败记忆**：新建 `services/ws_thumb_queue.rs` 进程级 worker 池（N = 可用并行度一半钳 1..=4，Condvar 常驻，仿 preview_queue 自管结构）；跨请求去重键 =（workspace 根, rel+mtime+size 缓存键茎），队列中/进行中跳过、执行前重查新鲜度；失败记忆进程级 `HashSet`（存 workspace.rs，mtime/size 变自然失效，不落盘），命中不再重试。**用户可感知变化**：解码失败条目由恒空盒落回系统格式图标（thumbKind=formatIcon）——worker 当场生成图标随事件带回 + 列举 entry() 失败记忆分支同口径；`ThumbReady` 负载新增 `thumbKind` 字段，WsEntry 不加字段。批量回吐 = 凑满 16 或排空 emit 一帧；切空间清 pending。
- **B 列举挪 spawn_blocking**：`list_workspace_dir` / `request_workspace_thumbs` 改 async + spawn_blocking，同步 IO 与 exe 图标 COM 提取（SHELL_ICON_LOCK 保留）不占 tokio worker。
- **C 视口优先**：AssetCard 既有 IntersectionObserver `cardVisible` + ListRowCard 挂载（≈ 视口 + 800px buffer）上报 ws store，120ms 固定节拍合批 `priority=true` 插队队首；loadDir 全量请求不变排队尾后台补发；patchThumbs 按 thumbKind 回填（仅 asset 补 w/h）。

验证：cargo test **541 绿**（新增 6 测：worker 钳位 / 插队保序 / 去重 / 失败记忆重试归零 / 池全量完成 / 列举失败落回图标）；clippy -D warnings 零告警；typecheck 0 错。实测（临时探针）：12 张 4000×3000 PNG 首开串行 1007ms → 池 284ms ≈ 3.5×。**待实机走查**：大目录首开可见区先出图 / 滚动补发跟手 / 损坏文件显示格式图标。
