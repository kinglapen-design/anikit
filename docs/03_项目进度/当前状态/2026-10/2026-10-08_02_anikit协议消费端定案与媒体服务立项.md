# 当前状态：anikit:// 消费端定案与媒体服务立项（2026-10-08）

用户问 `anikit://item|folder` 有哪些消费端 → 全库核查三层全空（仅 menuOps 复制链接生产端；前端无解析 / 系统协议未注册 / 详情 links 只读占位且 shell_open 只放行 http/https / MCP 不经 URI），与 2026-08-21_04 核查结论一致。五轮讨论拍板，纯方案轮零代码。

核心定案 = **双形态分工**：`anikit://item/{id}` = 内部标识符（复制链接 / links 字段 / 内部 MD 引用 / MCP 参数，内部解析消费永不经系统）；`http://127.0.0.1:{port}` = 对外可点击形态（`/item/{id}` 图片渲染 + `/open/item/{id}` 点击跳转回 AniKit，外部编辑器与 AI 客户端零注册零插件）。

逐项：**deep-link 系统注册废案**（2026-08-21 定案作废——/open 端点全替代，「少开一标签」不值注册表 + 单实例转发）；**复制文件路径形态废弃**（info 黑箱不可辨认 + 磁盘名随重命名死链 + Obsidian 不渲染 vault 外）；外部 MD 用图 = 本地 http 媒体服务（ID 寻址改名不死，端口 ≠ 17701 须提醒）；内部 MD = 渲染层解析双形态引用 + 粘贴补全 + 点击渲染层拦截（源码裸语法，勾销 PreviewText 两个 09 待办）；**链接图标快捷入口搁置**（用户自评不如复制粘贴快）；links 输入框可编辑 + scheme 分流跳转；MCP 参数吃 URI + 返回附 http open 形态 uri；**打包导出归 AniKit 侧**（认双形态引用 → assets/ + 改写相对路径，工作空间文档右键直通免导入——外部写文档 → AniKit 打包 → 发送闭环）。
