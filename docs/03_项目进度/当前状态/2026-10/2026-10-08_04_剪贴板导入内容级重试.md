# 当前状态：剪贴板导入内容级重试（2026-10-08）

用户实机报「外部复制一张图片，马上 Ctrl+V 粘贴进 APP 像空值，要等一下才好」。定因 = 单次读取 × 外部程序异步提交剪贴板的竞态：`import_clipboard` 在按键瞬间读一次（图片 → CF_HDROP 文件列表 → base64 文本），而截图工具先走 UI 动画、浏览器复制大图先编码，内容常晚几十到几百毫秒才到，单次读三路皆空报错、被前端静默降级吞掉，表现成「没反应」。修复 = 三路读取收进内容级重试循环（50ms × 10 ≈ 最长 500ms，任何一路有内容即停——有内容 = 写入方已提交完毕），三分支优先级与落盘语义不动。序号仲裁同款竞态（内部剪贴板非空时可能粘出旧内容）与失败静默口径维持原案不动（治它会拖慢内部粘贴手感 / 静默是 2026-07-27 定案）。599 测绿 + cargo check 净。**待实机走查：截图复制即粘 / 浏览器大图即粘 / 纯文本粘贴仍静默 / 内部粘贴手感无回归**。踩坑 107 新立。详见 [开发日志 2026-10-08_11](../../02_开发日志/2026-10/2026-10-08_11_剪贴板导入内容级重试.md)。
