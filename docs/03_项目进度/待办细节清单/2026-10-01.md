**断链口径（随 b 定案）**：**只标记不自动剔除**——目标根被挪 / 改名 / 删除后，链接目录显示「链接失效」态（置灰 / 角标，不弹窗骚扰），右键给「重新指向… / 移除链接」；开空间校验登记清单时失效条目标记保留（区别于 pinned 的静默剔除——目标可能只是挪了，自动剔除会丢修复机会）；不做按卷扫描猜新位置的自愈。

**junction 语义备忘**（讨论结论，防再走弯）：junction = 门不是房间——reparse point 存目标绝对路径、透明转发，名下无任何内容；目标内部文件移动 / 改名不影响（根还在即通），只有目标根本身被动才断链；断链不伤已落盘文件；Explorer 删 junction 只删链接（SHFileOperation 对 junction 的行为仍列 spike 红线验证）。**跨盘符 = 可以**（2026-10-02 用户问后实机实证：E: 建门 → C: 目标经门读写正常；目标只须本机 NTFS 卷，不能指网络 / UNC 路径）——不能跨卷的是**硬链接**（文件级必须同卷，阶段九的课题，与 junction 无关）；/D 符号链接能指网络路径但要管理员 / 开发者模式权限，选型 junction 因此成立（普通用户可建）。

**b 技术清单**（原立项五条保留）：① `resolve_under` 越界口径为登记过的链接子树开口子（登记清单落 `.anikit/workspace.json` + reparse point 扫描校验，同 pinned 机制；现状 = 链接目录能显示但打开即空列表——canonicalize 落根外被拒）；② **spike：RDC 递归监听是否穿透 junction**——不穿透则每个链接目标单独起 watcher，`changed_dirs`（2026-10-01 精准重扫已落地）做「目标前缀 ↔ 链接 rel」双向映射；③ 缓存键 = 链接 rel ⇒ `.anikit` 留空间内、链接目标保持干净（优点）；④ 删除 / 重命名链接本身的语义验证（回收站删 junction 须只删链接 = 安全红线）；⑤ 树 / 卡片的链接标识与 hasSubDir 穿透。

**统一模型与阶段九交汇**（随硬链接批次定，本轮不动）：工作空间 = 真实磁盘结构的统一呈现层——目录级 = junction 纳入（b），文件级 = 硬链接落盘（PRD §04 库素材出库，阶段九）。库素材硬链接落进链接目录 = 落真实目标（junction 透明），同卷成 / 异卷败（跨卷回退 = 复制 or 拒绝提示随阶段九）；库侧链接记录建议存 canonicalize 后真实路径（junction 断则记录不死），随阶段九一起拍。
