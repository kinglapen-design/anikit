## 立项候选（2026-10-01 用户提出，下个会话做）：工作空间 ↔ 资源管理器拖拽联动 + 符号链接方向定案

**背景**：ws 视口当前整体落在 `content.isNoImportView`（stores/content.ts:511），拖入直接弹拒入窗——「只读底座，导入语义未立项」；用户只能在资源管理器里打开 workspace 目录本体拖文件进去。应用内拖拽（卡片→树行/文件夹卡片移动）已有，缺的是与资源管理器的双向联动。

### A. 拖拽联动（先改 PRD 02，再动工）

- **拖入（Explorer → ws）**：App.vue `onDragDropEvent` 全局拖放已有库导入流，加 ws 分支——落点判定（树行 / 文件夹卡片 / 视口空白各挂 data 属性）→ 复制进对应 ws 目录（复用 `copy_entries` 语义，重名 `_n` 规避现有；watcher 热刷新自动回视图，known_ops 回声消重既有）。**决策点：一律复制（非破坏，推荐）还是 Explorer 惯例（同盘移动 / 跨盘复制 + 修饰键）**。
- **拖出（ws → Explorer / 其他应用）**：机制现成、无需 spike——库卡片拖出窗口已走 `drag::start_drag`（CF_HDROP，lib.rs `drag_assets`；dragOperation.ts 在指针越出窗口边界的手势途中一次 IPC 直达 DoDragDrop，踩坑 004 主线程约束）。ws 卡不可用的唯一原因 = 命令入参是 assetId 集、经库 index 解析真实路径，ws 合成假 id 不能进（dragOperation.ts:693 既有排除注释）。而 ws 条目前端本就持有 wsPath 绝对路径、无需解析——落地 = 新按路径版命令（`validated_ws_path` 校验 + 同一 `drag::start_drag`）+ dragOperation 拖出分支（ws: 键 → wsPath 集）。
- **延展项（可拆独立轮）**：库 ↔ ws 互拖——ws 拖入库树 = 走导入流；库卡片拖入 ws = 导出副本到目录。content.ts:510 注释原留「库互通另行立项」。

### B. 符号链接方向定案（用户待决，两向不互斥）

- **方向 a：workspace 整目录链出**（`mklink /J` 指向任意路径）。技术近乎零成本：`resolve_under` 的 canonicalize 口径天然兼容（根与目标都解析到真实位置）；watcher 挂链接路径 = 监听真实目标（RDC 对 junction 根有效）；`.anikit` 缓存跟内容走。代价 = 空间自包含语义破（备份/迁移空间不带工作区内容）。**建议 = 验证 + 文档写明支持（小活），不立大项**。
- **方向 b：外部文件夹链接进 workspace**（推荐立项，符合「工作空间 = 统一工作入口」心智：素材散处挂载进来一处浏览/发送，空间自包含不破，可挂多个，删链接不动外部内容）。PRD 依据：`01_储存空间` 开篇「路径稳定性优先级最高：素材能不做实质物理迁移就不做」即方向 b 的哲学原文；§04 否决虚拟节点的三条理由（热刷新要开口子 / 资源管理器所见不一致 / 操作需特判）对「虚拟挂载」方案同样成立——junction 是磁盘真实结构，与 ws 磁盘实况语义天然同向。技术成本清单：① `resolve_under` 越界口径要为登记过的链接子树开口子（链接清单落 workspace.json 或运行时 reparse point 扫描；现状 = 链接目录能显示但打开即空列表——canonicalize 落在根外被拒）；② **spike：RDC 递归监听是否穿透 junction**——不穿透则每个链接目标单独起 watcher，changed_dirs（2026-10-01 精准重扫落地）要做「目标前缀 ↔ 链接 rel」双向映射；③ 缓存键用链接 rel ⇒ `.anikit` 留空间内、链接目标保持干净（优点）；④ 删除/重命名链接本身的语义验证（回收站删 junction 须只删链接）；⑤ 树/卡片的链接标识与 hasSubDir 穿透。**与 §04「工作空间链接落盘」（库素材 → ws = NTFS 硬链接，文件级 / 同卷，原 2.9 挪阶段九）互补不冲突**：那是出库方向，b 是纳入方向；交汇点 = 库素材硬链接进「链接目录」时撞跨卷约束（外部目录多异卷），PRD 预留的回退口径（复制 or 拒绝提示）随阶段九定。
