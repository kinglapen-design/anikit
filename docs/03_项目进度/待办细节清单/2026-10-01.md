## 工作空间性能优化候选（用户问「还有优化空间吗」盘点，新会话可接）

2026-09-26 已落地（勿重复做）：缩略图 worker 池（固定并发 + 跨请求去重 + 失败记忆 + 格式图标落回）、list/thumbs 命令挪 spawn_blocking、视口可见卡 120ms 合批 priority 插队、非图片条目从缓存缩略图文件头回填 w/h、缓存键有界命名、peaks 缓存换锚。以下按预期收益排序：

1. **fs-changed 精准重扫（收益最大）**：现状 = `workspace-fs-changed` 负载恒 `()`，前端 300ms 去抖后 `rescanLoaded()` **全量重扫所有已加载目录**（展开树深 + 开过视口多时，任何一处变动 = N 个目录全量列举）。改法：notify 回调本就有变更路径——后端 `start_watch` 把路径转 rel 父目录去重集随事件带出（`.anikit` 过滤与 known_ops 回声消重逻辑保持不动），前端按集重扫；路径解析失败 / 越界回退全量。触点：`services/workspace.rs start_watch` / `FS_CHANGED_EVENT` 负载形状、`stores/ws.ts rescanLoaded` 与 `wsOps.initWsListeners`。
2. **`list_dir` 逐文件 syscall 瘦身**：现状每次列举对每个文件最多做——`thumbnail::probe`（读源文件头探尺寸）+ `fresh_thumb_path` 两次 `is_file`（webp/png 双扩展名探测）+ 非图片缓存命中时再 `image::image_dimensions` 读缩略图头 + exe 一次 `is_file`。万级目录每次列举 = 数万次 syscall。方向：②最优先——列目录时 `read_dir` thumbs 缓存目录**一次**拿文件名集合进内存匹配（一次 syscall 消掉 2N 次 is_file）；①次之——probe 尺寸按 (rel,mtime,size) 缓存（同 thumbs 键径）；③ exe 图标探测并入②同径。触点：`services/workspace.rs entry()` / `fresh_thumb_path` / `fresh_exe_icon_path`。
3. **视口挂载无新鲜度重读**：`ContentArea` 挂载 ws 视口即 `loadDir` 全量重读，无「已加载且其间无变更」跳过。依赖 ① 落地（有精准失效后才敢跳过），届时评估。触点：`components/ContentArea.vue` ws 分支、`stores/ws.ts loadDir`。
4. （观察项，不立项）缩略图 worker 池并发上限 = 可用并行度一半钳 4，偏保守；若实机大目录首开仍嫌慢，再评估提上限或按队列深度弹性。
