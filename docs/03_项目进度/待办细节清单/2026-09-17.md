## ① AI 外接通道（MCP）——优先级：先干（must-have）

**背景**：工作重点转向漫剧生产——AI 需大量看资产写提示词、批量生成镜头版本；资源管理器预览不行，导入 APP 后 AI 又读不到库。内置 Agent 太遥远，先用外部 Agent 工具控制 APP（MCP 路线，与 PRD 08_AI功能 L1~L3 同方向）。

**现状红利**：业务全指令化（100+ Tauri command 即工具面）；plugin_ws / frame_stream 两个常驻 WS 通道的「请求-回执」模式可照抄；资产在磁盘上（webp 缩略图 + JSON 元数据），Agent 有文件权限即可零集成看图。

**走法（先快后稳）**：
1. 先写 PRD 立项（工具面 + 传输选型：推荐 localhost HTTP+SSE 直连，stdio sidecar 次之）；
2. **只读 MCP**（≈2-3 天）：search_assets / list_folders / get_asset_detail / 缩略图与源图路径 / 读提示词·标签·描述——薄壳转发既有 command，跑通「批量看资产写提示词」真实流程；
3. 验证好用再上**写入闸**（再 ≈2-3 天）：写提示词/打标签/写描述/导入/改名——全部走既有撤销纪律（单写点 + 单撤销步，危险操作确认闸）；
4. 可选起步垫：库索引导出小命令（树 + 资产清单 + 缩略图路径 dump 成一份 json/md），几小时先有，验证闭环。

**注意**：MCP 工具注册表与重构的「插件 API 注册表」= 同一份资产（见 ②），一次投入两处兑现；8.2 批量生成缩略图共享同一套通道基础。

## ② 代码重构——目标与阶段表（验收标准先行）

**验收标准（三条线，非「能跑就行」）**：
- 回归零：走查 19 条 + 核心流程（导入/整理/预览/分屏拖拽/剪贴板）照旧；
- 结构红线不破：死代码清零、一数据文件一写点、UI 无业务逻辑（规范第 1 条 + 阶段一五查账）；
- **终极验收 = 下次加功能只动自己一个文件夹、不动主线**（以接下来 2~3 个功能的落地痛感为准）。

**扩展性目标（插件包容——代办/随手记/网页/3D/读剧本/QQ 音乐控件全走插件，不进主线）**：
- 一切 kind-switch 改注册表（预览/卡片/视口/菜单/悬浮栏 spec：一类一文件 + 一行注册，barSpecs 为范式）；
- 定义内部插件贡献点：侧栏分段 / 工具栏按钮 / 内容视口 / 悬浮栏 / 模态窗——插件只填坑，坑外摸不到；
- 插件 API = 带元数据的命令注册表（只读白名单先行）= 未来 MCP tools 清单（见 ①）；
- 纪律：可选重件懒加载；功能文件夹自包含、删除即净。

**旧样式烧减（不靠肉眼，三件套）**：
- token 级：grep 烧 legacy 引用（--c1~5 / --text-* / --brand 系）按文件计数至零；
- 组件级：组件目录 + 设计系统预览页为验收面——旧件（AppModal 系/AppButton/AppInput/IconButton 根件/AppSegmented/AppCheckbox 等）逐面板替换，消费方清零才删件；
- 记账：本清单加一页「旧样式烧减账」，烧一笔勾一笔。

**阶段表（垂直切片，每片独立可交付可回滚，逐片过走查脚本）**：
- A 地基（1~2 天）：盘点 + 安全网（探针修/如实挂起、typecheck+cargo test 基线、走查清单固化为验收脚本）；
- B 扩展点抽取：注册表四件（预览/卡片/视口/插件贡献点），一件一提交；
- C 旧样式烧减：按三件套逐面板烧，一面板一提交；
- D 耦合手术：待办细节清单里「补丁摞补丁」业务按迭代逐个拆。

**与阶段七 UI 重构余量（预览族等打磨）不冲突、可并行**（用户定：AI 线先走，重构余量穿插消化）。
