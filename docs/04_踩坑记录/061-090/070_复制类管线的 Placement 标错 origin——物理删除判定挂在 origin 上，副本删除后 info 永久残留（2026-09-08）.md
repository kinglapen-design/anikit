## 070 复制类管线的 Placement 标错 origin——物理删除判定挂在 origin 上，副本删除后 info 永久残留（2026-09-08）

- **现象：** 用户实机测出——创建副本后删除这个文件（丢回收站 → 彻底清除），`assets/{新ID}.info` 物理目录还在，数据层记录已清，成「无主资产」孤儿（开库自检只能扫出警告，源头不断）。
- **根因：** `duplicate_placements` 把副本的唯一 Placement 标为 `origin: false`（链接语义，模块头注释自述"duplicate = info 目录整体复制 + 新 ID + 链接 Placement"），但 PRD 定义副本 = 物理复制为全新资源（新 ID、独立 info），**从此完全独立**——它是物理本体，落点理应是 origin Placement。回收站彻底清除按「快照含 origin = 资产本体在站」判定物理删除（2026-08-19 位置级模型），副本被当「纯位置记录」只删记录、不动磁盘。同管线导入建档 / 克隆文件夹都正确挂了 origin=true，只有创建副本标错。同根因还连带三处暗伤：① 单位置副本不满足「设为原始文件」菜单条件（`!origin && liveCount > 1`），用户无自救入口；② 重命名副本走链接语义只改显示名，磁盘 originName 不同步；③ 副本刻意保留源 hash 利于导入查重命中，但查重选「用已存入文件导入」找不到 origin 直接报「资源数据异常：缺少原始位置记录」。
- **修法：** ① duplicate 两分支（同文件夹紧随原件 / 跨文件夹段首前插）origin 改 true，与导入 / 克隆同口径——副本删除随本体物理清除、重命名走磁盘段改名、查重可"用已存入文件导入"；② 存量自愈：开库自检 `fix_missing_origins`——库内有活位置无 origin、且回收站无其 origin 快照的资产，items 序首条位置置 origin（排除「origin 在站、全链接存活」合法过渡态，PRD 01 规则 8；一资产只扶正首条，保 origin 恒 ≤ 1）；③ 回归测试两条：副本删除 → 回收站彻底清除 → 副本 info 物理删、源不动；开库扶正三态（存量副本扶正 / 过渡态不动 / 已有 origin 不多置）。
- **预防：** ① **复制类管线落笔先分「链接指向」与「独立本体」**：产物是新 ID + 独立 info 目录 = 物理本体 → origin Placement；产物只是同一 assetId 的又一个落点 = 链接 → origin=false——duplicate 当初按"在源后面插一条"的直觉写了链接语义，忘了本体身份在 info 复制那一步已经易主；② **凡是挂物理生命周期判定的标记（origin 决定回收站物理删除），新管线接入时要把该标记的下游消费者列出来逐一过**（回收站 purge / 重命名磁盘段 / 查重 useExisting / 设为原始文件菜单），只写创建侧不查消费侧必漏；③ 数据模型允许「无 origin 资产」存在（规则 8 用户自主态）时，物理回收路径不能只靠 origin 一条线兜底——本坑靠开库自检扶正收口，同类"合法但回收不到"的态要在设计时就点名。
