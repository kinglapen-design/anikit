# 090. 共享池时代判定口径残留——无主扫描按当前库引用集，他库资产全误报无主（2026-09-26）

## 现象

空间内建第二个资源库 / 切换资源库时，弹「发现 N 个无主资产文件」警告：新建的空库报 908 个（全是另一库的资产），切回旧库又报新库刚导入的 1 个。资产实际都好好的。

## 原因

assets 池 2026-08-12 已上移到**空间级**（多库共池，删除孤儿清理 / 合并都建立在共享语义上），但开库自检的无主 info 扫描（2026-09-03 随资产污染修复落地）判定引用集时仍用**当前库**的 folders ∪ recycle——池是空间级、判定是库级，口径错位：凡他库引用的资产，在当前库视角全是"数据层无记录"。

单库空间时代这个 bug 隐形（唯一库即全部引用），多库一建即爆。

## 解法

引用集改空间级并集：`space::referenced_assets_space` = 空间内各库 folders ∪ recycle 磁盘态并集，再 ∪ 当前库内存态（自检修复未落盘的窗口期保守兜底）；`scan_orphan_infos` 签名改传引用集。并集构建失败（某库数据文件损坏）→ 跳过孤儿判定只清空壳——**宁可漏报不可误报**（误报会诱导用户清掉他库资产，漏报只是下轮再扫）。

## 预防

- **凡「判定资产归属 / 是否被引用」的逻辑，先问口径是库级还是池级**——assets 池空间级化后，一切按当前库 folders/recycle 反推资产存亡的写法都是错的（孤儿清理 delete_library 的 library_orphans 一开始就是各库并集，是对的；无主扫描后落地反而踩坑）。
- 多库场景的回归测试要进自检类功能的验收清单：单库绿 ≠ 多库对。
