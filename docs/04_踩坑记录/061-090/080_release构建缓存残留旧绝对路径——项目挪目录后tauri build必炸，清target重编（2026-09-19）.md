# 080. release 构建缓存残留旧绝对路径——项目挪目录后 tauri build 必炸，清 target/release 重编（2026-09-19）

## 现象

项目日常 dev / cargo test 一切正常，`pnpm tauri build --no-bundle` 打 release 时报错：`failed to read plugin permissions: failed to read file '\\?\E:\workspace\01_projects\...\target\release\build\tauri-xxx\out\permissions\app\autogenerated\commands\app_hide.toml'：系统找不到指定的路径 (os error 3)`——注意路径是 `E:\workspace\...`，而项目实际在 `E:\anikit\workspace\...`，前缀整段丢失。

## 原因

`target/release/` 是项目还在旧路径（`E:\workspace\...`）时构建留下的缓存：cargo 指纹与 tauri 构建脚本的 out 目录里烧死了旧绝对路径。dev 构建用的是 `target/debug/`，持续增量早就是新路径，所以只有 release 一碰就炸。路径失效具有潜伏性——不打包永远不暴露。

## 解法

把陈旧 release 目录整个挪开重编（别原地删，留退路）：`mv src-tauri/target/release src-tauri/target/release.stale-YYYYMMDD` → `pnpm tauri build --no-bundle` 全量重编（本机 1m54s）→ 验证包没问题后再删旧目录。

## 预防

- 项目目录挪位置 / 改名的当天，顺手把 `src-tauri/target/` 整个挪开重建（debug + release 一起），不留潜伏雷。
- 打包链只认 `pnpm tauri build`（踩坑 076），别用 `cargo build --release` 直编。
- 报错里出现「路径前缀与实际项目位置不符」即缓存陈旧信号，先怀疑 target 缓存，别怀疑代码。
