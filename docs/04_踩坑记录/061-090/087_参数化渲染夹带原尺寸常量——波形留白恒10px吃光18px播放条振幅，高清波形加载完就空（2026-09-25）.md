# 087 参数化渲染夹带原尺寸常量——波形上下留白恒 10px 吃光 18px 播放条振幅，高清波形「加载完就空」（2026-09-25）

## 现象

用户实机报两条：① 音频播放条加载完后波形是空的（只剩品牌色播放头）；② 加载前能看到的那条波形是「旧的波形图」（info 缩略图拉伸，糊）。两条同一根因：按需重采样（get_waveform）的高清图生成出来就是空的——加载前前端回退显示 info 缩略图（旧图），加载完换成高清图反而全空。

## 原因

`render_waveform`（src-tauri/src/services/media.rs）的上下留白写死 `WAVEFORM_MARGIN = 10`（px）——这是 5.1 定稿时为 **640×272 缩略大图**定的常量。2026-07-26 波形改按需重采样后，同一渲染函数服务任意尺寸请求，但留白没有跟着参数化：播放条内容高只有 18px，`max_half = h/2 - margin = 9 - 10 = 0`（saturating_sub 兜成 0）→ 每列纵线区间退化成中线一个点 → 全图只剩 1px 细中线，mask 后肉眼全空。大图（272 高）请求一直正常，所以旧预览大图时代从没暴露；WaveProgress 接入播放条（2026-09-09）后 18px 小高度请求才踩中——又被 2026-09-09 起的前端高度塌陷 bug（`.fbp-progress` 无高 → 请求 0 高）盖着，直到塌陷修好（同日 §59）才浮出来。

## 解法

留白随高度等比收缩：`let margin = WAVEFORM_MARGIN.min(h / 27)`（10/272 = 原比例）——272 及以上恒 10（原口径不变），48px margin 1，18px margin 0 满幅（播放条波形本就该满幅，对齐 Eagle）。回归钉 `render_waveform_small_height_keeps_amplitude`：18px 高 0.8 振幅断言 cy-6 处有波形。缓存无需处理：cache/waveforms 会话级开库清空（library.rs:216），重启即重渲。

## 预防

- **渲染函数参数化（任意尺寸）时，函数内一切 px 常量都要过一遍「随尺寸缩放还是恒定」**——留白 / 描边 / 圆角 / 发丝宽度这类按原稿尺寸拍的值，小尺寸请求必然失真。本坑若当时把 margin 写成比例值就不会发生。
- 「回退图正常、高清图反而坏」是特征信号：两条产物链（info 缩略图 vs 按需重渲）共用渲染函数但尺寸档不同，**尺寸档差异**先查。
- 全空类观感 bug 别只信 DOM / 像素单点的旧测试——旧测试全是 272 高断言，小高度档一个都没有；参数化入口的测试矩阵应覆盖实际请求的极端档（本坑最小 18px vs 原稿 272px）。
