# 089 预览全局单例「跟激活面板飘」——新标签抢预览 / 分屏丢预览 / 双面板左右跳（2026-09-25）

## 现象

用户实机三报（附演示视频）：① 预览中点「+」新标签，预览不退反飘进新标签（新标签应是干净文件列表，还得手动 Esc 退一次）；② 预览中分屏，预览「自己丢失」回到文件列表；③ 想左右两个面板各预览一张图对比，双击后预览在左右之间来回跳。

## 原因

预览是全局单例（`preview.assetKey` 唯一），而显示判定写的是「**谁激活谁显示**」（ContentArea `previewActive = preview.assetKey && 本 panel 激活`）——预览没有「属主」概念，跟着 dockview 的激活面板走。于是：新标签激活 = 预览飘进新标签；分屏新 panel 激活 = 原标签预览「丢」给它；两面板轮流双击轮流激活 = 预览左右跳。三现象同根，与「是不是同一文件夹」无关。修复方向也顺理成章：预览记属主（`preview.panelId` = 打开时激活面板），显示判定改「assetKey 非空且本 panel 是属主」，B 面板双击 = 属主明确改记 B，属主标签关闭即退出（tabs.syncMirror 顺手清理）。

## 探针排查过程（三个探针坑比 bug 本身更值得留档）

1. **dockview 只渲染激活 panel 内容**（非激活卸载）——按 `.content-area` 数组逐面板读预览态恒只得 1 个元素，首版快照全废；**tab 激活走 pointerdown**——合成 `click()` 不激活 tab（pinia state 实证 active 没变），事件序列必须 pointerdown + pointerup。
2. **多组时每组各自渲染自己激活的 tab**——分屏后 `.content-area` 数量 = 组数，`querySelector` 拿第一个 = 组0（属主预览）被误读成「新分屏抢了预览」；断言要按「组序数组」判定（期望 `[属主 True, 新分屏 False]`）而非拿首元素。
3. 右键菜单挂在 TabItem 根（`.dock-tab`，`.dv-tab` 的**子级**）——contextmenu dispatch 到外层 `.dv-tab` 不到监听元素（事件向上冒泡不到孩子），菜单静默不开。

## 预防

- **全局单例状态 + 多面板 UI = 必须显式绑定属主**（面板 / 窗口 / 上下文），「谁激活谁生效」的隐式跟随在多面板下必飘——本次是预览，同类隐患盘点时按这个信号查（单例 store × 多实例宿主）。
- 探针驱动 dockview 三记：只渲激活 panel（快照按激活切换逐次读）/ tab 激活用 pointerdown 序列 / 右键菜单 dispatch 到 Vue 监听元素本体（组件根类名先查再写，别猜外壳）。
- pinia state 可直接读（`#app.__vue_app__.config.globalProperties.$pinia.state.value`）——行为与状态对不上时先打 state 再猜 DOM，本轮一步锁定「click 没激活」靠的就是它。
