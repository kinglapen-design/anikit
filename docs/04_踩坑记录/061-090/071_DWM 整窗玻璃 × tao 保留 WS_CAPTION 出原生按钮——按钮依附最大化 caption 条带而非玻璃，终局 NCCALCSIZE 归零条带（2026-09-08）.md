## 071 DWM 整窗玻璃 × tao 保留 WS_CAPTION 出原生按钮——按钮依附最大化 caption 条带而非玻璃，终局 NCCALCSIZE 归零条带（2026-09-08）

- **现象：** 无边框 + 云母主窗口（063 六轮终态配置），最大化/全屏后右上角冒出一组系统默认窗口按钮（最小化/还原/关闭）压在自定义 `.win-controls-overlay` 上；最大化**过渡动画里同样闪这组按钮**（一轮修法落地后复验实机再报）；常态也有——hover 窗口顶边细条会露出原生关闭钮的红色 hover 细条（用户实机三报）。
- **原因：** tao 建窗**无条件保留** `WS_CAPTION | WS_SYSMENU | MIN/MAXIMIZEBOX`（`window_state.rs` to_window_styles），无边框靠 WM_NCCALCSIZE 返 0。DWM 把原生标题栏按钮画在「WS_CAPTION + 顶部非客户区条带」上：常态条带 = Win11 顶边 inset（tao `calculate_insets_for_dpi`，dpi/96 圆整，150% = 2px）细条；**最大化条带 = tao NCCALCSIZE 最大化特判（客户区 = rcWork，tao 0.35.3 `event_loop.rs:2124`）与系统默认最大化矩形（rcWork 外扩 frame 厚度）之间让出的 caption 区**。整窗玻璃延伸（-1）是云母载体、让按钮更醒目，但**按钮的容身之地是条带不是玻璃**：最大化过渡动画期 DWM 按目标态条带绘制，与玻璃 margins 无关。
- **三轮修法两轮翻车（实机用户连报）：** ① 最大化态撤玻璃——按钮没了但玻璃 = 云母载体被抽，整窗纯黑；② 摘 `WS_CAPTION`——按钮没了但 caption 同时扛着 DWM 阴影/圆角/边框体系（007/063 终局），全窗白边环、阴影丢失；两轮当日回滚。③ 「动画前撤玻璃」（守卫拦 `WM_WINDOWPOSCHANGING` 预撤 + 前端实色兜底）——稳态按钮没了、实色兜住纯黑，但**最大化动画期照闪**：动画期按钮由 WS_MAXIMIZE + 条带驱动绘制，撤玻璃够不着。教训升级：玻璃、caption、**最大化条带**三者职责必须分开列清，动哪个先问另外两层。
- **终局解法（对齐 Codex/Electron 无边框路线）：** 守卫 subclass 接管两条消息让最大化条带不存在——`WM_NCCALCSIZE`（wParam≠0 且已最大化）：客户区 = 整窗矩形（`rgrc[0]` 输入即窗口矩形，保持不动，返回 0 不下放 tao；非最大化照旧下放，shadow insets 边框阴影体系不动；自动隐藏任务栏的边客户区留 1px，照搬 tao `has_edge`/`SHAppBarMessage` 补偿）；`WM_GETMINMAXINFO`：先下放让 tao 填 min/max 尺寸约束，再覆盖 `ptMaxPosition`/`ptMaxSize` = 所在显示器 rcWork——最大化矩形正好工作区，内容四边不外扩不被裁。**玻璃恒 -1 不再按态切换，云母最大化保留**（Codex 实机先例：最大化云母在、无原生按钮；DWM 并不因最大化关 backdrop），前端 `.window.fx-mica.maximized` 实色兜底同步删除。改动 = `window_fx::main_window_guard` ② + lib.rs 删 Resized 切换状态机 + App.vue 删兜底。
- **预防：** 自绘标题栏窗口的原生按钮问题，先分清按钮绘制依附的**三要素**——玻璃延伸 / `WS_CAPTION` / 非客户区条带，再定杀哪环；「过渡动画期」的绘制按**目标态 frame 几何**进行，动画前改状态（撤玻璃）够不着动画期的绘制依据（条带几何）。DWM 层 headless 截不到（063），只能实机验；探针截屏必须先做前台断言。对照组思路值钱：**找一个做对了的同类应用（Codex：最大化云母在、无按钮）反推其窗口配置路线**，比纯机制推演快。
