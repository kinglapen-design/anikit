# 域闸命令跨域复用——无主资产打开走工作空间 reveal_path 必败（2026-10-13）

## 现象

无主资产警告弹窗（OrphanInfosAlert）每行尾部的「在资源管理器中打开」按钮，点一次弹一条「路径不在当前工作空间内」，任何无主资产都打不开。

## 原因

前端 `revealOrphanInfo` 图省事直接复用了通用命令 `reveal_path`（commands::workspace）。该命令内嵌 `validated_ws_path` 校验：路径必须在**当前空间 workspace/ 目录内**——这是工作空间右键族的越界闸。而无主资产躺在**空间级 assets 池**里，与 workspace/ 平级，永远过不了这道闸，必败。

隐蔽点：命令名 `reveal_path` 不带域字样的「通用感」掩盖了它内嵌的域校验；编译层与单测层全无信号（校验是运行时路径比对），按钮自 2026-09-21 换代接入起就没真正能用过，直到用户实机点出报错。

## 解法

域专属命令各配校验基准：新命令 `reveal_orphan_info`（commands::library）走 `validated_pool_path`——与 `validated_ws_path` 同构，但基准从 workspace 根换成空间级 assets 池（`paths::assets_dir(space.root)` + `is_under` 同闸拦 `..` 逃逸 + 存在性检查），过了才 `shell_open::reveal`。前端 `revealOrphanInfo` 改调新命令。回归测试 `pool_path_validation_accepts_info_rejects_others` 钉死池内放行 / workspace 路径拒 / 不存在拒 / `..` 逃逸拒四态。

## 预防

- **带「路径必须在 X 内」校验的命令是域专属命令，跨域调用前先看校验基准**——名字越通用（reveal_path / open_path）越容易让人忽略它内嵌的域闸。新需求落点不在原域（workspace → assets 池）时，正确动作是抄同构壳换基准，不是直接复用。
- 报错文案自带域名（「不在当前**工作空间**内」）是定位捷径：用户截图里这句话就直接指认了校验基准错了域。
- 弹窗行尾操作钮这类「接上就完」的小链路，至少要点一次真实数据再走查通过——纯静态接线 + 无回归测试 = 必败链路可以潜伏一个月。
