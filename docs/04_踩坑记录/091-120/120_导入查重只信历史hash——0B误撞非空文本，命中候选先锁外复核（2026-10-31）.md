# 导入查重只信历史 hash

## 现象

多个 0 KB TXT 导入时，全部与一条 21.3 KB 的 `提示词.md` 报重复。空文件之间确实内容相同，但它们与这条非空 Markdown 的匹配明显错误。

## 原因

该 Markdown 的 origin 真实大小为 21,805 字节、真实 SHA-256 为 `22ef4e…`，metadata 却保留空内容哈希 `e3b0c4…`。导入管线只用 metadata.hash 建索引，命中后直接生成冲突，不再读取 origin。文本保存回写与读取触点自愈只能覆盖各自路径，不能保证历史记录已经全部修正。

## 解法

查重分类前复核命中候选：短锁筛选本批 incoming hash 对应的可见普通资产，锁外并行重算 origin；size / hash 漂移先回写 metadata 再同步索引，随后才按真实哈希分类。并发变更通过旧名、旧 size、旧 hash 比对跳过，不覆盖新状态。真实重复仍走原冲突流程。

回归测试必须先在旧实现复现假冲突，再验证修复后正常导入、元数据修正，以及另一个真正相同的空文件仍会判重。

## 预防

内容指纹有明确更新机制，也不等于所有历史快照必然新鲜。涉及“相同 / 不同”的破坏性或大体积决策时，不能无条件信任可能漂移的派生字段；命中后的复核范围应限于候选，重 IO 不得占全局库锁。测试要同时覆盖“误报消失”和“真重复保留”，防止用取消空文件判重来掩盖问题。
