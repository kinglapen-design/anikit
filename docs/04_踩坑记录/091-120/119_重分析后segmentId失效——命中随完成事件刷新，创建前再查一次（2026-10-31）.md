# 重分析后 segmentId 失效

## 现象

重试视频分析后，界面仍显示旧命中，点击「创建虚拟片段」返回「语义片段不存在，请重新搜索后再创建」。后端数据库中的新 segmentId 与界面保存的旧值不同。

## 原因

基础分析采用替换式写入，重试会删除并重建分段，segmentId 随之变化。查询结果属于派生数据快照，不会自动随 SQLite 更新。完成事件和用户的下一次点击还可能连续发生，单靠延迟刷新仍有竞态。后端拒绝陈旧命中是正确防线，不能为通过创建而接受旧索引。

## 解法

App 初始化即注册分析完成监听，完成后按各面板当前视口重新查询并更新 segmentId，覆盖从 MCP 启动的任务。创建动作本身再重查当前面板一次，取得最新命中后交给后端复核模型、分析版本和源指纹。这样既不放宽陈旧数据校验，也消除了完成事件与点击之间的竞态。

最终已验证「重试分析 → 命中更新 → 右键创建 → 范围播放」，MCP 32 工具和独立便携包同链通过。

## 预防

派生 ID 必须按生命周期管理，不能把一次查询结果当永久身份。修改派生索引后应刷新所有读模型；用户动作使用派生 ID 时，还要考虑事件尚未到达、刷新尚未完成的窗口期。验收不能只测创建时的静态索引，必须覆盖重分析后创建。
