# 098 dockview 对已激活 panel 重复 openPanel 无守卫——pane 聚焦 / 切标签即 detach 重挂内容，内嵌滚动位置归零（2026-10-02）

- **现象：** md 预览滚到中部后，点击另一 pane 再点回来（pane 重新聚焦），文档自动回到第一行；同 group 切换标签页再切回同样归零。刷新 / 重载类排查全部不成立——文件没有重读、组件没有重挂载、元素引用同一、display 正常，唯独 scrollTop 变 0。
- **根因链：** `panelApi.setActive()` → `dockviewComponent.setActivePanel` → `group.model.openPanel(panel)`——dockview-core（7.0.4）的 `openPanel` 对**已是 active 的 panel** 无守卫，直接 `contentContainer.renderPanel(panel)`：`renderPanel` 先把 panel 的内容元素 `remove()`，再经 `renderContainer.attach()` 重新追加（dist/cjs/dockview/components/panel/content.js:131）。**同元素 detach → reattach，浏览器销毁滚动盒，scrollTop 归零**。MutationObserver 实锤轨迹 = `.dv-content-container` childList `-1` 后 `+1`。Vue 全程无感（组件不重建、不重渲染），所以任何「状态为什么变了」的排查都扑空——变化发生在 DOM 层、由第三方库驱动。同 group 切标签页是同一 `renderPanel` 换 panel 路径，旧 panel 元素同样被 remove（切回时重新 append），内嵌滚动一样丢。网格视口（AssetGrid）不受害 = 它的滚动状态本来就在 store（ui.scrollPositions 落盘），DOM 重挂后 transform 重算自愈；裸滚动的预览文本类全灭。
- **解法：** 应用层滚动保活（不动 node_modules）：滚动位置记进组件闭包（@scroll 记录，DOM 操作够不着）；MutationObserver 盯本 panel 宿主 `.dv-content-container` 的 childList——变化即 dockview 重挂了内容，凡 scrollTop 小于记录值的容器恢复（首拍直改 + nextTick 补一拍防布局未稳被钳）；切素材 load() 清零防旧位置拉回新文档。v-show（display:none ↔ block）是同款归零的另一条路径（display 恢复后滚动位置不还原），MO 感知不到 DOM 未变的显隐切换，走 watch(editing/split) 恢复。实现 = PreviewText 的 keepEls / keepPos / restoreKeeps。
- **预防：** ①**排查「状态没变但表现丢了」类 bug，先把 DOM 层变化纳入嫌疑**——pinia 状态、组件生命周期、元素同一性都正常时，用 MutationObserver 记录目标元素的子树 / 属性 / 移除事件，一拍即现形（本次 `reads 计数 + sameEl 比对 + MO 轨迹` 三件套一次定位）。②**第三方布局库（dockview / splitview 系）对 panel 内容的 detach/reattach 是常态**（激活、移动、悬浮、跨 group 拖都可能触发），内嵌滚动容器（overflow auto 的 div、textarea、canvas 取景）默认都会丢滚动——新面板接入时滚动保活应作为 checklist 项过一遍。③dockview 的 `openPanel` 重复调用无守卫属上游缺陷（对 active panel 重渲染无意义），若日后升级 dockview 可复查上游是否修复，修了保活机制也无害（恢复条件不触发）。
