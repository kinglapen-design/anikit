# 子目录视口搜索 rel 丢前缀——「按查询锚点剥前缀」映射模型的坑（2026-10-07）

## 现象

工作空间搜索实机二轮三报同根：子目录视口里搜索，命中文件双击预览报「该格式暂时无法播放」、缩略图全空、右键「打开目标文件夹」连环 toast 回退到根。根视口搜索一切正常。

## 原因

`ws_search` 把 Everything 返回的绝对路径按**搜索锚点**（scope 目录的绝对路径）剥前缀算 rel——`path:"根\子目录"` 查询的命中被映射成「相对子目录」而不是「相对工作空间根」。子目录视口搜索时 rel 少了视口段，下游按「根 + 错 rel」拼绝对路径全部落空：预览播放源 is_file=false 降级、缩略图缓存键查不中且入队解析丢弃、跳转目标目录不存在触发幽灵回退。

隐蔽点：**根视口（scope=""）锚点 = 根**，映射恰好正确——首轮探针与自测全在根视口跑，全绿假象。三条看似无关的实机故障，真身是同一个一字母级偏差（剥错前缀）。

## 解法

范围解析改「查询腿」模型：每条腿显式携带（查询锚点 anchor，映射前缀 base）两个角色分开——anchor 给 Everything 查（链接子树时用真实目标路径），base 给命中映射拼（恒为门词法 scope_rel / 链接 rel）。`rel = base + 剥 anchor 后的子路径`，恒工作空间根相对。回归测试 `map_hits_scoped_stays_root_relative` 钉死。

## 预防

- **「剥前缀映射」类代码，anchor 与 base 是两个角色，必须显式分开**——图省事复用一个值，在 anchor ≠ 根的范围场景必然出错（链接目标 / 子目录 scope 都是）。
- 路径映射测试矩阵至少覆盖：根 scope、子目录 scope、链接门 scope 三档——只测根 = 测了个寂寞（本坑实录）。
- 症状不在作案现场：预览 / 缩略图 / 导航三处全坏，病灶在上游一个映射函数——多症状同现先找共同数据生产者，比逐处排查快一个量级。
