# 096 Tauri 拖拽事件坐标是物理像素——125% 缩放下落点命中区整体偏移，混用坐标系全链错位（2026-10-01）

- **现象：** OS 文件拖入悬停高亮（2026-10-01_08 落地）实机走查：指针拖到**侧边栏右侧**就触发视口整片高亮（还没进内容区），拖到**内容视口右侧**反而消失——命中区比视觉区整体向左偏了一截（用户实机 1920 屏 125% 缩放）。
- **根因链：** `webview.onDragDropEvent` 的 `payload.position` 类型是 `PhysicalPosition`（@tauri-apps/api 2.11.1 `webview.d.ts:25` 类型定义实证）——**物理像素**；而前端命中用的 `document.elementFromPoint` 与 `getBoundingClientRect` 都是 **CSS 逻辑像素**。显示器缩放 100% 时两者相等，一切正常；**缩放 125% 时物理 = 逻辑 × 1.25**，事件坐标直接当逻辑坐标用 = 命中区放大 1.25 倍 → 屏幕上看就是整体向左偏移（左侧越界进侧边栏、右侧缺一块）。此前库导入的落点解析（`App.vue onDrop` 用事件坐标 `elementFromPoint` 找 `[data-folder-id]`）从 2026-09 起就带着同一错位潜伏——树行导入目标在缩放下静默错（点在树行右半会解析成视口或落空，落回「导入到当前文件夹」兜底，无报错所以无人察觉）；直到高亮把命中区可视化，错位才显性。
- **解法：** `App.vue` 的 `onDragDropEvent` 处理器入口统一换算：`position / window.devicePixelRatio` 转逻辑像素，再传给悬停高亮（`osFileDragHover`）与落盘（`onDrop`）两条路径——一处换算全链受益（库导入树行落点随修）。
- **预防：** ①**凡是把系统 / Tauri 事件的坐标喂给 DOM API，先确认坐标空间**——Tauri 侧窗口位置、尺寸、拖拽坐标默认物理像素（dpi 模块 Physical* / Logical* 两套类型就是为此存在），DOM / PointerEvent 恒逻辑像素；混用前先除 `devicePixelRatio`。②「缩放 100% 正常、>100% 错位」类 bug 的共同指纹是**命中区 / 绘制区按比例偏移**，实机缩放不是 100% 时优先怀疑坐标系。③兜底型逻辑（落点解析失败回退当前目录）会把定位类错误吞成「功能大致能用」，长期潜伏——给关键落点加可视化（如本次高亮）是让错位显性的有效手段。
