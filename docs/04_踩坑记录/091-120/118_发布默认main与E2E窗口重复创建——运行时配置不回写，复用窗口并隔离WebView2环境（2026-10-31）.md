# 发布默认 main 与 E2E 窗口重复创建

## 现象

开发模式传 `TAURI_CONFIG={"app":{"windows":[]}}` 可以启动验收实例，但同一方式运行 release 时在 setup 阶段失败：`a webview with label main already exists`。构建成功不能证明发布实例可启动。

## 原因

release 已嵌入默认 `main` 窗口，`TAURI_CONFIG` 不会按运行时环境变量重建配置。验收代码又无条件创建同名窗口，于是重复创建。该问题与模型、便携包 DLL 无关。

## 解法

创建前先查 `app.get_webview_window("main")`，只在不存在时构建验收窗口。release 复用默认窗口，以 `WEBVIEW2_USER_DATA_FOLDER` 隔离浏览器 profile，以 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 临时提供调试端口。`open_devtools()` 只在 debug 构建启用，release 通过该临时端口验证真实页面。普通启动的单实例、协议注册和默认窗口行为不变。

修复后独立便携包的模型、CPU、检索、片段和 MCP 全链通过，ZIP 完整性也通过。

## 预防

验收必须实际启动 release 页面，不能只验证编译或后端端口。分别覆盖「配置无 main 需要新建」与「默认 main 已存在需要复用」两条路径。浏览器 profile 必须随隔离配置目录走；不要把开发配置覆盖误当成 release 运行时能力，也不要为图方便永久开放 CDP。
