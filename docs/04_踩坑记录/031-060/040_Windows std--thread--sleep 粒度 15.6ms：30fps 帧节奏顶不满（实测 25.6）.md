## 040 Windows std::thread::sleep 粒度 15.6ms：30fps 帧节奏顶不满（实测 25.6）

- **现象：** 2026-08-20 spike 壳 pace=1 原速播放实测：50 路 H264（30fps 源）每路稳态仅 25.6fps；50 路 GIF（10fps 源，100ms/帧）每路 9.1fps 接近顶满。
- **原因：** Windows 默认定时器分辨率 15.6ms——`sleep(33ms)` 实际睡到 ~48ms（向上取整到粒度倍数），30fps 节奏天然顶不满；100ms 睡眠只 +15% 偏差，动图场景影响小。
- **解法：** spike 阶段不处理（25.6fps 卡片预览已流畅，CPU 29% 数据有效）；铺量两路——① `timeBeginPeriod(1)` 提定时器精度（进程级，退出配 timeEndPeriod）；② 更优：节奏权交消费端——后端全速/半速解码、帧槽恒持最新帧，前端 rAF 节奏取帧渲染（天然 60Hz 对齐、无睡眠精度问题，帧槽模型 spike 已验证）。
- **预防：** Windows 上做帧调度/节流，凡 sleep < 50ms 都要想到 15.6ms 粒度；高精度场景优先"生产者全速 + 消费者节奏"模型，别让生产者睡。
